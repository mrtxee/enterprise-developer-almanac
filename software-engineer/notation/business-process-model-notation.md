## Что такое BPMN

BPMN (Business Process Model and Notation) — международный стандарт для визуального моделирования бизнес-процессов. Он позволяет наглядно, точно и однозначно описывать, как работают бизнес-процессы — от заказа до доставки, от оформления кредита до обработки возврата.

Объекты моделирования — бизнес-аналитики, разработчики, тестировщики, руководители и клиенты.

> BPMN — это «язык» для рисования процессов. Как UML — для систем, так BPMN — для процессов.

## Зачем нужен BPMN

| Проблема | Как решает BPMN |
| --- | --- |
| Бизнес говорит: «Нужно ускорить обработку заказов» | Рисуется текущий процесс → видны задержки |
| Разработчики не понимают, что от них хотят | BPMN-диаграмма — точный «технический» рецепт для разработки |
| Процессы описаны в Word-документах — никто не читает | Диаграмма визуальна, понятна даже менеджеру без технического бэкграунда |
| При изменении процесса всё ломается | BPMN-диаграмму можно сгенерировать в код (BPMN 2.0) → автоматизировать в системах (Camunda, Activiti, Flowable) |
| Нет единого представления процесса | BPMN — единый язык для всех участников проекта |

> BPMN — это мост между бизнесом и IT.

## Основные элементы BPMN

| Группа | Символ | Назначение | Пример |
| --- | --- | --- | --- |
| Flow Objects | круг, прямоугольник, ромб | Основные «строительные блоки» процесса | События, Действия, Шлюзы |
| Connecting Objects | стрелки | Связывают элементы | Потоки (Sequence Flow), Сообщения (Message Flow) |
| Swimlanes | пул и полосы | Показывают, кто отвечает за действия | Пул — система/организация, Полоса — роль/отдел |
| Artifacts | заметки, группы | Дополнительная информация | Данные, Заметки, Группы |
| Data | значки данных | Управление данными в процессе | Вход/выход данных, данные-объекты |

## Ключевые символы

| Символ | Название | Значение |
| --- | --- | --- |
| Круг | Event (Событие) | Что начинает или заканчивает процесс: `Start Event` — начало, `End Event` — окончание, `Intermediate Event` — промежуточное событие (таймаут, получено сообщение) |
| Прямоугольник с закруглёнными углами | Activity (Действие) | Работа, которую нужно выполнить: `Task` — простая задача, `Sub-Process` — вложенный процесс |
| Ромб | Gateway (Шлюз) | Решение, какой путь выбрать: `Exclusive Gateway` — один из путей (XOR), `Inclusive Gateway` — один или несколько (OR), `Parallel Gateway` — все пути одновременно (AND) |
| Стрелка | Sequence Flow | Порядок выполнения действий внутри одного пула |
| Пунктирная стрелка | Message Flow | Обмен сообщениями между разными участниками (пулами) |
| Пул (Pool) | Участник процесса | Например: «Клиент», «Сайт», «Бухгалтерия» |
| Полоса (Lane) | Роль внутри пула | Например, в пуле «Сайт» — полосы: «Frontend», «API», «База данных» |

## Пример 1: Оформление заказа в интернет-магазине

**BPMN-диаграмма**

```mermaid
---
title: Пример BPMN: оформление заказа в интернет-магазине
---
graph TD
    A[Start Event: Клиент зашёл на сайт] --> B[Task: Выбрать товар]
    B --> C[Task: Добавить в корзину]
    C --> D[Task: Перейти к оформлению]
    D --> E[Gateway: Есть ли адрес доставки?]
    E -->|Да| F[Task: Выбрать адрес]
    E -->|Нет| G[Task: Ввести новый адрес]
    F --> H[Task: Выбрать способ оплаты]
    G --> H
    H --> I[Gateway: Оплата прошла?]
    I -->|Да| J[Task: Создать заказ в системе]
    I -->|Нет| K[Task: Показать ошибку оплаты]
    J --> L[Task: Отправить email подтверждения]
    L --> M[End Event: Заказ оформлен]
    K --> N[End Event: Оплата не прошла]
```

**Разбор**

| Элемент | Роль |
| --- | --- |
| Пул | `Клиент` + `Сайт` (два участника) |
| Полосы | В пуле «Сайт»: `Frontend`, `Backend`, `База данных` |
| События | Начало (клиент зашёл), конец (заказ оформлен) |
| Задачи | «Добавить в корзину», «Отправить email» |
| Шлюзы | Решения: «Есть адрес?», «Оплата прошла?» |
| Сообщения | Сайт → Клиент: «Подтверждение заказа» |

> Это не просто схема — это точная спецификация, которую можно автоматизировать в Camunda, Flowable, SAP или другом BPMN-движке.

## Пример 2: Обработка возврата товара в компании

**BPMN-диаграмма**

```mermaid
---
title: Пример BPMN: обработка возврата товара
---
graph TD
    A[Start: Клиент отправил запрос на возврат] --> B[Task: Проверить срок возврата]
    B --> C[Gateway: Срок не истёк?]
    C -->|Да| D["Task: Создать RMA (возвратный номер)"]
    C -->|Нет| E[Task: Отказать в возврате]
    E --> F[End: Возврат отклонён]
    D --> G[Task: Отправить инструкцию клиенту]
    G --> H[Task: Ждать возврат товара]
    H --> I[Task: Проверить состояние товара]
    I --> J[Gateway: Товар в порядке?]
    J -->|Да| K[Task: Вернуть деньги]
    J -->|Нет| L[Task: Отказать с объяснением]
    K --> M[Task: Отправить уведомление о возврате денег]
    L --> N[Task: Отправить уведомление об отказе]
    M --> O[End: Возврат завершён]
    N --> O
```

**Польза**

| Преимущество | Объяснение |
| --- | --- |
| Видны задержки | Например, «Ждать возврат товара» может занимать 7 дней |
| Видно, кто отвечает | Клиент отправляет, отдел возвратов проверяет, бухгалтерия возвращает деньги |
| Можно автоматизировать | Система автоматически генерирует RMA при условии «срок не истёк» и отправляет email через шаблон |
| Можно тестировать | Проверяются все ветки: «возврат с браком», «срок истёк», «оплата не прошла» |
| Можно обучать сотрудников | Новая сотрудница смотрит на диаграмму и сразу понимает, как обрабатывать возврат |

## Пример 3: Создание нового сотрудника (HR-процесс)

```mermaid
---
title: Пример BPMN: создание нового сотрудника
---
graph TD
    A[Start: HR получил запрос на найм] --> B[Task: Проверить бюджет]
    B --> C[Gateway: Бюджет есть?]
    C -->|Да| D[Task: Отправить предложение кандидату]
    C -->|Нет| E[Task: Отказать в найме]
    E --> F[End: Найм отклонён]
    D --> G[Task: Подождать ответ кандидата]
    G --> H[Gateway: Кандидат согласен?]
    H -->|Да| I[Task: Инициировать оформление]
    H -->|Нет| J[Task: Уведомить рекрутера]
    J --> K[End: Кандидат отказался]
    I --> L[Task: Подготовить документы]
    L --> M[Task: Зарегистрировать в HRIS]
    M --> N[Task: Назначить менеджера]
    N --> O[Task: Подготовить рабочее место]
    O --> P[Task: Отправить приветственное письмо]
    P --> Q[End: Сотрудник принят]
```

> Процесс можно автоматизировать в HR-системе (например, SAP SuccessFactors): при получении запроса автоматически проверяется бюджет, при согласии кандидата генерируются документы, при оформлении создаётся аккаунт в Active Directory.

## Преимущества BPMN

| Преимущество | Объяснение |
| --- | --- |
| Универсальный язык | Понятен бизнесу, IT, тестировщикам, руководству |
| Визуальный | Диаграмму проще понять, чем 20 страниц Word |
| Точность | Каждый символ имеет строгое значение — нет двусмысленности |
| Автоматизация | BPMN 2.0 — это не только схема, а исполняемый XML-код |
| Поддержка инструментов | Camunda, Activiti, Flowable, Signavio, Bizagi, ARIS, Lucidchart |
| Соответствие стандартам | ISO 19510 — международный стандарт моделирования процессов |

## Как создать BPMN-диаграмму

**Инструменты**

| Инструмент | Особенности |
| --- | --- |
| Camunda Modeler | Бесплатный, профессиональный, поддерживает BPMN 2.0 + автоматизация |
| Lucidchart | Онлайн, дружелюбный, шаблоны, интеграция с Confluence |
| Draw.io / diagrams.net | Бесплатно, легко, можно экспортировать в PNG/PDF |
| Signavio | Корпоративный, мощный, для больших процессов |
| Bizagi Modeler | Для бизнес-аналитиков, с визуальным дизайном |
| Visual Paradigm | Поддерживает BPMN + UML + ERD |

## Лучшие практики

| Правило | Объяснение |
| --- | --- |
| Начинайте с цели | Не рисуйте «всё сразу» — сначала определите, что нужно улучшить |
| Используйте пул и полосы | Показывайте, кто делает что — это ключ к пониманию |
| Не перегружайте диаграмму | Если больше 15–20 элементов — разбейте на подпроцессы |
| Используйте имена | Называйте задачи глаголами: «Отправить письмо», а не «Письмо» |
| Согласуйте с бизнесом | Покажите диаграмму менеджеру — если он не понимает, перерисуйте |
| Создавайте версии | `v1.0`, `v1.1` — процессы меняются |

## Когда использовать BPMN

| Ситуация | Рекомендация |
| --- | --- |
| Описывается сложный бизнес-процесс | Используйте BPMN |
| Автоматизируется процесс (BPM-система) | Используйте BPMN 2.0 |
| Обучаются сотрудники | Используйте BPMN — нагляднее, чем инструкции |
| Согласование с IT | BPMN — общий язык |
| Нужно документировать процесс | BPMN — стандартный формат |
| Простой процесс в 3 шага | Можно обойтись без BPMN — просто список |

## Итог

| Что было | Что стало |
| --- | --- |
| Размытые требования: «Сделайте, чтобы заказы быстрее обрабатывались» | Чёткая диаграмма: «Почему заказы медленно обрабатываются — вот где задержка» |
| Споры: «А как это работает?» | Диаграмма — единственный источник правды |
| Ручная работа | Возможность автоматизировать процесс |
| Непонимание между отделами | Один язык для всех — бизнес, IT, QA, руководство |

> _«BPMN — это не про то, как рисовать красивые схемы. Это про то, чтобы бизнес и IT перестали говорить на разных языках.»_ — BPMN Specification Group, OMG

**BPMN — это не просто схема, а инструмент управления бизнесом.**
