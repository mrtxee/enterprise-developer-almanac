## Определение FURPS+

**FURPS+** — стандартизированный набор критериев качества программного обеспечения, разработанный для систематического анализа и оценки **нефункциональных требований** (непосредственно связанных с качеством системы, а не с её функциональностью).

**FURPS+** — акроним, расшифровываемый как:

| Буква | Расшифровка        | Описание                                                                    |
| ----- | ------------------ | --------------------------------------------------------------------------- |
| **F** | **Functionality**  | Функциональность — что система делает                                       |
| **U** | **Usability**      | Удобство использования — насколько легко ею пользоваться                    |
| **R** | **Reliability**    | Надёжность — насколько стабильно она работает                               |
| **P** | **Performance**    | Производительность — насколько быстро и эффективно она работает             |
| **S** | **Supportability** | Поддерживаемость — насколько легко её развивать, тестировать, обслуживать   |
| **+** | **Plus**           | Дополнительные требования: дизайн, ограничения, стандарты, безопасность и т.д. |

**FURPS+** был разработан Robert Grady #👨 и Candace Caswell #👨 в 1990-х годах и стал стандартом в инженерии ПО (особенно в IBM и корпоративной среде).

## Компоненты FURPS+

### Functionality (функциональность)

«Что система делает?» — описывает основные функции и возможности системы.

**Примеры требований**

- Система должна позволять пользователю создавать заказ.
- Система должна поддерживать 5 языков интерфейса.
- Система должна экспортировать отчёты в PDF и Excel.
- Должна быть поддержка многопользовательского режима.

Это **функциональные требования**, но в FURPS+ они рассматриваются как качество функциональности (полнота, точность, масштабируемость функций).

### Usability (удобство использования)

«Насколько легко пользователю работать с системой?»

**Примеры требований**

- Интерфейс должен быть понятен новичку без обучения.
- Все действия должны выполняться за ≤ 3 клика.
- Система должна поддерживать клавиатурные сочетания.
- Должна быть доступна помощь (tooltips, FAQ, видеоинструкции).
- Должна соответствовать стандартам WCAG (доступность для инвалидов).

Это UX/UI-требования, часто оцениваются через юзабилити-тесты.

### Reliability (надёжность)

«Сколько времени система работает без сбоев?»

**Примеры требований**

- Система должна быть доступна 99.9% времени (30 минут простоя в месяц).
- При сбое сервера система должна восстановиться за ≤ 5 минут.
- Система не должна терять данные при внезапном отключении питания.
- Должна быть возможность восстановления из резервной копии.

Это SLA-требования: uptime, MTBF (среднее время между сбоями), recovery time.

### Performance (производительность)

«Как быстро и эффективно система работает?»

**Примеры требований**

- Отклик системы при поиске должен быть ≤ 1 секунда.
- Система должна обрабатывать 1000 запросов в секунду.
- Загрузка страницы должна занимать ≤ 2 секунды на 4G.
- Потребление памяти — не более 512 МБ на экземпляр.

Это технические метрики: latency, throughput, scalability, resource usage.

### Supportability (поддерживаемость)

«Насколько легко систему можно развивать, тестировать и обслуживать?»

**Примеры требований**

- Код должен быть покрыт тестами на 80%.
- Система должна быть логируема (логи в JSON, доступны в ELK).
- Должна быть поддержка CI/CD (автоматический деплой).
- Конфигурация должна быть вынесена в файлы (не в код).
- Должны быть API для мониторинга (health checks, metrics).

Это DevOps- и инженерные требования, часто называются maintainability.

### Plus (дополнительные требования)

Это все остальные важные аспекты, которые не вписываются в первые 5 категорий.

**Примеры требований**

| Подкатегория                    | Примеры                                                   |
| ------------------------------- | --------------------------------------------------------- |
| **Design Constraints**          | Должна работать на iOS 15+, Android 10+, Chrome, Firefox  |
| **Implementation Requirements** | Должна быть написана на Java 17, использовать Spring Boot |
| **Interface Requirements**      | API должен соответствовать OpenAPI 3.0, использовать JWT  |
| **Security**                    | Должна поддерживать OAuth2, шифрование данных по AES-256  |
| **Legal / Regulatory**          | Соответствие GDPR, HIPAA, PCI-DSS                         |
| **Portability**                 | Должна работать на Linux, Windows, Docker                 |
| **Installability**              | Должна устанавливаться одним скриптом `install.sh`        |
| **Internationalization**        | Поддержка UTF-8, локализация дат, валют, языков           |

**Plus** — это «всё остальное», что влияет на успех системы, но не является чисто функциональным или техническим.

| **F**     | Пользователь может сменить пароль               | Функциональное   | Требования заказчика |

## Зачем нужен FURPS+

| Цель                                              | Объяснение                                                                                                    |
| ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| **Структурировать нефункциональные требования**   | Без FURPS+ требования размазываются: «система должна быть быстрой», «удобной», «надёжной» — но не измеримо.   |
| **Помочь в планировании**                         | Позволяет распределить ресурсы: если важна производительность — нужны нагрузочные тесты, оптимизация БД.      |
| **Обеспечить баланс**                             | Не увлекаться функциональностью в ущерб надёжности или безопасности.                                          |
| **Создать измеримые критерии**                    | Можно проверить: «99.9% uptime» — да/нет.                                                                     |
| **Использовать в архитектурных решениях**         | Например, для высокой надёжности — выбираем кластер, репликацию, отказоустойчивость.                          |

## FURPS+ и ISO 25010

| FURPS+                                       | ISO 25010                                                                                                                                     |
| -------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| Простой, удобный для бизнеса и аналитиков    | Стандарт ISO, более формальный и сложный                                                                                                      |
| Основан на практике IBM                      | Основан на научной классификации                                                                                                              |
| 6 категорий                                  | 8 характеристик: функциональность, надёжность, удобство, эффективность, поддерживаемость, переносимость, безопасность, удобство использования |
| Часто используется в корпоративной среде     | Используется в госзакупках, аэрокосмосе, медицине                                                                                             |

> **FURPS+** — это «удобная версия» ISO 25010 для повседневной практики.

## Как использовать FURPS+ в проекте

**Шаги**

1. Создайте таблицу FURPS+ в документации (Confluence, Notion, Word).
2. Для каждого требования присвойте категорию (F, U, R, P, S, +).
3. Для каждого задайте измеримый критерий:
  - «Система должна быть быстрой» — не измеримо;
  - «Поиск должен отвечать ≤ 500 мс при 100 одновременных запросах» — измеримо.
1. Выделите приоритеты (высокий/средний/низкий).
2. Проверяйте соответствие на каждом этапе: тестирование, ревью, релиз.

## Пример: FURPS+ для веб-приложения

| Категория | Требование | Измеримо? |
|-----------|-----------|-----------|
| **F** | Пользователь может загрузить файл | ✅ |
| **U** | Форма загрузки должна быть на русском и английском | ✅ |
| **R** | Приложение должно быть доступно 99.9% времени | ✅ |
| **P** | Загрузка файла 100 МБ должна занимать ≤ 10 сек | ✅ |
| **S** | Код должен быть покрыт тестами ≥ 80% | ✅ |
| **+** | Приложение должно быть совместимо с Chrome, Firefox, Safari | ✅ |
| **+** | Данные пользователей должны храниться в ЕС | ✅ (GDPR) |

## Итог

> **FURPS+** — это не теория, а практический инструмент, который помогает командам не забывать о качестве, когда они сосредоточены на функциях.

> **Функциональность — это то, что система делает. FURPS+ — это то, как она это делает.**

**FURPS+** — это страховка от технического долга и неудовлетворённых пользователей.
