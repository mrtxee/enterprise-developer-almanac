## ITIL

**ITIL (Information Technology Infrastructure Library)** — это практический фреймворк (библиотека подходов и процессов) для **управления ИТ-услугами** (ITSM): от планирования и предоставления до постоянного улучшения.

ITIL помогает выстроить процессы так, чтобы ИТ-служба работала как сервисная организация: понятные услуги, [[SLI|SLA]], инциденты, изменения и непрерывное улучшение.

## Введение

**Определение**

> **ITIL** описывает какие процессы нужны для ИТ-услуг и как их организовать, что служит «best practice» для большинства компаний.

- Развивается организацией **AXELOS**.
- Версии: **ITIL v3** (5 этапов жизненного цикла услуги) и **ITIL 4** (34 практики, ориентир на ценность и Agile).
- Применим не только к ИТ: подходы используют и для других «служебных» подразделений.

## Жизненный цикл услуги (ITIL v3)

| Стадия | Содержание |
|--------|-----------|
| **Strategy** (стратегия) | Зачем услуга существует, цели, портфель услуг |
| **Design** (дизайн) | Проектирование услуги: SLA, архитектура, поставщики |
| **Transition** (переход) | Внедрение: изменения, релизы, развёртывание |
| **Operation** (эксплуатация) | Ежедневная работа: инциденты, запросы, мониторинг |
| **Improvement** (непрерывное улучшение) | Анализ и оптимизация услуг |

В ITIL 4 стадии заменены **цепочкой создания ценности** и **практиками**, но идея та же: проектируем → внедряем → эксплуатируем → улучшаем.

## Что даёт ITIL

- **Единый язык** для общения ИТ и бизнеса.
- **Готовые процессы**: что делать при сбое, при изменении, при запросе.
- **Измеримость**: SLA, метрики, KPI.
- **Ориентация на ценность** для бизнеса.
- **Снижение хаоса** при росте компании.

## Ключевые процессы

| Процесс | Что решает |
|---------|-----------|
| **Управление инцидентами** | Быстро восстановить услугу после сбоя |
| **Управление проблемами** | Найти и устранить корневые причины |
| **[[change-management|Управление изменениями]]** | Контролируемые изменения без хаоса |
| **Управление запросами** | Выполнение стандартных запросов (доступ, пароль) |
| **Управление уровнем услуг (SLA)** | Договорённости о качестве услуги |
| **Управление каталогом услуг** | Один список того, что ИТ предоставляет |

## Роли и функции

| Роль / функция | Обязанность |
|----------------|------------|
| **Service Desk** | Единая точка контакта пользователей |
| **Собственник услуги** | Ответственность за услугу целиком |
| **Менеджер изменений** | Контроль изменений |
| **Менеджер инцидентов** | Координация реагирования на сбои |

## Кто использует ITIL

| Тип организации | Зачем |
|-----------------|-------|
| **Крупные компании** | Упорядочить ИТ-процессы, совместимость с аудитами |
| **Аутсорсинговые ИТ-подрядчики** | Доказывать качество услуг по SLA |
| **Госструктуры** | Требования к процессам, соответствие регламентам |
| **Стартапы (растущие)** | Структура для сервисной поддержки без бюрократии |

## Уровни сертификации

| Уровень | Тема |
|---------|------|
| **Foundation** | Базовые понятия ITIL |
| **Practitioner** | Применение отдельных практик |
| **Managing Professional** | Практики ИТ-управления (ITIL 4 MP) |
| **Strategic Leader** | Стратегическое управление ИТ (ITIL 4 SL) |
| **Master** | Комплексное экспертное владение |

## Когда использовать ITIL

| Ситуация | Рекомендация |
|----------|--------------|
| Сложность с инцидентами, нет единого процесса | Внедрять процесс управления инцидентами |
| Хаос при изменениях в прод | Внедрять управление изменениями |
| Поддержка растёт, нет Service Desk | Начать с единой точки контакта |
| Компания маленькая, процессов мало | Начать с малого: инциденты + запросы, без полного ITIL |
| Есть аудит, требуются SLA | Зафиксировать услуги и SLA |

## Внедрение

1. **Начать с малого** — выбрать 1–2 процесса (обычно инциденты и запросы).
2. **Определить услуги** — каталог услуг и владельцы.
3. **Настроить SLA** — договорённости о времени реакции и восстановления.
4. **Внедрить Service Desk** — единая точка контакта.
5. **Автоматизировать** — тикет-система (Jira, ServiceNow), оповещения.
6. **Измерять и улучшать** — метрики и непрерывный анализ.

## Особенности

- ✅ Стандартизирует ИТ-процессы, понятные бизнесу.
- ✅ Даёт измеримость (SLA, метрики).
- ✅ Снижает хаос при росте и аудитах.
- ✅ Масштабируется от малого до корпоративного уровня.
- ❌ Может выглядеть бюрократично при буквальном применении.
- ❌ Полное внедрение требует времени и ресурсов.
- ❌ Для стартапов избыточно без адаптации под масштаб.

## Порядок изучения

- Сначала понять **ценность услуги** и **жизненный цикл**.
- Затем изучить **основные процессы**: инциденты, изменения, запросы.
- Потом — **SLA и каталог услуг**.
- И в конце — связь с инструментами (ServiceNow, Jira Service Management) и автоматизацией.

## Итог

**ITIL** — самый распространённый фреймворк управления ИТ-услугами: процессы, роли, SLA. Его сила — в готовых ответах «что делать» при типовых ситуациях поддержки ИТ. Рекомендуется вводить постепенно, начиная с процессов инцидентов и запросов.
