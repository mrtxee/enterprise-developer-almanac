## Request и Query в Kubernetes

Краткое объяснение разницы между **query** и **request** в контексте Kubernetes (k8s).

### Request — запрос ресурсов для Pod

Это **гарантия минимальных ресурсов**, которые Pod получит от кластера.

- Указывается в манифесте Pod.
- Используется **планировщиком (scheduler)**, чтобы выбрать подходящий узел.
- Пример:

  ```yaml
  resources:
    requests:
      cpu: "0.25"    # 250m
      memory: "128Mi"
  ```

- Kubernetes гарантирует, что Pod получит как минимум столько CPU и памяти.

> Без `requests` Pod может быть запланирован на перегруженный узел — это плохо для стабильности.

### Query — запрос к API Kubernetes

Это **ваше действие**, когда вы спрашиваете у кластера информацию.

- Выполняется через `kubectl`, `curl` или другие инструменты.
- Примеры:

  ```bash
  kubectl get pods                    # query: "Покажи все Pod"
  kubectl get nodes -o wide           # query: "Покажи все узлы"
  curl -H "Authorization: Bearer..." https://api-server/api/v1/pods
  ```

- Это **не часть конфигурации**, а способ **получить данные** из кластера.

### Главное отличие

| Термин     | Где используется         | Что означает                          |
|---|---|---|
| `request` | В манифесте Pod          | Сколько ресурсов Pod хочет получить    |
| `query`   | В команде пользователя   | Что пользователь хочет узнать у кластера |

> **Простая аналогия:**
> - **`request`** — как заявка на электроэнергию: «Мне нужно 5 кВт для работы».
> - **`query`** — как звонок в диспетчерскую: «Какие серверы сейчас работают?»
