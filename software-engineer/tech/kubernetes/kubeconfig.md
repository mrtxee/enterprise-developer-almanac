Этот файл называется **Kubeconfig** (обычно имеет имя `config` и лежит в папке `~/.kube/`).

## 📄 Что это за файл?

Это **файл конфигурации доступа** к Kubernetes-кластеру.

Его главная задача — сказать утилите `kubectl` (и другим инструментам, таким как Helm, ArgoCD, Lens):

1. **ГДЕ** находится кластер (адрес API-сервера).
2. **КТО** вы (ваши учетные данные/ключи).
3. **КАК** устанавливать защищенное соединение (сертификаты CA).
4. **ГДЕ** работать по умолчанию (namespace).

Без этого файла `kubectl` не знает, к какому кластеру подключаться, и выдаст ошибку, которую вы видели ранее (`dial tcp [::1]:8080: connectex: No connection could be made...`).

---

## 🔍 Разбор структуры файла

Файл состоит из трех основных блоков, которые связываются через имена (`name`):

### 1. `clusters` (Кластеры)

Здесь описаны физические адреса кластеров.

```yaml
clusters:
- cluster:
    certificate-authority-data: L... # Сертификат центра сертификации (CA) для проверки подлинности сервера
    server: https://10.1.2.3:5443    # Адрес API-сервера Kubernetes
  name: mydel-dev-cluster            # Уникальное имя этого кластера в конфиге
```
> **Смысл:** "Есть кластер с именем `mydel-dev-cluster`, он живет по адресу `https://10.1.2.3:5443`".

### 2. `users` (Пользователи)

Здесь хранятся ваши личные ключи для аутентификации.

```yaml
users:
- name: mydel-dev-admin              # Имя пользователя в конфиге
  user:
    client-certificate-data: L...    # Ваш личный сертификат (публичный ключ)
    client-key-data: L...            # Ваш приватный ключ (храните в секрете!)
```
> **Смысл:** "Пользователь `mydel-dev-admin` может доказывать свою личность с помощью этих ключей".

### 3. `contexts` (Контексты) — Самое важное!

Контекст — это **связка** Кластера + Пользователя + Namespace. Это удобная "пресета" настроек.

```yaml
contexts:
- context:
    cluster: mydel-dev-cluster       # Ссылка на блок clusters
    namespace: ctdl3-dev             # Namespace по умолчанию для этого контекста
    user: mydel-dev-admin            # Ссылка на блок users
  name: mydel-dev-cluster            # Имя самого контекста
```
> **Смысл:** "Когда я использую контекст `mydel-dev-cluster`, я подключаюсь к кластеру `mydel-dev-cluster` от имени пользователя `mydel-dev-admin` и сразу попадаю в неймспейс `ctdl3-dev`".

### 4. `current-context`
```yaml
current-context: mydel-dev-cluster
```
> **Смысл:** "Прямо сейчас активен именно этот контекст. Все команды `kubectl` будут выполняться против него".

## 🛠 Как им пользоваться?

### Способ 1: Автоматический (По умолчанию)

`kubectl` автоматически ищет файл по пути:

* **Linux/Mac:** `~/.kube/config`
* **Windows:** `C:\Users\<ВашеИмя>\.kube\config`

Если вы сохраните этот текст в файл `config` в этой папке, то просто выполняя команды, вы будете работать с этим кластером:

```bash
kubectl get pods
# Эта команда выполнится в кластере 10.1.2.3, в неймспейсе ctdl3-dev
```

### Способ 2: Через переменную окружения (Для скриптов/CI)

Если вы не хотите класть файл в домашнюю папку (например, в CI/CD пайплайне), вы можете указать путь к файлу явно:

```bash
export KUBECONFIG=/path/to/this/file.yaml
kubectl get pods
```

Или передать флаг напрямую:

```bash
kubectl --kubeconfig=/path/to/this/file.yaml get pods
```

### Способ 3: Переключение между несколькими кластерами

Если у вас есть доступ к нескольким кластерам (Dev, Stage, Prod), вы можете добавить их все в один файл `config` (дополнив списки `clusters`, `users`, `contexts`).

Тогда переключаться между ними можно командой:

```bash
# Посмотреть доступные контексты
kubectl config get-contexts

# Переключиться на другой
kubectl config use-context <имя-другого-контекста>
```

## ⚠️ Важные предупреждения

1. **Безопасность:** В этом файле находятся `client-key-data` (приватные ключи). **Никогда не выкладывайте этот файл в открытый репозиторий (GitHub/GitLab)!** Если злоумышленник получит этот файл, он получит полный доступ к вашему кластеру.
2. **Срок действия:** Сертификаты (`certificate-authority-data`, `client-certificate-data`) часто имеют срок годности. Если кластер пересоздали или сертификаты истекли, файл нужно обновить (обычно через команду типа `aws eks update-kubeconfig` или скачиванием нового конфига из веб-интерфейса облака).
3. **Namespace:** Обратите внимание, что в контексте указан `namespace: ctdl3-dev`. Это значит, что если вы выполните `kubectl get pods`, вы увидите поды **только** из этого неймспейса. Чтобы увидеть все, нужно добавить флаг `-A` или `--all-namespaces`.

## ✅ Резюме

Этот файл — ваш **"пропуск"** в кластер.

1. Сохраните его как `config` в папку `.kube` в вашем домашнем директории.
2. Убедитесь, что `current-context` указывает на нужный вам кластер.
3. Пользуйтесь `kubectl` как обычно.
