## Software composition analysis

Самые подходящие обобщающие понятия:

- **Software composition analysis (SCA) tools** — наиболее точный термин: и cdxgen, и Trivy используют в контексте SCA (анализ состава ПО, поиск зависимостей и уязвимостей).
- **Security scanning tools** — более широкое понятие: инструменты сканирования безопасности (уязвимости, секреты, конфигурации).
- **Dependency and vulnerability analysis tools** — если хочется явно подчеркнуть работу с зависимостями и уязвимостями.
- **Инструменты анализа состава программного обеспечения (SCA)** — прямой перевод SCA, технически корректно.
- **Инструменты сканирования безопасности** — универсальный и понятный вариант.
- **Инструменты анализа зависимостей и уязвимостей** — развёрнутый вариант, хорошо отражает функционал обоих инструментов.

---

| Инструмент | Назначение                                                                                                                             |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| **cdxgen** | Генератор **SBOM** (Software Bill of Materials) в формате **CycloneDX**. Составляет инвентарь всех компонентов и зависимостей проекта. |
| **Trivy**  | Комплексный сканер безопасности: ищет **уязвимости (CVE)**, мисконфигурации, секреты, лицензии. Может также генерировать SBOM.         |

Простая аналогия:

- **cdxgen** — «переписывает все ингредиенты» в вашем ПО.
- **Trivy** — «проверяет, нет ли среди ингредиентов испорченных» и смотрит на настройки безопасности.

## Что берут на вход

### cdxgen

Принимает **путь к проекту, файлу или образу**:

```bash
cdxgen -t java -o bom.json /path/to/project
cdxgen -t docker -o bom.json my-image:latest
```

Анализирует манифесты зависимостей (`pom.xml`, `package.json`, `go.mod` и т.д.) и lock-файлы.

### Trivy

Принимает **разные типы целей**:

```bash
trivy image my-image:latest          # образ контейнера
trivy fs /path/to/project            # файловая система проекта
trivy repo https://github.com/...    # git-репозиторий
trivy config ./k8s/                  # IaC-манифесты
trivy rootfs /                       # rootfs
```

## Что возвращают на выход

### cdxgen

Возвращает **SBOM в формате CycloneDX** (JSON или XML):

```json
{
  "bomFormat": "CycloneDX",
  "specVersion": "1.5",
  "components": [
    { "type": "library", "name": "log4j-core", "version": "2.14.1", "purl": "pkg:maven/org.apache.logging.log4j/log4j-core@2.14.1" }
  ]
}
```

Это **инвентарь**, а не отчёт об уязвимостях. Сам по себе уязвимости не ищет — для этого его скармливают сканерам (например, `dependency-track` или тому же Trivy).

### Trivy

Возвращает **отчёт о найденных проблемах**:

```
┌──────────────────┬────────────────┬──────────┬───────────────────┐
│     Library      │ Vulnerability  │ Severity │  Fixed Version    │
├──────────────────┼────────────────┼──────────┼───────────────────┤
│ log4j-core 2.14.1│ CVE-2021-44228 │ CRITICAL │ 2.15.0            │
└──────────────────┴────────────────┴──────────┴───────────────────┘
```

Форматы вывода: `table` (по умолчанию), `json`, `sarif`, `cyclonedx`, `spdx`.

Что находит:

- **Уязвимости** (CVE) в зависимостях и ОС-пакетах.
- **Мисконфигурации** (Kubernetes, Terraform, Dockerfile).
- **Секреты** (ключи, пароли в коде).
- **Лицензии** (с рисками).
- **Сгенерированный SBOM**, если нужно.

## Ключевое отличие

|                              | **cdxgen**                                            | **Trivy**                         |
| ---------------------------- | ----------------------------------------------------- | --------------------------------- |
| Главная цель                 | Составить **инвентарь** компонентов                   | Найти **уязвимости и проблемы**   |
| Сам ищет CVE?                | ❌ Нет                                                 | ✅ Да                              |
| Генерирует SBOM?             | ✅ Это основная задача                                 | ✅ Как побочная функция            |
| Глубина анализа зависимостей | Очень глубокая (много форматов, детальные метаданные) | Хорошая, но фокус на безопасности |
| Мисконфигурации / секреты    | ❌                                                     | ✅                                 |

## Когда что использовать

- **Нужен качественный, детальный SBOM** для compliance, передачи в Dependency-Track или инвентаризации → **cdxgen**.
- **Нужно быстро проверить образ/проект на уязвимости, секреты и мисконфигурации** в CI → **Trivy**.
- **Нужно и то и другое** → генерируете SBOM через `cdxgen`, затем сканируете его:
  ```bash
  cdxgen -t java -o bom.json .
  trivy sbom bom.json
  ```

  Или просто используете `trivy` для обоих задач, если глубины его анализа достаточно.

---

### Итог одной строкой

**cdxgen** — генератор инвентаря (SBOM). **Trivy** — сканер уязвимостей, который умеет и инвентарь. В DevSecOps-пайплайне часто стоят вместе: один составляет список, другой по этому списку ищет дыры.
