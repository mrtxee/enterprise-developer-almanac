## Команда git config

Текущие настройки Git просматриваются командой `git config` с разными флагами — в зависимости от того, что нужно: всё сразу, только конкретный параметр или источник значения.

## Основные команды

- **Все настройки (с учётом всех уровней: local, global, system):**
  ```bash
  git config --list
  # или короче
  git config -l
  ```

- **С указанием, откуда взято каждое значение (полезно при конфликтах):**
  ```bash
  git config --list --show-origin
  ```

  Вывод имеет вид: `file:/home/user/.gitconfig    user.name=Ivan` или `file:.git/config    branch.main.remote=origin`.

- **Только локальные настройки репозитория (`.git/config`):**
  ```bash
  git config --list --local
  ```

- **Только глобальные настройки пользователя (`~/.gitconfig`):**
  ```bash
  git config --list --global
  ```

- **Системные настройки (для всех пользователей на машине):**
  ```bash
  git config --list --system
  ```

## Просмотр конкретного значения

- **Итоговое значение параметра:**
  ```bash
  git config user.email
  git config core.editor
  ```

- **То же, но с источником:**
  ```bash
  git config --show-origin user.email
  ```

## Расположение файлов настроек

Знание уровней помогает понять, где искать настройки вручную:

- **Локально (для текущего репозитория):** `.git/config` в корне репозитория.
- **Глобально (для пользователя):** `~/.gitconfig` (Linux/macOS) или `%USERPROFILE%\.gitconfig` (Windows).
- **Системно (для всей машины):** `/etc/gitconfig` (Linux), `C:\ProgramData\Git\config` (Windows).

## Практика в CI/CD

- В CI/CD (в том числе в Argo Workflows) важно убедиться, что в рантайме нет неожиданных локальных настроек — для этого удобно выполнять `git config --list --show-origin` в логах джобы.
- При деплое в Kubernetes (например, sidecar-контейнер с Git) полезно явно задавать нужные конфиги через переменные или монтируемые конфиг-файлы и проверять их той же командой.
- Если в команде разные настройки у разработчиков, `--show-origin` быстро покажет, где переопределено значение (например, локально в репозитории вместо глобального).

## Где хранятся локальные настройки

Локальные настройки проекта хранятся не в файле `.gitconfig`, а в файле **`config`** (без точки в начале) прямо внутри `.git`:

```text
/my-project/.git/config
```

## Путаница с именем файла

- **Глобальные настройки** (для пользователя) лежат в `~/.gitconfig` (отсюда и имя с точкой).
- **Локальные настройки** (для конкретного репозитория) лежат в `.git/config` — это отдельный файл, он не называется `.gitconfig`.

Git использует их по приоритету: локальный (`.git/config`) переопределяет глобальный (`~/.gitconfig`), а тот — системный (`/etc/gitconfig`).

## Проверка источника значения

Выполнение в корне проекта:

```bash
git config --list --show-origin
```

Вывод содержит строки вида:

```text
file:.git/config    user.name=Ivan
file:.git/config    core.editor=vim
```

Это и есть локальные настройки, хранящиеся в `/my-project/.git/config`.

## Практический нюанс: .git/config в артефактах сборки

Файл `.git/config` **не нужно коммитить** и не стоит включать в артефакты сборки (в том числе в Docker-образы или в CI-пайплайны типа Argo Workflows): он содержит локальные настройки конкретного репозитория и может включать чувствительные данные (например, переопределения remote-адресов, credential-помощников).

Чтобы зафиксировать настройки для всей команды (например, `core.autocrlf`, `receive.denyCurrentBranch`), лучше вынести их в:

- шаблон `.gitattributes` (он коммитится и работает предсказуемо);
- скрипты инициализации в CI;
- документированные требования к окружению.

## Приоритет уровней конфигурации

Локальный файл `.git/config` может переопределить настройки из блока `[user]` в `~/.gitconfig` (глобальный). Git использует иерархию уровней конфигурации, и локальный уровень имеет **наибольший приоритет**:

1. **Локальный** (`.git/config` в репозитории) — переопределяет всё.
2. **Глобальный** (`~/.gitconfig`) — значения по умолчанию для пользователя.
3. **Системный** (`/etc/gitconfig` или аналог) — настройки для всей машины.

Если в обоих файлах задан, например, `user.name`, Git возьмёт значение из `.git/config`.

## Пример

**В `~/.gitconfig`:**

```ini
[user]
    name = Ivan Petrov
    email = ivan.personal@example.com
```

**В `/my-project/.git/config`:**

```ini
[user]
    name = Ivan Petrov (Work)
    email = ivan@company.com
```

Для этого репозитория Git будет использовать `Ivan Petrov (Work)` и `ivan@company.com` — глобальные значения игнорируются.

## Проверка применяемого значения

Выполнение в корне проекта:

```bash
git config --list --show-origin | grep -E '^user\.(name|email)'
```

Вывод имеет вид:

```text
file:.git/config    user.name=Ivan Petrov (Work)
file:.git/config    user.email=ivan@company.com
```

Это показывает, что используется локальная настройка.

## Практические правила для CI/CD

- **Для рабочих репозиториев** нормальная практика — локально переопределять `user.email`, чтобы коммиты подписывались корпоративным email, а не личным.
- **В CI/CD (Argo, GitHub Actions) не стоит полагаться на `.git/config`** для задания `user.name/email`: в рантайме этого файла нет. В пайплайне значения задаются явно через переменные или команды:
  ```bash
  git config --local user.name "CI Bot"
  git config --local user.email "ci-bot@company.com"
  ```
- **Не коммить `.git/config`**: он не должен попадать в репозиторий (и не попадает, потому что лежит внутри `.git/`). Это персональные настройки конкретного клона репозитория.

## Частые ошибки

- Пытаться положить «шаблон» `.git/config` в корень проекта и коммитить его — бесполезно: Git не читает его оттуда.
- Думать, что `git init` копирует глобальные `user.name/email` в локальный конфиг — он этого не делает. Если локально не задано, Git просто берёт глобальное значение «на лету».

## Изменение глобальных настроек user

Для обновления значений в блоке `[user]` файла `~/.gitconfig` (глобальные настройки) используются команды с флагом `--global`:

```bash
git config --global user.name "Пример Имени"
git config --global user.email "mail@example.com"
```

## Проверка обновления

```bash
git config --global --list | grep -E '^user\.(name|email)'
# или сразу с источником:
git config --list --show-origin | grep -E '^user\.(name|email)'
```

Вывод должен содержать строки с `file:~/.gitconfig`.

## Нюансы применения

- **Это глобальные настройки**: они применяются ко всем репозиториям на машине, если в них не заданы локальные переопределения (в `.git/config`).
- **В CI/CD (Argo, GitHub Actions) на эти настройки полагаться нельзя**: там нет пользовательского `~/.gitconfig`. В пайплайне значения задаются явно, например:
  ```bash
  git config --local user.name "CI Bot"
  git config --local user.email "ci-bot@company.com"
  ```
- **Старые коммиты не меняются**: новые значения влияют только на будущие коммиты. Для исправления автора в уже сделанных коммитах используется `git commit --amend` или `git filter-repo`.
