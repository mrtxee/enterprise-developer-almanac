Все типы пакетов можно разделить на три большие группы: **нативные (системные)**, **универсальные (кросс-дистрибутивные)** и **ручные (портативные)**.

## Нативные (системные) пакетные менеджеры

Эти пакеты привязаны к конкретному семейству дистрибутивов. Они самые быстрые и идеально интегрированы, но собраны под конкретную версию ОС.

| Тип пакета              | Дистрибутивы                                | Для чего используется                                                                                       |
| :---------------------- | :------------------------------------------ | :---------------------------------------------------------------------------------------------------------- |
| **`.deb`**              | Debian, Ubuntu, Linux Mint, Astra Linux     | Основной стандарт для самой многочисленной ветки Linux. Используется на серверах, ПК и встроенных системах. |
| **`.rpm`**              | Red Hat, Fedora, openSUSE, CentOS, ALTLinux | Корпоративный стандарт (Red Hat). Используется в бизнесе, банках, госструктурах.                            |
| **`pkg.tar.xz / .zst`** | Arch Linux, Manjaro, EndeavourOS            | Rolling-release модель. Даёт самые свежие версии софта.                                                     |
| **`.apk`**              | Alpine Linux                                | Сверхлёгкий (минималистичный). Используется в контейнерах Docker, на роутерах и во встраиваемых системах.   |
| **`.eopkg`**            | Solus                                       | Современный десктопный дистрибутив (редкий, но интересный формат).                                          |
| **`.xbps`**             | Void Linux                                  | Для энтузиастов, которые хотят Linux без systemd.                                                           |

> **Когда использовать:** всегда, когда это возможно. Это родной для дистрибутива способ установки.

## Универсальные (кросс-дистрибутивные) форматы

Эти пакеты работают на любом дистрибутиве, решая проблему «зависимостей». Содержат все библиотеки внутри себя.

| Тип пакета   | Магазин / Репозиторий | Технология изоляции              | Когда использовать                                                                                                |
| :----------- | :-------------------- | :------------------------------- | :---------------------------------------------------------------------------------------------------------------- |
| **Flatpak**  | Flathub               | Да (Bubblewrap)                  | **Современные GUI-приложения** (Spotify, GIMP, Blender, IDE). Лучший выбор для десктопа.                          |
| **Snap**     | Snap Store            | Да (AppArmor)                    | Когда нужна строгая изоляция или приложение от Canonical (например, серверные версии LXD, сервисы IoT).           |
| **AppImage** | AppImageHub           | Нет (просто скачанный файл)      | Для портативных версий: скачал, дал права, запустил. Удобно хранить на флешке или тестировать беты без установки.  |

> **Когда использовать:** если в нативных репозиториях программа слишком старая, либо её там нет, либо нужна изоляция от системы.

## Высокоуровневые (менеджеры языков программирования)

Эти пакеты содержат библиотеки и зависимости для разработчиков, а не конечные приложения.

| Менеджер | Экосистема | Расширения файлов | Назначение |
| :--- | :--- | :--- | :--- |
| **pip** | Python | `.whl`, `.tar.gz` | Установка Python-библиотек (Django, NumPy, TensorFlow). |
| **npm / yarn** | Node.js | — (папка `node_modules`) | Установка JS-фреймворков (React, Vue, Express). |
| **cargo** | Rust | `.crate` | Установка программ и библиотек на Rust. |
| **go mod** | Golang | — | Управление Go-модулями. |
| **gem** | Ruby | `.gem` | Установка Ruby on Rails и утилит. |
| **composer** | PHP | `.phar` | Управление PHP-зависимостями (Laravel, Symfony). |

> **Важное отличие:** эти пакеты ставятся в домашнюю папку пользователя (`~/.local` или `~/go`), а не в систему, и не видны глобальному менеджеру пакетов (`apt` или `pacman`).

## Архивные / портативные форматы (ручная установка)

Способ установки «дедовским методом»: скачать исходники или бинарники и положить вручную.

| Тип                | Расширение              | Как работает                 | Когда используют                                                                                       |
| :----------------- | :---------------------- | :--------------------------- | :----------------------------------------------------------------------------------------------------- |
| **Исходный код**   | `.tar.gz`, `.tar.xz`    | Компиляция командой `make`   | Когда нужна специфическая сборка (оптимизация под свой процессор) или программа не упакована в пакеты. |
| **Бинарный архив** | `.tar.gz`, `.tgz`       | Распаковал — и готово        | Старые игры, проприетарное ПО от производителей (MATLAB, некоторые драйверы).                          |
| **Ядро Linux**     | `vmlinuz` + `initramfs` | Ручное копирование в `/boot` | Сборка кастомного ядра без использования пакетного менеджера.                                          |

## Контейнеризация (как альтернатива пакетам)

Хотя это не «пакеты» в строгом смысле, они часто заменяют установку ПО — особенно на серверах.

| Формат | Инструмент | Смысл |
| :--- | :--------------- | :-------------------------------------------------------------------------------------------------------- |
| **Образ контейнера** | Docker, Podman | Внутри контейнера — своя ОС (обычно Alpine) и ваше приложение. Не требует установки зависимостей на хост. |
| **Образ виртуальной машины** | QEMU, VirtualBox | Полная изоляция на уровне гипервизора. |

> **Когда использовать:** для микросервисов и CI/CD, когда нужно изолировать приложение от основной системы.

## Итоговая шпаргалка

| Ситуация | Типичные форматы |
| :--- | :--- |
| Обычный пользователь (Ubuntu / Debian) | `.deb`, **Flatpak**, AppImage |
| Обычный пользователь (Arch Linux) | `pkg.tar.zst`, **Flatpak**, AUR |
| Серверный администратор | `.deb` / `.rpm`, **Snap** (для LXD), Docker |
| Программист на Python | `pip` + `.deb` / `.rpm` |
| Пользователь корпоративного дистрибутива (RHEL) | `.rpm` |

**Короткий ответ:** основных типов пакетов пять — **нативные** (`.deb`, `.rpm`, `pkg.tar.xz`), **универсальные** (Flatpak, Snap, AppImage), **менеджеры языков** (pip, npm, cargo), **ручные архивы** (исходники) и **контейнеры** (Docker).

## Универсальные пакеты в Arch Linux

Такие форматы, как **Flatpak**, **Snap** и **AppImage**, объединяют под понятием **«Универсальные (или кросс-дистрибутивные) пакеты»**.

**Все три формата официально поддерживаются в Arch Linux.** Разница лишь в том, как они интегрированы в систему и насколько «родными» их можно считать.

### Flatpak — официальная поддержка

Flatpak доступен прямо из официальных репозиториев Arch Linux и считается полностью поддерживаемым решением.

**Установка:**

```bash
sudo pacman -S flatpak
```

После установки добавляется репозиторий Flathub, чтобы получить доступ к приложениям.

Flatpak отлично интегрируется с GNOME — через GNOME Software (если установлен пакет `gnome-software-plugin-flatpak`) или через графические менеджеры вроде `xPackageManager`, которые умеют работать с Flatpak из коробки.

> **Важно:** Flatpak работает корректно и нативно в Arch Linux.

### Snap — доступен через AUR

Snap не входит в официальные репозитории Arch, но его можно установить из **AUR** (Arch User Repository). Это сообщество пользователей, которые поддерживают пакеты, не вошедшие в официальные репозитории.

**Установка:**

```bash
git clone https://aur.archlinux.org/snapd.git
cd snapd
makepkg -si
```

После установки потребуется включить демон:

```bash
sudo systemctl enable --now snapd.socket
```

**Особые требования:**

- Для полноценной работы песочницы (confinement) необходимо включить **AppArmor**, иначе все Snap-пакеты будут работать в режиме `devel` с неограниченным доступом к системе.
- Требуется перезагрузка или выход из системы для корректной работы.
- Установка Snap-пакетов требует прав root.

**Важное предупреждение:** Arch Linux официально **не предоставляет поддержку** для проблем, связанных со Snap. При проблемах обращение идёт в сообщество Snapcraft.

### AppImage — работает без установки

**AppImage не требует установки как такового** — это формат «скачал и запустил». Поддержка в Arch Linux есть на уровне совместимости: AppImage работает практически на любом современном дистрибутиве Linux, включая Arch.

**Как использовать:**

```bash
# Скачанный AppImage-файл
chmod +x your-app.AppImage
./your-app.AppImage
```

**Особенности:**

- Не требует установки демонов или служб
- Файл самодостаточен — содержит все зависимости внутри
- Может конфликтовать с некоторыми библиотеками из-за различий в glibc
- Для интеграции в меню приложений нужны сторонние инструменты (например, `appimaged`)

**Интересный факт:** существует проект **ArchImage**, который позволяет создавать AppImage из пакетов Arch Linux (включая AUR) с полным набором зависимостей.

## Сравнительная таблица: Flatpak vs Snap vs AppImage

| Характеристика | Flatpak | Snap | AppImage |
|----------------|---------|------|----------|
| **Установка в Arch** | `sudo pacman -S flatpak` | Из AUR (`makepkg -si`) | Не требуется |
| **Официальные репозитории** | ✅ Да | ❌ Нет (только AUR) | ❌ Нет |
| **Требует демона** | ✅ `flatpak` (запускается автоматически) | ✅ `snapd` (нужно включать вручную) | ❌ Нет |
| **Интеграция с GUI** | ✅ Отличная (GNOME Software, xPackageManager) | ⚠️ Ограниченная | ⚠️ Ручная |
| **Изоляция** | ✅ Песочница (Bubblewrap) | ⚠️ Требует AppArmor | ❌ Нет |
| **Кому подходит** | Всем, кто хочет современные приложения | Пользователям, которым нужны специфичные Snap-приложения | Тем, кто хочет «скачал и запустил» |

## Что выбрать

1. **Flatpak** — **рекомендуемый выбор** для большинства пользователей Arch. Он официально поддерживается, легко устанавливается и отлично интегрируется с системой, особенно на GNOME.
2. **Snap** — только если **нужна программа, которая есть только в Snap Store**, или планируется миграция с Ubuntu. Нужно быть готовым к ручной настройке AppArmor и отсутствию официальной поддержки от сообщества Arch.
3. **AppImage** — идеален для **портативных приложений** или ситуаций, когда ПО не должно «засорять» систему. Просто скачивается и запускается без установки.

**Совет:** при знакомстве с универсальными пакетами в Arch Linux стоит начать с Flatpak — это самый простой и надёжный путь.
