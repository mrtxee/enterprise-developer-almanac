Задача: расширить `/home` за счёт соседней NTFS-партиции, **но при этом сохранить саму NTFS-партицию** (просто уменьшив её на 50 ГБ).

Это называется **перераспределением пространства между разделами**.

## Анализ текущей ситуации

Посмотрим точное расположение разделов:

```bash
lsblk -o NAME,SIZE,TYPE,MOUNTPOINT
sudo parted /dev/nvme0n1 print free
```

**Ключевой момент:** для успешного расширения `/home` (ext4) свободное место должно находиться **непосредственно после** этого раздела.

## Целевое расположение разделов

**Идеальное расположение (что нужно):**

```text
[SWAP] [ / ] [ /home ] [ NTFS ]
                           ↑
                     свободное место после NTFS не нужно
```

**Проблема:** чтобы расширить `/home` и оставить NTFS, нужно **уменьшить NTFS с левой стороны** (передвинуть её правую границу влево) и **расширить `/home` вправо**.

**Условия выполнимости:**

1. **NTFS находится сразу после `/home`** (непосредственно рядом)
2. **NTFS не зашифрована** и не используется системой

## Уменьшение NTFS-раздела (выделение 50 ГБ)

### Через GParted (рекомендуется)

```bash
sudo gparted
```

1. Выбрать NTFS-раздел.
2. Клик правой кнопкой → **«Resize/Move»**.
3. В поле **«Free space preceding»** (свободное место перед) указать `50` (или `51200` MB).
   - Так создаётся 50 ГБ **слева** от NTFS, которые можно будет присоединить к `/home`.
4. Нажать **«Resize/Move»**, затем **«Apply»** (зелёная галочка).

**Важно:** если GParted не позволяет уменьшить NTFS, возможные причины:

- файловая система NTFS повреждена (проверка через `chkdsk` из Windows);
- раздел зашифрован BitLocker (нужно отключить шифрование).

### Через командную строку (ntfsresize)

```bash
# Проверяем NTFS-раздел
sudo ntfsfix /dev/nvme0n1pX  # X — номер NTFS

# Уменьшаем файловую систему (например, до 30 ГБ, если исходный размер 80 ГБ)
sudo ntfsresize --size 30G /dev/nvme0n1pX

# Удаляем и заново создаём раздел в fdisk
sudo fdisk /dev/nvme0n1
# - удаляем NTFS-раздел (d)
# - создаём новый с нужным размером (n)
# - сохраняем (w)

# Расширяем файловую систему до нового размера
sudo ntfsresize /dev/nvme0n1pX
```

Этот метод сложнее и опаснее — лучше использовать GParted.

## Расширение /home за счёт освободившегося места

После уменьшения NTFS слева от него появится **50 ГБ неразмеченного пространства**, которое должно находиться сразу после `/home`.

**В GParted:**

1. Отмонтировать `/home`, если он смонтирован: `sudo umount /home`.
2. Клик правой кнопкой на раздел `/home` → **«Resize/Move»**.
3. Потянуть правую границу `/home` вправо, заполнив всё доступное место (50 ГБ).
4. Нажать **«Resize/Move»**, затем **«Apply»**.

**Через командную строку:**

```bash
# Проверяем ext4
sudo e2fsck -f /dev/nvme0n1pY  # Y — номер /home

# Расширяем раздел на 50 ГБ
sudo growpart /dev/nvme0n1 Y 50G

# Расширяем файловую систему
sudo resize2fs /dev/nvme0n1pY
```

## Создание пустой NTFS-партиции на оставшемся месте

После расширения `/home` справа от него должно остаться свободное место (оставшаяся часть бывшего NTFS).

**В GParted:**

1. Клик на **неразмеченное пространство** (unallocated).
2. Выбрать **«New»**.
3. Тип файловой системы: **ntfs**.
4. Нажать **«Apply»**.

**В командной строке:**

```bash
# Создаём раздел
sudo fdisk /dev/nvme0n1
# - n (новый раздел)
# - выбираем номер (следующий свободный)
# - Enter (начало по умолчанию)
# - Enter (конец по умолчанию)
# - w (сохранить)

# Форматируем как NTFS
sudo mkfs.ntfs -f /dev/nvme0n1pZ  # Z — номер нового раздела
```

## Проверка и монтирование

После изменений новая структура проверяется, и разделы монтируются обратно:

```bash
# Проверяем новую структуру
lsblk
sudo parted /dev/nvme0n1 print free

# Монтируем /home обратно
sudo mount /home

# Монтируем новую NTFS-партицию (по желанию)
sudo mkdir /mnt/new_ntfs
sudo mount /dev/nvme0n1pZ /mnt/new_ntfs
```

## Важные предупреждения

1. **Резервное копирование** — обязательно! Любая операция с разделами может привести к потере данных.
2. **NTFS должна быть целостной** — перед уменьшением она проверяется в Windows командой `chkdsk /f`.
3. **Порядок разделов критичен** — если между `/home` и NTFS есть другие разделы, операция невозможна.
4. **GParted может предложить переместить данные** — если `/home` не примыкает к NTFS, потребуется перемещение разделов (это долго и рискованно).
5. **Live USB** — если `/home` является системным (корневым) разделом, операции нужно выполнять с загрузочной флешки (Arch ISO).

## Альтернативное (более простое) решение

Если нужно всего 50 ГБ для `/home`, а NTFS потом всё равно нужна, можно создать файл-образ и смонтировать его как дополнительное пространство:

```bash
sudo fallocate -l 50G /tmp/home_extra.img
sudo mkfs.ext4 /tmp/home_extra.img
sudo mount -o loop /tmp/home_extra.img /mnt/extra_home
```

Но это не увеличит реальный раздел `/home`, а лишь добавит дополнительное пространство через монтирование.

## Итог

План выполним, но требует аккуратности и GParted. Если разделы расположены правильно, операция займёт 10-15 минут. Если нет — лучше не рисковать и оставить всё как есть, либо использовать LVM в будущем.
