## Управление пакетами в Arch Linux

В Arch Linux управление пакетами осуществляется через менеджер `pacman`. В отличие от дистрибутивов с графическими магазинами приложений, здесь всё делается через терминал. Процесс можно разбить на три этапа: от просмотра до полной очистки системы.

### Просмотр установленных пакетов

Ключевые команды `pacman` для навигации:

| Задача | Команда | Что покажет |
| :--- | :--- | :--- |
| Список всех пакетов | `pacman -Q` | Простой список всех установленных пакетов. |
| Только явно установленные | `pacman -Qe` | Пакеты, установленные вручную (обычно программы и игры). |
| Пакеты из AUR | `pacman -Qm` | Пакеты, установленные не из официальных репозиториев (вручную или через `yay`). |
| Поиск конкретного пакета | `pacman -Qs <имя>` | Находит установленный пакет по ключевому слову (например, `pacman -Qs firefox`). |
| Узнать размер пакета | `LC_ALL=C pacman -Qi \| awk '/^Name/{name=$3} /^Installed Size/{print $4$5, name}' \| sort -h` | Сортирует все программы по размеру (самые большие внизу), чтобы понять, что «съедает» место. |

Зелёные пакеты в выводе — часто не отдельные программы, а библиотеки, нужные другим приложениям. Удаляя их, можно сломать систему, поэтому действуйте аккуратно.

### Удаление ненужного

```bash
# найти пакет по описанию
pacman -Qs video
# удалить пакет по имени
sudo pacman -Rsn showtime
```

Когда пакет для удаления найден, используется `pacman -R` с разными флагами для разного результата:

| Ситуация | Команда | Эффект |
| :--- | :--- | :--- |
| Базовая | `sudo pacman -R <имя>` | Удалит только сам пакет. Если у пакета есть зависимости, которые не нужны другим программам, они останутся (станут «сиротами»). |
| Правильная (полная) | `sudo pacman -Rs <имя>` | Лучший вариант для обычного удаления. Удалит пакет и все его зависимости, которые не нужны другим программам. |
| Радикальная | `sudo pacman -Rns <имя>` | То же, что выше, но ещё удаляет глобальные конфиги (файлы `.pacsave`). |
| С каскадом | `sudo pacman -Rc <имя>` | Осторожно! Удалит пакет и всё, что от него зависит. Может снести половину системы, если удалить важную библиотеку. |

Пример — удалить игру `supertuxkart` и связанные с ней библиотеки, которые не нужны другим программам:

```bash
sudo pacman -Rs supertuxkart
```

### Генеральная уборка (чистка системы)

После удаления программ в системе остаётся технический «мусор», который мешает, только если мало места на диске.

#### Удаление «сирот» (неиспользуемых зависимостей)

Это пакеты, которые когда-то поставились как часть другой программы, но потом программа была удалена, а «хвосты» остались:

```bash
# Сначала посмотрим, кто есть в сиротах
pacman -Qdt

# Удаляем их всех разом (если список не пуст)
sudo pacman -Rns $(pacman -Qdtq)
```

#### Очистка кэша Pacman

Arch хранит все скачанные версии пакетов в папке `/var/cache/pacman/pkg/`. Если давно не чистили, там могут лежать гигабайты старых версий.

- `sudo pacman -Sc` — удалит только устаревшие версии (оставит последнюю).
- `sudo pacman -Scc` — кардинально удалит все скачанные файлы. Если отключится интернет, нельзя будет переустановить пакет из кэша.

#### Очистка AUR-хелперов (yay, paru)

Хелперы тоже скапливают кэш сборки в домашней папке:

```bash
# Для yay
yay -Scc

# Для paru
paru -Scc
```

**Итоговая памятка**

1. **Удалить ненужное:** `sudo pacman -Rs <программа>`.
2. **Вычистить сирот:** `sudo pacman -Rns $(pacman -Qdtq)`.
3. **Почистить кэш:** `sudo pacman -Sc`.

Эти три шага поддерживают систему в тонусе без переустановки. Если не уверены, нужен ли пакет, просто не удаляйте его.

## Команда pacman -S --needed base-devel git

**`sudo`**

Запускает команду с правами суперпользователя (администратора). Нужно, потому что установка пакетов требует доступа к системным файлам, который ограничен для обычных пользователей.

**`pacman`**

Основной менеджер пакетов в Arch Linux и дистрибутивах на его основе (Manjaro, EndeavourOS и т. д.). Отвечает за:

- установку, удаление и обновление пакетов;
- синхронизацию с репозиториями;
- разрешение зависимостей.

**`-S`** (или `--sync`)

Флаг, который указывает `pacman` найти и установить пакеты из репозиториев. По сути, команда «установить».

**`--needed`**

Опция, которая заставляет `pacman` не переустанавливать пакеты, если они уже установлены в последней версии. Это полезно:

- чтобы сэкономить время и трафик;
- при повторном запуске скриптов настройки системы.

Без этой опции `pacman` попытается переустановить пакеты, даже если они уже есть.

**`base-devel`**

Группа пакетов, содержащая базовые инструменты для сборки программного обеспечения из исходного кода:

- компиляторы (например, `gcc` для C/C++);
- утилиты сборки (`make`, `autotools`, `cmake`);
- инструменты, необходимые для работы `makepkg` (утилиты для создания пакетов Arch Linux).

Группа обязательна для ручной установки пакетов из AUR (Arch User Repository) или сборки собственных пакетов.

**`git`**

Пакет с распределённой системой контроля версий Git. Он нужен для:

- клонирования репозиториев (в т. ч. из AUR, где пакеты хранятся как Git-репозитории);
- отслеживания изменений в коде;
- работы с удалёнными репозиториями (например, GitHub, GitLab).

**Что делает вся команда целиком**

Команда `sudo pacman -S --needed base-devel git` устанавливает (или проверяет актуальность установки) набор инструментов для сборки ПО (`base-devel`) и системы контроля версий Git (`git`) с правами администратора, не переустанавливая их, если они уже стоят в последней версии.

**Когда это нужно**

Чаще всего команду выполняют перед работой с AUR — пользовательским репозиторием, где хранятся пакеты, отсутствующие в официальных источниках. Чтобы установить пакет из AUR:

1. Скачать его исходный код (обычно через `git clone`).
2. Собрать пакет с помощью `makepkg`.
3. Установить полученный пакет с помощью `pacman`.

Для шагов 1 и 2 как раз нужны `git` и пакеты из `base-devel`.

**Пример последующего действия**

После выполнения этой команды можно установить популярный AUR-помощник `yay`:

```bash
git clone https://aur.archlinux.org/yay.git
cd yay
makepkg -si
```
