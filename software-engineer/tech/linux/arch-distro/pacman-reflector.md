## Зеркала в Arch Linux

Управление репозиториями (зеркалами) в Arch Linux — ключевая задача: от него напрямую зависят скорость загрузки пакетов и их актуальность.

### Где взять актуальный список зеркал

Список официальных зеркал Arch Linux находится на странице [Pacman Mirrorlist Generator](https://archlinux.org/mirrorlist/). На ней можно:

- выбрать страну (например, `Russia`, `Germany`, `United States`);
- выбрать протокол (`https` — самый надёжный);
- исключить зеркала, которые не синхронизировались больше суток;
- нажать «Generate Mirror List» — получить готовый файл `mirrorlist`, который копируется в систему.

### Как выбрать и установить зеркала

Самый правильный способ — использовать утилиту Reflector. Она автоматически тестирует зеркала, сортирует их по скорости и свежести и обновляет конфигурацию.

**Установка Reflector** (обычно уже есть в системе):

```bash
sudo pacman -S reflector
```

**Автоматическая настройка** (10 самых быстрых и свежих зеркал из России и Германии, сортировка по скорости):

```bash
sudo reflector --country Russia --country Germany --age 12 --protocol https --latest 30 --sort rate --save /etc/pacman.d/mirrorlist
```

Опция `--age 12` означает «зеркала, обновлённые за последние 12 часов».

Другие полезные примеры:
- только Россия, самые быстрые: `sudo reflector --country Russia --protocol https --sort rate --save /etc/pacman.d/mirrorlist`
- по глобальной скорости: `sudo reflector --age 12 --latest 20 --sort rate --save /etc/pacman.d/mirrorlist`

**Настройка вручную (без Reflector):**

1. Сделайте резервную копию старого списка: `sudo cp /etc/pacman.d/mirrorlist /etc/pacman.d/mirrorlist.backup`.
2. Отредактируйте файл: `sudo nano /etc/pacman.d/mirrorlist`.
3. Вставьте сгенерированные строки (зеркала в начале файла имеют приоритет), удалите старые или закомментируйте их (`#`).

### Главное правило Arch Linux

Порядок зеркал в файле `/etc/pacman.d/mirrorlist` имеет значение: pacman скачивает пакеты из первого зеркала в списке, а если оно недоступно — переходит ко второму и так далее. Поэтому самые быстрые и надёжные зеркала должны быть вверху файла; именно это делает команда `reflector --sort rate`.

### Как обновлять зеркала

Недостаточно настроить зеркала один раз — со временем они замедляются или выходят из строя.

Способ 1. Запускать Reflector вручную раз в 1–2 недели.

Способ 2. Автоматизировать через таймер systemd. Reflector поставляется с готовым сервисом и таймером:

```bash
sudo systemctl enable reflector.timer
sudo systemctl start reflector.timer
```

Зеркала будут обновляться автоматически раз в неделю, используя настройки из файла `/etc/xdg/reflector/reflector.conf` (его нужно предварительно настроить, добавив те же параметры, что в примере команды выше).

### Частые ошибки и их решение

- **`failed to synchronize all databases (unable to lock database)`** — другой процесс pacman (например, автоматическое обновление в GUI-магазине) уже работает. Закройте все менеджеры пакетов.
- **`signature is invalid` или `corrupted package`** — проблема не в зеркалах, а в ключах: `sudo pacman -Sy archlinux-keyring && sudo pacman -Su`.
- **После обновления зеркал `pacman -Syu` всё равно медленный** — проверьте, что файл `/etc/pacman.d/mirrorlist` действительно изменился; возможно, новый список сохранён не туда.

## Rolling Release и свежесть зеркал

### Что значит «обновлённые за последние 12 часов»

Это означает, что список пакетов (метаданные) на сервере зеркала синхронизирован с главным сервером Arch Linux не позднее 12 часов назад.

- «Свежее» зеркало (менее 12 часов) — только что получило все новые версии пакетов и обновлений.
- «Устаревшее» зеркало (более 2–3 дней) — застряло в прошлом: старые версии ядра, драйверов, библиотек.

### Почему это критично для Arch

Суть Arch Linux — это Rolling Release: система обновляется непрерывно, и все пакеты должны быть одной версии, соответствующей одному моменту времени (слепку репозитория). При использовании старого зеркала получается «слепок прошлого», а обновление через новое зеркало даёт сегодняшний «слепок». Это создаёт риск поломки системы.

### Что будет, если поставить `--age` больше (например, 7 дней)

1. Система начнёт «отставать» — пакеты недельной давности.
2. Главная опасность: при обновлении pacman скачает разницу между неделей назад и сегодняшним днём — огромный скачок. В стабильных дистрибутивах ([[linux-distros|Ubuntu]], [[linux-distros|Debian]]) это норма, но в Arch это чревато конфликтами: программа требует новую библиотеку, которой нет из-за старого зеркала. Pacman выдаст ошибку `failed to commit transaction (conflicting files)` или частично обновит систему, что может привести к kernel panic или нерабочему графическому интерфейсу после перезагрузки.

### Настройка `--age` на примере

Плохой выбор (опасно) — без указания возраста берутся все зеркала, даже мёртвые:

```bash
sudo reflector --country Spain --sort rate --save /etc/pacman.d/mirrorlist
```

Хороший выбор (безопасно) — только живые зеркала, обновлявшиеся последние 12 часов, отсортированные по скорости:

```bash
sudo reflector --country Spain --age 12 --protocol https --sort rate --save /etc/pacman.d/mirrorlist
```

Европейский выбор (оптимально для Испании) — соседи по региону с сохранением `--age 12`:

```bash
sudo reflector --country France --country Germany --country Portugal --age 12 --sort rate --save /etc/pacman.d/mirrorlist
```

### Правило выбора `--age`

| `--age` | Оценка | Последствия |
| --- | --- | --- |
| 12 часов | Золотой стандарт для Arch | Свежие пакеты, отсекаются ~90% проблемных зеркал |
| 48 часов (2 дня) | Рискованно, но допустимо в медленных странах | Возможны мелкие конфликты при обновлении |
| > 7 дней | Категорически нет | Rolling Release превращается в «замороженный» и обновление почти гарантированно ломает систему |

Если не находится ни одного зеркала (ошибка `no mirrors found`), увеличьте до `--age 24` или смените страну на соседнюю.

## Полнота зеркал

### Что хранится на зеркалах

Каждое зеркало синхронизируется с главным хранилищем и содержит те же данные:

- все пакеты из репозиториев `core`, `extra`, `community`, `multilib`;
- файлы с подписями (`.sig`) для проверки целостности;
- базы данных пакетов (`core.db`, `extra.db` и т.д.), которые использует `pacman -Sy`.

Пакет `firefox` будет бит-в-бит одинаковым на зеркале в России, Германии и США.

### Адрес «центрального» репозитория

Центрального «одного» сервера, куда ходят все, у Arch Linux нет. Есть главный сервер для разработчиков (`gerolde.archlinux.org`), доступный для чтения только разработчикам и доверенным зеркалам. Увидеть его содержимое можно через сайт Arch Linux:

- веб-интерфейс просмотра пакетов: [archlinux.org/packages](https://archlinux.org/packages/)
- Git-репозиторий файлов PKGBUILD: [gitlab.archlinux.org/archlinux/packaging/packages](https://gitlab.archlinux.org/archlinux/packaging/packages)

Напрямую использовать эти адреса в `pacman` нельзя — обязателен один из публичных зеркал из файла `/etc/pacman.d/mirrorlist`.

### Почему используется система зеркал

1. **Нагрузка.** Тысячи пользователей по всему миру не могут одновременно качать гигабайты обновлений с одного сервера.
2. **Скорость.** Ближайшее зеркало даёт скорость загрузки в 10–100 раз выше.
3. **Отказоустойчивость.** Если зеркало «лежит», pacman переключается на следующее в списке.

### Размер репозитория

Полный архив всех пакетов Arch Linux занимает более 100 ГБ (на начало 2025 года). В это входят все версии пакетов за всё время (хранятся сжатыми) и пакеты для архитектур `x86_64` (основная) и иногда `aarch64`.

### Как проверить, что зеркало полное

```bash
pacman -Sy
```

Если получается список файлов баз данных (`core.db`, `extra.db` ...) без ошибок — зеркало синхронизировано. Для проверки конкретного пакета:

```bash
pacman -Si имя_пакета
```

Информация о версии и контрольной сумме будет одинаковой для всех свежих зеркал.

### Задержка зеркал

Зеркала содержат все пакеты, но синхронизируются с задержкой:

- главный сервер — моментально (недоступен для публики);
- официальные зеркала — обычно отстают на 1–6 часов;
- некоторые публичные зеркала (не из списка Arch) — могут отставать на дни.

Именно поэтому в Reflector используется `--age 12` — чтобы зеркало было не только полным, но и свежим.

## Итог

- Зеркала идентичны: каждое содержит полную копию центрального репозитория.
- Центрального публичного URL нет: вместо него используется автоматическая генерация списка на [Pacman Mirrorlist Generator](https://archlinux.org/mirrorlist/).
- Разница только во времени последней синхронизации (свежести) и скорости доступа.

Для просмотра центрального репозитория как файловой системы используется зеркало с самым большим uptime — по сути, это и есть «центральный репозиторий» для пользователя.
