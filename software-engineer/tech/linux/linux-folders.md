## Filesystem Hierarchy Standard (FHS)

Структуру каталогов Linux стандартизирует **FHS (Filesystem Hierarchy Standard)** — документ, поддерживаемый **Linux Foundation** (текущая версия — 3.0). Это не закон, а конвенция, которой следуют практически все дистрибутивы.

### Основные идеи FHS

1. **Единообразие** — одинаковая структура во всех дистрибутивах: пользователь и программа всегда знают, где искать файл.
2. **Классификация данных по двум осям:**
   - **Shareable / Unshareable** — можно ли делиться с другими машинами (по сети).
   - **Static / Variable** — меняется ли без вмешательства администратора.
3. **Разделение read-only и writable** — `/` и `/usr` можно монтировать только для чтения или по сети, а изменяемые данные вынесены в `/var`, `/run`.
4. **Отделение системы от пользователя** — системные файлы (`/etc`, `/usr`) отдельно от пользовательских данных (`/home`).
5. **Совместимость с UNIX-традицией** и современный **usrmerge**: `/bin`, `/sbin`, `/lib` стали симлинками на `/usr/bin`, `/usr/sbin`, `/usr/lib`.

| | Статичные | Переменные |
| --- | --- | --- |
| **Общие** | `/usr`, `/opt` | `/var/mail`, `/var/spool` |
| **Локальные** | `/etc` | `/var/log`, `/run` |

### Назначение каталогов (кратко)

#### Корневой уровень

| Каталог | Назначение |
| --- | --- |
| `/` | Корень файловой системы |
| `/bin` | Основные команды пользователя (`ls`, `cp`) → симлинк на `/usr/bin` |
| `/boot` | Ядро (`vmlinuz`), initramfs, файлы загрузчика |
| `/dev` | Файлы устройств (`/dev/sda`, `/dev/tty`) |
| `/etc` | Конфигурация системы (host-specific), статичная |
| `/home` | Домашние каталоги пользователей |
| `/lib` | Основные общие библиотеки → симлинк на `/usr/lib` |
| `/media` | Точки монтирования съёмных носителей (USB, CD) |
| `/mnt` | Временные монтирования вручную |
| `/opt` | Сторонние самодостаточные пакеты (Chrome, Steam) |
| `/proc` | Виртуальная ФС: процессы и информация ядра |
| `/root` | Домашний каталог суперпользователя |
| `/run` | Runtime-данные с момента загрузки (PID, сокеты) |
| `/sbin` | Бинарники администрирования (`fdisk`, `mkfs`) → симлинк на `/usr/sbin` |
| `/srv` | Данные сервисов, предоставляемых системой (www, ftp) |
| `/sys` | Виртуальная ФС sysfs: устройства и драйверы ядра |
| `/tmp` | Временные файлы (очищаются при загрузке) |
| `/usr` | Вторичная иерархия — программы, библиотеки, документация, не требуемые на ранних этапах загрузки. Считается «только для чтения» после загрузки |
| `/var` | Переменные данные: логи (`/var/log`), почта (`/var/mail`), спулы (`/var/spool`), временные файлы, которые не должны удаляться при перезагрузке |

#### `/usr` — вторичная иерархия (read-only, общие данные)

| Каталог | Назначение |
| --- | --- |
| `/usr/bin` | Основные команды пользователя |
| `/usr/lib` | Библиотеки и внутренние исполняемые файлы |
| `/usr/local` | ПО, установленное администратором вручную (вне пакетного менеджера) |
| `/usr/sbin` | Бинарники администрирования |
| `/usr/share` | Архитектурно-независимые данные (иконки, man-страницы, темы) |
| `/usr/src` | Исходные коды (например, ядра) |

#### `/var` — переменные данные (пишутся в runtime)

| Каталог | Назначение |
| --- | --- |
| `/var/cache` | Кэш приложений (pacman, AUR) |
| `/var/lib` | Состояние программ (базы данных, состояние пакетов) |
| `/var/log` | Журналы системы и приложений |
| `/var/spool` | Очереди (печать, почта, cron) |
| `/var/tmp` | Временные файлы, сохраняемые после перезагрузки |

### Итог

FHS превращает хаос в предсказуемость:

- статичное общее — в `/usr`;
- конфигурация — в `/etc`;
- изменяемое — в `/var`;
- runtime — в `/run`;
- пользовательское — в `/home`.

**Важные концепции FHS**

- **Разделение `/` и `/usr`**: раньше `/usr` мог быть отдельным томом, поэтому всё необходимое для загрузки до монтирования `/usr` должно быть в `/bin`, `/sbin`, `/lib`.
- **Только для чтения vs изменяемые данные**:
  - `/usr`, `/bin`, `/sbin` — read-only после загрузки;
  - `/var`, `/tmp`, `/run` — изменяемые.
- **Локальное ПО**: `/usr/local` защищено от обновлений системного пакетного менеджера.

### Совместимость

Большинство современных дистрибутивов (Ubuntu, Fedora, Debian, RHEL, Arch) следуют FHS, хотя могут быть небольшие отклонения — например, символические ссылки вроде `/bin → /usr/bin` в системах с unified `/usr`.

> **Примечание:**
> - Каталоги вроде `/proc`, `/sys`, `/dev` — виртуальные (существуют только в памяти).
> - В современных дистрибутивах (например, Fedora, Arch) часто используется unified `/usr`, где `/bin → /usr/bin`, `/sbin → /usr/sbin`, `/lib → /usr/lib` (реализовано через символические ссылки). Это всё ещё совместимо с FHS.

## /home

Краткое описание назначения директорий в домашней папке пользователя (основано на стандарте XDG, спецификациях Flatpak и POSIX):

- **`~/.local/share`** — пользовательские данные приложений: файлы, которые не являются ни настройками, ни временным кэшем (например: пользовательские шрифты, иконки, сохранения игр, профили браузеров).
- **`~/.state/local`** — нестандартная папка. Стандарт XDG предполагает наличие папки `~/.local/state` (для хранения состояния приложений: история команд, логи, данные для функции «отменить»). Если папка именно `~/.state`, её создал специфичный самописный скрипт или программа.
- **`~/.var/app`** — данные, конфигурации и кэш приложений, установленных через **Flatpak**. Папка обеспечивает изоляцию (песочницу) Flatpak-приложений от остальной части домашней директории.
- **`~/.config`** — пользовательские файлы конфигурации (настройки программ). Современный стандарт, который предотвращает «замусоривание» корня домашней папки множеством скрытых файлов вида `.имя_программы`.
- **`~/.cache`** — временные данные, которые можно безопасно удалить для освобождения места (эскизы изображений, кэш браузера, кэш загруженных пакетов). Если удалить папку, программы просто создадут её заново и наполнят по мере необходимости.
- **`~/.archi`** — нестандартная папка. В Arch Linux или общих стандартах Linux такой директории не существует. Вероятно, это артефакт конкретного AUR-пакета, стороннего скрипта или опечатка. Содержимое проверяется командой `ls -la ~/.archi`, чтобы понять, какая программа её создала.
- **`~/.profile`** — скрипт инициализации оболочки (shell). Выполняется при входе пользователя в систему (login shell, например, при входе через графический менеджер или по SSH) для настройки переменных окружения (например, добавления путей в `PATH`), алиасов и других параметров сессии.
- `~/.config/dconf/user` — бинарный файл с пользовательскими настройками GNOME (именно его используют gsettings и dconf).

**Резюме:** папки `.config`, `.local/share`, `.cache` и `.profile` — строгий стандарт организации домашнего каталога. `.var/app` — стандарт для Flatpak. Остальные две (`.state/local` и `.archi`) требуют проверки, так как не являются системными.

### Что можно безопасно удалить (или очистить) для сброса GNOME

Эти директории содержат кэш, временные данные и пользовательские настройки, которые при новой установке лучше начать с нуля:

- `~/.cache/` — кэш приложений, эскизы, временные файлы. После удаления всё пересоздастся автоматически. Самый безопасный кандидат на полное удаление.
- `~/.local/share/Trash/` — корзина. Можно очистить, чтобы не переносить удалённые файлы.
- `~/.local/share/gnome-shell/` — в некоторых случаях там накапливаются проблемные данные сессии. Не удаляйте целиком, если важны расширения, но можно выборочно почистить содержимое.
- `~/.config/gnome-session/` — настройки сессий GNOME. Удаление сбросит поведение автозапуска и сохранённых сессий.
- `~/.gconf/` и `~/.local/share/gconf/` — устаревшие настройки GConf (в современном GNOME почти не используются, но могут остаться от старых пакетов). Можно удалить.
- `~/.dbus/` — файлы сессии D-Bus. Удаляются без последствий, пересоздаются при входе.

> **Важно:** не удаляйте сам файл `~/.config/dconf/user` (бинарная база dconf) «на всякий случай» — это основной источник настроек GNOME. Если нужно сбросить настройки GNOME, лучше не удалять файл, а перезаписать его пустой базой или использовать `dconf reset -f /`.

### Папки, которые не надо удалять (там ваши данные)

- `~/Documents`, `~/Downloads`, `~/Pictures`, `~/Videos`, `~/Music` — личные файлы.
- `~` (корневая папка пользователя) — там могут быть важные файлы напрямую (`.bashrc`, `.zshrc`, проекты и т. п.).
- `~/.ssh/` — ключи SSH, `known_hosts`. Потеря ключей означает потерю доступа к серверам.
- `~/.gnupg/` — ключи GnuPG.
- `~/.local/share/applications/` — пользовательские `.desktop`-файлы (ярлыки).
- `~/.local/share/flatpak/` (если используется Flatpak) — установленные пользователем приложения и их данные.
- `~/.var/app/` (если используются Flatpak-приложения в песочнице) — данные приложений.

## FHS vs XDG

| Критерий | FHS (Filesystem Hierarchy Standard) | XDG Base Directory Specification |
| --- | --- | --- |
| Масштаб | Вся операционная система (глобально) | Домашняя директория пользователя (локально, `~`) |
| Цель | Упорядочить файлы ОС для администраторов, пакетных менеджеров и самой системы | Предотвратить «замусоривание» корня домашней папки сотнями скрытых файлов (`.имя_программы`) |
| Ключевые пути | `/etc`, `/usr`, `/var`, `/bin`, `/opt` | `~/.config`, `~/.local/share`, `~/.cache`, `~/.local/state` |
| Права доступа | Обычно требует прав `root` для изменения | Полные права у обычного пользователя |
| Пример | Глобальная конфигурация приложения лежит в `/etc/nginx/nginx.conf` | Пользовательская конфигурация того же приложения лежит в `~/.config/nginx/nginx.conf` |

**Главный вывод:** это не конкурирующие, а взаимодополняющие стандарты. FHS управляет структурой системы от корня (`/`), а XDG управляет структурой внутри домашней папки пользователя (`~`), чтобы личные данные и настройки были организованы предсказуемо и аккуратно.

## directory slash

В контексте путей к файлам в операционных системах Linux и Windows `./` имеет одинаковое значение: оно указывает на текущий каталог.

**Объяснение:**

- `./` означает «текущий каталог».
- Например, команда `./script.sh` в Linux запустит файл `script.sh`, находящийся в текущем каталоге.
- Аналогично, в Windows `.\script.bat` означает запуск файла `script.bat`, расположенного в текущем каталоге.

**Важно:**

- В Linux использование `./` обязательно для запуска исполняемого файла из текущего каталога, потому что по умолчанию текущий каталог не входит в переменную окружения PATH.
- В Windows использование `.\` не обязательно для запуска локального файла, но может использоваться для явного указания пути.

**Итак:**

| ОС | Значение `./` | Пример использования |
| --- | --- | --- |
| Linux | Текущий каталог | `./my_script.sh` |
| Windows | Текущий каталог (аналог `.\`) | `.\my_script.bat` или просто `my_script.bat` |
