## Как пользоваться rkhunter

**rkhunter (Rootkit Hunter)** — сканер руткитов: проверяет системные бинарники на предмет известных сигнатур руткитов, аномалий в системных файлах, подозрительных сетевых портов, скрытых файлов и т.п. Важно понимать его архитектуру сразу: это **сканер известного**, а не поведенческий анализ — он сравнивает ваши бинарники с хешами/сигнатурами из своей базы и ловит классические руткиты; свежий кастомный бэкдор он не заметит.

### 1. Установка

```bash
sudo pacman -S rkhunter
```

### 2. Первичная настройка — создание базы хешей

Это **обязательный первый шаг**, без него каждая проверка будет давать сотни ложных срабатываний. После установки система «чистая» (вы ей доверяете на этом этапе) — записываем её состояние как эталон:

```bash
# Обновить базу данных (сигнатуры руткитов)
sudo rkhunter --update

# Обновить базу версий (данные о свежих уязвимостях)
sudo rkhunter --versioncheck

# Создать эталонные хеши всех системных файлов и учётных записей
sudo rkhunter --propupd
```

`--propupd` записывает в `/var/lib/rkhunter/db/` хеши бинарников, данные об учётных записях, группах, портах. **Все последующие проверки сравниваются с этим снапшотом.**

⚠️ Важно: если вы потом обновите систему (`pacman -Syu`), хеши бинарников изменятся — нужно пересоздать базу, иначе получите лавину «предупреждений». Лучший порядок:

```bash
sudo pacman -Syu
sudo rkhunter --propupd    # заново эталонизируем уже обновлённую систему
```

### 3. Запуск проверки

```bash
# Интерактивный режим (задаёт вопросы по ходу — нажимайте Enter)
sudo rkhunter --check
sudo rkhunter --check | tee /tmp/rkhunter.log

# Автоматический, с подробным отчётом в файл
sudo rkhunter --check --rwo > /tmp/rkhunter-report.txt
less /tmp/rkhunter-report.txt

# Быстрый пропуск интерактивных вопросов
sudo rkhunter --check --skip-keypress
```

Что он проверяет (этапы в отчёте):

1. **System tools** — бинарники (`ls`, `ps`, `netstat` и др.) на предмет троянов;
2. **Rootkits** — сигнатуры известных руткитов (Adore, Knark, Beastkit и десятки других);
3. **Network** — подозрительные порты, промискуитетный режим интерфейсов;
4. **Local host** — аномалии в учётных записях, группах, `/tmp`, SUID-файлах, ядре.

### 4. Чтение результатов

В конце отчёта — сводка `RootKit Hunter version ... File updated: ...`. Каждая строка помечается:

- `[ OK ]` — чисто;
- `[ Warning ]` — требует внимания;
- `[ None found ]` — руткит не обнаружен (норма);
- `[ Skipped ]` — проверка пропущена (например, нет нужного файла).

### 5. Разбор типичных ложных срабатываний в Arch

На Arch почти гарантированно увидите Warning'и — это **ложные срабатывания**, а не заражение. Типичные:

| Warning | Причина на Arch | Что делать |
|---|---|---|
| `System tools signatures` / `ps`, `ls` changed | Вы обновили пакет после `--propupd` | `sudo rkhunter --propupd` |
| `Hidden directory found: /etc/.java` | Легитимный каталог JDK | Игнорировать или внести в whitelist |
| `Suspicious file types found in /dev` | udev/`/dev/shm` временные файлы, особенно с SELinux/AppArmor | Проверить вручную, обычно норма |
| `Checking for string '...' found` в бинарниках | Совпадение строк внутри легитимных бинарей (например, `egrep` в ядре) | Смотреть, что именно; обычно совпадение |
| `File properties have changed: /usr/bin/...` | Свежий апдейт пакета | `sudo rkhunter --propupd` |

### 6. Whitelist — чтобы ложные срабатывания не повторялись

Постоянные ложные срабатывания заносятся в конфиг `/etc/rkhunter.conf`:

```bash
# Разрешить скрытый каталог (пример)
ALLOWHIDDENDIR="/etc/.java"

# Разрешить изменённый бинарник (не рекомендуется без проверки!)
# SCRIPTWHITELIST="/usr/bin/some_binary"

# Исключить SUID-файл из проверки
# ALLOW_SUID_FILE="/usr/lib/some_suid_binary"
```

После правки конфига проверка не должна выдавать по нему Warning.

### 7. Автоматизация

```bash
# Проверка по cron (ежедневно в 3:00, отчёт в /var/log/rkhunter.log)
sudo rkhunter --cronjob --rwo --skip-keypress --summary

# Пакет не создаёт таймер systemd автоматически — можно добавить самостоятельно:
sudo systemctl edit --full --force rkhunter.timer
```

Или проще — через `/etc/cron.daily/rkhunter`:

```bash
#!/bin/bash
/usr/bin/rkhunter --cronjob --rwo --skip-keypress --summary 2>/dev/null
```

### Практический минимум для начала

```bash
sudo pacman -S rkhunter
sudo rkhunter --update && sudo rkhunter --versioncheck
sudo rkhunter --propupd          # после установки/обновления системы
sudo rkhunter --check --rwo      # смотреть отчёт
# повторять --propupd после каждого pacman -Syu
```

### Честные ограничения

1. **Сигнатурный принцип** — ловит известное, пропускает новое (kernel-level руткиты типа Reptile он часто не видит).
2. **Эталон может быть отравлен** — если система уже заражена на момент `--propupd`, база записана с трояном, и проверка будет «чистой». Поэтому базу надо создавать на свежей установке.
3. **Дополнение, а не замена** — в связке с `pacman -Qkk`, AIDE, opensnitch и здравым смыслом. Для детекции именно руткитов в ядре полезнее загрузка с live-USB и сравнение бинарников извне, но rkhunter как первая линия — ок.

## Руткит

**Руткит** — вредоносное ПО, которое получает права root и **прячет своё присутствие** в системе.

Название: *root* (права суперпользователя) + *kit* (набор инструментов).

Ключевые свойства:

1. **Скрытность** — главная цель. Маскирует свои файлы, процессы, сетевые соединения. Например, подменяет команды `ps`, `ls`, `netstat` так, что заражённые файлы и процессы не отображаются — поэтому вы их не видите при обычной проверке.
2. **Привилегии** — работает с правами root, имеет полный контроль над системой.
3. **Постоянство** — переживает перезагрузки (внедряется в автозагрузку, ядро, загрузчик).

Где живёт (от простого к сложному):

- **Пользовательский уровень** — подменённые бинарники (`ps`, `ls`). Легко обнаружить (сравнением хешей — как делает `pacman -Qkk` или rkhunter).
- **Уровень ядра (kernel rootkit)** — модуль вредоносного кода внутри самого ядра Linux. Видит всё, фильтрует любую информацию от всех программ — обычными средствами **не обнаружить** в принципе, нужна проверка извне (загрузка с live-USB).

**Итог:** руткит — это не «вирус, который портит файлы», а **невидимый захватчик с правами администратора**. Опасен не действием, а тем, что его нельзя увидеть штатными средствами уже заражённой системы — поэтому и нужны rkhunter, AIDE и проверки извне.
