> При миграции обязательно надо:
> - сохранить всё содеримое /home
> - перенести все gnome extenstions с найстройками

> - перенести все настройки gnome, включая keyboard shortcuts

## 🔄 Миграция Arch Linux GNOME → Manjaro GNOME с сохранением всего

Сразу важное: **полностью бесшовной миграции "поверх" Arch не существует** — репозитории Arch и Manjaro различаются, и попытка сменить их "на месте" почти гарантированно сломает систему. Единственный надёжный путь — **чистая установка Manjaro с сохранением `/home`** и последующим восстановлением настроек. Это реально и даёт именно тот результат, который вам нужен.

---

### ⚠️ Что перенесётся, а что — частично

| Что | Переносится? | Нюанс |
|-----|-------------|-------|
| Содержимое `/home` | ✅ Полностью | Файлы, документы, конфиги приложений |
| Расширения GNOME | ✅ Да | Могут потребовать переустановки под версию GNOME в Manjaro |
| Настройки расширений | ✅ Да | Хранятся в dconf |
| Настройки GNOME + хоткеи | ✅ Да | Через `dconf dump/load` |
| Установленные приложения | ⚠️ По списку | Переустановка из pacman/AUR, версии могут отличаться |
| Настройки приложений | ✅ Да | Живут в `~/.config` и `~/.local` (внутри `/home`) |

---

### 📋 Шаг 0. Подготовка в Arch (до установки Manjaro)

#### 1. Список пакетов
```bash
mkdir -p ~/f/manjaro-migrate/backup

# Явно установленные пакеты (основные репозитории)
pacman -Qqe > ~/f/manjaro-migrate/backup/packages.txt

# Пакеты из AUR
pacman -Qqm > ~/f/manjaro-migrate/backup/aur-packages.txt

# Полный список всех пакетов (для справки)
pacman -Q > ~/f/manjaro-migrate/backup/all-packages.txt
```

#### 2. Бэкап всех настроек GNOME (включая хоткеи)
```bash
# Полный дамп dconf (это ВСЕ настройки GNOME + расширений + хоткеи)
dconf dump / > ~/f/manjaro-migrate/backup/dconf-full.ini

# Отдельно ветку горячих клавиш (для контроля)
dconf dump /org/gnome/settings-daemon/plugins/media-keys/ > ~/f/manjaro-migrate/backup/hotkeys.ini
dconf dump /org/gnome/desktop/wm/keybindings/ >> ~/f/manjaro-migrate/backup/hotkeys.ini
```

#### 3. Бэкап расширений GNOME
```bash
# Пользовательские расширения + их данные
cp -r ~/.local/share/gnome-shell/extensions ~/f/manjaro-migrate/backup/gnome-extensions

# Список расширений (для сверки)
ls ~/.local/share/gnome-shell/extensions > ~/f/manjaro-migrate/backup/extensions-list.txt

# Настройки расширений тоже в dconf — уже сохранены в dconf-full.ini
```

#### 4. Список включённых расширений
```bash
gsettings get org.gnome.shell enabled-extensions > ~/f/manjaro-migrate/backup/enabled-extensions.txt
gsettings get org.gnome.shell disabled-extensions > ~/f/manjaro-migrate/backup/disabled-extensions.txt
```

### 💾 Шаг 1. Сохранение `/home`

Здесь **два сценария** — выберите свой:

#### 🅰️ Сценарий A: `/home` на отдельном разделе

Проверьте:

```bash
lsblk -f
df -h | grep home

> lsblk
NAME        MAJ:MIN RM   SIZE RO TYPE MOUNTPOINTS
sda           8:0    1 466,5G  0 disk 
└─sda1        8:1    1 466,5G  0 part /mnt/usb-Generic_MassStorageClass_000000002402-0:0-part1
sdb           8:16   1    22K  1 disk 
nvme0n1     259:0    0 953,9G  0 disk 
├─nvme0n1p1 259:1    0   300M  0 part -win
├─nvme0n1p2 259:2    0    16M  0 part -win
├─nvme0n1p3 259:3    0   170G  0 part -win
├─nvme0n1p4 259:4    0     1G  0 part /boot
├─nvme0n1p5 259:5    0    32G  0 part [SWAP]
├─nvme0n1p6 259:6    0    90G  0 part /
└─nvme0n1p7 259:7    0 660,6G  0 part /home

```

Если `/home` — отдельный раздел (например, `/dev/nvme0n1p4`):

- При установке Manjaro **не форматируйте** этот раздел, просто смонтируйте его как `/home`.
- **Всё содержимое сохранится автоматически.**

#### 🅱️ Сценарий B: `/home` внутри корневого раздела `/`

Нужен внешний носитель. Полный бэкап:

```bash
# Запомните UID вашего пользователя (важно для восстановления прав!)
id $(whoami)

# Бэкап /home на внешний диск (с сохранением прав и симлинков)
sudo rsync -aAXv --progress /home/ /run/media/you/EXTERNAL_DISK/home-backup/
```
> ⚠️ **Запишите UID/GID** (команда `id`) — при создании пользователя в Manjaro нужно будет совпадение, иначе потеряете права на файлы.

---

### 🖥️ Шаг 2. Установка Manjaro

1. Загрузитесь с `manjaro-gnome-26.0.4-260327-linux618.iso`.
2. Запустите установщик **Calamares**.
3. На этапе **разметки диска** выберите **«Ручная разметка» (Manual Partitioning)**:

| Раздел | Точка монтирования | Форматировать? |
|--------|-------------------|----------------|
| EFI (ESP) | `/boot/efi` | ❌ Не форматировать (или форматировать, если хотите чистый загрузчик) |
| Корень `/` | `/` | ✅ Форматировать (ext4/btrfs) |
| **`/home` (сценарий A)** | `/home` | ❌ **НЕ форматировать!** |
| swap | — | по желанию |

1. **Критично для сценария A:** в Calamares снимите галочку "Format" с раздела `/home`.
2. При создании пользователя:
   - **Сценарий A:** создайте пользователя с **тем же именем**, что было в Arch. Если UID отличается — после установки исправите права (см. шаг 3).
   - **Сценарий B:** создайте пользователя, затем восстановите `/home` из бэкапа.

---

### ♻️ Шаг 3. Восстановление после установки

#### 1. Проверьте права на `/home` (если UID не совпал)
```bash
# Посмотрите текущий UID
id $(whoami)

# Если UID отличается от старого — исправьте владельца рекурсивно
sudo chown -R $USER:$USER /home/$USER
```

#### 2. Восстановление настроек GNOME + хоткеи
```bash
# Полный импорт всех настроек
dconf load / < ~/f/manjaro-migrate/backup/dconf-full.ini

# Проверка хоткеев
dconf dump /org/gnome/settings-daemon/plugins/media-keys/
```
> ⚠️ Если `dconf load` выдаст ошибки по отдельным ключам — это нормально: версии схем GNOME в Arch и Manjaro могут немного отличаться. Большинство настроек применится.

#### 3. Восстановление расширений
```bash
# Копируем расширения обратно
mkdir -p ~/.local/share/gnome-shell
cp -r ~/f/manjaro-migrate/backup/gnome-extensions ~/.local/share/gnome-shell/

# Включаем их (подставьте из вашего списка)
gsettings set org.gnome.shell enabled-extensions "['user-theme@gnome-shell-extensions.gcampax.github.com', ...]"
```
> 💡 **Реалистично:** если версия GNOME Shell в Manjaro отличается от Arch, часть расширений может быть несовместима. В этом случае проще переустановить их из [extensions.gnome.org](https://extensions.gnome.org) — настройки из dconf всё равно подтянутся.

#### 4. Восстановление приложений
```bash
# Просмотрите список
cat ~/f/manjaro-migrate/backup/packages.txt

# Установите пакетным менеджером Manjaro (pacman/pamac)
# Manjaro имеет pamac с GUI — удобно для выбора
sudo pacman -S $(cat ~/f/manjaro-migrate/backup/packages.txt | tr '\n' ' ')
```
> ⚠️ **Нюансы:**
> - Некоторые пакеты из Arch в Manjaro называются иначе или отсутствуют — такие ставьте вручную.
> - **AUR-пакеты** (`aur-packages.txt`) нужно установить отдельно: `pamac build <имя>` или через `yay`.
> - Конфигурации приложений (в `~/.config`) уже на месте из `/home` — они подхватятся автоматически.

---

### 🧪 Шаг 4. Проверка результата

```bash
# Все ли расширения на месте
gnome-extensions list

# Работают ли хоткеи
gsettings get org.gnome.desktop.wm.keybindings switch-applications

# Версия GNOME в Manjaro
gnome-shell --version
```

### 🎯 Итоговый план

1. **В Arch:** `pacman -Qqe` + `dconf dump /` + копирование `~/.local/share/gnome-shell/extensions` → на внешний носитель.
2. **Определите,** отдельный ли раздел у `/home`.
3. **Установите Manjaro** с ручной разметкой: корень форматировать, `/home` — **не форматировать** (сценарий A) или восстановить из бэкапа (сценарий B).
4. **Восстановите:** `dconf load /`, расширения, приложения по списку.

---

### 💡 Честные рекомендации

- **Самый надёжный вариант** — если `/home` на отдельном разделе. Тогда 90% ваших данных и настроек приложений переедут автоматически.
- **Сделайте полный бэкап `/home`** даже в сценарии A — на случай ошибки разметки. Цена ошибки слишком высока.
- **Будьте готовы** к тому, что 5–10% пакетов придётся подбирать вручную из-за различий репозиториев Arch и Manjaro.
- **Проверьте версию GNOME** в Manjaro 26.0.4 и в вашем Arch: если они сильно различаются, расширения могут потребовать переустановки.

Если скажете, на каком разделе у вас `/home` (вывод `lsblk -f`), помогу составить точную схему разметки для установщика Manjaro. 🛠️

---

При переустановке Arch Linux с сохранением `/home` и того же пользователя **не стоит просто «удалять папки наугад»**: в `/home` лежат не только настройки, но и все ваши личные файлы (документы, фото, проекты).

Ниже — какие папки **имеет смысл очистить или удалить**, если цель — сбросить окружение GNOME до «чистого» состояния, и какие **категорически нельзя трогать**.

---

### Что можно безопасно удалить (или очистить) для сброса GNOME

Эти директории содержат кэш, временные данные и пользовательские настройки, которые при новой установке лучше начать с нуля:

- `~/.cache/` — кэш приложений, эскизы, временные файлы. После удаления всё пересоздастся автоматически. Это **самый безопасный кандидат на полное удаление**.
- `~/.local/share/Trash/` — корзина. Можно очистить, чтобы не переносить удалённые файлы.
- `~/.local/share/gnome-shell/` — в некоторых случаях там накапливаются проблемные данные сессии. Не удаляйте целиком, если важны расширения, но можно выборочно почистить содержимое.
- `~/.config/gnome-session/` — настройки сессий GNOME. Удаление сбросит поведение автозапуска и сохранённых сессий.
- `~/.gconf/` и `~/.local/share/gconf/` — устаревшие настройки GConf (в современном GNOME почти не используются, но могут остаться от старых пакетов). Можно удалить.
- `~/.dbus/` — файлы сессии D-Bus. Удаляются без последствий, пересоздаются при входе.

> **Важно:** не удаляйте сам файл `~/.config/dconf/user` (бинарная база dconf) «на всякий случай» — это основной источник настроек GNOME. Если хотите сбросить настройки GNOME, лучше не удалять файл, а **перезаписать** его пустой базой или использовать `dconf reset -f /`.

---

### Папки, которые **не надо удалять** (там ваши данные)

- `~/Documents`, `~/Downloads`, `~/Pictures`, `~/Videos`, `~/Music` — ваши личные файлы.
- `~` (корневая папка пользователя) — там могут быть важные файлы напрямую (`.bashrc`, `.zshrc`, проекты и т. п.).
- `~/.ssh/` — ключи SSH, `known_hosts`. Потеря ключей означает потерю доступа к серверам.
- `~/.gnupg/` — ключи GnuPG.
- `~/.local/share/applications/` — ваши пользовательские `.desktop`-файлы (ярлыки).
- `~/.local/share/flatpak/` (если используется Flatpak) — установленные пользователем приложения и их данные.
- `~/.var/app/` (если используются Flatpak-приложения в песочнице) — данные приложений.

---

### Особый случай: расширения GNOME Shell

Если вы активно использовали расширения GNOME, их настройки и данные могут быть в:

- `~/.local/share/gnome-shell/extensions/`

Если хотите **полностью сбросить** все расширения — можно удалить эту папку. Если хотите сохранить расширения и их настройки — **не удаляйте**.

---

### Практический совет: не удаляйте, а архивируйте

Вместо удаления лучше сделать так:

```bash
cd ~
tar czf home-config-backup.tar.gz .config .local .cache .gconf .dbus .gnome .gnome2
```

Тогда вы:

1. Сохраните все старые настройки в архиве.
2. Сможете удалить папки из `/home`.
3. При необходимости восстановите нужные части из архива.

---

### Как правильно сбросить настройки GNOME (альтернатива удалению папок)

Если цель — «чистый» GNOME без потери личных файлов, лучше использовать инструменты сброса, а не ручное удаление:

- Сбросить все настройки GNOME:
  ```bash
  dconf reset -f /
  ```
- Или сбросить только определённую ветку, например, тему и шрифты:
  ```bash
  gsettings reset-recursively org.gnome.desktop.interface
  ```

Это безопаснее и чище, чем удалять файлы вручную.

---

### Важное предупреждение про Arch Linux

Arch — rolling release. Если вы сохраняете старый `/home` от старой системы и ставите новую версию, возможны:

- Несовместимость форматов кэша (например, у Firefox, Thunderbird, Evolution).
- Конфликты настроек расширений GNOME при обновлении версий оболочки.

Поэтому **очистка `~/.cache/` и выборочный сброс dconf** — самый надёжный путь.

Если скажете, какая именно проблема вас беспокоит (например, «GNOME тормозит», «не загружается сессия», «хочу чистый рабочий стол»), подскажу точечные действия вместо тотальной очистки.
