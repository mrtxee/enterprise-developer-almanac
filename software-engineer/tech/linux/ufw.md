## Установка

Установка UFW и его графической оболочки GUFW на домашнем ноутбуке с [[linux-distros|Arch Linux]]:

```bash
sudo pacman -S ufw gufw
```

`ufw` — это сам брандмауэр (командная строка), а `gufw` — графический интерфейс к нему (опционально, удобно для новичков).

---

## Базовая настройка UFW

### Установите правила по умолчанию

Запрещаем все входящие подключения, разрешаем все исходящие:

```bash
sudo ufw default deny incoming
sudo ufw default allow outgoing
```

### Разрешите SSH

Если подключаетесь к ноутбуку по [[ssh-scp-sftp|SSH]] из локальной сети, это правило обязательно:

```bash
sudo ufw allow ssh
```

Это разрешит подключения по SSH на стандартном порту (22).

### Включите UFW

```bash
sudo ufw enable
```

При первом запуске команда может попросить подтверждения, так как включение может разорвать текущие SSH-соединения.

### Проверьте статус и правила

```bash
sudo ufw status verbose
```

Ожидаемый вывод:

```text
Status: active
Logging: on (low)
Default: deny (incoming), allow (outgoing), deny (routed)
New profiles: skip

To                         Action      From
--                         ------      ----
22/tcp                     ALLOW IN    Anywhere
```

## Настройка через GUFW

1. Запустите приложение GUFW из меню приложений.
2. В главном окне:
   - Переключите статус на «Включён» (Enabled).
   - В списке «Входящие» (Incoming) выберите «Запретить» (Deny).
   - В списке «Исходящие» (Outgoing) выберите «Разрешить» (Allow).
3. Для добавления правил (например, для SSH или торрент-клиента):
   - Нажмите «Добавить правило» (Add Rule).
   - Выберите «Simple» или «Advanced».
   - Укажите порт (например, 22 для SSH) и направление (In).
   - Нажмите «Добавить» (Add).

## Дополнительные правила для повседневного использования

**Для торрент-клиента (qBittorrent)** — разрешить входящие подключения на порт, используемый в настройках клиента (обычно в диапазоне 6881–6889):

```bash
sudo ufw allow 6881/tcp
sudo ufw allow 6881/udp
```

**Для Bonjour/Avahi (обнаружение сетевых устройств):**

```bash
sudo ufw allow 5353/udp
```

**Для общего доступа к файлам (Samba):**

```bash
sudo ufw allow 139/tcp
sudo ufw allow 445/tcp
```

## Управление правилами

**Посмотреть все правила с номерами:**

```bash
sudo ufw status numbered
```

**Удалить правило по номеру** (например, номер 3):

```bash
sudo ufw delete 3
```

**Удалить правило по параметрам:**

```bash
sudo ufw delete allow from 192.168.1.0/24 to any port 5353 proto udp
```

**Полностью отключить UFW:**

```bash
sudo ufw disable
```

**Сбросить все правила к заводским:**

```bash
sudo ufw reset
```

---

## Включение логирования

Для диагностики подключений включите логирование:

```bash
sudo ufw logging on
```

Логи пишутся в системный журнал:

```bash
sudo journalctl -u ufw -f
```

Это покажет, какие пакеты блокируются, и позволит уточнить порт.

## Настройка UFW для GNOME Quick Share

**Определение прослушиваемых портов:**

```bash
sudo ss -tunap
```

Пример вывода для gnomeqs:

```text
udp   UNCONN  0  0  127.0.0.1:53769     0.0.0.0:*    users:(("gnomeqs",pid=8663,fd=17))
udp   UNCONN  0  0  0.0.0.0:5353         0.0.0.0:*    users:(("gnomeqs",pid=8663,fd=22))
tcp   LISTEN  0  128  0.0.0.0:45753      0.0.0.0:*    users:(("gnomeqs",pid=8663,fd=15))
```

Итог по портам: UDP `127.0.0.1:53769`, UDP `0.0.0.0:5353`, TCP `0.0.0.0:45753`.

**Добавление правил:**

```bash
# Разрешить mDNS (UDP 5353) для обнаружения устройств в локальной сети
sudo ufw allow from 192.168.0.0/16 to any port 5353 proto udp
# Разрешить порт передачи данных
sudo ufw allow from 192.168.0.0/16 to any port 45753 proto tcp
sudo ufw allow from 192.168.0.0/16 to any port 30000:50000 proto tcp
```

> [!info] `192.168.0.0/16` — это вся сеть класса B: все адреса от 192.168.0.0 до 192.168.255.255. `/16` означает, что первые 16 бит (первые два числа) фиксированы (192.168), а остальные могут быть любыми.

**Проверка правил и применение изменений:**

```bash
sudo ufw status verbose
sudo ufw reload
```

## Категории портов

Все порты делятся на три диапазона, регламентированные IANA (Internet Assigned Numbers Authority):

1. **Системные (Well-Known Ports): 0–1023**
   - Назначение: зарезервированы для системных служб и протоколов.
   - Кто использует: только приложения с правами суперпользователя (root).
   - Примеры: `22` (SSH), `80` (HTTP), `443` (HTTPS), `25` (SMTP).
2. **Зарегистрированные (Registered Ports): 1024–49151**
   - Назначение: менее критичные, но широко распространённые приложения и сервисы.
   - Кто использует: обычные пользовательские приложения, работающие как серверы.
   - Примеры: `3306` (MySQL), `5432` ([[PostgreSQL|PostgreSQL]]), `8080` (альтернативный HTTP).
3. **Эфемерные/Динамические (Dynamic / Private Ports): 49152–65535**
   - Назначение: временные порты, которые ОС выдаёт программам на время соединения.
   - Кто использует: любое клиентское приложение (браузер, мессенджер, торрент-клиент), инициирующее исходящее соединение.
   - Примеры: `49152`, `54231` и т.д.

---

## Что такое эфемерные порты

Когда браузер открывает веб-страницу, он не использует порт `443` — это порт сервера. Вместо этого операционная система (ядро) выдаёт случайный свободный порт из динамического диапазона, например `52413`, и привязывает его к браузеру. Порт остаётся занятым до закрытия соединения.

Эфемерные порты нужны, чтобы одно приложение (например, браузер) могло поддерживать тысячи одновременных соединений с разными серверами. У каждого соединения свой уникальный эфемерный порт, что позволяет системе правильно направлять входящие пакеты обратно в нужное приложение.

В контексте UFW и Quick Share: ноутбук слушает порт `5353` (системный, для mDNS) и порт передачи файлов (например, `43243`, категория зарегистрированных), а для исходящего подключения к порту `45753` другого устройства использует эфемерный порт (например, `38510`). Такие соединения не нужно открывать в UFW.

**Сводная таблица**

| Диапазон | Название | Назначение | Кто использует |
| --- | --- | --- | --- |
| 0–1023 | Системные | Критические сервисы (SSH, HTTP) | Только root |
| 1024–49151 | Зарегистрированные | Сервисы приложений (MySQL, игры) | Пользовательские серверы |
| 49152–65535 | Эфемерные | Временные клиентские соединения | Браузеры, клиенты |

## Важное уточнение

В Linux системные администраторы могут изменить диапазон эфемерных портов. Текущие настройки можно посмотреть командой:

```bash
cat /proc/sys/net/ipv4/ip_local_port_range
```

Обычно это диапазон `32768–60999`, что немного отличается от стандарта IANA, но суть остаётся той же.
