## TOGAF

> **The Open Group Architecture Framework**  
> (Архитектурная рамка Open Group)

**TOGAF** — это **международный стандарт** **разработки, проектирования, планирования и управления архитектурой предприятия ([[Enterprise Architecture]])**. 

Он предоставляет **методологию, набор инструментов и лучшие практики**, чтобы **связать бизнес-цели с IT-решениями**.

> TOGAF — это **«инструкция по сборке»** для архитектора предприятия:  
> *«Как превратить стратегию компании в реальную IT-систему без хаоса, дублирования и перерасхода бюджета?»*

> ✅ **TOGAF — это не про технологии. Это про управление сложностью.**


---

## ✅ Основные компоненты TOGAF

TOGAF — это не одна диаграмма, а **целая система**, состоящая из нескольких частей. 

| Часть | Название                                  | Описание                                                         |
| ----- | ----------------------------------------- | ---------------------------------------------------------------- |
| **1** | **Architecture Development Method (ADM)** | Главный процесс — **пошаговый метод** создания архитектуры       |
| **2** | **Architecture Content Framework**        | Стандартные **выходы архитектуры**: диаграммы, модели, документы |
| **3** | **Enterprise Continuum**                  | Классификация архитектурных решений — от общих до специфичных    |
| **4** | **Architecture Capability Framework**     | Как построить **команду архитекторов**, процессы, поддержку      |
| **5** | **TOGAF Reference Models**                | Готовые шаблоны (например, **TRM** — Technical Reference Model)  |

## ✅ Какие проблемы решает TOGAF?

| Проблема                                          | Как TOGAF помогает                                                              |
| ------------------------------------------------- | ------------------------------------------------------------------------------- |
| ❌ Бизнес хочет цифровизации, а IT — «сделать CRM» | ✅ TOGAF связывает бизнес-цели → архитектуру → системы                           |
| ❌ В компании 50 систем, все разные, не связаны    | ✅ TOGAF даёт методы **инвентаризации, стандартизации, устранения дублей**       |
| ❌ Нет понимания, кто за что отвечает              | ✅ TOGAF вводит **роли архитекторов**, **управление изменениями**                |
| ❌ Каждый проект — «с нуля»                        | ✅ TOGAF предлагает **единый процесс (ADM)** — одинаковый для всех проектов      |
| ❌ Системы не масштабируются, не интегрируются     | ✅ TOGAF учит **архитектурные принципы**: модульность, открытость, совместимость |

## ✅ Architecture Development Method – ADM

Это **ядро TOGAF** — 9-этапный циклический процесс проектирования архитектуры.

**🔄 9 этапов ADM (упрощённо):**

| Этап  | Название                                          | Что делает                                                                                      |
| ----- | ------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| **0** | **Предварительный этап**                          | Подготовка: создание архитектурной команды, установление принципов, определение масштаба        |
| **1** | **Архитектура предприятия (Architecture Vision)** | Создаётся **видение** — зачем нужна архитектура? Какие цели? Кто заинтересован?                 |
| **2** | **Бизнес-архитектура**                            | Описывает **бизнес-процессы, цели, структуру, роли** (связь с [[BCM\|Business Capability Map]]) |
| **3** | **Архитектура информации**                        | Описывает **данные**: что хранится, где, как связаны (Data Model, Data Flow)                    |
| **4** | **Архитектура приложений**                        | Описывает **приложения**: какие системы есть, как они взаимодействуют ([[IT Landscape Map]]]!)  |
| **5** | **Технологическая архитектура**                   | Описывает **инфраструктуру**: серверы, сети, облака, безопасность                               |
| **6** | **Реализация архитектуры**                        | Планирование **реализации**: проекты, фазы, ресурсы, риски                                      |
| **7** | **Миграция планирования**                         | План перехода от **текущего состояния** к **целевому** ([[Technology Roadmap\|Roadmap]])        |
| **8** | **Управление архитектурой**                       | **Контроль** и **адаптация** архитектуры в процессе реализации                                  |
| **9** | **Архитектурная оценка**                          | Проверка, достигнуты ли цели — **оценка результатов**                                           |

> ✅ **ADM — это не линейный процесс, а цикл.**  
> После этапа 9 вы возвращаетесь к этапу 0 — архитектура **постоянно развивается**.

## ✅ Enterprise Continuum

Это **классификация архитектурных решений** от **общих** до **специфичных**.

| Уровень                                | Пример                                         |
| -------------------------------------- | ---------------------------------------------- |
| **Foundation Architecture**            | Общие принципы (например, ISO 19770, ITIL)     |
| **Industry Architecture**              | Стандарты для банков (BPMN), медицины (HL7)    |
| **Organization-Specific**              | Внутренние стандарты вашей компании            |
| **Architecture Building Blocks (ABB)** | Готовые компоненты: CRM, ERP, BI               |
| **Solution Building Blocks (SBB)**     | Конкретная реализация: Salesforce, SAP S/4HANA |

> ✅ **TOGAF помогает выбирать: использовать готовое решение или строить с нуля?**

## ✅ Architecture Content Framework?

Это **стандартные документы и модели**, которые вы должны создавать на каждом этапе ADM.

| Тип документа                       | Пример                                           |
| ----------------------------------- | ------------------------------------------------ |
| **Business Architecture**           | Business Capability Map, BPMN-диаграммы          |
| **Data Architecture**               | ER-диаграммы, Data Dictionary, Data Flow Diagram |
| **Application Architecture**        | IT Landscape Map, API Catalog, Component Diagram |
| **Technology Architecture**         | Network Diagram, Cloud Topology, Security Policy |
| **Implementation & Migration Plan** | Roadmap, Project Portfolio, Risk Register        |

> ✅ TOGAF **не требует** конкретных инструментов — вы можете использовать **Draw.io, Lucidchart, Confluence, Excel** — главное, **структурировать**.

## ✅ TOGAF vs Другие стандарты

| Сравниваемый стандарт                                | Чем отличается от TOGAF                                                                                          |
| ---------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| **Zachman Framework**                                | Фокус на **матрице вопросов** (Что? Как? Где? Кто? Когда? Почему?) — больше теоретический, TOGAF — практичный    |
| **FEAF (Federal Enterprise Architecture Framework)** | Для **государственных организаций США** — TOGAF — универсален                                                    |
| **ArchiMate**                                        | **Язык моделирования** (как UML для архитектуры) — TOGAF — **методология**, которая может использовать ArchiMate |
| **ITIL**                                             | Управление **IT-услугами** — TOGAF — управление **архитектурой**                                                 |
| **COBIT**                                            | Управление **IT-управлением и контролем** — TOGAF — про **проектирование**                                       |

> ✅ **TOGAF — это «как делать». ArchiMate — «как рисовать». ITIL — «как поддерживать».**

## ✅ Пример: Как TOGAF помогает при цифровой трансформации

### 🎯 Цель компании:
> *«Стать лидером по онлайн-продажам в регионе»*

### ❌ Без TOGAF:
> - Закупили CRM  
> - Закупили ERP  
> - Закупили BI  
> - Не связали их  
> - Потратили 100 млн — ничего не работает  
> - Бизнес недоволен  

### ✅ С TOGAF:
1. **Этап 1 (Vision)**: «Нам нужно улучшить способность «Продажи через цифровые каналы»»  
2. **Этап 2 (Business)**: Описали процессы: «Приём заказа → Обработка → Доставка → Поддержка»  
3. **Этап 3 (Data)**: Определили: «Клиент, заказ, товар, платеж — ключевые сущности»  
4. **Этап 4 (Application)**: Выбрали:  
   - CRM: Salesforce (для продаж)  
   - ERP: SAP S/4HANA (для логистики)  
   - BI: Power BI (для аналитики)  
5. **Этап 5 (Technology)**: Все в облаке AWS  
6. **Этап 6–7**: План миграции:  
   - Сначала CRM → затем ERP → затем интеграция  
   - Срок: 12 месяцев  
7. **Этап 8–9**: Контроль, оценка — **рост продаж на 40% за год**

> ✅ **TOGAF превратил хаос в стратегию.**
