## Правильное название

- **Английское:** spaghetti code.
- **Русское:** спагетти-код.

## Отличия spaghetti code от boilerplate code

| Критерий | Boilerplate code | Spaghetti code |
| --- | --- | --- |
| Суть и назначение | Повторяющиеся стандартизированные фрагменты кода для настройки базовой структуры приложений или модулей; «нетворческий» код, повторяющийся с минимальными изменениями (подключение модулей, настройка компилятора, организация точки входа в программу). Цель — ускорить разработку, обеспечить совместимость и единообразие. | Плохо спроектированный, слабо структурированный, запутанный код, трудный для понимания и поддержки; хаотичная логика, множество вложенных условий, бесструктурные переходы (особенно оператор `GOTO`), сложные зависимости. Поток выполнения программы напоминает «клубок спагетти» — извилистый и запутанный. Возникает из-за неопытности разработчиков, давления по срокам, оптимизации времени исполнения без учёта структуры. |
| Цели появления | Появляется осознанно — часть стандартной практики разработки, необходимая для функционирования программы; норма в программировании (например, блок `main()` в Java, конструкция `if __name__ == "__main__":` в Python). | Чаще всего результат ошибок в проектировании, спешки, отсутствия планирования; считается антипаттерном. |
| Примеры | Подключение модулей: `#include <stdio.h>` (C), `import java.io.*;` (Java); структура [[html5|HTML]]: `<!DOCTYPE html>`, `<html>`, `<head>`, `<body>`; аннотация `@SpringBootApplication` в Spring Boot. | Код с множеством операторов `GOTO`, создающих хаотичные переходы; глубоко вложенные условия (`if-else`) и циклы, затрудняющие понимание логики; смешивание бизнес-логики, ввода/вывода и обработки ошибок в одном блоке; пример на Бейсике с избыточными переходами для простой задачи печати чисел и их квадратов. |
| Последствия и обработка | Не является проблемой сам по себе, но усложняет код при избыточном использовании; минимизируется системами сборки, автогенераторами кода, препроцессорами, метапрограммированием. | Затрудняет поддержку, расширение и отладку программы; увеличивает риск ошибок при внесении изменений; требует рефакторинга для улучшения читаемости и поддерживаемости. |
| Оценка с точки зрения качества кода | Нейтральный элемент разработки — необходим, но желательно минимизировать. | Признак низкого качества кода, сигнализирует о проблемах в архитектуре и дизайне программы. |

**Вывод**

[[boilerplate|Boilerplate code]] — «полезная рутина» для структуры программы, а spaghetti code — «болезнь» кода, требующая лечения (рефакторинга) для поддержания здорового проекта.
