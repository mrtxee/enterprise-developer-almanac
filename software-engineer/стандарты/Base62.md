# Base62

**Base62** — это позиционная система счисления и схема кодирования «бинарные данные → текст», использующая набор из 62 алфавитно‑цифровых символов для компактного представления данных в удобочитаемом формате.

**Состав набора символов**

Стандартный алфавит Base62 включает:
* цифры: `0–9` (10 символов);
* заглавные буквы: `A–Z` (26 символов);
* строчные буквы: `a–z` (26 символов).

Всего: 10 + 26 + 26 = 62 символа.

Типичный порядок символов: `0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz`. Некоторые реализации меняют порядок (например, `0–9a–zA–Z`), но внутри одной системы он должен быть неизменным.

**Как работает кодирование**

Алгоритм основан на **последовательном делении числа на 62**:
1. Исходное число (или ID) делят на 62.
2. Остаток от деления соответствует индексу символа в алфавите Base62.
3. Частное используют как новое число для следующего шага.
4. Процесс повторяют, пока частное не станет равным нулю.
5. Символы считывают в обратном порядке (от последнего остатка к первому) — это и есть итоговое закодированное значение.


**Пример:** десятичное число 11 157 в Base62 превращается в строку `2TX`:
* $11\,157 \div 62 = 180$ (остаток 17 → символ `T`);
* $180 \div 62 = 2$ (остаток 56 → символ `X`);
* $2 \div 62 = 0$ (остаток 2 → символ `2`).
* Результат: `2TX` (читаем остатки справа налево).

Преимущества Base62

* **Компактность.** По сравнению с десятичной (Base10) или шестнадцатеричной (Base16) системами Base62 позволяет представлять большие числа меньшим количеством символов. Например, 7‑символьная строка Base62 даёт $62^7 \approx 3{,}5$ трлн уникальных комбинаций, тогда как 7 цифр Base10 — только 10 млн.
* **URL‑совместимость.** В отличие от Base64 (который использует символы `+`, `/`, `=`), Base62 содержит только буквы и цифры — их можно безопасно использовать в URL без кодирования.
* **Удобочитаемость.** Строки Base62 проще воспринимать и запоминать, чем длинные числовые ID или последовательности с спецсимволами.
* **Эффективность.** Подходит для высоконагруженных систем: например, генерация 1 000 коротких URL в секунду исчерпает 7‑символьную ёмкость Base62 лишь через 110+ лет.


Где применяется

* **Сервисы сокращения URL** (Bitly, TinyURL и др.): преобразуют длинные ссылки в короткие коды (например, `bit.ly/2TX`).
* **Генерация уникальных идентификаторов:** для записей в БД, файлов, сессий, токенов.
* **Обфускация ID:** скрывает реальные числовые идентификаторы в API или интерфейсах (например, вместо `/user/12345` — `/user/aB3xK`).
* **Сериализация данных:** компактное представление бинарных данных или UUID в текстовом формате.
* **Облачные сервисы:** например, Amazon QLDB использует Base62 для кодирования 128‑битных ID документов.

## Ограничения и нюансы


* **Чувствительность к регистру.** Различает `A` и `a`, что может вызвать проблемы в системах с case‑insensitive сравнением (например, некоторые базы данных).
* **Визуальная неоднозначность.** Символы `0` (ноль) и `O` (заглавная «о»), `1` (единица), `l` (строчная «л») и `I` (заглавная «и») могут выглядеть одинаково в некоторых шрифтах, что повышает риск ошибок при ручном вводе.
* **Отсутствие единого стандарта.** Разные реализации могут использовать разный порядок символов в алфавите, что затрудняет совместимость.

# Base62 vs Base64
> 🔤 Base62 vs Base64: сравнение кодировок

🎯 Основное различие

| Кодировка  | Символы                        | Использование                           |
| ---------- | ------------------------------ | --------------------------------------- |
| **Base62** | `0-9A-Za-z` = **62 символа**   | Генерация коротких URL, идентификаторов |
| **Base64** | `0-9A-Za-z+/` = **64 символа** | Кодирование бинарных данных в текст     |

---

## 📊 Подробное сравнение

| Критерий                  | **Base62**                                          | **Base64**                                         |
| ------------------------- | --------------------------------------------------- | -------------------------------------------------- |
| **Алфавит**               | `0-9A-z`                                            | Base62 + `+` , `/`                                 |
| **Размер алфавита**       | 62 символа                                          | 64 символа                                         |
| **Безопасность для URL**  | ✅ Полностью безопасен                               | ❌ Содержит `+` и `/`, которые нужно экранировать   |
| **Эффективность сжатия**  | Менее эффективен (меньше символов → длиннее строка) | Более эффективен (больше символов → короче строка) |
| **Стандартизация**        | кастомные реализации)                               | Стандарт [[RFC 4648 Base16 Encodings]]                              |
| **Использование padding** | Нет                                                 | Да (`=` в конце для выравнивания)                  |

## 💻 Примеры

### Base62 (URL Shortener)
```python
# Число 123456789 → короткий ID
def base62_encode(num):
    chars = "0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz"
    result = ""
    while num > 0:
        result = chars[num % 62] + result
        num //= 62
    return result or "0"

print(base62_encode(123456789))  # → "8M0kX"
```

### Base64 (Кодирование изображения)
```python
import base64

# Кодирование строки
text = "Hello World"
encoded = base64.b64encode(text.encode()).decode()
print(encoded)  # → "SGVsbG8gV29ybGQ="

# Декодирование
decoded = base64.b64decode(encoded).decode()
print(decoded)  # → "Hello World"
```

## 📈 Эффективность: сколько символов нужно?

| Исходные данные | Base62 | Base64 |
|-----------------|--------|--------|
| 1 байт (8 бит) | 2 символа | 2 символа |
| 3 байта (24 бита) | 4 символа | **4 символа** |
| 6 байт (48 бит) | 9 символов | **8 символов** |
| 1 KB | ~1375 символов | **~1366 символов** |

> 💡 **Base64 на ~0.7% эффективнее**, но требует экранирования в URL.

## 🏥 Когда использовать что?

### ✅ Используйте **Base62**, если:
- Создаёте **короткие URL** (bit.ly, tinyurl)
- Нужны **читаемые идентификаторы** без спецсимволов
- Работаете с **ограниченным набором символов** (например, QR-коды)
- Хотите **избежать экранирования** в URL

### ✅ Используйте **Base64**, если:
- **Кодируете бинарные данные** (изображения, файлы)
- Нужна **стандартная совместимость**
- Работаете с **API, email, HTTP** (где спецсимволы допустимы)
- Требуется **максимальная эффективность** сжатия

## ⚠️ Важные нюансы

### Base62 проблемы:
- **Нет единого стандарта** — разные реализации могут использовать разный порядок символов
- **Чувствителен к регистру** — `A` ≠ `a`
- **Меньше плотность** — длиннее строки для тех же данных

### Base64 проблемы:
- **Спецсимволы в URL**: `+` и `/` ломают ссылки
- **Padding (`=`)** может вызывать проблемы в некоторых системах
- **Не читаем для человека** — сложно запомнить или продиктовать

## 🔧 URL-Safe Base64

Для использования Base64 в URL существует **модифицированная версия**:

| Стандартный Base64 | URL-Safe Base64 |
|--------------------|-----------------|
| `+` | `-` |
| `/` | `_` |
| `=` | Удаляется или заменяется |

```python
# URL-safe Base64 в Python
import base64

encoded = base64.urlsafe_b64encode(b"Hello World").decode().rstrip('=')
print(encoded)  # → "SGVsbG8gV29ybGQ"
```

> 💡 **URL-Safe Base64** часто лучше **Base62** для API токенов, JWT и подобных задач.

## 💬 Итог

> **Base62** — для **человекочитаемых идентификаторов** без спецсимволов.  
> **Base64** — для **эффективного кодирования бинарных данных** со стандартной совместимостью.

> 📌 **Правило выбора**:  
> - Нужно в URL без экранирования? → **Base62**  
> - Кодируете бинарные данные? → **Base64**  
> - Нужен стандарт для API? → **URL-Safe Base64**
