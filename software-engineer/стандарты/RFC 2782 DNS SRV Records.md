**RFC 2782 DNS SRV Records** — это стандарт, позволяющий хранить в DNS не только IP-адреса хостов (как в A/AAAA записях), но и **информацию о сервисах**, работающих на этих хостах.

### 🔑 Ключевая особенность
SRV-запись указывает:
1. **Какой сервис** запущен (например, `_ldap`, `_sip`, `_http`).
2. **На каком порту** он слушает (не только стандартные 80/443).
3. **Приоритет и вес** для балансировки нагрузки между несколькими серверами.

### 📝 Формат записи
```text
_Service._Proto.Name TTL Class SRV Priority Weight Port Target
```
*Пример:*
```dns
_sip._tcp.example.com. 86400 IN SRV 10 5 5060 sipserver1.example.com.
_sip._tcp.example.com. 86400 IN SRV 20 5 5060 sipserver2.example.com.
```
*(Клиент сначала попробует `sipserver1` (приоритет 10), если он недоступен — переключится на `sipserver2` (приоритет 20).)*

### 🚀 Зачем нужен в облаке и микросервисах?
1. **Service Discovery без реестра:** Клиенты могут найти бэкенды, просто сделав DNS-запрос. Не нужен отдельный Consul/Etcd для простых сценариев.
2. **Динамические порты:** Если сервис запускается на случайном порту (например, в Kubernetes или Docker), SRV позволяет сообщить клиентам актуальный порт.
3. **Балансировка и отказоустойчивость:** Встроенная поддержка приоритетов (failover) и весов (load balancing) на уровне DNS.

### 💡 Где используется?
- VoIP (SIP), XMPP (Jabber), LDAP, Kerberos.
- Внутреннее обнаружение сервисов в гибридных инфраструктурах.
- Как альтернатива жестко прописанным `host:port` в конфигурациях приложений.

> ⚠️ **Ограничение:** Не все клиенты поддерживают SRV (браузеры — нет, но многие библиотеки для Go, Java, Python — да).
