## Branch mispredict

**Branch mispredict** (ошибочное предсказание ветвления) — ситуация, когда процессор неверно предсказал направление выполнения программы в точке ветвления (например, при выполнении условного оператора `if` или цикла) и выполнил не те инструкции.

### Как работает предсказание ветвлений

Современные процессоры используют **спекулятивное выполнение** (speculative execution), чтобы повысить производительность:

- До того как условие будет вычислено, процессор **прогнозирует**, по какой ветке пойдёт выполнение (будет ли условие истинным или ложным).
- Он **заранее загружает и начинает выполнять** инструкции по предполагаемому пути.
- Если прогноз оказался верным, выполнение продолжается без задержек.
- Если прогноз ошибочен — возникает **branch mispredict**.

### Что происходит при branch mispredict

Когда процессор понимает, что ошибся с предсказанием:

- **Отменяет все результаты** спекулятивно выполненных инструкций (как будто их и не было).
- **Очищает конвейер** (pipeline) от неверных инструкций.
- **Загружает правильные инструкции** из верной ветки кода.
- **Начинает выполнение заново** с корректного места.

Этот процесс требует времени — обычно **от 10 до 20 тактовых циклов** процессора.

### Пример

Рассмотрим код:

```asm
dec eax        ; Уменьшаем значение в регистре eax на 1
jz .zero      ; Если eax == 0, перейти на метку .zero
...          ; Код, который выполнится, если eax != 0
.zero:       ; Метка, куда переходим, если eax == 0
```

**Сценарий с ошибкой предсказания:**

- Процессор прогнозирует, что `eax` не будет равен 0, и начинает выполнять код после `...`.
- Но на самом деле `eax` оказался равен 0 — условие `jz` сработало.
- Процессор обнаруживает ошибку, отменяет выполненные инструкции, переходит на `.zero`.
- Возникает задержка — это и есть **branch mispredict**.

### Почему это важно

- **Производительность.** Ошибки предсказания — одна из главных причин снижения производительности. В критических участках (циклы, горячие функции) они могут замедлить работу в разы.
- **Безопасность.** Уязвимости типа Spectre используют особенности спекулятивного выполнения и предсказания ветвлений для утечки данных.
- **Оптимизация.** Разработчики оптимизируют код, чтобы уменьшить вероятность ошибок предсказания (например, упорядочивают условия в `if` по вероятности выполнения).

### Как измерить

Количество ошибок предсказания отслеживается инструментами профилирования:

- В Linux: `perf stat -e branches,branch-misses ./your_program`.
- Пример вывода:
  ```text
  358 209 branches
  14 026 branch-misses  # 3,92 % of all branches
  ```
- Хороший показатель — **менее 5 %** ошибок от общего числа ветвлений.

### Краткий итог

- **Branch mispredict** — ошибка процессора в прогнозировании направления ветвления.
- Приводит к **отмене спекулятивно выполненных инструкций** и задержке в 10–20 тактов.
- Критически влияет на **производительность** кода.
- Измеряется инструментами профилирования (например, `perf` в Linux).

### Упорядочивание условий по вероятности

Располагайте ветви в `if-else` от наиболее вероятных к наименее вероятным. Компиляторы часто генерируют код, оптимизированный под первый блок.

**Плохо:**

```c
if (is_error) {
  handle_error();
} else {
  process_data(); // выполняется в 99 % случаев
}
```

**Хорошо:**

```c
if (!is_error) {
  process_data();
} else {
  handle_error();
}
```

### Использование подсказок компилятору

#### Для GCC/Clang: `__builtin_expect`

Позволяет явно указать, какая ветвь более вероятна.

- `__builtin_expect(condition, 1)` — условие истинно;
- `__builtin_expect(condition, 0)` — условие ложно.

**Пример:**

```c
#define likely(x)   __builtin_expect((x), 1)
#define unlikely(x) __builtin_expect((x), 0)

if (unlikely(error_code)) {
  handle_error();
} else {
  process_data();
}
```

#### Атрибуты C++20

- `[[likely]]` — ветвь, скорее всего, будет выполнена;
- `[[unlikely]]` — ветвь, скорее всего, не будет выполнена.

**Пример:**

```cpp
if ([[unlikely]] error_code) {
  handle_error();
} else [[likely]] {
  process_data();
}
```

### Branchless-программирование (программирование без ветвлений)

Заменяйте условные операторы арифметическими или побитовыми операциями. Особенно эффективно для простых условий.

**Пример функции минимума:**

**С ветвлением:**

```c
int min(int a, int b) {
  if (a < b) return a;
  else return b;
}
```

**Без ветвления:**

```c
int min_branchless(int a, int b) {
  return b + ((a - b) & ((a - b) >> 31));
}
```

**Пример преобразования регистра:**

**С ветвлением:**

```c
void to_upper(char* str) {
  for (; *str; ++str) {
    if (*str >= 'a' && *str <= 'z')
      *str -= 32;
  }
}
```

**Без ветвления:**

```c
void to_upper_branchless(char* str) {
  for (; *str; ++str) {
    int diff = *str - 'a';
    *str -= ((unsigned)diff < 26) * 32;
  }
}
```

### Разворачивание циклов (Loop Unrolling)

Уменьшает количество проверок условия цикла.

**До:**

```c
for (int i = 0; i < n; i++) {
  process(data[i]);
}
```

**После:**

```c
for (int i = 0; i < n; i += 4) {
  process(data[i]);
  process(data[i+1]);
  process(data[i+2]);
  process(data[i+3]);
}
```

### Табличные методы

Заменяйте сложные условия на поиск в предварительно подготовленной таблице.

**Пример для бинарного поиска:**

```c
size_t positions[] = {left, right};
while (left < right) {
  size_t middle = left + (right - left) / 2;
  positions[search_for >= array[middle]] = middle;
}
```

### Оптимизация структур данных

- **Выравнивание данных** (data alignment) — помогает процессору эффективнее загружать данные.
- **Локальность данных** (data locality) — располагайте часто используемые вместе данные рядом в памяти.
- Используйте **структуры массивов** (SoA) вместо **массивов структур** (AoS), если обрабатываете поля отдельно.

### Профилирование и анализ

Инструменты для выявления проблемных мест:

- **Linux:** `perf stat -e branches,branch-misses ./your_program`
- **Intel VTune** — профилировщик с детализацией по branch mispredict.
- **Valgrind** с модулем `branch-predict`.

### Выбор алгоритмов

Отдавайте предпочтение алгоритмам с меньшим количеством условных переходов:

- для поиска — хеш-таблицы вместо бинарного поиска;
- для сортировки — алгоритмы с предсказуемыми ветвлениями.

### Настройки компилятора

Оптимизации, помогающие уменьшить branch mispredict:

- `-O2`, `-O3` — общие оптимизации;
- `-funroll-loops` — разворачивание циклов;
- `-fprofile-arcs` — профилирование для оптимизации ветвлений;
- `-march=native` — оптимизация под конкретную архитектуру процессора.

### Важные предостережения

- **Не оптимизируйте без бенчмарков.** Иногда «оптимизированный» код работает медленнее из-за особенностей конвейера процессора.
- **Учитывайте архитектуру.** То, что работает на x86-64, может не работать на ARM.
- **Соблюдайте баланс читаемости и производительности.** Не жертвуйте понятностью кода ради микрооптимизаций.
- **Тестируйте на реальных данных.** Профилируйте с данными, близкими к продакшн-нагрузке.
- **Помните о компромиссах.** Branchless-код может использовать больше инструкций, но быть быстрее за счёт отсутствия pipeline stalls.

### Чек-лист по снижению branch mispredict

- Упорядочивайте условия по вероятности выполнения.
- Используйте подсказки компилятору (`__builtin_expect`, `[[likely]]`/`[[unlikely]]`).
- Применяйте branchless-техники для простых условий.
- Разворачивайте циклы там, где это уместно.
- Используйте табличные методы вместо сложных условий.
- Оптимизируйте структуры данных для лучшей локальности.
- Профилируйте код перед и после оптимизаций.
- Выбирайте алгоритмы с предсказуемым поведением ветвлений.
- Настраивайте компилятор на агрессивную оптимизацию.
