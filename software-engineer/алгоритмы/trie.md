# префиксное дерево – trie
**trie** (префиксное дерево) играет ключевую роль для эффективного хранения и поиска данных с **иерархической структурой**. Рассмотрим, как это работает.

**Trie** (от _re**trie**val_ «возвращаемое») — это древовидная структура данных, где:
- Каждый узел представляет **часть ключа** (обычно символ или цифру).
- Путь от корня до листа соответствует **полному ключу**.    
- Позволяет эффективно искать строки с общими префиксами.

Пример trie для слов: "post", "postgres", "sql"
```plain
       root
        |
        p
        |
        o
        |
        s
        |
        t
       / \
      g   (end)
     /
    r
    |
    e
    |
    s
   / \
(end) sql
```

**Ключевые особенности**
- Подходит для данных с **естественной иерархией** (строки, IP-адреса, геоданные).
- Позволяет эффективно искать по **префиксам, диапазонам и сложным условиям**.
- В отличие от B-деревьев, SP-GiST **не требует сбалансированности**, что дает гибкость.
    
**Примеры типов данных**
1. **Текстовые строки** (поиск по префиксу, LIKE 'abc%').
2. **IP-адреса** (хранение в виде битовых последовательностей).
3. **Геометрические данные** (разбиение пространства).
   
 **Ограничения**
- **Неэффективен** для точного поиска (`=`) в больших наборах данных (лучше B-Tree).
- **Нет сортировки** (в отличие от B-Tree).
- **Не поддерживает** все типы данных (только те, для которых определены операторы SP-GiST)

Существует оптимизированная версия префиксного дерева – [[radix tree]]
