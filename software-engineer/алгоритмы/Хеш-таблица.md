Хеш-таблица — структура данных, реализующая интерфейс ассоциативного массива, а именно, она позволяет хранить пары (ключ, значение) и выполнять три операции: 
1. операцию добавления новой пары, 
2. операцию удаления,
3. операцию поиска пары по ключу. 

Существуют два основных варианта хеш-таблиц: 
1. хеш-таблиц с открытой адресацией 
	- Хеш-таблица является массивом ${\displaystyle H}$, элементы которого есть пары
2. хеш-таблица списочного типа
	- Хеш-таблица является списком пар

Выполнение операции в хеш-таблице начинается с вычисления [[Хеш-функция|хеш-функции]] от ключа. Получающееся **хеш-значение**  ${\displaystyle i={\mbox{hash}}(key)}$ играет роль индекса в массиве ${\displaystyle H}$. Затем выполняемая операция (добавление, удаление или поиск) перенаправляется объекту, который хранится в соответствующей ячейке массива ${\displaystyle H[i]}$.

Ситуация, когда для различных ключей получается одно и то же хеш-значение, называется коллизией. Такие события не так уж и редки — например, при вставке в хеш-таблицу размером 365 ячеек всего лишь 23 элементов вероятность коллизии уже превысит 50% (если каждый элемент может равновероятно попасть в любую ячейку) — см. парадокс дней рождения. Поэтому механизм разрешения коллизий — важная составляющая любой хеш-таблицы.

В некоторых специальных случаях удаётся избежать коллизий вообще. Например, если все ключи элементов известны заранее (или очень редко меняются), то для них можно найти некоторую совершенную хеш-функцию, которая распределит их по ячейкам хеш-таблицы без коллизий. Хеш-таблицы, использующие подобные [[Хеш-функция|хеш-функции]], не нуждаются в механизме разрешения коллизий, и называются **хеш-таблицами с прямой адресацией**.

Число хранимых элементов, делённое на размер массива ${\displaystyle H}$ (число возможных значений хеш-функции), называется **коэффициентом заполнения хеш-таблицы** `load factor` и является важным параметром, от которого зависит среднее время выполнения операций. 

**Оценка сложности операций на хэш-таблицей**

|               | В среднем | В худшем случае |
| ------------- | --------- | --------------- |
| Расход памяти | $O(n)$    | $O(n)$          |
| Поиск         | $O(1)$    | $O(n)$          |
| Вставка       | $O(1)$    | $O(n)$          |
| Удаление      | $O(1)$    | $O(n)$          |

## HashMap в Java

HashMap - базируется на массиве бакетов, элементов типа `HashMap.Node`.
- Конфигурируемые параметры HashMap: int initialCapacity и float loadFactor    
    $capacity = number\ of\ buckets\ *\ loadFactor$
- При добавлении объекта номер бакета рассчитывается по формуле:
    $index\ =\ hashCode(key)\ \&\ (n-1)$, где
    - $n$ — количество bucket-ов 
	    - значение длины массива, default=16.
    - $key$ — входные данные
    - $\&$ — побитовое И

Хэширование выполняется в методе `hashCode()`
* Важно правильно реализовать метод `hashCode()` для обеспечения лучшей производительности класса HashMap.
### метод int hashCode()

Метод `hashCode()` используется для получения хэш кода объекта. Этот метод наследуется для всех классов от `class Object`.

`class Object —> public native int hashCode()` написан на нативном языке и возвращает ссылку памяти объекта в целочисленной форме: `идентификационный хеш — identity hash code`.

Вследствие того, что JVM перемещает объекты по памяти, `hashCode()` унаследованный от Object может меняться. Очевидное решение - запомнить `hashCode()` при инициации объекта. Но это может привести к тому, что у нескольких объектов может возникнуть одинаковый хэшкод.

**Контракт методов $equals–hashCode$** 
1. `hashCode()` должен последовательно возвращаться одинковое значение `int` , при условии что информация, используемая при сравнении equals() для объекта, не изменяется
    * hashCode() может меняться для одних и тех же объектов в разных рантаймах
2. Если у объектов `equals()==true`, то $hashCode()$ должен возвращать одинаковое значение.
3. Если у объектов `equals()==false`, то `hashCode()` может возвращать одинаковое значение. Но для производительности лучше чтобы были разные.
### buckets
Корзина `bucket` — ячейка массива в которой лежит односвязный список узлов **Entry.** Два или более узла могут иметь один и тот-же bucket. В этом случае для связи узлов используется структура данных связанный список.
* Entry содержит поля: `hash`, `key`, `value`, `next`,

```java
static class Node<K,V> implements Map.Entry<K,V> {
  final int hash;
  final K key;
  V value;
  Node<K,V> next;
...
transient Node<K,V>[] table;
}
```

`transient` — это модификатор, указываемый перед полем для обозначения того, что данное поле не может быть сериализовано.
