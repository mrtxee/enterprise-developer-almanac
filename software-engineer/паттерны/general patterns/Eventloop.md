**Event Loop (цикл событий)** — это **основной механизм**, лежащий в основе **асинхронного, неблокирующего программирования** в однопоточных средах (например, Node.js, Python asyncio, Netty, JavaScript в браузере и др.).

> 💡 Его задача — **эффективно обрабатывать множество задач одновременно, используя всего один (или несколько) поток**, без блокировки при операциях ввода-вывода (I/O).

---

## 🔄 Простая аналогия

Представьте **официанта в кафе**:

- Он **один** (один поток), но обслуживает **много столов**.
- Принял заказ → отнёс на кухню → пока готовят, **обслуживает других гостей**.
- Когда блюдо готово — получает уведомление и относит клиенту.

👉 Официант **не стоит и не ждёт** у плиты — он **делает другую полезную работу**.

**Event Loop — это и есть "официант"** вашей программы.

---

## 🧠 Как работает Event Loop?

### Основные компоненты:

1. **Call Stack** — стек вызовов (где выполняется синхронный код).
2. **Callback Queue** — очередь отложенных задач (колбэков).
3. **Event Loop** — цикл, который:
   - Когда Call Stack **пуст**, берёт задачу из Callback Queue и помещает в Call Stack.
4. **Event Demultiplexer / I/O Polling** — системный механизм (например, `epoll` в Linux), который отслеживает завершение I/O-операций (чтение файла, ответ от сети и т.д.).

### Пример (Node.js / JavaScript):

```js
console.log('1');

setTimeout(() => {
  console.log('2');
}, 0);

console.log('3');
```

**Вывод:**
```
1
3
2
```

**Почему?**
- `console.log('1')` и `console.log('3')` — синхронные → сразу в стек.
- `setTimeout` — асинхронный → регистрируется в системе, колбэк ставится в очередь.
- Event Loop помещает колбэк в стек **только после завершения текущего кода**.

## ⚙️ Архитектура Event Loop (на примере Node.js)

```
   ┌───────────────────────┐
   │        ТАКТЫ          │
   └──────────┬────────────┘
              ▼
   ┌───────────────────────┐
   │  1. Таймеры (setTimeout, setInterval) │
   ├───────────────────────┤
   │  2. I/O колбэки       │
   ├───────────────────────┤
   │  3. idle, prepare     │
   ├───────────────────────┤
   │  4. Poll (основная фаза) │ ← тут обрабатываются I/O события
   ├───────────────────────┤
   │  5. check (setImmediate)│
   ├───────────────────────┤
   │  6. Close колбэки     │
   └───────────────────────┘
              ▲
              └── Цикл повторяется
```

> 🔁 Event Loop постоянно крутится, проверяя, что можно выполнить **неблокирующим образом**.

## 🌐 Где используется Event Loop?

| Среда | Реализация |
|-------|-----------|
| **Node.js** | libuv (C++) |
| **JavaScript (браузер)** | Встроенный в движок (V8, SpiderMonkey) |
| **Python** | `asyncio` (с `loop`) |
| **Java** | Netty, Vert.x (через `EventLoopGroup`) |
| **Rust** | `tokio`, `async-std` |

> 💡 **Spring [[WebFlux]]** на Netty использует event loop под капотом — поэтому он неблокирующий и масштабируемый.

## 🧩 Event Loop vs Многопоточность

| Подход | Event Loop | Многопоточность (thread-per-request) |
|--------|-----------|--------------------------------------|
| **Потоки** | 1 (или N = CPU cores) | Много (1 на запрос) |
| **Память** | Мало (стек вызовов один) | Много (каждый поток — 1-2 МБ) |
| **Переключение** | Лёгкое (в коде) | Тяжёлое (ОС) |
| **Блокировки** | Запрещены! | Разрешены |
| **Сложность** | Асинхронная логика | Синхронная логика, но гонки/deadlock |

> ✅ Event Loop **эффективен при I/O-bound нагрузке** (сеть, БД, файлы).  
> ❌ Не подходит для CPU-bound задач (математика, обработка видео).

---

## ⚠️ Важно: НЕ БЛОКИРУЙТЕ Event Loop!

Все операции внутри event loop должны быть **быстрыми и неблокирующими**.

**Плохо (блокирует):**
```js
// Node.js
const start = Date.now();
while (Date.now() - start < 5000) {} // Цикл 5 секунд — ВСЁ ЗАВИСАЕТ!
```

**Хорошо (неблокирующий):**
```js
setTimeout(() => {
  // Выполнится через 5 сек, не блокируя loop
}, 5000);
```

> 💥 Если вы выполните тяжёлую CPU-операцию в event loop — **все запросы "заморозятся"**.

---

## 🎯 Итог

> **Event Loop — это цикл, который позволяет одному потоку эффективно управлять множеством асинхронных операций без ожидания (без блокировки).**  
> Он делает возможным:
> - Высокую масштабируемость (10K+ соединений)
> - Эффективное использование ресурсов
> - Реактивные и неблокирующие системы (WebFlux, Node.js и др.)

Без event loop не было бы современного веба в том виде, в каком мы его знаем ✅
