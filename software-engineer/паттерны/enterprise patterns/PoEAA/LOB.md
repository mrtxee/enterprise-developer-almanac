# Large Object – LOB
Разберу расшифровку и суть этих терминов:

**1. LOB** – Large Object

* **Расшифровка:** *Large Object* («большой объект»).
* **Суть:** общий термин для обозначения типов данных, способных хранить очень большие объёмы информации — значительно больше, чем стандартные типы вроде `VARCHAR` или `INT`.

**2. BLOB** – Binary Large Object

* **Расшифровка:** *Binary Large Object* («двоичный большой объект»).
* **Суть:** тип данных для хранения **двоичной** (нетекстовой) информации.
* **Что хранится:**
    * изображения (`JPEG`, `PNG`);
    * аудиофайлы (`MP3`, `WAV`);
    * видеофайлы (`MP4`, `AVI`);
    * исполняемые файлы (`EXE`, `DLL`);
    * архивы (`ZIP`, `RAR`);
    * любые другие файлы в их «сыром» (бинарном) виде.
* **Особенности:** база данных не пытается интерпретировать содержимое `BLOB` — она просто сохраняет и отдаёт последовательность байтов.

**3. CLOB** – Character Large Object

* **Расшифровка:** *Character Large Object* («символьный большой объект»).
* **Суть:** тип данных для хранения больших объёмов **текстовой** информации.
* **Что хранится:**
    * длинные статьи или документы;
    * HTML‑страницы;
    * XML‑ или JSON‑документы;
    * логи или журналы событий;
    * исходный код программ.
* **Особенности:** в отличие от `BLOB`, `CLOB` учитывает кодировку символов (например, `UTF‑8` или `ASCII`), что позволяет корректно выполнять текстовые операции (поиск, подстроки и т. д.).

---

**Сравнение в таблице**

| Параметр | BLOB | CLOB |
|--------|------|------|
| **Расшифровка** | Binary Large Object | Character Large Object |
| **Тип данных** | Двоичные (бинарные) данные | Текстовые (символьные) данные |
| **Примеры** | Изображения, аудио, видео, EXE‑файлы | Статьи, HTML, XML, JSON, логи |
| **Кодировка** | Не имеет кодировки, последовательность байтов | Имеет кодировку (UTF‑8, ASCII и т. д.) |
| **Операции** | Сохранение/загрузка файла целиком | Поиск текста, извлечение подстрок |

---

**Важные нюансы**

1. **Реализация в СУБД.** Названия и нюансы работы могут отличаться в разных системах управления базами данных:
    * **Oracle:** чётко разделяет `BLOB`, `CLOB`, а также `NCLOB` (для Unicode‑текста).
    * **MySQL:** использует `BLOB` и `TEXT` (аналог `CLOB`; есть вариации по размеру: `TINYTEXT`, `MEDIUMTEXT`, `LONGTEXT`).
    * **SQL Server:** использует `VARBINARY(MAX)` для бинарных данных (аналог `BLOB`) и `VARCHAR(MAX)` для текста (аналог `CLOB`).
    * **PostgreSQL:** использует универсальный тип `BYTEA` для бинарных данных и `TEXT` для неограниченного текста.
2. **Размеры.** Все эти типы могут иметь разные вариации по максимальному размеру:
    * `TINYBLOB` / `TINYTEXT` — до 255 байт;
    * `BLOB` / `TEXT` — до 64 КБ;
    * `MEDIUMBLOB` / `MEDIUMTEXT` — до 16 МБ;
    * `LONGBLOB` / `LONGTEXT` — до 4 ГБ.
3. **Производительность.** Хранение больших объектов *внутри* БД может замедлить её работу. Альтернатива — хранить в БД только путь к файлу, а сам файл — в файловой системе. Выбор зависит от требований к безопасности, репликации и удобству бэкапов.
