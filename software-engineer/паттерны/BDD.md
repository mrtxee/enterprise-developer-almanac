## BDD-стиль (Behavior-Driven Development)

**BDD** (разработка через поведение) — это подход к разработке ПО, который фокусируется на **поведении системы с точки зрения пользователя**. Это эволюция TDD, где тесты пишутся не на языке разработчика, а на **естественном, предметно-ориентированном языке**, понятном всем участникам команды (включая бизнес-аналитиков, тестировщиков, менеджеров).

---

### 📝 Ключевая идея

> **«Пишем тесты как сценарии поведения, а не как технические проверки»**

Вместо того чтобы писать «тест для метода getUser()», мы пишем «сценарий: пользователь получает свои данные».

---

### 🧩 Структура сценария (Given-When-Then)

Это фундаментальный шаблон BDD, который описывает поведение системы в трёх частях:

| Блок | Назначение | Пример |
|------|------------|--------|
| **Given** (Дано) | Исходное состояние системы | Пользователь зарегистрирован и авторизован |
| **When** (Когда) | Действие пользователя или системы | Пользователь запрашивает свой профиль |
| **Then** (Тогда) | Ожидаемый результат | Система возвращает корректные данные |

---

### 📋 Пример на языке Gherkin (Cucumber)

```gherkin
Feature: Вход в систему
  Scenario: Успешный вход
    Given пользователь зарегистрирован с логином "user" и паролем "pass"
    When пользователь вводит логин "user" и пароль "pass"
    Then система перенаправляет на главную страницу
    And пользователь видит приветствие "Добро пожаловать, user!"
```

Этот же сценарий потом автоматизируется в коде (например, через Cucumber, JBehave или Spock).

| Инструмент | Описание |
|------------|----------|
| **Cucumber** | Самый известный BDD-фреймворк (Gherkin) |
| **Spock** | Нативный BDD-стиль в Groovy |
| **JBehave** | Java-реализация BDD |
| **SpecFlow** | Для .NET |
| **Behat** | Для PHP |

---

### ✅ Преимущества BDD

- **Единый язык** для всей команды (бизнес, разработка, тестирование).
- **Живая документация** — сценарии всегда актуальны, т.к. являются тестами.
- **Улучшенное качество требований** — сложно написать сценарий к непонятному требованию.
- **Меньше технических деталей** в тестах — фокус на поведении.

---

### ❌ Недостатки

- Может быть **избыточным** для простых проектов.
- Требует **дисциплины** в написании сценариев.
- Иногда сложно перевести технический тест в BDD-формат.

---

### 🎯 Резюме

| TDD (Test-Driven)                        | BDD (Behavior-Driven)             |
| ---------------------------------------- | --------------------------------- |
| Фокус на коде                            | Фокус на поведении                |
| Технический язык                         | Предметно-ориентированный язык    |
| Разработчик                              | Вся команда                       |
| Пример: `assertEquals(expected, actual)` | Пример: `then result == expected` |
