## Enterprise patterns

Корпоративные (предпринимательские) паттерны описывают решения для типовых задач бизнес-приложений: работа с БД, транзакции, объектно-реляционное отображение (ORM) и структурирование доменной логики.

### Где узнать больше

- **Мартин Фаулер** — «Шаблоны корпоративных приложений» (PoEAA), книга о паттернах корпоративного уровня.
- Классическая книга, введение в паттерны бизнес-приложений и лучшие практики их построения.

### Паттерны, которые стоит знать

#### Active Record (Активная запись)

**Смысл:** каждая запись/строка таблицы — это объект класса, который хранит данные и поведение (валидация, CRUD, связи).

**Характеристики:**

- простая реализация;
- нарушение SRP (таблица = класс);
- поле для приложений с несложной логикой;
- используется в Rails, Django ORM.

**Пример:**

```php
class User extends Model
{
    public $name;
    public $email;
}
```

**Где искать:** строки таблицы = объекты, класс = таблица, свойства = колонки.

#### Identity Map (Карта личностей)

**Смысл:** хранит кэш объектов, уже загруженных из БД, гарантирует, что каждый объект загружается только один раз — в один объект.

**Характеристики:**

- объект появляется один раз (identity);
- экономия запросов к БД;
- поддержание согласованности.

**Пример:**

```php
class IdentityMap
{
    protected $items = [];

    public function get($id)
    {
        return $this->items[$id] ?? null;
    }

    public function set($id, $object)
    {
        $this->items[$id] = $object;
    }
}
```

#### Lazy Load (Ленивая загрузка)

**Смысл:** отложенная загрузка данных. Объект создаётся без данных или с частью данных, а остальное загружается при обращении.

**Характеристики:**

- сокращает запросы к БД;
- объект загружает зависимости по требованию;
- снятие большой нагрузки при старте.

**Пример:**

```php
class User
{
    protected $posts;

    public function posts()
    {
        if ($this->posts === null) {
            $this->posts = Post::whereUser($this->id);
        }

        return $this->posts;
    }
}
```

#### Unit of Work (Единица работы)

**Смысл:** «координирует запись изменений и разрешает проблемы параллелизма». Собирает все изменения в одну транзакцию, следит за согласованностью.

**Зачем:**

- одна транзакция на бизнес-операцию;
- защита от гонок (Race Conditions);
- понятный контроль сохранения.

**Пример:**

```php
class UnitOfWork
{
    protected $pending = [];

    public function register($object)
    {
        $this->pending[] = $object;
    }

    public function commit()
    {
        foreach ($this->pending as $object) {
            $object->save();
        }
    }
}
```

#### Repository (Репозиторий)

**Смысл:** «отделяет логику получения данных и объектов домена от доступа к БД». Посредник между логикой приложения и хранением данных.

**Зачем:**

- скрыть запросы и детали ORM;
- упростить тестирование (заменяем на mock);
- одно место — изменение запросов.

**Пример:**

```php
interface UserRepository
{
    public function findByEmail($email);
    public function getAll();
}
```

#### Data Mapper (Преобразователь данных)

**Смысл:** слой между объектами домена и таблицами БД. Доменный объект не знает о существовании схемы данных.

**Характеристики:**

- полная изоляция домена от БД;
- сложность реализации;
- встречается в Doctrine, Hibernate.

**Пример:**

```php
class UserMapper
{
    public function find($id) { ... }
    public function insert($user) { ... }
    public function update($user) { ... }
}
```

#### DDD (Доменно-ориентированное проектирование)

**Смысл:** разработка сосредоточена вокруг бизнес-логики — «домена». Строится общий язык (Ubiquitous Language) между бизнесом и кодом.

**Основные понятия DDD:**

- **Агрегаты** — группа объектов домена с единым корнем;
- **Объекты-значения (Value Objects)** — неизменяемые объекты-значения;
- **События домена (Domain Events)** — реакция на изменения в домене;
- **Ограниченный контекст (Bounded Context)** — границы модели.

### Категории паттернов

#### Паттерны организации логики

- **Transaction Script** — логика в виде набора процедур/скриптов (простая, но дублирующаяся);
- **Domain Model** — логика в объектах домена (гибкая, но сложнее);
- **Table Module** — аналог Domain Model, данные и методы сгруппированы по таблицам.

#### Паттерны хранения данных

- **Row Data Gateway** — объект на каждую запись в таблице;
- **Table Data Gateway** — объект на таблицу БД (методы работы с таблицей).

#### Паттерны объектно-реляционного отображения

- **Active Record**;
- **Data Mapper**;
- **Identity Map**;
- **Lazy Load**;
- **Unit of Work**.

#### Паттерны доступа к данным

- **Repository**;
- **Query Object** — инкапсулирует запрос;
- **Metadata Mapping** — описание связи класс-таблица в метаданных.

### Вывод

**Итог:** знание enterprise-паттернов — обязательный минимум для разработчика корпоративных приложений. Они помогают строить гибкую, тестируемую и масштабируемую архитектуру, отвязывая приложение от деталей БД и инструментов.
