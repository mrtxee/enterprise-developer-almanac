### Краткий обзор Fluentd

**Fluentd** — это открытый инструмент для сбора, обработки и передачи логов (данных о событиях) в режиме реального времени. Работает по принципу «сборщика данных» (data collector) и относится к классу решений *log aggregator*.

#### Основные задачи

Fluentd решает следующие задачи:
* сбор логов из разных источников (приложения, серверы, контейнеры, базы данных и т. д.);
* нормализация данных — приведение разнородных логов к единому формату (чаще всего JSON);
* фильтрация и обогащение данных (добавление меток, метаданных, трансформация);
* маршрутизация — отправка обработанных данных в нужные хранилища или сервисы.

#### Как работает

Архитектура Fluentd основана на **плагинах** и следует схеме **Input → Filter → Output**:
1. **Input** — приём данных из источников (файлы, сети, HTTP, Docker и др.).
2. **Filter** — обработка: фильтрация, изменение структуры, добавление полей.
3. **Output** — отправка данных в конечные системы (базы данных, хранилища, очереди сообщений и т. п.).

#### Ключевые особенности

* **Унификация данных.** Приводит логи разных форматов к единому виду (обычно JSON).
* **Богатая экосистема плагинов.** Более 500 официальных и пользовательских плагинов для интеграции с сервисами (Elasticsearch, Amazon S3, Kafka, Slack и др.).
* **Надёжность.** Гарантирует доставку данных: поддерживает буферизацию и повторные попытки отправки при сбоях.
* **Лёгкость и масштабируемость.** Потребляет мало ресурсов, подходит для контейнеров (например, в Kubernetes).
* **Гибкая конфигурация.** Настраивается через простой YAML‑файл — без программирования.
* **Поддержка структурированных логов.** Хорошо работает с JSON, что упрощает дальнейший анализ.

#### Типичные сценарии использования

* централизованный сбор логов в распределённых системах и микросервисах;
* логирование в Kubernetes и Docker‑средах;
* передача логов в системы мониторинга и аналитики (ELK Stack, Graylog);
* архивация логов в облачные хранилища (Amazon S3, Google Cloud Storage);
* интеграция разнородных источников данных в единый пайплайн.

#### Пример конфигурации (YAML)

```yaml
<source>
  @type tail
  path /var/log/app.log
  format json
  tag app.logs
</source>

<filter app.logs>
  @type record_transformer
  <record>
    environment "production"
  </record>
</filter>

<match app.logs>
  @type elasticsearch
  host localhost
  port 9200
  index_name fluentd
</match>
```

**Что делает этот конфиг:**
1. Читает JSON‑логи из файла `/var/log/app.log` (источник `tail`).
2. Добавляет поле `environment: "production"` к каждой записи.
3. Отправляет данные в Elasticsearch.

#### Краткий итог

Fluentd — это гибкий и надёжный «транспорт» для логов: он собирает данные из множества источников, приводит их к единому формату и направляет в нужные системы. Особенно популярен в контейнеризированных и облачных средах.
