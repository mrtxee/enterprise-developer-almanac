## Парадигма ООП
>**Парадигма** — «взгляд на мир»

Парадигма ООП - парадигма программирования которая предлагает воспринимать бизнес-логику приложений, как объекты. `Объекты` — это сущности у которых есть `поля (состояния) и методы`. Каждый объект — это сущность некоторого `класса`. Все классы java являются наследуют базовый класс [[Object]].
Есть постулаты ООП, направленные на повышение повышение эффективности кода в рамках данной парадигмы. Повышение эффективности выражено в
- структурирование методов и полей
    - При функциональной парадигме с ростом программы у нас растет простыня методов которых становится слишком много и разработчик начинает теряться. В то время как ООП позволяет строить упорядоченную иерархическую стркутуру програмных сущностей, в которой ориентироваться на много проще
- ооп позвляет упростить групповую разработку и повысить переиспользование кода
## Принципы ООП
Все принципы нужно использовать для цели повышения степени **переиспользуемости кода**
### Наследование
- Предлагается расширять имеющиеся классы объектов через наследование. Класс-наследник получает от родителя весь набор полей и методов, но при этом его возможности расширяются. Это позволяет не писать похожие методы дважды, что повышает возможность к переиспользованию кода
- В Java можно унаследовать интерфейс или класс через диерктивы `implements` или `extends`. Разница между интерфейсом и классм в том, что интерфейс прежде всего следует использовать как форму контракта между разработчиком и клиентами класса. Класс может унаследовать несколько интфейсов, но только один класс.
### Инкапсуляция
Сокрытие реализации
- закрываем сущности модификаторами доступа `pirvate`, `protected`. Это вероятность нежелательного поведения и возникновения сайдэффектов.
### Полиморфизм
Одна форма может иметь несколько реализаций
```Java
Animal cat = new Cat();
Animal dog = new Dog();
```
Бывают следующие типы полиморфизма
#### полиморфизм подтипов — истинный полиморфизм
через разную реализацию методов внутри интерфейса
#### параметрический полифморфизм (генерики)
через применение генериков позволяет одному методу работать не зависимо от типов данных
#### ad hoc полифморфизм
делается через перегрузку входных параметров метода
### Инверсия контроля — Inversion of Control
Инверсия управления (англ. Inversion of Control, IoC) — важный принцип объектно-ориентированного программирования, используемый для уменьшения зацепления (связанности) в компьютерных программах[1]. Также архитектурное решение интеграции, упрощающее расширение возможностей системы, при котором поток управления программы контролируется фреймворком

> _**==Don’t call us — we call you!==**_
#### Методы реализации IoC
- Шаблон [[gof]] `Factory pattern`
- Шаблон [[gof]] `Locator`
- Внедрение зависимости (англ. `Dependency injection`)
    - Через конструктор (англ. Constructor injection)
    - Через метод класса (англ. Setter injection)
    - Через интерфейс внедрения (англ. Interface injection)
- Контекстный поиск (англ. contextualized `Lookup`)
### Композиция «has a»
- принцыпы, который является альтернативой постулата Наследования.
    - Наследование предлагает концепцию Предметы → Мебель → Стул
    - Композиция предлагает концепцию Стул «has a» Спинка, «has a» Ножки, «has a» сиденье
        - Композиция предлагает включаение более мельких простных сущностей.
            - Пример `инекция зависимсоти` — когда мы вместо того, чтобы описывать зависимость внутри объекта, указываем внешний интерфейс зависимости, и передаем сущносить данного интерфейса в конструктор.
`**Композиция**` (`агрегирование` по значению) — более строгий вариант агрегирования. Когда включаемый объект может существовать только как часть контейнера. Если контейнер будет уничтожен, то и включённый объект тоже будет уничтожен.
`**Агрегирование**` (англ. `object aggregation, object composition`), или, как его называли ранее, делегирование — методика создания нового класса из уже существующих классов путём их включения. Об агрегировании также часто говорят как об «отношении принадлежности» по принципу «у машины есть корпус, колёса и двигатель».
