## RFC 7231: HTTP/1.1 Семантика и Содержимое

### Введение

**RFC 7231** — ключевой стандарт HTTP/1.1, опубликованный в июне 2014 года. Он определяет семантику HTTP-методов, заголовков и кодов состояния. Документ заменил устаревший RFC 2616 и является частью серии RFC 7230-7237.

**Основное содержание:**

- Методы HTTP (GET, POST, PUT, DELETE, etc.)
- Заголовки запросов и ответов
- **Коды состояния HTTP (Status Codes)**
- Правила обработки контента
- Механизмы согласования содержимого (content negotiation)

---

### Классы кодов состояния HTTP

Коды состояния HTTP разделены на 5 классов:

| Класс | Диапазон | Описание |
|-------|----------|----------|
| **1xx** | 100-199 | Информационные (Informational) |
| **2xx** | 200-299 | Успешные (Success) |
| **3xx** | 300-399 | Перенаправления (Redirection) |
| **4xx** | 400-499 | Ошибки клиента (Client Error) |
| **5xx** | 500-599 | Ошибки сервера (Server Error) |

---

### 1xx: Информационные коды

| Код | Название | Описание |
|-----|----------|----------|
| **100** | Continue | Сервер получил заголовки запроса и готов принять тело. Клиент должен продолжить отправку. |
| **101** | Switching Protocols | Сервер соглашается сменить протокол по запросу клиента (например, на [[web-socket|WebSocket]]). |
| **102** | Processing | (WebDAV) Сервер получил и обрабатывает запрос, но ответ ещё не готов. |
| **103** | Early Hints | Сервер отправляет предварительные заголовки до основного ответа (для ускорения загрузки ресурсов). |

---

### 2xx: Успешные коды

| Код | Название | Описание |
|-----|----------|----------|
| **200** | OK | Запрос успешно выполнен. Ответ содержит запрошенные данные. |
| **201** | Created | Запрос успешно выполнен, создан новый ресурс. Обычно возвращается после POST. |
| **202** | Accepted | Запрос принят на обработку, но она ещё не завершена. |
| **203** | Non-Authoritative Information | Ответ успешен, но метаданные взяты не с исходного сервера. |
| **204** | No Content | Запрос успешен, но тело ответа пустое. |
| **205** | Reset Content | Запрос успешен, клиент должен сбросить представление документа. |
| **206** | Partial Content | Сервер вернул часть ресурса (для range-запросов). |
| **207** | Multi-Status | (WebDAV) Ответ содержит информацию о нескольких ресурсах. |
| **208** | Already Reported | (WebDAV) Ресурс уже был сообщён в предыдущем ответе. |
| **226** | IM Used | Сервер выполнил запрос с использованием Instance Manipulations. |

---

### 3xx: Перенаправления

| Код | Название | Описание |
|-----|----------|----------|
| **300** | Multiple Choices | Ресурс имеет несколько представлений. Клиент должен выбрать одно. |
| **301** | Moved Permanently | Ресурс перемещён навсегда. Новый URL в заголовке Location. |
| **302** | Found | Ресурс временно находится по другому URL. **Важно:** метод запроса может измениться на GET. |
| **303** | See Other | Ответ на запрос находится по другому URL. Клиент должен использовать GET. |
| **304** | Not Modified | Ресурс не изменялся с момента последнего запроса (для кэширования). |
| **305** | Use Proxy | (Устарел) Запрос должен быть выполнен через прокси. |
| **307** | Temporary Redirect | Ресурс временно перемещён. **Метод запроса не должен изменяться.** |
| **308** | Permanent Redirect | Ресурс перемещён навсегда. **Метод запроса не должен изменяться.** |

---

### 4xx: Ошибки клиента

| Код | Название | Описание |
|-----|----------|----------|
| **400** | Bad Request | Сервер не может обработать запрос из-за синтаксической ошибки. |
| **401** | Unauthorized | Требуется аутентификация. |
| **402** | Payment Required | Зарезервирован для будущих систем оплаты. |
| **403** | Forbidden | Сервер понял запрос, но отказывается его выполнять. |
| **404** | Not Found | Ресурс не найден на сервере. |
| **405** | Method Not Allowed | Метод запроса не поддерживается для данного ресурса. |
| **406** | Not Acceptable | Сервер не может предоставить ресурс в формате, приемлемом для клиента. |
| **407** | Proxy Authentication Required | Требуется аутентификация на прокси-сервере. |
| **408** | Request Timeout | Сервер не дождался полного запроса от клиента. |
| **409** | Conflict | Запрос конфликтует с текущим состоянием ресурса. |
| **410** | Gone | Ресурс был удалён и больше не доступен. |
| **411** | Length Required | Сервер требует заголовок Content-Length. |
| **412** | Precondition Failed | Условие в заголовке (If-Match, If-None-Match и т.д.) не выполнено. |
| **413** | Payload Too Large | Тело запроса превышает допустимый размер. |
| **414** | URI Too Long | [[url-scheme|URI]] запроса слишком длинный. |
| **415** | Unsupported Media Type | Формат данных запроса не поддерживается сервером. |
| **416** | Range Not Satisfiable | Запрошенный диапазон байтов недоступен. |
| **417** | Expectation Failed | Сервер не может выполнить требование из заголовка Expect. |
| **418** | I'm a teapot | (Шуточный) Сервер отказывается варить кофе в чайнике. |
| **421** | Misdirected Request | Запрос направлен на сервер, который не может его обработать. |
| **422** | Unprocessable Entity | (WebDAV) Сервер понял формат, но не может обработать содержимое. |
| **423** | Locked | (WebDAV) Ресурс заблокирован. |
| **424** | Failed Dependency | (WebDAV) Запрос не выполнен из-за неудачи предыдущего запроса. |
| **425** | Too Early | Сервер не готов обработать запрос (защита от replay-атак). |
| **426** | Upgrade Required | Клиент должен сменить протокол. |
| **428** | Precondition Required | Сервер требует условный запрос (If-Match и т.д.). |
| **429** | Too Many Requests | Клиент отправил слишком много запросов (rate limiting). |
| **431** | Request Header Fields Too Large | Заголовки запроса слишком большие. |
| **451** | Unavailable For Legal Reasons | Ресурс недоступен по юридическим причинам. |

---

### 5xx: Ошибки сервера

| Код | Название | Описание |
|-----|----------|----------|
| **500** | Internal Server Error | Общая ошибка сервера. |
| **501** | Not Implemented | Сервер не поддерживает функциональность, необходимую для выполнения запроса. |
| **502** | Bad Gateway | Сервер, выступая как шлюз или прокси, получил недопустимый ответ от вышестоящего сервера. |
| **503** | Service Unavailable | Сервер временно недоступен (перегрузка или технические работы). |
| **504** | Gateway Timeout | Сервер-шлюз не дождался ответа от вышестоящего сервера. |
| **505** | HTTP Version Not Supported | Сервер не поддерживает версию HTTP, указанную в запросе. |
| **506** | Variant Also Negotiates | (Экспериментальный) Сервер обнаружил внутреннюю ошибку конфигурации. |
| **507** | Insufficient Storage | (WebDAV) Сервер не может сохранить представление ресурса. |
| **508** | Loop Detected | (WebDAV) Сервер обнаружил бесконечный цикл при обработке запроса. |
| **510** | Not Extended | Серверу требуется расширение протокола для выполнения запроса. |
| **511** | Network Authentication Required | Клиент должен пройти аутентификацию в сети. |

---

### Ключевые принципы RFC 7231

#### 1. Идемпотентность методов
- **Идемпотентные:** GET, PUT, DELETE, HEAD, OPTIONS, TRACE
- **Не идемпотентные:** POST, PATCH

#### 2. Безопасность методов
- **Безопасные:** GET, HEAD, OPTIONS, TRACE (не изменяют состояние ресурса)

#### 3. Кэширование
- Кэшируемые по умолчанию: GET, HEAD
- Не кэшируемые: POST, PUT, DELETE, PATCH

#### 4. Обработка неизвестных кодов
- Клиент должен понимать класс кода (1xx-5xx)
- Неизвестный код в известном классе обрабатывается как стандартный для этого класса

### Примеры использования

#### Успешное создание ресурса
```http
POST /api/users HTTP/1.1
Content-Type: application/json

{"name": "John", "email": "john@example.com"}

HTTP/1.1 201 Created
Location: /api/users/123
Content-Type: application/json

{"id": 123, "name": "John", "email": "john@example.com"}
```

#### Условный запрос (кэширование)
```http
GET /api/resource HTTP/1.1
If-None-Match: "abc123"

HTTP/1.1 304 Not Modified
```

#### Ошибка валидации
```http
POST /api/users HTTP/1.1
Content-Type: application/json

{"name": "", "email": "invalid"}

HTTP/1.1 422 Unprocessable Entity
Content-Type: application/json

{"errors": {"name": "is required", "email": "is invalid"}}
```
