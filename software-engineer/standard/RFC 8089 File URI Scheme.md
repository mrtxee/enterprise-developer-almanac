RFC 8089 The file URI Scheme

**RFC 8089 «The file URI Scheme»** — это стандарт, который формально описывает URI‑схему `file:` для адресации файлов в локальной файловой системе или на сетевом ресурсе.

## Кратко: зачем он нужен

Раньше схема `file:` использовалась повсеместно, но её синтаксис и семантика были описаны неоднозначно и реализовывались по‑разному в браузерах, ОС и приложениях. RFC 8089 не вводит новую схему, а **нормализует** уже существующую: фиксирует, как правильно писать `file:`‑URI, чтобы они работали предсказуемо везде.

---

## Что именно стандартизирует RFC 8089

- **Синтаксис URI.** Формально задаёт структуру: `file://<authority>/<path>`. Authority обычно пустой (локальная машина) или содержит имя хоста/IP. Путь — это путь к файлу в файловой системе.
- **Кодирование символов.** Чётко говорит, какие символы должны быть percent‑encoded, а какие можно оставлять как есть. Например, пробелы — только как `%20`, не как `+`.
- **Семантику пути.** Разъясняет, как интерпретировать путь в разных ОС: Unix‑пути начинаются с `/`, Windows‑пути в URI должны быть нормализованы к Unix‑стилю (с прямыми слешами), а буква диска кодируется особым образом (например, `file:///C:/path/file.txt`).
- **Поведение при отсутствии authority.** Если authority пуст (`file:///path`), URI трактуется как «на текущей машине».
- **Ограничения и предостережения.** RFC подчёркивает, что `file:`‑URI не предназначены для передачи по сети как полноценные веб‑ресурсы: у них нет HTTP‑метаданных, кэширования, аутентификации и т. д. Браузеры и приложения часто ограничивают их использование из соображений безопасности.

---

## Примеры

- **Unix‑система:** `file:///home/user/document.txt`
- **Windows (диск C:):** `file:///C:/Users/user/document.txt`
- **С указанием хоста (сетевой ресурс):** `file://server.example.com/share/path/file.txt` (на практике поддержка такого варианта сильно ограничена).

---

## Важные нюансы

- **Не путать с `file:///` и относительными путями.** В коде и конфигах часто пишут просто путь к файлу без схемы; `file:`‑URI нужен именно там, где ожидается URI (например, в API, конфигах, ссылках).
- **Безопасность.** Многие браузеры блокируют скрипты и AJAX‑запросы к `file:`‑ресурсам, чтобы предотвратить чтение произвольных файлов с диска через JS.
- **Совместимость.** RFC 8089 помогает избежать ошибок при обмене URI между системами: например, когда приложение на Linux генерирует URI для Windows‑клиента.

Учитывая твои прошлые задачи (работа с путями, сборками, артефактами, Docker и т. п.), `file:`‑URI могут встречаться в:

- конфигурациях инструментов (ссылки на локальные файлы);
- логах и отчётах (указание путей к артефактам);
- передаче путей между компонентами в распределённой среде.
