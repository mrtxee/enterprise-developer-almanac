## RFC 5424 Syslog Protocol

**RFC 5424** — стандарт [[org-ietf|IETF]] под названием **The Syslog Protocol**, определяющий формат сообщений и способ передачи журнальных записей (syslog) между устройствами и системами.

**Суть протокола**

Это «почтовый ящик» для системных сообщений: программа генерирует лог, а Syslog упаковывает его в специальный формат и отправляет на удалённый сервер (syslog server).

**Ключевые элементы**

- **Отправитель (sender)** — устройство/приложение, создающее лог.
- **Сборщик (collector)** — сервер, принимающий и хранящий логи.
- **Формат сообщения** — строгая структура с заголовком и телом.

**Формат сообщения (пример)**

```text
<34>1 2025-01-15T10:00:00Z myhost myapp 1234 - - Сервер запущен
```

| Часть | Что значит |
| --- | --- |
| `<34>` | Приоритет (facility + severity) |
| `1` | Версия протокола (RFC 5424) |
| `2025-01-15T10:00:00Z` | Временная метка |
| `myhost` | Имя хоста |
| `myapp` | Имя приложения |
| `1234` | ID процесса (Procid) |
| `- -` | Message ID и Structured Data (пустые) |
| `Сервер запущен` | Само сообщение |

**Зачем нужен RFC 5424**

- **Стандартизирует** передачу логов между разными системами.
- **Расширяет** старую версию (RFC 3164) поддержкой структурированных данных, временной зоны и UTF-8.
- **Позволяет** централизованно собирать логи со всего IT-ландшафта для анализа, мониторинга и расследования инцидентов.

**Где применяется**

- [[SIEM|SIEM]]-системы (Splunk, ELK).
- Сетевые устройства (роутеры, фаерволы).
- Серверы Linux/Unix (rsyslog, syslog-ng).
- Повсюду, где нужен централизованный сбор событий.

### Формат сообщения

Формат сообщения: `HEADER STRUCTURED-DATA MSG`

- **HEADER** — обязательная часть:
    - **PRI** — приоритет (facility и severity);
    - **VERSION** — версия формата (1);
    - **TIMESTAMP** — время в формате ISO 8601 ([[internet-date-time|RFC 3339]]);
    - **HOSTNAME** — имя хоста или его IPv4/IPv6-адрес;
    - **APP-NAME** — имя приложения-источника;
    - **PROCID** — идентификатор процесса;
    - **MSGID** — идентификатор типа сообщения.
- **STRUCTURED-DATA** — структурированные данные (набор SD-ID с параметрами); при их отсутствии используется «-».
- **MSG** — текст сообщения (в кодировке UTF-8).

HEADER вместе с STRUCTURED-DATA ограничен 1024 октетами, вся строка сообщения — 2048 октетов.
