## Конспект ключевых идей книги Effective Java

Книга *Effective Java* #📘 Джошуа Блоха #👨 структурирована в виде отдельных статей — каждая посвящена конкретному правилу или рекомендации по написанию качественного Java‑кода. Ниже — основные идеи, сгруппированные по тематическим блокам.

### Создание и уничтожение объектов

- **Статические фабричные методы вместо конструкторов.** Они могут иметь осмысленные имена, кэшировать объекты, возвращать подтипы и не требуют создания нового объекта при каждом вызове.
- **Шаблон Builder** для классов с множеством параметров (особенно опциональных). Позволяет избежать «телескопических конструкторов».
- **Контроль над синглтонами:** используйте приватный конструктор или `enum` для гарантии единственного экземпляра.
- **Избегайте создания лишних объектов.** Переиспользуйте, где возможно, особенно для неизменяемых типов.
- **Уничтожайте устаревшие ссылки.** Это помогает избежать утечек памяти (memory leaks).
- **Осторожнее с `finalize()`.** Метод ненадёжен и может привести к задержкам в сборке мусора; предпочтительнее использовать `try‑with‑resources` или явное закрытие ресурсов.

### Методы, общие для всех объектов

- **`equals()`: соблюдайте контракт.** Симметричность, транзитивность, рефлексивность, согласованность и работа с `null`.
- **Всегда переопределяйте `hashCode()` вместе с `equals()`.** Равные объекты должны иметь одинаковые хеш‑коды.
- **Переопределяйте `toString()`.** Делает отладку и логирование удобнее.
- **Осторожно с `clone()`.** Часто лучше использовать конструктор копирования или фабричный метод.
- **Рассмотрите реализацию `Comparable`.** Упрощает сортировку и сравнение объектов.

### Классы и интерфейсы

- **Предпочитайте композиции наследованию.** Композиция повышает гибкость и снижает связанность.
- **Предпочитайте интерфейсы абстрактным классам.** Интерфейсы позволяют множественную реализацию и облегчают тестирование.
- **Минимизируйте изменяемость (immutability).** Неизменяемые объекты потокобезопасны, проще в отладке и могут кэшироваться.
- **Делайте классы `final`, если они не предназначены для наследования.** Иначе чётко документируйте контракт переопределения методов.

### Общие принципы проектирования

- **Соблюдайте принцип наименьшего удивления.** Поведение кода должно быть предсказуемым.
- **Сводите зависимости к минимуму.** Чем меньше модулей зависят друг от друга, тем легче сопровождать код.
- **Выявляйте ошибки как можно раньше.** Лучше на этапе компиляции, чем во время выполнения.
- **Пишите самодокументируемый код.** Ясные имена, чёткие контракты и минимальная сложность улучшают читаемость.

### Обобщения (Generics), перечисления (Enums), аннотации

- **Используйте обобщения для типобезопасности.** Избегайте непроверенных приведений (`unchecked casts`).
- **Enums — мощный инструмент.** Они типобезопасны, могут содержать методы и поля, предпочтительнее констант `int`.
- **Аннотации для метаданных.** Используйте их для документирования, генерации кода и проверок на этапе компиляции.

### Методы и API

- **Проверяйте параметры на корректность.** Используйте `Objects.requireNonNull()` и валидацию границ.
- **Защитное копирование (`defensive copying`).** Предотвращает изменение внутренних данных извне.
- **Продуманные сигнатуры методов.** Чёткие имена, понятные типы параметров и возвращаемые значения.
- **Осторожнее с varargs.** Могут привести к созданию лишних массивов; используйте только когда это действительно нужно.
- **Документируйте API.** Javadoc должен объяснять поведение, ограничения и исключения.

### Параллелизм (Concurrency)

- **Предпочитайте высокоуровневые утилиты низкоуровневой синхронизации.** Используйте `Executor`, `Concurrent Collections`, `Future`, `CompletableFuture` вместо ручного управления потоками.
- **Избегайте блокировок, где возможно.** Неизменяемость и атомарные классы (`AtomicInteger` и т. д.) упрощают многопоточность.
- **Следите за безопасностью и живучестью (safety & liveness).** Избегайте deadlocks, livelocks и race conditions.

### Сериализация

- **Осторожнее с сериализацией.** Она усложняет эволюцию классов и может привести к уязвимостям.
- **Реализуйте кастомную сериализацию только при необходимости.** Контролируйте `serialVersionUID`, используйте `readObject()`/`writeObject()` для защиты инвариантов.

### Производительность и оптимизация

- **Не оптимизируйте преждевременно.** Сначала — ясность и корректность, затем — профилирование и точечные улучшения.
- **Избегайте преждевременного кэширования.** Кэшируйте только «горячие» данные с понятной стратегией инвалидации.
- **Экономно используйте строки.** Конкатенация в цикле может быть дорогой; рассмотрите `StringBuilder`.

### Общие лучшие практики

- **Используйте `try‑with‑resources`** для автоматического закрытия ресурсов (`AutoCloseable`).
- **Обрабатывайте исключения осмысленно.** Не игнорируйте их; логируйте или перебрасывайте с контекстом.
- **Обновляйтесь до новых версий Java.** Используйте лямбды, Streams, `var` и другие современные возможности для упрощения кода.
