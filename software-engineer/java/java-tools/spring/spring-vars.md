## Плейсхолдеры переменной окружения

В Spring-приложении можно использовать значения из переменных окружения либо значения по умолчанию — это делается в конфигурационных файлах через синтаксис плейсхолдеров `${VAR:default}`. Spring Boot берёт настройки из переменных окружения, system properties или файлов конфигурации, при этом переменные окружения имеют приоритет над файлами.

**Пример в application.yml**

```yaml
# Значение из переменной окружения PORT, если она задана; иначе будет использоваться значение 8080.
server:
  port: ${PORT:8080}
```

**Пример в application.properties**

```properties
# Если переменная окружения MY_ENV_VAR не установлена, будет использовано defaultValue.
custom.value=${MY_ENV_VAR:defaultValue}
```

**В коде с помощью @Value**

```java
// Сначала ищется переменная окружения MY_ENV_VAR; если её нет — используется defaultVal.
@Value("${MY_ENV_VAR:defaultVal}")
private String myValue;
```

## Особенности

В именах переменных окружения нельзя использовать точки — их обычно заменяют на подчёркивания (`MY_ENV_VAR`), а в Java-проперти можно обозначить всё точками (`my.env.var`). Spring автоматически преобразует такие имена из переменных окружения.

## Приоритеты источников конфигурации

Источники конфигурации по убыванию приоритета:

- Параметры командной строки
  - Переменные окружения
    - `application.yml` / `application.properties` внутри JAR
      - Значения по умолчанию в коде

Этот механизм универсален для Spring Boot и стандартного Spring и позволяет гибко конфигурировать приложение для разных окружений без изменения исходников или пересборки.
