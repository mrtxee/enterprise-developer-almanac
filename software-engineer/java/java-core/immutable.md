## Immutable-объекты

Immutable-объекты нужны для безопасности, потокобезопасности, простоты и предсказуемости. Они не могут быть изменены после создания, что исключает множество ошибок и уязвимостей.

### Причины использования

**Потокобезопасность (Thread Safety)**
Immutable-объекты автоматически потокобезопасны — их можно свободно передавать между потоками без синхронизации. Мутируемые объекты в многопоточной среде требуют `synchronized`, `volatile`, `Lock` и т. д., что сложно и подвержено ошибкам.

**Защита от побочных эффектов**
Если метод возвращает immutable-объект, вызывающий код гарантированно знает, что объект не изменится «под капотом» и что он не сможет его испортить. Например, в сервисе управления доступом или кэширования при запросе состояний следует возвращать копию или immutable-коллекцию.

**Простота и предсказуемость**
Immutable-объекты:
- легко понимать — их состояние фиксировано;
- легко тестировать — нет скрытых изменений состояния;
- не имеют «истории» — всегда в одном известном состоянии.

Это особенно важно в функциональном программировании, где чистые функции не имеют побочных эффектов.

**Использование в качестве ключей в хеш-таблицах**
Immutable-объекты безопасны в качестве ключей в `HashMap`, `HashSet`, так как хеш-код (`hashCode()`) должен быть стабильным. Если объект изменится после добавления в `HashMap`, он может «потеряться», потому что изменится его хеш-код.

**Кэширование и переиспользование**
Immutable-объекты можно безопасно кэшировать и переиспользовать. Примеры в Java — пул строк (String Pool) и константы `BigInteger`, `BigDecimal`.

**Пример пула строк**

```java
String a = "hello";
String b = "hello";
assert a == b; // true — один и тот же объект в пуле
```

**Построение надёжных систем**
Immutable-объекты упрощают:
- [[domain-driven-design]] ([[Domain-Driven Development]]) — value objects должны быть immutable;
- [[event-sourcing]] — события immutable по определению;
- React-style UI — состояние immutable, поэтому легко отслеживать изменения.

### Когда использовать immutable-объекты

Immutable-объекты идеальны для:
- [[PoEAA|DTO]];
- конфигурационных объектов;
- ключей в `Map`;
- состояний в многопоточных приложениях;
- значений, которые не должны меняться.

### Как создать immutable-класс

```java
public final class Person {
    private final String name;
    private final int age;

    public Person(String name, int age) {
        this.name = name;
        this.age = age;
    }

    public String getName() { return name; }
    public int getAge() { return age; }

    // НЕТ сеттеров!
    // Все поля — final
    // Класс — final (чтобы нельзя было наследоваться и добавить mutable-поля)
}
```

Для коллекций: оборачивай в `Collections.unmodifiableList()` или используй `List.copyOf()` (Java 10+).

### Сравнение Mutable и Immutable

| Критерий | Mutable | Immutable |
| -------- | ------- | --------- |
| Потокобезопасность | Требует синхронизации | Автоматически безопасен |
| Безопасность как ключ в Map | Опасно | Безопасно |
| Побочные эффекты | Возможны | Исключены |
| Потребление памяти | Менее (изменяется на месте) | Более (создается новый объект при «изменении») |
| Производительность | Быстрее при частых изменениях | Медленнее при частых «изменениях» |
| Простота отладки | Сложнее (состояние меняется) | Проще (состояние фиксировано) |

### Использование immutable-объектов в Java

| Класс | Почему immutable |
| ----- | ---------------- |
| `String` | Безопасность, String Pool, ключи в Map |
| `Integer`, `Long` и другие wrapper-классы | Безопасность, кэширование, ключи |
| `LocalDateTime`, `Instant` (java.time) | Предсказуемость, безопасность в многопоточности |
| `BigInteger`, `BigDecimal` | Точность, безопасность в вычислениях |
| `Optional<T>` | Логическая целостность |

## Эффективная неизменяемость

Иногда объект мутабельный (mutable) по структуре, но эффективно неизменяемый (effectively immutable) — если после публикации его никто не изменяет.

**Пример**

```java
final List<String> items = List.of("a", "b", "c"); // immutable list
```

Такой объект можно безопасно использовать как immutable.

**Вывод**
Immutable-объекты — фундаментальный паттерн для написания надежного, безопасного и простого кода. Они особенно важны в многопоточных приложениях, системах с высокими требованиями к безопасности, функциональном и реактивном программировании.

Правило большого пальца: делай классы immutable по умолчанию, mutable — только если есть веская причина.

**Советы**
- Используй `record` (Java 14+) — они immutable по умолчанию:
```java
public record Person(String name, int age) {}
```
- В коллекциях используй `List.copyOf()`, `Set.copyOf()`, `Map.copyOf()`.
- Избегай публичных мутабельных полей.
- Возвращай копии или immutable-обёртки из геттеров.
