## Как работает JMM

ОВЁС — основной вопрос её существования (модели памяти Java): **какие значения может прочитать конкретный read в программе?**

JMM строит все возможные пути исполнения программы:

1. Вначале действия структурируются в PO, SO: Synchronization Order = Program Order + Synchronization Actions.
2. Потом действия различных потоков связываются через SW.
3. В результате возникает Happens-Before — отношение порядка выполнения.

JMM отбрасывает запрещённые исполнения на основе структурных ограничений, проверок и валидаций.

Оставшиеся варианты исполнения разрешены. Таких вариантов много, и в некоторых могут возникать сайд-эффекты.

## Кэш-лайны и False Sharing

- **[[cache-line]]** — это блок памяти, с которым работает CPU для ускорения доступа.
- **False Sharing** — частая проблема в многопоточности, когда потоки борются за одну cache line.
- **Оптимизация:** выравнивание данных, минимизация shared-переменных, использование `@Contended`.

**Как работает**

- Когда процессор обращается к ячейке памяти, в кэш загружается **целая cache line**, содержащая эту ячейку, обычно **64 байта** (может быть 32, 128 байт).
- Последующие обращения к соседним данным происходят быстрее, так как они уже в кэше.
- Если два ядра CPU работают с разными переменными, но они попадают в **одну cache line**, это вызывает конфликты:
  - Ядро 1 меняет `переменную A` → кэш-линия помечается как "грязная".
  - Ядро 2 читает `переменную B` из той же строки → вынуждено загружать обновлённые данные из кэша Ядра 1, хотя `B` не изменилась.
  - **Результат:** производительность падает из-за избыточной синхронизации.

## SC-DRF (Sequential Consistency-Data Race Free)

**SC-DRF: Executions**

Execution: $E = \langle P, A, \xrightarrow{po}, \xrightarrow{so}, W, V, \xrightarrow{sw}, \xrightarrow{hb} \rangle$

- **$E$** — выполнение (execution)
- $P$ — программа (program)
- $A$ — множество действий программы (actions)
- $\xrightarrow{po}$ — program order, порядок программного кода
- $\xrightarrow{so}$ — synchronization order, порядок синхронизации
- $W(r)$ — «write seen function», возвращает запись, которую видит данное чтение $r$
- $V(r)$ — значение, которое прочитало конкретное чтение $r$
- $\xrightarrow{sw}$ — synchronizes-with order, отношение «synchronizes-with»
- $\xrightarrow{hb}$ — happens-before order, отношение «happens-before»

> SC-DRF is the formal model for sequential consistency in concurrent programming.

Модель SC-DRF гарантирует Sequential Consistency, но только если мы избавимся от всех гонок данных (data race).

Модель SC-DRF через последовательность локальных трансформаций строит HB-очередность выполнения операций программы.

### Data Race — гонка данных

Состояние **гонки данных** (data race) возникает, когда два или более потока пытаются получить доступ к одной и той же не финальной переменной без синхронизации.

В состоянии гонки данных могут возникнуть изменения, которые не будут видны другим потокам. Это повлечёт чтение устаревших данных, бесконечные циклы, повреждённые структуры данных или неточные вычисления.

### SC — Sequential Consistency

Принцип, согласно которому результат выполнения параллельного кода должен быть не отличим от того, как если бы все операции были выполнены в последовательности кода, заданной разработчиком.

## PO — Program Order

Порядок действий внутри одного потока.

- PO связывает порядок действий только внутри одного потока, и его не хватает, чтобы обеспечить SC.

Так как PO — отношение частичного порядка (не обеспечивает полный порядок), Java предлагает использовать Synchronization Actions для связывания порядка выполнения задач между разными потоками.

**Program Order + Synchronization Actions = Synchronization Order**

---

## SO — Synchronization Order

Synchronization Actions образуют Synchronization Order — полный порядок.

Synchronization Order — это надстройка, которая получается из Program Order + Synchronization Actions.

---

## SA — Synchronization Actions

- volatile read/write
- lock monitor, unlock monitor
- первое (синтетическое) и последнее действие в потоке, действия, запускающие поток
- операции, обнаруживающие завершение потока (`Thread.join()`, `Thread.isInterrupted()` и т. п.)

---

## SW — Synchronization With Order

Некоторый порядок выполнения операций в многопоточке, который связывает порядок выполнения операций между параллельными потоками.

### Roach motel — «ловушка для таракана»

Принцип оптимизации стекового выполнения JMM, который позволяет заменить вызовы одной сущности в разных потоках и вернуть один объект всем потокам, вместо того чтобы повторно делать одинаковую работу в разных потоках.

---

## Happens-Before Order

Порядок следования, который объединяет Synchronization With Order с Program Order.

- PO — даёт семантику внутри потока.
- SW — даёт связь между потоками.

Happens-Before (HB) — отношение частичного порядка. Наделён свойствами:

- отсутствуют циклы;
- Happens-Before Consistency (HBC): поток исполнения обязан видеть последние записи в HB.
