## ARP (Address Resolution Protocol)

**Уровень:** канальный (модель OSI, уровень 2).

**Назначение:** сопоставление IP‑адресов с MAC‑адресами в локальной сети (LAN).

## Зачем нужен

- IP‑адреса используются на сетевом (3 по [[osi]]) уровне (для маршрутизации между сетями);
- MAC‑адреса — на канальном (2 по [[osi]]) уровне (для доставки кадров внутри LAN);
- ARP «связывает» их, чтобы пакеты могли дойти до получателя в одной подсети.

## Как работает

1. **Запрос ARP (ARP Request)**
   - Устройство (например, ПК) знает IP‑адрес получателя, но не его MAC.
   - Оно отправляет **широковещательный запрос** («Кто имеет IP `192.168.1.10`? Сообщите свой MAC!»).
   - Пакет рассылается всем устройствам в LAN (MAC‑адрес назначения: `FF:FF:FF:FF:FF:FF`).

2. **Ответ ARP (ARP Reply)**
   - Устройство с нужным IP‑адресом отвечает своим MAC‑адресом.
   - Отправитель сохраняет пару `(IP, MAC)` в **ARP‑таблице** (кэш).

3. **Доставка кадра**
   - Теперь отправитель может сформировать Ethernet‑кадр с корректным MAC‑адресом получателя.

## Пример ARP‑таблицы (на ПК)

```text
  IP‑адрес         MAC‑адрес          Тип
  192.168.1.1     00:1A:2B:3C:4D:5E  динамический
  192.168.1.10    00:AA:BB:CC:DD:EE  динамический
```

## Особенности

- **Кэширование:** ARP‑записи хранятся временно (обычно 15–45 минут).
- **Широковещание:** запросы рассылаются всем устройствам в подсети.
- **Безопасность:** ARP уязвим к атакам (ARP spoofing/poisoning), когда злоумышленник подменяет MAC‑адреса.

## Команды для работы с ARP

- **Windows:** просмотр ARP‑таблицы и удаление записи:

  ```bash
  arp -a
  arp -d 192.168.1.10
  ```

- **Linux/macOS:** просмотр таблицы соседей и удаление записи:

  ```bash
  ip neigh
  sudo arp -d 192.168.1.10
  ```
