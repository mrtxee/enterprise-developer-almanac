**Server Side Includes (SSI)** — это простая технология, позволяющая динамически собирать HTML-страницы на стороне сервера перед отправкой клиенту. Она позволяет вставлять в HTML-код различные элементы (другие файлы, переменные, результаты выполнения скриптов) с помощью специальных директив.

## **Как работает SSI?**

1. **Запрос клиента**: Браузер запрашивает HTML-страницу (обычно с расширением `.shtml`)
2. **Обработка сервером**: Веб-сервер (Apache, Nginx) анализирует файл, находит SSI-директивы
3. **Выполнение инструкций**: Сервер выполняет указанные действия (включает файлы, выполняет скрипты)
4. **Формирование ответа**: Сервер отправляет клиенту готовый HTML-код


## **Недостатки SSI**
1. **Ограниченная функциональность** — не подходит для сложной логики
2. **Безопасность** — директивы `exec` могут быть опасны
3. **Устаревание** — вытесняется более современными технологиями
    

---

## **Современные альтернативы SSI**

1. **PHP includes**:
    

php

<?php include 'header.php'; ?>

2. **JavaScript (клиентский)**:
    

html

<script>fetch('header.html').then(...)</script>

3. **Шаблонизаторы**:
    
    - Jinja2 (Python)
        
    - Twig (PHP)
        
    - Handlebars (JavaScript)
        
4. **Статические генераторы сайтов**:
    
    - Jekyll
        
    - Hugo
        
    - Gatsby
        
5. **Компонентный подход**:
    
    - React
        
    - Vue.js
        
    - Web Components
        

---

## **Когда еще используют SSI сегодня?**

1. **Легаси-системы** — поддержка старых проектов
    
2. **Простая статика** — когда не нужно поднимать полноценный бэкенд
    
3. **Микросервисы** — сборка страницы из разных сервисов
    
4. **Кэширующие прокси** — Edge Side Includes (ESI) в CDN
    

**Пример ESI (для CDN):**

html

<esi:include src="/header.html"/>
<esi:include src="/weather-widget?city=moscow"/>
