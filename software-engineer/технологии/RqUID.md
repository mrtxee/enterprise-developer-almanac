Разберу подробно, чем отличаются **UID** и **RqUID** — это принципиально разные идентификаторы с разными целями и областями применения.



## UID (Unique Identifier)


**UID** — общий термин для уникального идентификатора объекта или субъекта. В зависимости от контекста может означать:

* **UUID/GUID** — глобально уникальный идентификатор (128‑битное значение, например, `123e4567-e89b-12d3-a456-426614174000`);
* **ID записи** в БД (автоинкрементный или [[UUID]]);
* **любой уникальный ключ** для идентификации сущности.

**Характеристики UID:**
* **Постоянность.** Обычно присваивается один раз и не меняется.
* **Привязка к сущности.** Идентифицирует конкретный объект (пользователя, заказ, товар).
* **Глобальность.** Часто должен быть уникальным во всей системе или даже во всех системах.
* **Хранение.** Сохраняется в БД как атрибут сущности.
* **Жизненный цикл.** Существует столько же, сколько и сама сущность.

**Примеры UID:**
* ID пользователя в соцсети: `uid=15928374`;
* UUID заказа: `order_id=a1b2c3d4-e5f6-7890-1234-56789abcdef0`;
* ID товара в каталоге: `product_uid=P12345`.

## RqUID (Request Unique Identifier)


**RqUID** — специальный заголовок HTTP‑запроса, содержащий уникальный идентификатор **конкретного запроса**.

**Характеристики RqUID:**
* **Временность.** Создаётся для одного запроса и имеет ограниченный срок жизни (обычно 24–72 часа).
* **Привязка к запросу.** Идентифицирует не сущность, а операцию (создание, обновление, чтение).
* **Клиентская генерация.** Генерируется клиентом перед отправкой запроса.
* **Идемпотентность.** Позволяет системе распознать повторный запрос с тем же RqUID и вернуть результат первого выполнения.
* **Логирование.** Используется для трассировки запроса в логах (от клиента до сервера и обратно).
* **Не сохраняется как бизнес‑данные.** Хранится временно для технических нужд.

**Формат:** обычно UUID v4 (например, `RqUID: 123e4567-e89b-12d3-a456-426614174000`).


**Пример использования:**
```http
POST /api/v1/orders
RqUID: a1b2c3d4-e5f6-7890-1234-56789abcdef0
Content-Type: application/json

{
  "product_id": "P12345",
  "quantity": 2
}
```

## Сравнительная таблица

| Параметр | UID | RqUID |
|--------|---------|---------|
| **Назначение** | Идентификация сущности (кто/что это) | Идентификация операции (что сделано) |
| **Когда создаётся** | При создании сущности | Перед отправкой HTTP‑запроса |
| **Кто генерирует** | Сервер (при создании сущности) или система | Клиент (приложение, сервис) |
| **Где используется** | В БД, в URL, в payload | В заголовках HTTP‑запроса (`RqUID: ...`) |
| **Срок жизни** | Долгий (пока существует сущность) | Короткий (часы/дни для логирования) |
| **Уникальность** | Глобальная в рамках системы | Глобальная для запросов (не должен повторяться) |
| **Сохранение** | Да, как атрибут сущности | Да, временно (для проверки дубликатов) |
| **Пример значения** | `user_123`, `123e4567-...` | `a1b2c3d4-...` (всегда UUID) |
| **Цель** | Ссылка на объект, поиск, связь | Идемпотентность, трассировка, аудит |

## Практические сценарии


**Сценарий 1. Создание пользователя**
* **UID:** сервер генерирует `user_uid=abc123` и сохраняет в БД.
* **RqUID:** клиент генерирует `RqUID=uuid-for-create-request` для POST‑запроса. Если запрос повторится, сервер вернёт тот же `user_uid` без создания нового пользователя.

**Сценарий 2. Обновление баланса**
* **UID:** `account_uid=acc456` — идентификатор счёта.
* **RqUID:** `RqUID=uuid-for-update-balance` — гарантирует, что повторная отправка запроса не спишет деньги дважды.

**Сценарий 3. Отчётность**
* По **UID** находят все операции пользователя.
* По **RqUID** находят конкретный запрос в логах сервера (время, IP, статус).

## Краткий итог


* **UID** отвечает на вопрос **«Что это?»** (идентифицирует объект).
* **RqUID** отвечает на вопрос **«Что было сделано?»** (идентифицирует действие).

**Аналогия:**
* **UID** — номер паспорта человека (постоянный идентификатор личности).
* **RqUID** — номер квитанции в банке (временный идентификатор операции). Вы можете совершить несколько операций — у каждой будет свой номер квитанции, но паспорт останется тем же.
