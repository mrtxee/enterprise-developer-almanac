**MTU (Maximum Transmission Unit) в Ethernet — 1500 байт** — это максимальный размер *полезной нагрузки* (данных) в одном [[Ethernet frame|Ethernet‑кадре]], который может быть передан без фрагментации. Разберём подробно.

## Что такое MTU

**MTU** (Maximum Transmission Unit, максимальная единица передачи) — это максимальный объём данных (в байтах), который может быть передан в одном кадре канального уровня (L2) сети. Для классического Ethernet стандарт **MTU = 1500 байт**.

Важно: MTU не включает заголовки самого Ethernet‑кадра, а только *полезную нагрузку*.

## Состав Ethernet‑кадра

Полный кадр Ethernet (IEEE 802.3) состоит из:

* **Преамбула** (7 байт) + **SFD** (1 байт) — для синхронизации (не учитываются в MTU).
* **MAC‑адрес назначения** (6 байт).
* **MAC‑адрес источника** (6 байт).
* **Тип/длина** (2 байт, например, `0x0800` для IPv4).
* **Полезная нагрузка** (Payload) — **до 1500 байт (MTU)**.
* **FCS** (4 байт, контрольная сумма CRC).

**Общий размер кадра:** 14 (заголовки) + 1500 (данные) + 4 (FCS) = **1518 байт**. С учётом преамбулы и SFD — **1526 байт**.

## Почему именно 1500 байт?


Исторически значение 1500 байт было выбрано как компромисс:
* **Эффективность.** Большой MTU уменьшает долю служебных заголовков (накладных расходов) на единицу передаваемых данных.
* **Задержка.** Слишком большой MTU увеличивает задержку для коротких пакетов (например, голосового трафика), так как кадр занимает канал дольше.
* **Надёжность.** При ошибках передачи переотправлять меньший кадр эффективнее.
* **Совместимость.** Стандарт закрепился в 1980‑х и стал универсальным для Ethernet.

## MTU и протоколы верхних уровней


На верхних уровнях MTU влияет на размер передаваемых сегментов:
* **IPv4/IPv6.** MTU сети определяет **MSS** (Maximum Segment Size) для TCP. Обычно MSS = MTU − 40 байт (заголовки IPv4 + TCP), т. е. **1460 байт** для Ethernet.
* **Path MTU Discovery (PMTUD).** Механизм, позволяющий узлам автоматически определять минимальный MTU на всём пути следования пакета и избегать фрагментации.
* **Фрагментация.** Если пакет больше MTU, он разбивается на фрагменты (на уровне IP). Это создаёт дополнительную нагрузку на процессор и может снижать производительность.

## Jumbo Frames (MTU > 1500)

В современных сетях (особенно в ЦОД) используют **Jumbo Frames** — кадры с увеличенным MTU (обычно 9000 байт):
* **Плюсы:**
    * снижение накладных расходов (меньше заголовков на МБ данных);
    * повышение пропускной способности для больших файлов и бэкапов;
    * уменьшение нагрузки на CPU (меньше кадров для обработки).
* **Минусы:**
    * не все устройства поддерживают Jumbo Frames;
    * требуется единообразная настройка MTU на всех узлах пути;
    * больший риск потерь при ошибках передачи.

## Проблемы несоответствия MTU (MTU Mismatch)

Если MTU настроен неодинаково на разных устройствах:
* пакеты, превышающие MTU сегмента, отбрасываются;
* без PMTUD это приводит к «чёрным дырам» (соединения устанавливаются, но данные не передаются);
* решение — проверка и унификация MTU на всех интерфейсах.

## Как проверить и настроить MTU


* **Windows:**
    ```cmd
    netsh interface ipv4 show subinterfaces
    ping -f -l 1472 <адрес>  # тест MTU (1472 + 28 = 1500)
    ```
* **Linux:**
    ```bash
    ip link show
    ping -M do -s 1472 <адрес>
    ```
* **Cisco IOS:**
    ```
    show interfaces
    interface <id>
    mtu 1500
    ```

## Краткий итог

* **MTU 1500 байт** в Ethernet — стандарт для размера полезной нагрузки кадра.
* Определяет максимальный размер данных без фрагментации.
* Влияет на MSS (TCP) и производительность сети.
* Jumbo Frames (MTU > 1500) используются для оптимизации в специализированных сетях.
* Несоответствие MTU вызывает проблемы с передачей данных.
