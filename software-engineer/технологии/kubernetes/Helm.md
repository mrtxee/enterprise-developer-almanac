# Helm
Helm — это пакетный менеджер для [[software-engineer/технологии/kubernetes/Kubernetes]], который позволяет легко управлять развёртыванием, обновлением и удалением приложений.

Helm упрощает управление Kubernetes-приложениями, предоставляет удобный способ определения, установки и обновления Kubernetes-ресурсов.

Основные компоненты Helm:
* **Чарты (Charts)**
	* Чарты — это пакеты Helm, содержащие все необходимые описания Kubernetes-ресурсов для развёртывания приложения. Они включают шаблоны YAML-файлов, которые определяют конфигурацию и ресурсы Kubernetes — Pods, Services, Deployments и другие.
* **Репозитории (Repositories)**
	* Репозитории — это хранилища, где размещаются чарты. Репозитории упрощают доступ к чартам и управление ими, помогают легко находить и использовать готовые решения для распространённых задач, позволяют делиться чартами с другими пользователями и командами.
* **Релизы (Releases)**
	* Релизы — это развёрнутые инстансы чартов в кластере [[software-engineer/технологии/kubernetes/Kubernetes]]. Каждый раз, когда чарт устанавливается в кластер, создаётся новый релиз. Его можно обновлять, отменять и удалять, то есть эффективно управлять жизненным циклом приложений.

Helm решает несколько важных задач при работе с Kubernetes:
1. **Управление приложениями.** Позволяет легко развёртывать, обновлять и удалять приложения.
2. **Управление зависимостями.** Обеспечивает управление зависимостями между компонентами приложения.
3. **Версионирование и откаты.** Позволяет управлять версиями приложений и откатываться к предыдущим версиям при необходимости.
4. **Консистентность и воспроизводимость.** Гарантирует, что развёртывания будут идентичными во всех средах.

Цикл жизни Helm-чарта
* Создание Helm-чарта
* Развёртывание Helm-чарта
* Обновление Helm-чарта

# Helm vs Terraform

**[[Terraform]]** и **Helm** — это два фундаментальных инструмента в современном DevOps, но они решают разные задачи. Если говорить просто: **Terraform создает инфраструктуру, а Helm размещает на ней приложения.**

Вот подробное сравнение без привязки к конкретным проектам.

---

### 1. Основная аналогия
Представьте, что вы запускаете новый офис компании:
*   **Terraform** — это строители. Они арендуют землю, заливают фундамент, возводят стены, проводят электричество и интернет. Они готовят **здание** к работе.
*   **Helm** — это завхозы. Они завозят внутрь здания мебель, компьютеры, настраивают телефоны, вешают вывески и расставляют сотрудников по кабинетам. Они наполняют **здание содержанием**.

---

### 2. Terraform (Infrastructure as Code)
**Что это:** Инструмент для безопасного и эффективного создания, изменения и управления инфраструктурой.

*   **Что создает:** Виртуальные машины, сети (VPC), балансировщики нагрузки, базы данных (как сервис), политики доступа (IAM) и даже сами кластеры Kubernetes.
*   **Язык:** HCL (HashiCorp Configuration Language) — декларативный язык конфигурации.
*   **Как работает:** У Terraform есть файл состояния (`tfstate`). Он хранит «карту» всей вашей инфраструктуры. Когда вы вносите изменения, Terraform сравнивает желаемое состояние с реальным и показывает план изменений перед применением.
*   **Когда использовать:**
    *   Нужно создать кластер Kubernetes с нуля (например, в AWS EKS или Google GKE).
    *   Нужно создать облачные ресурсы (S3, RDS, EC2).
    *   Нужно настроить сеть и безопасность между компонентами.

### 3. Helm (Package Manager for Kubernetes)
**Что это:** Менеджер пакетов для Kubernetes (аналог `apt` для Linux или `pip` для Python, но для K8s).

*   **Что создает:** Ресурсы внутри уже существующего кластера Kubernetes: Pod'ы, Сервисы, Deployment'ы, ConfigMap, Secrets, Ingress.
*   **Язык:** YAML + Go Templates (упакованные в «Чарты»).
*   **Как работает:** Helm использует концепцию «Чартов» (Charts). Чарт — это набор файлов, описывающих приложение. Вы устанавливаете чарт, и Helm создает все необходимые ресурсы в кластере. Он хранит историю релизов прямо внутри кластера.
*   **Когда использовать:**
    *   Нужно установить сложное приложение в Kubernetes (например, Prometheus, Kafka, PostgreSQL внутри кластера).
    *   Нужно обновлять версии приложений (rollback, upgrade).
    *   Нужно управлять конфигурациями одного и того же приложения для разных окружений (Dev, Stage, Prod) через файлы значений (`values.yaml`).

---

### 4. Сравнительная таблица

| Характеристика         | Terraform                              | Helm                                               |
| :--------------------- | :------------------------------------- | :------------------------------------------------- |
| **Основная цель**      | Provisioning (Создание инфраструктуры) | Configuration Management (Управление приложениями) |
| **Уровень**            | Облако / Дата-центр / Кластер          | Внутри кластера Kubernetes                         |
| **Объекты**            | VM, Сети, БД, [[IAM]], K8s Cluster     | Deployments, Services, Pods, ConfigMaps            |
| **Хранение состояния** | Файл `tfstate` (локально или в S3)     | Secret/ConfigMap внутри самого K8s кластера        |
| **Жизненный цикл**     | Создание/Уничтожение ресурсов          | Установка/Обновление/Откат приложений              |
| **Шаблоны**            | Модули (Modules)                       | Чарты (Charts)                                     |

---

### 5. Как они работают вместе?
В современной архитектуре их почти всегда используют в связке, а не выбирают что-то одно.

**Типичный пайплайн:**
1.  **Terraform** разворачивает облачную инфраструктуру и создает пустой кластер Kubernetes.
2.  **Helm** подключается к этому кластеру и устанавливает туда необходимые приложения (мониторинг, логирование, бизнес-сервисы).

**Можно ли заменить одно другим?**
*   *Может ли Terraform ставить приложения в K8s?* Да, у Terraform есть Kubernetes Provider. Но это считается плохой практикой для сложных приложений, так как Terraform хуже управляет жизненным циклом обновлений (например, rolling updates) по сравнению с нативными механизмами K8s, которые использует Helm.
*   *Может ли Helm создавать инфраструктуру?* Нет, Helm не умеет создавать виртуальные машины или сети в облаке. Ему нужен уже готовый кластер.

### Итог
*   Если вам нужно **построить площадку** (серверы, сеть, кластер) — используйте **Terraform**.
*   Если вам нужно **запустить софт** на этой площадке (микросервисы, базы данных внутри K8s) — используйте **Helm**.
