**Маска подсети** — это параметр сетевой конфигурации, который определяет, какая часть IP‑адреса относится к **сети**, а какая — к **конкретному устройству (хосту)** в этой сети.

### Как выглядит
- В **десятичной записи** — четыре числа, разделённые точками (как IP‑адрес), например: `255.255.255.0`.
- В **формате CIDR** — косая черта и число (`/24`), обозначающее количество бит, отведённых под сеть.
**Соответствие форматов:**
- `255.255.255.0` ≡ `/24` (24 бита под сеть, 8 под хосты);
- `255.255.0.0` ≡ `/16` (16 бит под сеть, 16 под хосты);
- `255.255.255.128` ≡ `/25` (25 бит под сеть, 7 под хосты).
### Как маска подсети выделяет хост

Маска подсети «разделяет» IP‑адрес на две части:
1. **Часть сети** — определяет саму подсеть (общую для всех устройств в ней).
2. **Часть хоста** — уникальный идентификатор конкретного устройства внутри этой подсети.

**Пример:**
- IP‑адрес: `192.168.1.10`;
- маска подсети: `255.255.255.0` (`/24`).
**Разбор:**
- Первые три октета (`192.168.1`) — часть сети (определяется единицами в маске).
- Последний октет (`10`) — часть хоста (определяется нулями в маске).
Таким образом, в подсети `192.168.1.0/24`:
- адрес сети: `192.168.1.0` (не может быть адресом хоста);
- широковещательный адрес: `192.168.1.255` (тоже не для хоста);
- допустимые адреса хостов: от `192.168.1.1` до `192.168.1.254`.
### Ключевые свойства хоста в подсети
1. **Уникальный адрес**
   - В пределах одной подсети у каждого хоста свой IP (без дублирования).
   - За пределами подсети этот же IP может использоваться в другой сети (например, в VPN).

2. **Привязка к подсети**
   - Хост «знает» свою маску подсети, чтобы понимать:
     - какие адреса находятся в его локальной сети;
     - для каких адресов нужно использовать шлюз (маршрутизатор).

3. **Ограниченное количество хостов**
   - Число возможных хостов зависит от маски подсети. Например:
     - `/24` (255.255.255.0) → до 254 хостов;
     - `/16` (255.255.0.0) → до 65 534 хостов;
     - `/28` (255.255.255.240) → до 14 хостов.

4. **Неиспользуемые адреса**
   - Первый адрес подсети (например, `192.168.1.0`) — адрес сети, не назначается хостам.
   - Последний адрес (например, `192.168.1.255`) — широковещательный, тоже не для хостов.

### Зачем это нужно

- **Маршрутизация.** Хост сравнивает IP‑адрес получателя со своей маской, чтобы понять:
  - если адреса в одной подсети — отправляет пакет напрямую;
  - если в другой подсети — направляет через шлюз.
- **Безопасность.** Сегментация сети (разные подсети для отделов) ограничивает доступ между хостами.
- **Управление.** Администраторы назначают хостам IP‑адреса в рамках выделенных подсетей.

### Примеры

1. **Домашняя сеть**
   - Подсеть: `192.168.0.0/24`;
   - Хосты: ноутбук (`192.168.0.5`), смартфон (`192.168.0.10`), принтер (`192.168.0.20`).

2. **Офисная сеть**
   - Подсеть бухгалтерии: `10.0.1.0/24`, хосты: `10.0.1.10`, `10.0.1.11`;
   - Подсеть ИТ: `10.0.2.0/24`, хосты: `10.0.2.5`, `10.0.2.6`.

### Итог

**Хост в контексте маски подсети** — это:
- устройство с уникальным IP‑адресом в пределах подсети;
- часть адреса, определяемая нулями в маске подсети;
- элемент, для которого маска задаёт допустимый диапазон адресов и правила маршрутизации.
### Как работает (на примере)

**Дано:**
- IP‑адрес: `192.168.1.10`;
- маска подсети: `255.255.255.0` (`/24`).

**Шаг 1.** Переводим IP и маску в двоичный вид:
- IP: `11000000.10101000.00000001.00001010`;
- маска: `11111111.11111111.11111111.00000000`.

**Шаг 2.** Применяем логическое «И» (побитово):
```
  11000000.10101000.00000001.00001010  (IP)
& 11111111.11111111.11111111.00000000  (маска)
= 11000000.10101000.00000001.00000000  → 192.168.1.0 (адрес сети)
```
**Результат:**
- **Адрес сети:** `192.168.1.0`;
- **Адрес хоста:** `0.0.0.10` (последние 8 бит).

### Ключевые моменты
- Маска подсети **не меняется** для всех устройств в одной подсети.
- Чем **больше число после `/`** (например, `/28`), тем **меньше** устройств в подсети.
- Маска работает **только в паре с IP‑адресом** — без него её смысл теряется.
- В IPv6 маски тоже есть, но записываются только в формате CIDR (например, `/64`).
**Хост** в контексте маски подсети — это **конкретное устройство** (компьютер, сервер, принтер, смартфон и т. п.), подключённое к сети и имеющее уникальный IP‑адрес в рамках этой сети.
Первый и последний адреса в подсети имеют специальное назначение и **не могут быть назначены хостам** (устройствам). Разберём их функции.

### 1. Первый адрес подсети (адрес сети)

**Пример:** в подсети `192.168.1.0/24` первый адрес — `192.168.1.0`.

**Назначение:**
- идентифицирует саму подсеть как единый объект;
- служит «меткой» для маршрутизаторов и коммутаторов, чтобы понимать границы сети;
- используется в таблицах маршрутизации (например, в настройках роутера или файрвола).

**Почему нельзя назначить хосту:**
- если присвоить этот адрес устройству, маршрутизаторы перестанут корректно распознавать сеть;
- пакеты, адресованные сети, будут ошибочно направляться на устройство, нарушая работу всей подсети.

### 2. Последний адрес подсети (широковещательный адрес)

**Пример:** в подсети `192.168.1.0/24` последний адрес — `192.168.1.255`.

**Назначение:**
- для отправки **широковещательных (broadcast) сообщений** — пакетов, которые должны получить **все устройства в подсети**;
- примеры использования:
  - поиск DHCP‑сервера (клиент отправляет запрос на `255.255.255.255`, чтобы найти сервер);
  - ARP‑запросы (определение MAC‑адреса по IP);
  - уведомления о сетевых событиях (например, изменение конфигурации).

**Почему нельзя назначить хосту:**
- любой пакет, отправленный на этот адрес, будет доставлен **всем устройствам** в подсети одновременно;
- если назначить его конкретному устройству, оно будет получать дублирующиеся пакеты, а другие устройства могут пропустить важные широковещательные сообщения;
- нарушится работа протоколов, зависящих от broadcast‑рассылок.

### Итог: зачем нужны эти «запрещённые» адреса

1. **Адрес сети** (`192.168.1.0`) — обеспечивает:
   - корректную маршрутизацию между подсетями;
   - идентификацию сети в настройках оборудования.
2. **Широковещательный адрес** (`192.168.1.255`) — позволяет:
   - рассылать сообщения всем устройствам сразу;
   - поддерживать работу ключевых сетевых протоколов (DHCP, ARP).

**Важно:**
- количество доступных хостов в подсети всегда **на 2 меньше**, чем общее число адресов (из‑за вычета адреса сети и broadcast‑адреса);
- в подсети `/24` (256 адресов) можно назначить хостам только **254 адреса** (от `192.168.1.1` до `192.168.1.254`).
