## 📋 nohup — объяснение утилиты

**`nohup`** (no hang-up) — утилита Unix/Linux, которая **запускает процесс, нечувствительный к закрытию терминала**.

---

## 🎯 Зачем нужна?

| Проблема | Решение |
|----------|---------|
| Закрыл терминал → процесс убился | `nohup` игнорирует сигнал `SIGHUP` |
| Долгая задача в фоне | `nohup` + `&` = работает независимо |
| Нужно сохранить вывод | Автоматически пишет в `nohup.out` |

---

## 🧩 Синтаксис

```bash
nohup <команда> [аргументы] &
```

| Часть       | Описание                                                |
| ----------- | ------------------------------------------------------- |
| `nohup`     | Запускает команду, игнорируя `SIGHUP`                   |
| `<команда>` | Любая команда или скрипт                                |
| `&`         | Запуск в фоновом режиме (опционально, но рекомендуется) |

---

## 📁 Куда пишется вывод?

| Поток | По умолчанию | Как изменить |
|-------|--------------|--------------|
| **stdout** | `./nohup.out` | `nohup cmd > my.log 2>&1 &` |
| **stderr** | `./nohup.out` | `nohup cmd > my.log 2>&1 &` |
| **stdin** | `/dev/null` (игнорируется) | Не используется |

---

## 🧪 Примеры использования

### 1. **Запуск сервера**
```bash
nohup java -jar myapp.jar &
```

### 2. **С перенаправлением вывода**
```bash
nohup ./backup.sh > backup.log 2>&1 &
```

### 3. **С полным путём и логами**
```bash
nohup /opt/scripts/sync.sh >> /var/log/sync.log 2>&1 &
```

### 4. **Запуск с приоритетом**
```bash
nohup nice -n 10 long_task.sh &
```

## 🔍 Как проверить, что работает?

```bash
# Посмотреть процессы
ps aux | grep <имя_процесса>

# Посмотреть вывод
tail -f nohup.out

# Посмотреть открытые файлы процесса
lsof -p <PID>
```

---

## 🛑 Как остановить процесс?

```bash
# Найти PID
ps aux | grep <команда>

# Корректно остановить
kill <PID>

# Если не реагирует
kill -9 <PID>

# Или по имени
pkill -f <имя_процесса>
```

---

## ⚠️ Важные замечания

| Особенность | Пояснение |
|-------------|-----------|
| **Не демонызирует** | Процесс всё ещё привязан к сессии (для настоящих демонов используйте `systemd` или `supervisord`) |
| **Нет авто-рестарта** | Если процесс упадёт — не перезапустится (нужен `systemd` или `monit`) |
| **Переменные окружения** | Наследуются из текущей сессии |
| **Рабочая директория** | Остаётся той, из которой запустили |

---

## 🔄 nohup vs альтернативы

| Инструмент | Когда использовать |
|------------|-------------------|
| **`nohup`** | Быстрый запуск в фоне, простые задачи |
| **`screen` / `tmux`** | Интерактивная работа, можно вернуться в сессию |
| **`systemd`** | Production, авто-старт, логи, рестарт |
| **`supervisord`** | Управление несколькими процессами |
| **`disown`** | Если процесс уже запущен (после `Ctrl+Z` → `bg` → `disown`) |

## 🧩 Пример: типичный сценарий

```bash
# 1. Запускаем долгую задачу
nohup python3 process_data.py > process.log 2>&1 &

# 2. Видим PID
[1] 12345

# 3. Закрываем терминал → процесс продолжает работать

# 4. Позже проверяем прогресс
tail -f process.log

# 5. Когда закончит — проверяем статус
ps -p 12345  # Если нет вывода → процесс завершён
```

## 📌 Памятка

```
🚀 nohup cmd & 
   ↓
✅ Игнорирует закрытие терминала
✅ Пишет вывод в nohup.out (если не указано иное)
✅ Работает в фоне
❌ Не рестартует при падении
❌ Не заменяет systemd для продакшена
```

---

## 💡 Протип

> **Для разработки и ад-хок задач:** `nohup` — отлично.  
> **Для продакшена:** используйте `systemd`, `supervisord` или оркестраторы (Kubernetes).
