## Ansible: для чего нужен и основы использования


### Что такое Ansible

**Ansible** — это open‑source инструмент для автоматизации IT‑процессов: управления конфигурациями, развёртывания приложений, оркестрации задач на множестве серверов.


**Ключевые особенности:**
* **Безагентность**: не требует установки ПО на управляемые узлы (использует SSH для Linux/Unix, WinRM для Windows).
* **Декларативный подход**: вы описываете *желаемое состояние* системы, а не пошаговые действия.
* **Идемпотентность**: повторные запуски не меняют состояние, если цель уже достигнута.
* **Простота**: использует YAML для описания задач, Python для внутренней логики.
* **Масштабируемость**: управляет сотнями и тысячами серверов.


### Для чего используют Ansible

1. **Управление конфигурациями**  
   * настройка ОС и ПО на серверах;
   * управление пользователями и правами;
   * установка и обновление пакетов.

2. **Развёртывание приложений**  
   * автоматизация деплоя веб‑приложений, баз данных;
   * синхронизация файлов между серверами.

3. **Оркестрация**  
   * координация сложных workflows (например, обновление кластера);
   * последовательное выполнение задач на группах серверов.

4. **Работа с облаками**  
   * создание и управление ресурсами в AWS, Azure, GCP;
   * автоматизация инфраструктуры как кода (IaC).

5. **Мониторинг и безопасность**  
   * настройка систем логирования;
   * развёртывание политик безопасности;
   * аудит конфигураций.


### Основные компоненты Ansible

1. **Inventory (инвентарь)**  
   * файл (по умолчанию: `/etc/ansible/hosts`), содержащий список управляемых узлов;
   * группировка серверов по ролям (например, `[webservers]`, `[databases]`).


2. **Playbooks (плейбуки)**  
   * YAML‑файлы, описывающие задачи и процессы;
   * состоят из *plays* (секций для групп хостов) и *tasks* (задач).


3. **Modules (модули)**  
   * готовые «кирпичики» для выполнения действий (установка пакетов, копирование файлов и т. д.);
   * более 750 встроенных модулей (например, `apt`, `service`, `copy`).


4. **Roles (роли)**  
   * переиспользуемые наборы задач, переменных, шаблонов;
   * упрощают структурирование сложных конфигураций.


5. **Handlers (обработчики)**  
   * задачи, выполняемые *только при изменении* (например, перезапуск сервиса после правки конфига).


### Основы использования: пошаговый пример


#### 1. Установка Ansible
```bash
# Для Ubuntu/Debian
sudo apt update
sudo apt install ansible


# Для CentOS/RHEL
sudo yum install epel-release
sudo yum install ansible
```

#### 2. Настройка Inventory
Создайте файл `inventory.ini`:
```ini
[webservers]
web1.example.com
web2.example.com


[databases]
db1.example.com
```

#### 3. Создание Playbook
Создайте файл `deploy_apache.yml`:
```yaml
---
- name: Deploy Apache
  hosts: webservers
  become: true  # Запуск с привилегиями sudo


  tasks:
    - name: Install Apache
      apt:
        name: apache2
        state: present

    - name: Start Apache service
      service:
        name: apache2
        state: started
        enabled: yes


    - name: Copy index.html
      copy:
        src: ./index.html
        dest: /var/www/html/index.html
```

#### 4. Запуск Playbook
```bash
ansible-playbook -i inventory.ini deploy_apache.yml
```
### Ключевые команды
* `ansible-inventory --list` — просмотреть инвентарь;
* `ansible all -m ping` — проверить подключение к хостам;
* `ansible-playbook playbook.yml` — запустить плейбук.
### Преимущества Ansible
* **Простота освоения**: YAML и Python интуитивно понятны.
* **Отсутствие агентов**: не нужно устанавливать ПО на целевые серверы.
* **Широкая поддержка**: работает с Linux, Windows, облаками, сетевым оборудованием.
* **Активное сообщество**: множество готовых ролей и модулей на Ansible Galaxy.
* **Интеграция**: совместим с CI/CD (Jenkins, GitLab CI), облачными API.
### Ограничения
* **Слабая поддержка Windows** (по сравнению с Linux);
* **Нет GUI по умолчанию** (есть коммерческий Ansible Tower/AWX);
* **Требует базовых знаний** Linux/Windows, YAML, SSH.
### Когда стоит использовать Ansible
* Нужно управлять множеством серверов.
* Требуется автоматизировать рутинные задачи (деплой, обновления).
* Необходимо обеспечить единообразие конфигураций.
* Планируется работа с облачной инфраструктурой.
* Важно минимизировать ошибки из‑за ручного вмешательства.
