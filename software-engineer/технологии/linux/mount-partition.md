Разберу пошагово, как настроить автоматическое монтирование раздела NTFS в Arch Linux после перезагрузки — с разными вариантами реализации.

## Способ 1. Через `/etc/fstab` (рекомендуемый)

**Шаг 1. Определите UUID раздела**

```bash
lsblk -f
```
Или более детально:
```bash
sudo blkid | grep sda1
```
Запомните UUID вашего раздела (например, `UUID="1234-ABCD"`).

**Шаг 2. Создайте точку монтирования**

```bash
sudo mkdir -p /mnt/sd
```

**Шаг 3. Отредактируйте `/etc/fstab`**

Откройте файл:
```bash
sudo nano /etc/fstab
```
Добавьте строку (подставьте ваш UUID):
```
UUID=1234-ABCD  /mnt/sd  ntfs-3g  defaults,uid=1000,gid=1000,umask=0022  0  0
```
**Пояснения к параметрам:**
* `UUID=...` — уникальный идентификатор раздела (надёжнее, чем `/dev/sda1`);
* `/mnt/sd` — точка монтирования;
* `ntfs-3g` — драйвер для NTFS;
* `defaults` — стандартные опции монтирования;
* `uid=1000,gid=1000` — владелец и группа (обычно ваш пользователь);
* `umask=0022` — права доступа (755: чтение/запись для владельца, чтение для остальных);
* последние `0 0` — отключение dump и fsck для NTFS.

**Шаг 4. Проверьте конфигурацию**

Протестируйте монтирование без перезагрузки:
```bash
sudo mount -a
```
Проверьте, что раздел смонтирован:
```bash
df -h | grep /mnt/sd
```

## Способ 2. Через systemd‑юнит (альтернативный)

**Шаг 1. Создайте файл юнита**

```bash
sudo nano /etc/systemd/system/mount-sd.service
```
Вставьте содержимое:
```ini
[Unit]
Description=Mount NTFS partition /dev/sda1
After=network.target

[Service]
Type=oneshot
ExecStart=/bin/mount -t ntfs-3g /dev/sda1 /mnt/sd -o uid=1000,gid=1000,umask=0022
RemainAfterExit=yes

[Install]
WantedBy=multi-user.target
```

**Шаг 2. Активируйте юнит**

```bash
sudo systemctl daemon-reload
sudo systemctl enable mount-sd.service
sudo systemctl start mount-sd.service
```

**Шаг 3. Проверьте статус**

```bash
sudo systemctl status mount-sd.service
df -h | grep /mnt/sd
```

## Способ 3. Через скрипт в автозагрузке (простой, но менее надёжный)

**Шаг 1. Создайте скрипт**

```bash
nano ~/mount_ntfs.sh
```
Содержимое:
```bash
#!/bin/bash
sudo mount -t ntfs-3g /dev/sda1 /mnt/sd -o uid=1000,gid=1000,umask=0022
```
Сделайте исполняемым:
```bash
chmod +x ~/mount_ntfs.sh
```

**Шаг 2. Добавьте в автозагрузку GNOME**

1. Откройте **«Настройки»** → **«Приложения»** → **«Автозагрузка»**.
2. Нажмите **«Добавить»**.
3. Заполните:
   * **Имя:** `Mount NTFS`;
   * **Команда:** `/home/ваше_имя/mount_ntfs.sh`;
   * **Комментарий:** `Автоматическое монтирование NTFS‑раздела`.
4. Нажмите **«Добавить»**.

## Важные замечания и устранение неполадок

**Перед настройкой убедитесь, что:**
* Установлен драйвер `ntfs-3g`:
  ```bash
  sudo pacman -S ntfs-3g
  ```
* Раздел `/dev/sda1` существует и содержит NTFS:
  ```bash
  lsblk -f | grep sda1
  ```
* Точка монтирования `/mnt/sd` существует:
  ```bash
  ls -la /mnt/
  ```

**Устранение неполадок:**

* **Ошибка «UUID not found» в `fstab`**:
  * Проверьте UUID командой `blkid`.
  * Убедитесь, что раздел подключён и распознаётся системой.
* **Раздел не монтируется при загрузке**:
  * Проверьте логи: `journalctl -b -u mount-sd.service` (для юнита) или `dmesg | grep ntfs`.
  * Убедитесь, что `ntfs-3g` установлен.
* **Нет прав на запись**:
  * В `fstab` или юните проверьте параметры `uid`, `gid` и `umask`.
  * Замените `uid=1000` на ваш реальный UID (узнать: `id -u`).
* **Конфликт с другим монтированием**:
  * Удалите ручное монтирование: `sudo umount /mnt/sd`.
  * Перепроверьте `fstab` на дублирующие записи.

## Краткий итог: какой способ выбрать

| Способ | Плюсы | Минусы |
|------|------|-------|
| `/etc/fstab` | Надёжный, стандартный, быстрый | Требует знания UUID, ошибки могут помешать загрузке |
| systemd‑юнит | Гибкий, логирование, контроль через `systemctl` | Больше шагов настройки |
| Скрипт в автозагрузке | Простой, понятный | Зависит от GUI, может запуститься поздно |

**Рекомендация:** используйте **Способ 1 (`/etc/fstab`)** — это канонический способ в Linux. Он работает до запуска GUI, обеспечивает быстрое монтирование и легко администрируется.
