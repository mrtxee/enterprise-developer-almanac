## управление пакетами в Arch Linux

В Arch Linux управление пакетами осуществляется через менеджер **`pacman`**. В отличие от дистрибутивов с графическими магазинами приложений, здесь всё делается через терминал. Ниже я разбил процесс на три этапа: от просмотра до полной очистки системы.

### 1️⃣ Просмотр установленных пакетов

Прежде чем удалять, нужно понять, что у вас стоит. Вот ключевые команды `pacman` для навигации:

| Задача | Команда | Что покажет |
| :--- | :--- | :--- |
| **Список всех пакетов** | `pacman -Q` | Простой список всех установленных пакетов. |
| **Только явно установленные** | `pacman -Qe` | Пакеты, которые вы установили сами (обычно это программы и игры). |
| **Пакеты из AUR ('чужие')** | `pacman -Qm` | Пакеты, установленные не из официальных репозиториев (вручную или через `yay`). |
| **Поиск конкретного пакета** | `pacman -Qs <имя>` | Находит установленный пакет по ключевому слову (например, `pacman -Qs firefox`).  |
| **Узнать размер пакета** | `LC_ALL=C pacman -Qi \| awk '/^Name/{name=$3} /^Installed Size/{print $4$5, name}' \| sort -h` | Сортирует все программы по размеру (самые большие внизу), чтобы понять, что «съедает» место.  |

**Совет:** Зеленые пакеты — часто не отдельные программы, а библиотеки, которые нужны другим приложениям. Удаляя их, вы можете сломать систему, поэтому действуйте аккуратно.

### 2️⃣ Удаление ненужного

```bash
# найти пакет по описанию
pacman -Qs video
# удалить пакет по имени
sudo pacman -Rsn showtime
```

Когда нашли пакет для удаления, используйте `pacman -R` с разными флагами для разного результата.

| Ситуация | Команда | Эффект |
| :--- | :--- | :--- |
| **Базовая** | `sudo pacman -R <имя>` | Удалит только сам пакет. Если у пакета есть зависимости, которые не нужны другим программам, они останутся (станут «сиротами»). |
| **Правильная (полная)** | `sudo pacman -Rs <имя>` | **Лучший вариант для обычного удаления.** Удалит пакет и все его зависимости, которые не нужны другим программам.  |
| **Радикальная** | `sudo pacman -Rns <имя>` | То же, что выше, но еще удаляет глобальные конфиги (файлы `.pacsave`). Используйте, если хотите полностью стереть следы программы.  |
| **С каскадом** | `sudo pacman -Rc <имя>` | **Осторожно!** Удалит пакет и **ВСЕ**, что от него зависит. Может снести половину системы, если удалить важную библиотеку.  |

**Пример:** Чтобы удалить игру `supertuxkart` и связанные с ней библиотеки, которые не нужны другим программам, просто напишите:
```bash
sudo pacman -Rs supertuxkart
```

### 3️⃣ Генеральная уборка (чистка системы)

После удаления программ в системе часто остается технический «мусор», который мешает, только если у вас мало места на диске.

#### А. Удаление «сирот» (неиспользуемых зависимостей)
Это пакеты, которые когда-то поставились как часть другой программы, но потом эта программа была удалена, а «хвосты» остались.
```bash
# Сначала посмотрим, кто есть в сиротах
pacman -Qdt

# Удаляем их всех разом (если список не пуст)
sudo pacman -Rns $(pacman -Qdtq)
```


#### Б. Очистка кэша Pacman
Arch хранит все скачанные версии пакетов в папке `/var/cache/pacman/pkg/`. Если вы давно не чистили, там могут лежать гигабайты старых версий.
*   `sudo pacman -Sc` : Удалит только устаревшие версии (оставит последнюю).
*   `sudo pacman -Scc` : **Кардинально**. Удалит **ВСЕ** скачанные файлы. Если отключите интернет, вы не сможете переустановить пакет из кэша. 

#### В. Очистка AUR-хелперов (yay, paru)
Если вы ставите программы из AUR (например, через `yay`), хелперы тоже скапливают кэш сборки в домашней папке.
```bash
# Для yay
yay -Scc

# Для paru
paru -Scc
```


### Итоговая памятка (Что делать раз в месяц)

1.  **Удалить ненужное:** `sudo pacman -Rs <программа>`
2.  **Вычистить сирот:** `sudo pacman -Rns $(pacman -Qdtq)`
3.  **Почистить кэш:** `sudo pacman -Sc`

Эти три шага поддерживают систему в тонусе без переустановки. Если не уверены, нужен ли пакет, просто не удаляйте его.

Разберу команду `sudo pacman -S --needed base-devel git` по частям:

**1. `sudo`**

Запускает команду с правами суперпользователя (администратора). Это нужно, потому что установка пакетов требует доступа к системным файлам, который ограничен для обычных пользователей.

**2. `pacman`**

Основной менеджер пакетов в Arch Linux и дистрибутивах на его основе (Manjaro, EndeavourOS и т. д.). Отвечает за:
* установку, удаление и обновление пакетов;
* синхронизацию с репозиториями;
* разрешение зависимостей.

**3. `-S`** (или `--sync`)

Флаг, который указывает `pacman` найти и установить пакеты из репозиториев. По сути, это команда «установить».

**4. `--needed`**

Опция, которая заставляет `pacman` **не переустанавливать** пакеты, если они уже установлены в последней версии. Это полезно:
* чтобы сэкономить время и трафик;
* при повторном запуске скриптов настройки системы.

Без этой опции `pacman` попытается переустановить пакеты, даже если они уже есть.

**5. `base-devel`**

Группа пакетов, содержащая базовые инструменты для сборки программного обеспечения из исходного кода. В неё входят:
* компиляторы (например, `gcc` для C/C++);
* утилиты сборки (`make`, `autotools`, `cmake`);
* другие инструменты, необходимые для работы `makepkg` (утилиты для создания пакетов Arch Linux).

Эта группа **обязательна** для ручной установки пакетов из AUR (Arch User Repository) или сборки собственных пакетов.

**6. `git`**

Пакет с распределённой системой контроля версий Git. Он нужен для:
* клонирования репозиториев (в т. ч. из AUR, где пакеты хранятся как Git‑репозитории);
* отслеживания изменений в коде;
* работы с удалёнными репозиториями (например, GitHub, GitLab).

---

**Что делает вся команда целиком?**

Команда `sudo pacman -S --needed base-devel git` **устанавливает (или проверяет актуальность установки) набора инструментов для сборки ПО (`base-devel`) и системы контроля версий Git (`git`)** с правами администратора, не переустанавливая их, если они уже стоят в последней версии.

**Когда это нужно?**

Чаще всего эту команду выполняют **перед работой с AUR** (Arch User Repository). AUR — это пользовательский репозиторий, где хранятся пакеты, отсутствующие в официальных источниках. Чтобы установить пакет из AUR:
1. Нужно скачать его исходный код (обычно через `git clone`).
2. Собрать пакет с помощью `makepkg`.
3. Установить полученный пакет с помощью `pacman`.

Для шагов 1 и 2 как раз и нужны `git` и пакеты из `base-devel`.

**Пример последующего действия:**

После выполнения этой команды можно, например, установить популярный AUR‑помощник `yay`:
```bash
git clone https://aur.archlinux.org/yay.git
cd yay
makepkg -si
```
