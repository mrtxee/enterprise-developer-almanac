`dconf` — это низкоуровневая система для хранения настроек в GNOME и других приложениях на основе GTK. Её часто сравнивают с реестром Windows.

Это хранилище построено по принципу "ключ-значение" и организовано в иерархическую структуру, похожую на файловую систему. Оно пришло на смену устаревшей системе GConf и в настоящее время является основным бэкендом для большинства настроек окружения рабочего стола. На практике, когда вы меняете какую-либо настройку в GNOME, например, тему оформления или шрифт, это изменение сохраняется именно в базе данных `dconf`.

Важно понимать, что `dconf` — это не единый инструмент, а целая экосистема, состоящая из нескольких слоёв:

- **`dconf` (нижний уровень)**: Это серверная часть, которая работает в фоне через D-Bus (система для общения между приложениями) и непосредственно взаимодействует с файлом базы данных, обеспечивая быстрый доступ и синхронизацию настроек.
- **`GSettings` (высокоуровневый API)**: Это API (интерфейс для программирования), который разработчики используют в своём коде для чтения и записи настроек в `dconf`. Для работы с терминалом существует утилита `gsettings`, которая предоставляет удобные команды для просмотра и изменения параметров.
- **`dconf-editor` (графический интерфейс)**: Это графическая программа для наглядного просмотра и редактирования всей базы настроек.

### 💻 Управление настройками: от GUI до консоли

Существует два основных способа взаимодействия с `dconf`: через графический интерфейс или через командную строку. Последний способ особенно удобен для резервного копирования настроек и их быстрого восстановления.

`dconf-editor` позволяет визуально исследовать и изменять настройки. Если вы хотите более тонкого контроля, вы можете использовать командную строку. Ключевые команды для работы с `dconf` и `gsettings` сведены в таблицу:

| Инструмент | Действие | Команда |
| :--- | :--- | :--- |
| **`gsettings`** | Список всех схем и их описаний | `gsettings list-schemas` |
| **`gsettings`** | Получить значение ключа | `gsettings get SCHEMA KEY` |
| **`gsettings`** | Установить значение ключа | `gsettings set SCHEMA KEY VALUE` |
| **`dconf`** | Полный дамп всех настроек (для бэкапа) | `dconf dump / > backup.txt` |
| **`dconf`** | Восстановить настройки из бэкапа | `dconf load / < backup.txt` |
| **`dconf`** | Отслеживать изменения в реальном времени | `dconf watch /` |

Если после экспериментов с настройками что-то пошло не так, вы всегда можете вернуть систему к стандартному виду. Самый простой способ сбросить все настройки пользователя — удалить файл базы данных `~/.config/dconf/user` и перезагрузить сессию.

В более сложных случаях, например, в корпоративной среде, администраторы могут использовать `dconf` для централизованного управления настройками, создавая системные профили и блокируя определённые параметры для пользователей в файлах `/etc/dconf/db/`.

Если вы активно настраиваете свою систему, `dconf` и `gsettings` — это тот инструментарий, с которым вам точно стоит познакомиться поближе.

# 🔧 dconf — система конфигурации GNOME

## 🏗️ Архитектура: как это работает

```
Приложение (например, GNOME Shell)
       ↓
GSettings API (высокоуровневый интерфейс)
       ↓
dconf (бэкенд: бинарная база данных)
       ↓
Файл: ~/.config/dconf/user
```

### 🔑 Ключевые компоненты

| Компонент                  | Назначение                                                                          |
| -------------------------- | ----------------------------------------------------------------------------------- |
| **GSettings**              | API для приложений: чтение/запись настроек с валидацией типов                       |
| **dconf**                  | Бэкенд: хранит данные в бинарном виде, поддерживает слежение за изменениями         |
| **Схемы (`.gschema.xml`)** | Описывают доступные ключи, типы, значения по умолчанию (устанавливаются с пакетами) |
| **`~/.config/dconf/user`** | Файл базы данных пользователя (не редактировать вручную!)                           |

## 🗂️ Структура настроек

Настройки организованы в иерархию, похожую на пути файловой системы:

```
/
├── org/
│   ├── gnome/
│   │   ├── desktop/
│   │   │   ├── background/
│   │   │   │   └── picture-uri
│   │   │   ├── interface/
│   │   │   │   └── clock-format
│   │   │   └── wm/
│   │   │       └── preferences/
│   │   ├── shell/
│   │   │   └── favorite-apps
│   │   └── settings-daemon/
│   │       └── plugins/
│   │           └── power/
│   └── nautilus/
│       └── preferences/
└── org/
    └── gtk/
        └── settings/
            └── file-chooser/
```

### 📋 Формат ключа
```
<схема>/<путь>/<ключ>
```
**Примеры:**
- `org.gnome.desktop.interface clock-format`
- `org.gnome.shell favorite-apps`
- `org.gnome.nautilus.preferences default-folder-viewer`

## 💡 Практические примеры

### 🎨 Темизация интерфейса
```bash
# Тёмная тема для всех приложений GTK
gsettings set org.gnome.desktop.interface gtk-theme 'Adwaita-dark'

# Тёмная тема для GNOME Shell
gsettings set org.gnome.shell.extensions.user-theme name 'Adwaita-dark'

# Автоматическое переключение темы по времени суток
gsettings set org.gnome.desktop.interface color-scheme 'prefer-dark'
```

### ⌨️ Настройка клавиатуры и ввода
```bash
# Скорость повтора клавиш
gsettings set org.gnome.desktop.peripherals.keyboard repeat-interval 30
gsettings set org.gnome.desktop.peripherals.keyboard delay 300

# Раскладка по умолчанию
gsettings set org.gnome.desktop.input-sources sources "[('xkb', 'us'), ('xkb', 'ru')]"

# Переключение раскладки: Win+Space
gsettings set org.gnome.desktop.wm.keybindings switch-input-source "['<Super>space']"
```

### 🖥️ Рабочий стол и окна
```bash
# Показать значки на рабочем столе
gsettings set org.gnome.nautilus.desktop show-desktop-icons true

# Автоскрытие панели (Dock)
gsettings set org.gnome.shell.extensions.dash-to-dock autohide true

# Горячие углы: отключить
gsettings set org.gnome.desktop.interface enable-hot-corners false
```

### 🔐 Безопасность и приватность
```bash
# Отключить сбор телеметрии в GNOME Software
gsettings set org.gnome.software allow-updates false

# Не сохранять историю поиска в Nautilus
gsettings set org.gnome.nautilus.preferences default-search-in-background true
```

## 💾 Резервное копирование и восстановление

### 📦 Бэкап всех настроек
```bash
# Дамп всей базы (текстовый формат)
dconf dump / > ~/dconf-backup-$(date +%F).ini

# Или только ветку (например, GNOME Shell)
dconf dump /org/gnome/shell/ > ~/shell-backup.ini
```

### 📦 Экспорт и импорт всех измененных вами gsettings

Чтобы скопировать вообще все ваши ручные правки (темы, поведение мыши, фон и т.д.), используется `dconf dump /`.
```bash
# Шаг 1: Полный экспорт
dconf dump / > all_my_gnome_settings_backup

# Шаг 2: Полный импорт
dconf load / < all_my_gnome_settings_backup
```
**Важно:** Эта команда сбросит **все** текущие настройки и применит те, что сохранены в файле. На новой системе это может быть как плюсом, так и минусом — вы получите точную копию настроек, но все предыдущие изменения на целевой машине будут потеряны.


### ♻️ Восстановление
```bash
# Полное восстановление (осторожно: перезапишет текущие настройки!)
dconf load / < ~/dconf-backup-2024-01-15.ini

# Восстановление только одной ветки
dconf load /org/gnome/shell/ < ~/shell-backup.ini
```

### 🔄 Миграция на другой ПК
```bash
# На старом ПК: экспорт
dconf dump /org/gnome/ > gnome-settings.ini

# На новом ПК: импорт
dconf load /org/gnome/ < gnome-settings.ini

# Перезапустить GNOME Shell для применения (Wayland)
gnome-shell --replace & disown
```

## ⚠️ Важные предупреждения

| Риск                                        | Как избежать                                                                                                                        |
| ------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| **Некорректный тип значения**               | Всегда проверяйте тип через `gsettings describe <ключ>`. Строки требуют `"'текст'"`, массивы — `"['эл1', 'эл2']"`                   |
| **Повреждение базы `~/.config/dconf/user`** | Никогда не редактируйте файл вручную. Используйте `gsettings` или `dconf-editor`                                                    |
| **Настройки не применяются**                | Некоторые приложения требуют перезапуска. GNOME Shell — `Alt+F2` → `r` (X11) или `gnome-shell --replace` (Wayland)                  |
| **Конфликт с Flatpak**                      | Flatpak-приложения используют изолированный dconf: `~/.var/app/<id>/config/dconf/user`. Настройки системного dconf на них не влияют |

## 🔍 Диагностика и отладка

```bash
# Следить за изменениями настроек в реальном времени
dconf watch /

# Следить за конкретной веткой
dconf watch /org/gnome/shell/

# Проверить, существует ли ключ
gsettings get org.gnome.desktop.interface clock-format 2>&1 | grep -q "no such key" && echo "не найден" || echo "найден"

# Найти, где определена схема
pkgfile -b org.gnome.desktop.interface  # требует pacman-contrib
```

## 🧩 dconf vs GSettings: в чём разница?

| Аспект | `dconf` | `GSettings` |
|--------|---------|-------------|
| Уровень | Низкоуровневый бэкенд | Высокоуровневый API |
| Формат путей | `/org/gnome/...` (начинается с `/`) | `org.gnome...` (без начального `/`) |
| Формат значений | GVariant (требует точного синтаксиса) | Автоматическое преобразование типов |
| Валидация | Нет (можно записать некорректное значение) | Есть (проверяет тип и диапазон) |
| Рекомендация | Только для скриптов/бэкапов | Для повседневного использования |

> ✅ **Правило**: используйте `gsettings` для настройки, `dconf` — только для бэкапов или когда `gsettings` не справляется.

## 💡 Совет для разработчиков

Если вы пишете приложение на GTK/GNOME:
1. Описывайте настройки в `.gschema.xml`
2. Используйте `GSettings` API для доступа — это обеспечит:
   - Автоматическую валидацию
   - Интеграцию с dconf-editor
   - Возможность бэкапа через `dconf dump`
   - Слежение за изменениями (`GSettings::changed`)

Пример схемы: [GNOME GSettings Schema Guide](https://developer.gnome.org/gio/stable/gsettings-schema-guide.html)

Отличный вопрос! На самом деле файл `~/.config/dconf/user` **действительно бинарный**, но при просмотре текстовым редактором или через `cat` вы можете видеть в нём читаемые фрагменты. Это создаёт иллюзию текстового формата.

Разберём, почему так происходит и как устроен этот файл на самом деле.

# 🗃️ `~/.config/dconf/user`
> ~/.config/dconf/user
## 🏗️ Структура файла `~/.config/dconf/user`

```
┌─────────────────────────────┐
│ Заголовок (16 байт)         │
│ - Сигнатура, версия, флаги  │
├─────────────────────────────┤
│ Таблица смещений (offsets)  │
│ - Указатели на каждый ключ  │
├─────────────────────────────┤
│ Данные (GVariant-сериализ.) │
│ ├─ Строки: читаемый UTF-8   │
│ ├─ Числа: 4/8 байт бинарно  │
│ ├─ Булевы: 1 байт (0/1)     │
│ ├─ Массивы: длина + данные  │
│ └─ Варианты: тип + значение │
├─────────────────────────────┤
│ Индекс для быстрого поиска  │
└─────────────────────────────┘
```

> 💡 Именно поэтому файл нельзя редактировать в текстовом редакторе: сдвиг на 1 байт сломает все смещения, и dconf перестанет читать настройки.

---

## 🛠️ Как правильно просматривать и редактировать

| Задача                         | Инструмент       | Пример                                                |
| ------------------------------ | ---------------- | ----------------------------------------------------- |
| **Просмотр значения**          | `gsettings`      | `gsettings get org.gnome.desktop.interface gtk-theme` |
| **Просмотр в GUI**             | `dconf-editor`   | `dconf-editor` → навигация по дереву                  |
| **Экспорт настроек**           | `dconf dump`     | `dconf dump /org/gnome/desktop/interface/`            |
| **Импорт настроек**            | `dconf load`     | `dconf load / < backup.ini`                           |
| **Отладка в реальном времени** | `dconf watch`    | `dconf watch /org/gnome/shell/`                       |
| **Просмотр сырых данных**      | `xxd`, `hexdump` | `xxd ~/.config/dconf/user \| head`                    |

### Пример корректного экспорта (текстовый формат!)
```bash
$ dconf dump /org/gnome/desktop/interface/
[org/gnome/desktop/interface]
gtk-theme='Adwaita-dark'
clock-format='12h'
show-battery-percentage=true
```
→ Это **текстовое представление**, которое человек может читать и редактировать. Но оно **не равно** содержимому `~/.config/dconf/user`.

---

## ⚠️ Почему нельзя редактировать `~/.config/dconf/user` вручную

1. **Контрольные суммы**: файл содержит внутренние хеши для проверки целостности.
2. **Смещения (offsets)**: каждая запись ссылается на другие по байтовым позициям.
3. **Выравнивание (alignment)**: данные выровнены по 8 байт для быстрого доступа.
4. **Блокировка**: dconf держит файл открытым с `flock`, изменения «на лету» могут быть проигнорированы.

**Результат правки в редакторе**: dconf обнаружит повреждение, проигнорирует файл и создаст новый с настройками по умолчанию → вы потеряете все настройки.

## 💡 Аналогия для понимания

Представьте, что `~/.config/dconf/user` — это **база данных SQLite**:
- Вы можете открыть её в текстовом редакторе и увидеть фрагменты строк
- Но структура, индексы, типы данных — бинарные
- Правка «на глаз» сломает файл
- Правильный способ: использовать `sqlite3` CLI или приложение

Так и с dconf: используйте `gsettings`/`dconf-editor` как «клиент», а не редактируйте файл напрямую.

