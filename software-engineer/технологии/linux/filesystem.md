### Полный список файловых систем, встречающихся в Linux


Файловые системы можно разделить на несколько категорий.

#### 1. Основные (локальные) файловые системы

* **Ext (Extended File System)** — первая файловая система, разработанная специально для Linux.
	* **Ext2 (Second Extended File System)** — долгое время была файловой системой по умолчанию во многих дистрибутивах Linux. Не имеет журналирования.
	* **Ext3 (Third Extended File System)** — улучшенная версия Ext2 с поддержкой журналирования для защиты от повреждений при сбоях.
	* **Ext4 (Fourth Extended File System)** — современная версия, стандарт для большинства дистрибутивов Linux. Поддерживает файлы и файловые системы до 16 ТБ и 1 ЭБ соответственно. Обратно совместима с Ext2/Ext3.
* **XFS** — высокопроизводительная и масштабируемая файловая система от SGI. Отлично подходит для работы с большими файлами и наборами данных (поддерживает до 8 ЭБ файлов и 16 ЭБ ФС).
* **JFS (Journaled File System)** — создана IBM, отличается высокой надёжностью и эффективным использованием ресурсов.
* **Btrfs (B‑Tree File System)** — файловая система нового поколения с функциями управления устройствами, снапшотами, проверкой и восстановлением данных на лету, сжатием.
* **ReiserFS / Reiser4** — оптимизирована для работы с небольшими файлами, поддерживает журналирование. Reiser4 — более современная версия с шифрованием и улучшенной производительностью.
* **F2FS (Flash‑Friendly File System)** — разработана Samsung для флеш‑накопителей (SSD, SD‑карты, USB‑флешки). Оптимизирует износ и производительность.
* **ZFS (Zettabyte File System)** — изначально создана для Solaris, доступна в Linux через OpenZFS. Обладает продвинутым управлением хранилищем, снапшотами, клонированием, шифрованием. Требует много ОЗУ (рекомендуется от 8 ГБ).

#### 2. Виртуальные и псевдофайловые системы (специальные)

Эти ФС не хранят данные на диске, а предоставляют доступ к информации ядра или сервисам:

* **proc (/proc)** — отображает информацию о процессах и состоянии ядра в виде файлов и каталогов.
* **sysfs (/sys)** — предоставляет интерфейс для доступа к информации об устройствах и драйверах.
* **tmpfs** — хранит данные в оперативной памяти (RAM). Используется для `/tmp`, `/run`, `/var/run` и т. д. При перезагрузке данные теряются.
* **devtmpfs** — автоматически создаёт файлы устройств в `/dev` ещё до запуска `udev`.
* **debugfs** — предоставляет доступ к отладочной информации ядра.
* **securityfs** — используется модулями безопасности ядра (например, SELinux).
* **cgroup / cgroup2** — управляет группами контроля (cgroups) для изоляции и учёта ресурсов процессов.
* **hugetlbfs** — работает с огромными страницами памяти (huge pages).
* **pipefs** — внутренняя ФС для организации каналов (pipe) между процессами.

#### 3. Сетевые файловые системы

Позволяют монтировать удалённые ресурсы как локальные:


* **NFS (Network File System)** — стандартная сетевая ФС в Unix‑подобных системах. Позволяет монтировать каталоги с других компьютеров по сети.
* **CIFS / SMB** — используется для доступа к ресурсам Windows‑серверов и Samba.
* **SSHFS** — монтирование каталогов через SSH (использует FUSE).
* **GlusterFS** — распределённая сетевая файловая система для кластеров.
* **Lustre** — высокопроизводительная распределённая ФС, часто используется в суперкомпьютерах.

#### 4. Файловые системы на основе FUSE (в пространстве пользователя)

Работают через модуль FUSE, не требуют изменений в ядре:

* **EncFS** — шифрующая файловая система. Прозрачно шифрует файлы перед записью на диск.
* **Aufs (Another Union File System)** — объединяет содержимое нескольких каталогов в один виртуальный. Используется в Live CD и Docker.
* **OverlayFS** — похожа на Aufs, используется в контейнерах (Docker, LXC) и Live‑системах.
* **MFS (Memory File System)** — хранит данные в памяти, аналог tmpfs.
* **FUSE** — сам по себе не является ФС, а предоставляет интерфейс для создания пользовательских файловых систем.

#### 5. Специализированные и вспомогательные файловые системы

* **SquashFS** — сжатая файловая система только для чтения. Используется в Live‑дистрибутивах и встроенных системах.
* **ISO9660 / UDF** — файловые системы для оптических дисков (CD/DVD/Blu‑ray).
* **VFAT / FAT32 / exFAT** — поддержка файловых систем Windows. VFAT добавляет поддержку длинных имён к FAT.
* **NTFS** — файловая система Windows. В Linux поддерживается через драйверы ntfs‑3g (FUSE) или встроенный драйвер ядра.
* **Swap** — не является файловой системой в классическом понимании. Используется как виртуальная память (файл или раздел подкачки).
* **Pstore** — сохраняет логи ядра при аварийном завершении работы.
* **Autofs** — автоматически монтирует и размонтирует файловые системы по требованию.

### Как посмотреть доступные файловые системы в вашей системе


Чтобы увидеть список всех поддерживаемых файловых систем в текущем ядре, выполните:
```bash
cat /proc/filesystems
```

В выводе:
* строки с пометкой `nodev` — виртуальные или специальные файловые системы (не требуют блочного устройства);
* строки без `nodev` — обычные файловые системы, монтируемые на диски или разделы.


Если хотите, могу подробнее рассказать про какую‑то конкретную файловую систему или помочь с выбором ФС под ваши задачи!
