Разберу разницу между **Display Manager** (дисплейным менеджером) и **Greeter** (гретером) — это тесно связанные, но разные компоненты системы.


## Display Manager (дисплейный менеджер)

**Display Manager ([[Display Manager|DM]])** — системная служба (демон), которая управляет графическим входом в систему и жизненным циклом пользовательских сессий.


**Основные функции:**
* запускает графический сервер (X11 или Wayland);
* управляет аутентификацией пользователей (проверяет логин и пароль);
* запускает выбранную графическую оболочку (GNOME, KDE Plasma, XFCE и т. д.);
* управляет сессиями (автовход, гостевая сессия, переключение пользователей);
* взаимодействует с greeter, передавая ему данные для отображения;
* обрабатывает системные события (перезагрузка, выключение) из интерфейса greeter.


**Примеры DM:**
* GDM (GNOME Display Manager) — для GNOME;
* SDDM (Simple Desktop Display Manager) — по умолчанию для KDE Plasma;
* LightDM — лёгкий и модульный, подходит для разных окружений;
* LXDM — для LXDE/LXQt;
* XDM — классический менеджер для X Window System.

## Greeter (гретер)

**Greeter** — графический интерфейс дисплейного менеджера: то, что вы видите на экране входа (логин‑экран). Это «лицо» DM.

**Основные функции:**
* отображает экран входа с полями для ввода логина и пароля;
* показывает список пользователей (если настроен);
* позволяет выбирать графическую оболочку перед входом;
* предоставляет опции (гостевая сессия, перезагрузка, выключение);
* отвечает за визуальное оформление (темы, фон, шрифты, анимации);
* передаёт введённую пользователем информацию в DM для обработки.

**Примеры greeter:**
* `lightdm-gtk-greeter` — GTK‑based для LightDM;
* `lightdm-webkit2-greeter` — с поддержкой веб‑технологий;
* встроенный greeter в SDDM (написан на QML);
* `gdm-greeter` — стандартный для GDM.

## Ключевые отличия

| Критерий | Display Manager | Greeter |
|--------|---------------|---------|
| **Тип компонента** | Системная служба (демон) | Графический интерфейс (клиент) |
| **Роль** | Логика работы: аутентификация, запуск сессий, управление | Визуальное представление: оформление экрана входа, взаимодействие с пользователем |
| **Запуск** | Запускается на уровне системы (через systemd) при загрузке | Запускается DM как отдельный процесс для отображения интерфейса |
| **Взаимодействие** | Получает данные от greeter и выполняет действия (вход, выключение и т. д.) | Отправляет введённые данные (логин, пароль) в DM |
| **Замена** | Можно заменить на другой DM (например, GDM → LightDM) | Можно сменить greeter для одного DM (например, `lightdm-gtk-greeter` → `lightdm-webkit2-greeter`) |
| **Зависимость** | Может работать без графического интерфейса (в текстовом режиме) | Не может работать без DM — зависит от него |
| **Конфигурация** | Настраивается через системные файлы (`/etc/lightdm/lightdm.conf`, `/etc/gdm/custom.conf` и т. д.) | Настраивается отдельно (темы, расположение элементов, фон) |

## Как они работают вместе: пример

1. При загрузке система запускает **Display Manager** (например, LightDM).
2. LightDM определяет, какой **Greeter** использовать (например, `lightdm-gtk-greeter`), и запускает его.
3. Greeter отображает экран входа: поля для логина/пароля, список пользователей, кнопку выбора сессии.
4. Пользователь вводит данные и нажимает Enter.
5. Greeter передаёт логин и пароль в LightDM.
6. LightDM проверяет учётные данные, запускает выбранную графическую оболочку и передаёт управление ей.
7. Greeter скрывается, появляется рабочий стол.

---

## Практический пример: настройка LightDM + greeter

1. Установите LightDM:
   ```bash
   sudo pacman -S lightdm
   ```
2. Установите greeter (например, GTK‑версию):
   ```bash
   sudo pacman -S lightdm-gtk-greeter
   ```
3. Настройте LightDM, указав, какой greeter использовать. Отредактируйте `/etc/lightdm/lightdm.conf`:
   ```ini
   [Seat:*]
   greeter-session=lightdm-gtk-greeter
   user-session=gnome  # укажите вашу сессию (gnome, plasma, xfce и т. д.)
   ```
4. Включите автозапуск DM:
   ```bash
   sudo systemctl enable lightdm
   sudo systemctl start lightdm
   ```

## Краткий итог

* **Display Manager** — «мозг» экрана входа: отвечает за логику, аутентификацию и управление сессиями.
* **Greeter** — «лицо» экрана входа: отвечает за внешний вид и взаимодействие с пользователем.
* DM без greeter может работать в текстовом режиме; greeter без DM не работает вообще.
* Один DM может использовать разные greeter (особенно актуально для LightDM), но обычно имеет «родной» вариант (например, SDDM со своим QML‑greeter).

Разберу подробно, почему greeter не входит в состав графической оболочки и устанавливается отдельно.


## Основные причины разделения


1. **Независимость от сессии**

Greeter запускается *до* входа пользователя — когда графическая оболочка ещё не запущена. Он работает на уровне дисплейного менеджера (DM), а не внутри пользовательской сессии. Графическая оболочка стартует только *после* успешной аутентификации.


2. **Многопользовательская среда**
* На одном компьютере могут быть установлены разные графические оболочки (GNOME, KDE, XFCE и т. д.).
* Greeter предоставляет единый интерфейс входа для всех пользователей, независимо от того, какую оболочку они выберут.
* При выборе сессии в greeter запускается соответствующий `.desktop`‑файл из `/usr/share/xsessions/`.

3. **Безопасность**
* Greeter и DM работают от имени системного пользователя, изолированно от пользовательских сессий.
* Это предотвращает потенциальные уязвимости: даже если в графической оболочке есть эксплойт, он не затронет экран входа.
* Аутентификация (через PAM — Pluggable Authentication Modules) выполняется на системном уровне, до запуска пользовательского окружения.

4. **Гибкость конфигурации**
* Один DM может использовать разные greeter. Например, LightDM поддерживает:
    * `lightdm-gtk-greeter` (GTK);
    * `lightdm-kde-greeter` (Qt);
    * `lightdm-webkit2-greeter` (веб‑технологии).
* Пользователи могут выбирать оформление экрана входа независимо от выбранной графической оболочки.

5. **Унификация для разных устройств**
* На десктопах и серверах нужен полноценный greeter с выбором сессии, автовходом и т. д.
* На мобильных устройствах или специализированных системах может использоваться упрощённый экран входа (например, Unity 8 Greeter в Ubuntu Phone).
* Разделение позволяет адаптировать greeter под разные форм‑факторы, не меняя логику DM.


6. **Снижение зависимостей**
* Если бы greeter входил в состав оболочки, установка нескольких оболочек привела бы к конфликтам или избыточным зависимостям.
* Например, установка KDE потребовала бы компонентов GNOME, если бы GDM был встроен в GNOME.
* Раздельная установка позволяет минимизировать пакеты: можно поставить лёгкий greeter для минималистичного DM.


7. **Обновление и обслуживание**
* Исправления безопасности или новые функции для экрана входа можно выпускать независимо от обновлений графической оболочки.
* Администраторы могут тестировать новый greeter без переустановки всей графической среды.

## Как это работает на практике

**Сценарий 1. Несколько оболочек на одном ПК**
1. При загрузке запускается DM (например, SDDM) и его greeter.
2. Пользователь выбирает в меню greeter: «GNOME», «KDE» или «XFCE».
3. DM запускает соответствующую сессию через `.desktop`‑файл.
4. Greeter скрывается, появляется рабочий стол выбранной оболочки.

**Сценарий 2. Замена greeter**
1. Пользователь устанавливает новый greeter: `sudo pacman -S lightdm-webkit2-greeter`.
2. В конфигурации DM (`/etc/lightdm/lightdm.conf`) указывает:
   ```ini
   [Seat:*]
   greeter-session=lightdm-webkit2-greeter
   ```
3. Перезагружается — теперь используется новый экран входа, но все графические оболочки остаются доступными.

---

## Исключения (когда greeter встроен)

Есть случаи, когда greeter интегрирован в оболочку:
* **Unity 8** (Ubuntu Phone): использует встроенный greeter для экономии ресурсов и унификации UX на мобильных устройствах.
* **Специализированные сборки**: в киосках или embedded‑системах экран входа может быть частью приложения.

Но это исключения для узких сценариев. В классических десктопных дистрибутивах разделение DM и greeter — стандарт.

## Краткий итог


| Критерий | Greeter | Графическая оболочка |
|--------|---------|-------------------|
| **Время запуска** | До входа пользователя (на уровне DM) | После аутентификации (в пользовательской сессии) |
| **Зависимости** | Минимальные (только для отрисовки интерфейса) | Полные (библиотеки, сервисы, виджеты) |
| **Роль** | Аутентификация, выбор сессии | Рабочий стол, запуск приложений, управление окнами |
| **Изоляция** | Системный процесс (root) | Пользовательский процесс |

**Вывод:** разделение greeter и графической оболочки — архитектурное решение для гибкости, безопасности и совместимости. Оно позволяет использовать один экран входа для разных окружений, обновлять компоненты независимо и снижать риски, связанные с привилегированными процессами.
