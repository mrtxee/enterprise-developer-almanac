# LISTENERS и ADVERTISED_LISTENERS
В Apache Kafka параметры **`listeners`** и **`advertised.listeners`** управляют тем, **как брокер принимает подключения** и **какие адреса он сообщает клиентам**. Это критически важные настройки для корректной работы в сетях, особенно в Docker, Kubernetes или гибридных средах.

---

## 🔹 `listeners` — **где Kafka слушает**

Это список **адресов и портов внутри самого брокера**, на которых он принимает входящие подключения.

### Формат:
```properties
listeners=NAME://host:port,NAME2://host2:port2
```

- `host` может быть:
  - пустым (`://:9092`) → слушать на всех интерфейсах (`0.0.0.0`),
  - `localhost` → только локальные подключения,
  - конкретный IP.
- `NAME` — произвольное имя listener'а (например, `PLAINTEXT`, `INTERNAL`, `EXTERNAL`).
- Каждый listener должен иметь **уникальный порт**.

### Пример:
```properties
listeners=PLAINTEXT://:9092,CONTROLLER://:9093
```
→ Kafka будет принимать клиентские подключения на порту **9092** и управляющие (controller) — на **9093**.

> 💡 Это **внутренняя конфигурация брокера**. Клиенты сюда не смотрят напрямую.

---

## 🔹 `advertised.listeners` — **что Kafka говорит клиентам**

Это список адресов, **которые Kafka возвращает клиенту** после первоначального подключения. Клиент использует эти адреса для **последующих запросов** (например, к другим брокерам или для получения метаданных).

### Формат:
```properties
advertised.listeners=NAME://public-host:port,...
```

- Должен содержать **те же имена (`NAME`)**, что и в `listeners`.
- Адреса должны быть **доступны клиенту**, который к ним подключается.

### Пример:
```properties
advertised.listeners=PLAINTEXT://kafka.example.com:9092
```
→ Клиент подключается к `kafka.example.com:9092`, и Kafka говорит:  
> «Да, я тут. И все остальные запросы тоже отправляй сюда».

---

## 🔥 Ключевая разница

| Параметр | Где используется | Кто видит | Пример |
|--------|----------------|----------|--------|
| `listeners` | Внутри брокера Kafka | Только сам брокер | `PLAINTEXT://:9092` |
| `advertised.listeners` | Отправляется клиенту | Все клиенты (продюсеры, консьюмеры, Kafka UI) | `PLAINTEXT://localhost:9092` или `PLAINTEXT://kafka:9092` |

---

## 🌐 Типичный сценарий: Kafka в Docker

Вы хотите, чтобы:
- **Kafka UI (внутри Docker)** подключался по имени `kafka:9092`,
- **Ваше приложение на хосте** — по `localhost:9092`.

Тогда:

```yaml
# Внутри контейнера Kafka слушает на 9092 и 9093
KAFKA_LISTENERS: INTERNAL://:9093,EXTERNAL://:9092

# Клиентам сообщается разный адрес в зависимости от listener'а
KAFKA_ADVERTISED_LISTENERS: INTERNAL://kafka:9093,EXTERNAL://localhost:9092
```

- Kafka UI → подключается к `kafka:9093` → получает advertised-адрес `kafka:9093` → всё работает.
- Приложение на хосте → подключается к `localhost:9092` → получает `localhost:9092` → всё работает.

> ⚠️ Если указать `advertised.listeners=PLAINTEXT://localhost:9092`, а Kafka UI подключится к `kafka:9092`, то после получения метаданных он попытается подключиться к `localhost:9092` **внутри своего контейнера**, где `localhost` — это он сам → **ошибка**.

---

## ✅ Правило настройки

> **`advertised.listeners` должен содержать адреса, которые клиент реально может разрешить и использовать из своей сети.**

---

## 💡 Советы

1. **Имена listener'ов должны совпадать** в `listeners` и `advertised.listeners`.
2. **Порты в `listeners` должны быть уникальными**.
3. **Не используйте `localhost` в `advertised.listeners`**, если клиенты не на том же хосте.
4. В Docker:  
   - Для внутренних клиентов → `kafka:9092`,  
   - Для внешних → `localhost:9092` или публичный IP/DNS.
