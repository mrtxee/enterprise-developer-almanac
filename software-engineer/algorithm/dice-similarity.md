## Коэффициент Сёренсена — Дайса

### Связанные названия (важно не путать!)

Этот коэффициент тесно связан с другими метриками, которые иногда называют похожими именами:

| Название | Связь с Дайсом |
|----------|----------------|
| **F1-score (F-мера)** | Математически **идентичен** коэффициенту Дайса |
| **Jaccard index (коэффициент Жаккара)** | Похож, но другая формула |
| **Tanimoto coefficient** | Обобщение Жаккара для множеств |
| **Overlap coefficient** | Другая нормализация пересечения |

---

### Суть метода (кратко)

**Коэффициент Дайса** #👨 — это мера сходства двух множеств (в нашем случае — множеств биграмм слов). Он показывает, **какую долю от общего количества элементов составляют совпадения**.

#### Формула

$$
Dice = (2 × |A ∩ B|) / (|A| + |B|)
$$

Где:

- `|A ∩ B|` — количество **совпадающих** биграмм
- `|A|` — общее количество биграмм в первом тексте
- `|B|` — общее количество биграмм во втором тексте
- `2 ×` — удвоение, чтобы результат был в диапазоне **от 0 до 1** (или от 0% до 100%)

> [!INFO] Биграмма
> **Биграмма** (от греч. _bi_ — два и _gramma_ — запись, буква) — это непрерывная последовательность из **двух соседних элементов** в тексте.
> В зависимости от того, что мы считаем "элементом", биграммы делятся на два основных типа: Character Bigrams, Word Bigrams

---

### Наглядный пример

**Текст A:** "Лицензия разрешает использование"

**Текст B:** "Лицензия разрешает бесплатное использование"

#### Разбиваем на биграммы (пары соседних слов)

**Биграммы A:**

1. "Лицензия разрешает"
2. "разрешает использование"

**Биграммы B:**

1. "Лицензия разрешает"
2. "разрешает бесплатное"
3. "бесплатное использование"

#### Считаем

- Совпадений (`A ∩ B`): **1** (только "Лицензия разрешает")
- Всего биграмм в A: **2**
- Всего биграмм в B: **3**

#### Применяем формулу

$$
Dice = (2 × 1) / (2 + 3) = 2 / 5 = 0.4 = 40\%
$$

**Результат:** Тексты совпадают на **40%**.

---

### Почему именно биграммы?

- **Унарные слова** (по отдельности) не учитывают порядок → "кошка съела мышку" и "мышку съела кошка" дадут 100% сходства.
- **Триграммы** (по 3 слова) слишком чувствительны к малейшим изменениям.
- **Биграммы** — золотая середина: учитывают порядок слов, но устойчивы к небольшим вставкам/удалениям.

Именно поэтому GitHub использует **Dice на биграммах** для сравнения лицензий.

### Итоговая рекомендация

| Задача | Алгоритм |
|--------|----------|
| **Стандартные лицензии (MIT, Apache, GPL)** | **Dice на биграммах слов** ⭐ |
| Лицензии с добавленными/удаленными абзацами | Косинусное сходство на TF-IDF |
| Короткие тексты (< 50 слов) | Левенштейн на уровне слов |
| Нужно "как у GitHub" | Dice на биграммах + нормализация |

### Практический пример на Java 17 (Dice на биграммах)

```java
import java.util.*;
import java.util.regex.*;

public class LicenseSimilarity {

    public static double calculateSimilarity(String license1, String license2) {
        // 1. Нормализация
        String norm1 = normalize(license1);
        String norm2 = normalize(license2);

        // 2. Разбиваем на слова
        List<String> words1 = tokenize(norm1);
        List<String> words2 = tokenize(norm2);

        // 3. Строим биграммы
        Set<String> bigrams1 = buildBigrams(words1);
        Set<String> bigrams2 = buildBigrams(words2);

        if (bigrams1.isEmpty() && bigrams2.isEmpty()) return 100.0;
        if (bigrams1.isEmpty() || bigrams2.isEmpty()) return 0.0;

        // 4. Считаем пересечение
        Set<String> intersection = new HashSet<>(bigrams1);
        intersection.retainAll(bigrams2);

        // 5. Формула Дайса
        double dice = (2.0 * intersection.size()) / (bigrams1.size() + bigrams2.size());
        return dice * 100.0;
    }

    private static String normalize(String text) {
        // Удаляем блок копирайта (упрощенно)
        String noCopyright = text.replaceAll("(?i)copyright.*?\\n", "");
        // К нижнему регистру, оставляем только буквы/цифры/пробелы
        return noCopyright.toLowerCase().replaceAll("[^a-zа-яё0-9\\s]", " ")
                          .replaceAll("\\s+", " ").trim();
    }

    private static List<String> tokenize(String text) {
        return Arrays.asList(text.split(" "));
    }

    private static Set<String> buildBigrams(List<String> words) {
        Set<String> bigrams = new HashSet<>();
        for (int i = 0; i < words.size() - 1; i++) {
            bigrams.add(words.get(i) + " " + words.get(i + 1));
        }
        return bigrams;
    }
}
```

### Ключевой вывод

Для лицензий **важен порядок слов, но не важны точные символы**. Поэтому переход от **символьного** уровня (Левенштейн) к **токенному** (Dice на биграммах) дает:

- ✅ Скорость в 100–1000 раз выше.
- ✅ Устойчивость к форматированию и перестановкам.
- ✅ Результат, совпадающий с тем, что показывает GitHub.
