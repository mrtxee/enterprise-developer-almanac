### Правильное название

**Английское:** *boilerplate code*  
**Русское:** шаблонный код

### Что это такое?

**Boilerplate code (шаблонный код)** — это повторяющийся, стандартизированный фрагмент кода, который программисты используют для настройки базовой структуры приложений или модулей. Это «нетворческий» код, который приходится писать из-за требований:
* языка программирования;
* операционной системы;
* библиотеки подпрограмм;
* принятых паттернов разработки [```2```](https://ru.ruwiki.ru/wiki/%D0%A8%D0%B0%D0%B1%D0%BB%D0%BE%D0%BD%D0%BD%D1%8B%D0%B9_%D0%BA%D0%BE%D0%B4).

Он повторяется из функции в функцию, из программы в программу с минимальными изменениями.

**Примеры шаблонного кода:**
* подключение модулей (`#include <stdio.h>` в C, `import java.io.*;` в Java);
* настройка компилятора или системы сборки;
* организация точки входа в программу (`int main()` в C++, `public static void main(String[] args)` в Java);
* код инициализации и выхода (`return 0;` в C);
* базовая структура HTML (`<!DOCTYPE html>`, `<html>`, `<head>`, `<body>`);
* определения классов и методов по шаблону в ООП-языках;
* конфигурационные файлы (Maven/Gradle в Java, package.json в JavaScript) [```1```](https://www.phpcluster.com/boilerplate-code/)[```2```](https://ru.ruwiki.ru/wiki/%D0%A8%D0%B0%D0%B1%D0%BB%D0%BE%D0%BD%D0%BD%D1%8B%D0%B9_%D0%BA%D0%BE%D0%B4).

**Этимология термина:**
Слово *boilerplate* буквально переводится как «котельное железо». Термин пришёл из полиграфии в 1950-х годах:
* так называли готовые печатные формы (из железа), которые синдикаты присылали газетам;
* или формы для многократного использования (шапки газет, объявления) [```2```](https://ru.ruwiki.ru/wiki/%D0%A8%D0%B0%D0%B1%D0%BB%D0%BE%D0%BD%D0%BD%D1%8B%D0%B9_%D0%BA%D0%BE%D0%B4)[```5```](https://imperiumdynamics.com/blog/what-is-a-boilerplate-code.html).

### Для чего нужен boilerplate code?

Шаблонный код выполняет несколько ключевых функций:
1. **Создаёт стандартную структуру** — обеспечивает единообразие проектов, упрощает ревью и поддержку кода (особенно в командах).
2. **Ускоряет разработку** — позволяет не писать базовую логику с нуля, а использовать готовые блоки.
3. **Обеспечивает совместимость** с фреймворками и библиотеками (например, аннотации `@SpringBootApplication` в Spring Boot).
4. **Повышает читаемость и поддерживаемость** кода — другие разработчики быстрее понимают структуру проекта.
5. **Снижает количество ошибок** — проверенные шаблоны уменьшают риск типовых ошибок.
6. **Внедряет лучшие практики** — хорошо спроектированный шаблонный код включает отраслевые стандарты и паттерны.

**Примеры использования:**
* **Java:** класс с `main()`-методом для запуска приложения.
* **Python:** конструкция `if __name__ == "__main__":` для выполнения кода при прямом запуске скрипта.
* **HTML:** базовая оболочка с `<!DOCTYPE html>`, `<html>`, `<head>`, `<body>`.
* **Spring Boot:** аннотация `@SpringBootApplication` для инициализации приложения.
* **JavaScript/React:** структура компонента с `setState`, `render()`.

**Когда стоит избегать?**
* для простых скриптов или утилит (избыточная структура усложнит код);
* если фреймворк или инструмент генерирует шаблон автоматически;
* когда шаблонный код «прячет» логику программы, делая её менее понятной [```1```](https://www.phpcluster.com/boilerplate-code/).
