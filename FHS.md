**FHS (Filesystem Hierarchy Standard)** — это стандарт, определяющий структуру и содержимое каталогов в Unix-подобных операционных системах, в первую очередь в Linux. Он был разработан для обеспечения **единообразия** между различными дистрибутивами Linux, что упрощает:

- разработку ПО (например, установщики знают, куда класть файлы),
- администрирование систем,
- переносимость скриптов и приложений.

> ⚠️ Примечание: ты написал «fas», но, скорее всего, имел в виду **FHS** — *Filesystem Hierarchy Standard*. Стандарта под названием "fas" в контексте файловых систем Linux не существует.

---

### Основные принципы FHS

FHS определяет назначение каждого каталога верхнего уровня (в корне `/`) и какие типы файлов в них должны находиться.

Вот ключевые каталоги и их назначение (актуально для FHS 3.0, последней на 2026 год):

| Каталог         | Назначение |
|------------------|-----------|
| `/`              | Корень файловой системы. |
| `/bin`           | **Основные исполняемые файлы** (команды), необходимые в однопользовательском режиме (например, `ls`, `cp`, `bash`). Доступны всем пользователям. |
| `/sbin`          | **Системные исполняемые файлы**, требуемые для загрузки, восстановления, ремонта (например, `fdisk`, `iptables`, `reboot`). Обычно используются root. |
| `/lib`           | Библиотеки, необходимые для запуска программ из `/bin` и `/sbin`. Включает `.so`-файлы и модули ядра (`/lib/modules`). |
| `/etc`           | **Конфигурационные файлы** системы и приложений (обычно текстовые). Не содержит бинарных данных. |
| `/dev`           | Файлы **устройств** (устройства представлены как файлы, например, `/dev/sda`, `/dev/null`). Управляются ядром или `udev`. |
| `/proc`          | Виртуальная файловая система, отображающая информацию о **процессах и параметрах ядра** (все данные — в памяти, не на диске). |
| `/sys`           | Виртуальная ФС, предоставляющая информацию об **устройствах, драйверах и ядре** (часть sysfs). |
| `/tmp`           | Временные файлы. Могут быть удалены при перезагрузке. Доступна для записи всем. |
| `/var`           | **Переменные данные**: логи (`/var/log`), почта (`/var/mail`), спулы (`/var/spool`), временные файлы, которые **не должны** удаляться при перезагрузке. |
| `/usr`           | **Вторичные иерархии** — программы, библиотеки, документация, не требуемые на ранних этапах загрузки. Считается «только для чтения» после загрузки. |
| &nbsp;&nbsp;→ `/usr/bin` | Большинство пользовательских команд (не критичных для загрузки). |
| &nbsp;&nbsp;→ `/usr/sbin` | Некритичные системные команды. |
| &nbsp;&nbsp;→ `/usr/lib` | Библиотеки для `/usr/bin` и `/usr/sbin`. |
| &nbsp;&nbsp;→ `/usr/share` | Архитектурно-независимые данные (документация, иконки, локализация). |
| &nbsp;&nbsp;→ `/usr/local` | Локально установленное ПО (вручную или через `make install`). Имеет ту же структуру, что и `/usr`. |
| `/home`          | Домашние каталоги пользователей (например, `/home/alice`). |
| `/root`          | Домашний каталог пользователя `root`. |
| `/boot`          | Файлы, необходимые для **загрузки**: ядро (`vmlinuz`), initramfs, загрузчики (GRUB). |
| `/mnt`           | Временная точка монтирования для администратора (например, `/mnt/usb`). |
| `/media`         | Точки монтирования для **съёмных носителей** (CD, USB-флешки): `/media/user/disk`. |
| `/opt`           | Дополнительное ПО от сторонних производителей (часто самодостаточные пакеты, например, JetBrains IDE). |
| `/run`           | Временные файлы времени выполнения (PID-файлы, сокеты), создаваемые после загрузки. Заменил `/var/run` в современных системах. |

---

### Важные концепции FHS

- **Разделение `/` и `/usr`**: Раньше `/usr` мог быть отдельным томом, поэтому всё необходимое для загрузки до монтирования `/usr` должно быть в `/bin`, `/sbin`, `/lib`.
- **Только для чтения vs изменяемые данные**:  
  - `/usr`, `/bin`, `/sbin` — **read-only** после загрузки.  
  - `/var`, `/tmp`, `/run` — **изменяемые**.
- **Локальное ПО**: `/usr/local` защищено от обновлений системного пакетного менеджера.

---

### Совместимость

Большинство современных дистрибутивов (Ubuntu, Fedora, Debian, RHEL, Arch) следуют FHS, хотя могут быть небольшие отклонения (например, символические ссылки вроде `/bin → /usr/bin` в системах с **unified `/usr`**).

Вот пример типичного дерева файловой системы Linux, соответствующего **FHS (Filesystem Hierarchy Standard) 3.0**, с краткими пояснениями для ключевых каталогов:

```
/
├── bin/                 # Основные команды (ls, cp, bash...) — нужны при загрузке
├── boot/                # Файлы загрузчика и ядро (vmlinuz, initrd, grub/)
├── dev/                 # Устройства как файлы (sda, null, tty...)
│   ├── sda
│   ├── null
│   └── tty1
├── etc/                 # Конфигурационные файлы системы и приложений
│   ├── passwd
│   ├── hosts
│   ├── nginx/
│   └── systemd/
├── home/                # Домашние каталоги пользователей
│   ├── alice/
│   └── bob/
├── lib/                 # Системные библиотеки для /bin и /sbin
│   ├── libc.so.6
│   └── modules/         # Модули ядра
├── media/               # Точки монтирования для съёмных носителей
│   └── usb-drive/
├── mnt/                 # Временные точки монтирования (админские)
├── opt/                 # Дополнительное ПО от вендоров (например, /opt/google/chrome)
├── proc/                # Виртуальная ФС: информация о процессах и ядре
│   ├── 1/               # Информация о PID=1
│   └── cpuinfo
├── root/                # Домашний каталог суперпользователя root
├── run/                 # Временные данные времени выполнения (PID, сокеты)
│   ├── nginx.pid
│   └── dbus/
├── sbin/                # Системные команды (fdisk, iptables, reboot)
├── srv/                 # Данные сервисов (например, /srv/www для веб-сайтов)
├── sys/                 # Виртуальная ФС: информация об устройствах и драйверах (sysfs)
├── tmp/                 # Временные файлы (могут очищаться при перезагрузке)
├── usr/                 # Вторичная иерархия — "только для чтения" после загрузки
│   ├── bin/             # Большинство пользовательских программ (git, python, gcc...)
│   ├── lib/             # Библиотеки для /usr/bin
│   ├── share/           # Архитектурно-независимые данные (man-страницы, иконки, локализация)
│   │   ├── man/
│   │   └── icons/
│   ├── include/         # Заголовочные файлы C/C++
│   ├── local/           # Локально установленное ПО (вручную или через make install)
│   │   ├── bin/
│   │   └── lib/
│   └── sbin/            # Некритичные системные утилиты
└── var/                 # Изменяемые данные: логи, почта, кэш и т.д.
    ├── log/             # Системные логи (syslog, nginx/access.log...)
    ├── cache/           # Кэш приложений (например, /var/cache/apt)
    ├── lib/             # Переменные данные программ (например, состояния dpkg)
    ├── spool/           # Очереди (печати, почты)
    └── www/             # (Иногда) веб-контент (хотя правильнее — /srv/www)
```

> 💡 **Примечание**:  
> - Каталоги вроде `/proc`, `/sys`, `/dev` — **виртуальные** (существуют только в памяти).  
> - В современных дистрибутивах (например, Fedora, Arch) часто используется **unified `/usr`**, где `/bin → /usr/bin`, `/sbin → /usr/sbin`, `/lib → /usr/lib` (реализовано через символические ссылки). Это всё ещё совместимо с FHS.
