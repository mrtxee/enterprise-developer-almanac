> ISO/IEC/IEEE 29148:2018

**ISO/IEC/IEEE 29148:2018** — это международный стандарт, устанавливающий **единые требования к содержанию и структуре документов с требованиями** на программное обеспечение и системы.

Он объединяет и заменяет устаревшие стандарты IEEE 830 (SRS), ISO/IEC TR 29148-2 и другие, создавая универсальный фреймворк для спецификации требований.

### 🎯 Главная цель
Устранить разночтения между заказчиком, разработчиками и тестировщиками за счёт **стандартизированной структуры** документов требований.

### 📑 Ключевые разделы стандарта

| Раздел                            | Содержание                                                    |
| :-------------------------------- | :------------------------------------------------------------ |
| **Введение и область применения** | Назначение документа, целевая аудитория, определения          |
| **Общее описание продукта**       | Контекст, пользователи, ограничения, предположения            |
| **Функциональные требования**     | Что система должна делать (use cases, user stories, сценарии) |
| **Нефункциональные требования**   | Производительность, безопасность, надёжность, UX              |
| **Интерфейсы**                    | API, UI, аппаратные, коммуникационные интерфейсы              |
| **Трассируемость**                | Связь требований с бизнес-целями, дизайном и тестами          |

### 💡 Основные принципы

-   **Единство формы:** Одна структура для всех типов проектов (waterfall, agile, hybrid)
-   **Адаптивность:** Стандарт задаёт *минимальный набор* разделов; лишнее можно опускать, недостающее — добавлять
-   **Ориентация на верификацию:** Каждое требование должно быть **тестируемым** и **однозначным**
-   **Согласованность с жизненным циклом:** Совместим с ISO/IEC 12207 (процессы ЖЦ ПО) и ISO/IEC 15288 (системная инженерия)

### ⚠️ Чем НЕ является стандарт
-   Это **не шаблон** для копирования, а руководство по содержанию
-   Это **не методология** разработки (не предписывает Agile или Waterfall)
- Это **не замена** инструментам управления требованиями (Jira, Confluence), а основа для их настройки

### ✅ Когда применять
- При разработке SRS / Software Requirements Specification
- При аудите качества документации
- При передаче проекта между командами или подрядчиками
- Для соответствия регуляторным требованиям (медицина, авиация, финтех)

> **Ключевой вывод:** 29148:2018 превращает написание требований из творчества в **инженерную дисциплину**, снижая риски недопонимания и переделок.
