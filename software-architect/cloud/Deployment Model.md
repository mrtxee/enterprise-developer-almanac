### Deployment Model (модель развёртывания)

**Deployment Model** (модель развёртывания) — это способ организации и размещения ИТ-инфраструктуры (серверов, приложений, данных) для обеспечения работы сервисов. Она определяет, где и как будет работать программное обеспечение: на физических серверах, в облаке, на устройствах пользователей и т. д. Выбор модели зависит от требований к безопасности, масштабируемости, стоимости и другим параметрам.

#### Основные модели развёртывания

1. **VPC (Virtual Public Cloud) — виртуальное публичное облако:**
   * **Суть:** виртуальные серверы создаются заказчиком, но не привязаны к конкретному физическому серверу. Ресурсы берутся из пула объединённых серверов провайдера.
   * **Особенности:**
     * высокая гибкость и масштабируемость — ресурсы выделяются по требованию;
     * отказоустойчивость — если часть оборудования выходит из строя, ресурсы перебрасываются на рабочие хосты;
     * логическая изоляция среды, но физическая инфраструктура общая с другими клиентами;
     * оплата по мере использования ресурсов.
   * **Примеры:** Amazon AWS, Microsoft Azure, Google Cloud.
   * **Подходит для:** разработки и тестирования, облачных приложений с переменной нагрузкой, SaaS-сервисов.

2. **VPS (Virtual Private Server) — виртуальный частный сервер:**
   * **Суть:** несколько заказчиков делят один физический сервер, но каждый получает изолированную виртуальную среду (виртуальную машину).
   * **Особенности:**
     * баланс между контролем и стоимостью — больше свободы, чем у хостинга, но дешевле выделенного сервера;
     * фиксированный набор ресурсов (CPU, RAM, диск), который не зависит от других пользователей;
     * возможность установки ОС и ПО по своему выбору;
     * базовая изоляция от других виртуальных машин на сервере.
   * **Подходит для:** небольших сайтов, стартапов, приложений с умеренной нагрузкой, хостинга баз данных.

3. **Hosting (хостинг):**
   * **Суть:** физический сервер разделён на множество сегментов (контейнеров), каждый из которых отдаётся отдельному заказчику.
   * **Особенности:**
     * максимальная заполненность серверов — экономия ресурсов провайдера;
     * минимальные затраты для клиента (самый бюджетный вариант);
     * ограниченные возможности настройки — среда управляется провайдером;
     * общая операционная система для всех пользователей (обычно);
     * риск «соседства» — нагрузка от других сайтов может повлиять на работу вашего.
   * **Подходит для:** простых сайтов-визиток, блогов, небольших интернет-магазинов без сложной логики.

#### Другие распространённые модели (не из вашего изображения)

4. **Частное облако (Private Cloud):**
   * инфраструктура полностью принадлежит и управляется одной организацией;
   * максимальный контроль и безопасность, но высокие затраты на поддержание;
   * подходит для банков, госсектора, крупных корпораций с жёсткими требованиями к данным.

5. **Гибридное облако (Hybrid Cloud):**
   * сочетание частного и публичного облака;
   * чувствительные данные хранятся локально, а ресурсоёмкие задачи выносятся в публичное облако;
   * обеспечивает баланс между безопасностью и гибкостью.

6. **Общественное облако (Community Cloud):**
   * инфраструктура используется группой организаций с общими требованиями (например, отраслевыми стандартами);
   * компромисс между контролем и стоимостью — ресурсы делятся, но правила использования строгие.

#### Критерии выбора модели развёртывания

* **Бюджет:** хостинг < VPS < VPC < частное облако.
* **Контроль:** хостинг (минимальный) → VPS → VPC → частное облако (максимальный).
* **Безопасность:** частное облако > VPC/гибридное > VPS > хостинг.
* **Масштабируемость:** VPC (лучшая) > частное облако/гибридное > VPS > хостинг.
* **Сложность администрирования:** хостинг (проще) → VPS → VPC → частное облако (сложнее).

#### Вывод

Модель развёртывания напрямую влияет на:
* стоимость владения ИТ-инфраструктурой;
* уровень безопасности и изоляции ресурсов;
* возможности масштабирования и настройки;
* надёжность и доступность сервисов.

Правильный выбор модели зависит от конкретных задач проекта, его бюджета и требований к инфраструктуре.

# VPC vs VPS vs Hosting

| **Вид услуги**                   | **Описание**                                                                                                                                                                                                                                                                          |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **VPC (Virtual Public Cloud)**   | Виртуальные серверы, которые создаёт заказчик. Они не имеют привязки к конкретному физическому серверу. Ресурсы берутся из огромного пула объединённых серверов. Если часть оборудования выйдет из строя, виртуальный сервер начнёт брать ресурсы с рабочего хоста вместо нерабочего. |
| **VPS (Virtual Private Server)** | Несколько заказчиков размещаются на одном физическом сервере и делят его мощности между собой.                                                                                                                                                                                        |
| **Hosting**                      | Физический сервер разбит на множество сегментов. Каждый заказчик получает свой сегмент. Наполненность серверов у хостингов всегда максимальная.                                                                                                                                       |
