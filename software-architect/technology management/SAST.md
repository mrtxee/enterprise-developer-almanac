Конечно! **SAST** и **DAST** — это два основных подхода к **автоматизированному тестированию безопасности приложений**. Они дополняют друг друга и используются на разных этапах жизненного цикла разработки ([[SDLC]]).

---

## 🎯 Краткое сравнение

| Характеристика        | **SAST**                    | **DAST**                                 |
| --------------------- | --------------------------- | ---------------------------------------- |
| **Тип анализа**       | Статический (без запуска)   | Динамический (с запуском)                |
| **Что проверяет**     | Исходный код / байт-код     | Работающее приложение                    |
| **Когда применяется** | На этапе разработки (CI/CD) | На этапе тестирования / перед релизом    |
| **Уровень доступа**   | Требует доступ к коду       | Не требует доступа к коду                |
| **Аналогия**          | «Ревизия чертежей здания»   | «Испытание готового здания на прочность» |

---

## 🔍 1. SAST — Static Application Security Testing  
**(Статическое тестирование безопасности приложений)**

### Как работает:
- Анализирует **исходный код**, **байт-код** или **бинарники** **без запуска приложения**.
- Ищет **паттерны уязвимостей**:
  - SQL Injection
  - XSS (Cross-Site Scripting)
  - Hardcoded secrets
  - Небезопасные вызовы API

### Пример:
```java
// Уязвимый код
String query = "SELECT * FROM users WHERE id = " + userInput;
stmt.execute(query); // ← SAST найдёт потенциальный SQL Injection
```

### Плюсы:
- ✅ Находит уязвимости **на ранних этапах** (shift-left security).
- ✅ Показывает **точное место в коде**.
- ✅ Интегрируется в **IDE и CI/CD**.

### Минусы:
- ❌ Много **ложных срабатываний** (false positives).
- ❌ Не видит **runtime-уязвимости** (например, неправильная конфигурация).
- ❌ Требует доступа к **исходному коду**.

### Популярные инструменты:
- **SonarQube** (с Security Hotspots)
- **Checkmarx**
- **Fortify**
- **Semgrep**
- **Bandit** (Python)
- **ESLint-plugin-security** (JavaScript)

## 🔍 2. DAST — Dynamic Application Security Testing  
**(Динамическое тестирование безопасности приложений)**

### Как работает:
- Тестирует **запущенное приложение** через **HTTP/HTTPS** (как внешний злоумышленник).
- Отправляет **вредоносные запросы** и анализирует ответы:
  - SQL Injection payloads
  - XSS scripts
  - Path traversal
  - Незащищённые эндпоинты

### Пример:
```
GET /user?id=1' OR '1'='1
→ Если в ответе данные всех пользователей → уязвимость SQLi
```

### Плюсы:
- ✅ Находит **реальные уязвимости** в работающем приложении.
- ✅ Не требует доступа к коду (black-box testing).
- ✅ Обнаруживает **конфигурационные ошибки** (например, открытые админки).

### Минусы:
- ❌ Не показывает **место в коде** (только URL и payload).
- ❌ Может пропустить уязвимости, недоступные через UI/API.
- ❌ Требует **развёрнутое приложение**.

### Популярные инструменты:
- **OWASP ZAP** (бесплатный)
- **Burp Suite** (Professional/Community)
- **Acunetix**
- **Netsparker**

## 🧩 SAST + DAST = Полное покрытие

| Этап SDLC | Инструмент | Цель |
|----------|-----------|------|
| **Разработка** | SAST в IDE | Найти уязвимости до коммита |
| **CI/CD** | SAST + SCA | Блокировать сборку при критических уязвимостях |
| **Тестирование** | DAST | Проверить развёрнутое приложение |
| **Продакшен** | DAST + IAST | Мониторинг в реальном времени |

> 💡 **IAST** (Interactive AST) — гибрид: агент внутри приложения + внешние запросы.

## 📊 Пример интеграции в CI/CD

```yaml
# GitHub Actions
jobs:
  security:
    steps:
      - name: SAST (Semgrep)
        run: semgrep --config=p/security .

      - name: Запустить приложение
        run: npm start &

      - name: DAST (OWASP ZAP)
        run: zap-baseline.py -t http://localhost:3000
```

## ⚠️ Важные нюансы

1. **SAST ≠ линтер**  
   Линтер ищет стилевые ошибки, SAST — уязвимости.

2. **DAST ≠ нагрузочное тестирование**  
   DAST фокусируется на безопасности, а не на производительности.

3. **Оба подхода нужны**  
   SAST находит проблемы в коде, DAST — в конфигурации и runtime.

---

## 💡 Заключение

> - **SAST** — ваш «внутренний аудитор», который смотрит в код.  
> - **DAST** — ваш «внешний хакер», который бьёт по интерфейсу.

Вместе они дают **максимальное покрытие** и соответствуют принципу **«shift-left security»** — находить уязвимости как можно раньше.
