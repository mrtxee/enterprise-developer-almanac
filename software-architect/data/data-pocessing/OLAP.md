## OLAP

**OLAP (On-Line Analytical Processing)** — это подход к хранению и обработке данных, ориентированный на **быструю многомерную аналитику**: агрегаты, срезы, развороты, временные ряды.

OLAP используется там, где нужно отвечать на бизнес-вопросы вроде «продажи по регионам за квартал», а не выполнять тысячи транзакций как [[OLTP|OLTP]].

## Чем OLAP отличается от OLTP

| Критерий | **OLTP** | **OLAP** |
|----------|----------|----------|
| **Расшифровка** | On-Line Transaction Processing | On-Line Analytical Processing |
| **Назначение** | Обработка транзакций | Аналитика |
| **Запросы** | Короткие, быстрые | Сложные, агрегирующие |
| **Данные** | Текущие, изменяемые | Исторические, обычно только чтение |
| **Модель** | Нормализованная | Денормализованная (звёзды, снежинки) |
| **Нагрузка** | Много мелких записей | Мало, но тяжёлых чтений |
| **Примеры** | База интернет-магазина | ClickHouse, BigQuery, Snowflake |
| **Хранилище** | Рабочая БД | [[data-warehouse|Data Warehouse]] |

## Как работает OLAP

```mermaid
---
title: Поток данных в OLAP-хранилище
---
flowchart LR
    SRC[Источники: БД, логи, API] --> ETL[ETL/ELT]
    ETL --> DWH[(Data Warehouse)]
    DWH --> CUBE[OLAP-куб / колоночное хранилище]
    CUBE --> BI[BI-дашборды, отчёты]
```

- **[[ETL|ETL]] / [[ELT|ELT]]** — загрузка и трансформация данных.
- **[[data-warehouse|Data Warehouse]]** — хранилище исторических данных.
- **OLAP-куб** — многомерная модель для быстрых срезов.
- **BI** — дашборды и отчёты для пользователей.

## Основные характеристики

- Хранение в **колонках** (ClickHouse, BigQuery) — быстрее агрегаты.
- Партиционирование по времени — быстрые срезы периодов.
- Сжатие данных — большой объём на диске помещается компактно.
- Только **добавление** (append-only): старые записи не перезаписываются.

## Операции многомерного анализа

| Операция | Суть |
|----------|------|
| **Roll-up** | Агрегация вверх: с «день» на «месяц», с «город» на «регион» |
| **Drill-down** | Детализация вниз: с «месяц» на «день» |
| **Slice** | Фиксированный срез («только март») |
| **Dice** | Выборка подмножества по нескольким измерениям |
| **Pivot** | Разворот измерений (строки ↔ столбцы) |

## OLAP-куб

Многомерный куб имеет измерения (dimensions) и меры (measures):

- **Измерения:** время, регион, продукт, канал продаж.
- **Меры:** сумма продаж, количество заказов, маржа.

Связь измерений:

- время × регион × продукт → сумма продаж
- регион × канал продаж → количество заказов
- время × продукт → маржа

## Типы OLAP

| Тип | Как хранятся данные |
|-----|---------------------|
| **MOLAP** | В многомерном кубе (быстро, заранее агрегировано) |
| **ROLAP** | Считается на лету из реляционной БД (больше гибкости) |
| **HOLAP** | Гибрид: часть в кубе, часть в реляционной БД |

## Виды хранилищ данных

| Понятие | Описание |
|---------|----------|
| **[[data-warehouse|Data Warehouse]] (DWH)** | Центральная база исторических данных для аналитики |
| **[[data-mart|Data Mart]]** | Подмножество DWH для одной области (маркетинг, финансы) |
| **ETL** | Extract → Transform → Load (трансформация до загрузки) |
| **ELT** | Extract → Load → Transform (трансформация в хранилище) |
| **Лейк данных** | Хранилище «сырых» данных в исходном виде |

## Основные колоночные СУБД

| СУБД | Назначение |
|------|-----------|
| **ClickHouse** | Быстрая аналитика в реальном времени, колоночная |
| **BigQuery** | Облачные аналитические данные на Google Cloud |
| **Snowflake** | Облачное хранилище с отдельным слоем вычислений |
| **Redshift** | Аналитика на AWS |

## Когда использовать OLAP, а когда OLTP

| Ситуация | Рекомендация |
|----------|--------------|
| Онлайн-заказы, платежи | **OLTP** (рабочая БД) |
| Простой поиск по справочнику | **OLTP** |
| Продажи по кварталам по регионам | **OLAP** |
| Анализ воронки по времени | **OLAP** |
| Отчёт для руководства | **OLAP** (DWH + BI) |
| Высокая пиковая запись | **OLTP** + публикация аналитики в OLAP через ETL |

## Особенности

- ✅ Быстрые агрегации и срезы по большим объёмам.
- ✅ Хранение сжатых колонок экономно.
- ✅ Партиционирование по времени ускоряет выборки.
- ✅ Поддерживает историю без обновления старых строк.
- ❌ Плохо подходит для точечных обновлений строк.
- ❌ Требует продуманных моделей (созвездие, звёзды) для сложной аналитики.
- ❌ Работа с высоконагруженными параллельными записями затруднена (запись ограничена).

## Итог

**OLAP** — инструмент для аналитики и отчётов: колоночные СУБД, агрегаты, кубы, ETL/ELT в [[data-warehouse|DWH]]. **OLTP** — для рабочей нагрузки приложений. Часто они сочетаются: OLTP производит данные, ETL переносит их, OLAP отвечает на бизнес-вопросы.
