### Кратко о Hive Metastore

**Hive Metastore** — это централизованное хранилище метаданных для Apache Hive. Он хранит информацию о структуре данных (метаданные), а не сами данные.

#### Что хранит

В Hive Metastore содержатся сведения о:
* **таблицах** (имена, схемы);
* **колонках** (названия, типы данных);
* **разделах** (partitioning);
* **форматах файлов** ([[Parquet]], ORC, CSV и т. д.);
* **местоположении данных** в распределённом хранилище (HDFS, S3 и пр.);
* **свойствах таблиц** и другой служебной информации.

#### Как работает

1. Пользователь выполняет SQL‑подобный запрос в Hive (eg. `SELECT * FROM sales`), [[HiveQL]].
2. Hive обращается к Metastore, чтобы узнать:
   * где физически лежат данные таблицы `sales`;
   * как они структурированы (какие колонки, их типы);
   * на какие разделы разбита таблица.
3. Получив метаданные, Hive строит план выполнения запроса и обрабатывает данные.
4. При создании новой таблицы (`CREATE TABLE`) Hive записывает её описание в Metastore.

#### Архитектура

Типичная конфигурация включает три компонента:
1. **Hive Client** — инструмент, с которого пользователь отправляет запросы (CLI, Beeline и т. п.).
2. **Metastore Service** — сервис, который предоставляет API для чтения и записи метаданных.
3. **База данных** — реляционное хранилище для самих метаданных (обычно MySQL, PostgreSQL, Derby и др.).

#### Ключевые особенности

* **централизация** — метаданные доступны всем компонентам экосистемы (Hive, Spark, Presto и др.), если они подключены к одному Metastore;
* **совместимость** — позволяет разным инструментам согласованно работать с одними и теми же таблицами;
* **управление схемой** — поддержка эволюций схемы (например, добавление колонок);
* **поддержка разделов и бакетирования** — информация о partitioning и bucketing хранится и используется для оптимизации запросов.

#### Режимы развёртывания

* **Embedded** (встроенный) — Metastore и база данных запускаются в том же процессе, что и Hive (по умолчанию, подходит для тестов).
* **Local** — Metastore работает в отдельном процессе на том же сервере, база данных — локальная или удалённая.
* **Remote** — Metastore запущен как отдельный сервис, доступный по сети; несколько клиентов могут подключаться к нему одновременно (рекомендуется для продакшена).

#### Зачем нужен

Без Metastore Hive не смог бы:
* находить данные по имени таблицы;
* понимать структуру данных (колонки, типы);
* оптимизировать запросы с учётом разделов;
* обеспечивать единый взгляд на данные для разных инструментов.

### Краткий итог

**Hive Metastore = каталог (каталог метаданных) для Hive.** Он отвечает на вопросы:
* *Что* это за таблица?
* *Где* лежат её данные?
* *Как* они структурированы?

Это критически важный компонент для организации работы с данными в Hadoop‑экосистеме, обеспечивающий единую точку управления метаданными и совместимость между инструментами.
