# Privacy by Design (PbD, «Проектируемая конфиденциальность»)

## ✅ Что такое Privacy by Design?

> **Privacy by Design** — это подход, при котором **конфиденциальность и защита данных встроены в архитектуру и процессы системы**, а не добавлены позже.

### 💬 Простыми словами:
> «Не думай о приватности после запуска. Думай об этом до первой строки кода.»

---

## ✅ 7 принципов Privacy by Design (по Ann Cavoukian)

1. **Proactive not Reactive**  
   → Защита данных должна быть **проактивной**, а не реагировать на утечки.

2. **Privacy as the Default Setting**  
   → Пользователь **не должен ничего делать**, чтобы быть защищённым.

3. **Privacy Embedded into Design**  
   → Приватность — часть архитектуры, а не отдельный модуль.

4. **Full Functionality – Positive-Sum, not Zero-Sum**  
   → Безопасность ≠ жертва функциональностью. Можно иметь и то, и другое.

5. **End-to-End Security – Full Lifecycle Protection**  
   → Данные защищаются от сбора до удаления.

6. **Visibility and Transparency**  
   → Пользователь видит, как используются его данные.

7. **Respect for User Privacy – Keep it User-Centric**  
   → Интересы пользователя — в центре.

## ✅ Примеры реализации

### 🔹 Пример 1: Регистрация на сайте

| Без PbD | С PbD |
|--------|-------|
| Запрашивает email, телефон, адрес, ИНН | Запрашивает только email |
| Пароль хранится в открытом виде | Пароль хэшируется (bcrypt) |
| Нет согласия на рассылку | Есть чекбокс "Согласен на рассылку" |

> ✅ **Принцип**: Минимизация данных + согласие по умолчанию

---

### 🔹 Пример 2: Мобильное приложение

| Без PbD | С PbD |
|--------|-------|
| Запрашивает доступ к геолокации всегда | Запрашивает только при использовании карты |
| Хранит историю местоположений | Не хранит историю — только текущее место |
| Нет настроек приватности | Есть раздел "Приватность" в настройках |

> ✅ **Принцип**: Защита по умолчанию + прозрачность

---

### 🔹 Пример 3: Аналитика сайта

| Без PbD | С PbD |
|--------|-------|
| Отправляет IP, user-agent, cookies | Отправляет только агрегированные данные |
| Использует Google Analytics без согласия | Использует cookie-баннер и анонимизацию IP |

> ✅ **Принцип**: Минимизация + согласие

---

### 🔹 Пример 4: Удаление аккаунта

| Без PbD | С PbD |
|--------|-------|
| "Удалить аккаунт" = деактивация | "Удалить аккаунт" = полное удаление данных |
| Нет подтверждения | Есть подтверждение + срок удаления |

> ✅ **Принцип**: Полный жизненный цикл + уважение к пользователю

## ✅ Технические меры для PbD

| Мера | Описание |
|------|----------|
| **Data Minimization** | Собирайте только необходимые данные |
| **Encryption at Rest/Transit** | Шифрование данных в покое и при передаче |
| **Access Control** | Только авторизованные пользователи могут получить доступ |
| **Anonymization/Pseudonymization** | Удаляйте или заменяйте идентификаторы |
| **Audit Logs** | Логируйте доступ к данным |
| **Consent Management** | Управляйте согласиями пользователей |

# Типовые решения PbD
Вот **список типовых и наиболее распространённых решений**, которые применяются для реализации **Privacy by Design (PbD)** в реальных системах.

---

## ✅ 1. **Минимизация данных (Data Minimization)**

> Собирайте **только то, что действительно нужно**.

### 🛠️ Решения:
- Удаляйте неиспользуемые поля из форм
- Не запрашивайте ИНН, паспортные данные без необходимости
- Используйте **анонимные сессии** вместо персональных данных

> 💡 Пример: Регистрация через email → не требовать телефон, имя, адрес.

---

## ✅ 2. **Анонимизация и псевдонимизация**

> Заменяйте идентификаторы на анонимные токены.

### 🛠️ Решения:
- **Hashing** (например, `sha256(email)`)
- **Tokenization** (замена email на `user_12345`)
- **Дифференциальная приватность** (добавление шума в данные)
- **k-анонимность** (группировка записей)

> 💡 Пример: Аналитика — использует `user_id`, но не знает email.

---

## ✅ 3. **Шифрование данных**

> Защищайте данные **в покое и при передаче**.

### 🛠️ Решения:
- **TLS 1.3** для всех соединений
- **AES-256** для данных в базе
- **Client-side encryption** (шифрование до отправки на сервер)
- **Homomorphic encryption** (вычисления над зашифрованными данными)

> 💡 Пример: Пароли хранятся как `bcrypt(password)`.

---

## ✅ 4. **Управление согласиями (Consent Management)**

> Давайте пользователям **контроль над своими данными**.

### 🛠️ Решения:
- **Cookie-баннеры** с выбором категорий
- **Панель управления приватностью** в профиле
- **API для отзыва согласия**
- **Журнал согласий** (кто, когда, на что согласился)

> 💡 Пример: Настройки → «Отключить аналитику».

---

## ✅ 5. **Право на удаление (Right to Erasure / "Забвение")**

> Обеспечьте **полное удаление данных** по запросу.

### 🛠️ Решения:
- **Soft delete + hard delete** через N дней
- **Очистка бэкапов** (или шифрование с отдельным ключом)
- **Инвентаризация данных** (где хранятся данные пользователя)
- **Автоматизированный workflow удаления**

> 💡 Пример: «Удалить аккаунт» → удаляет всё за 30 дней.

---

## ✅ 6. **Прозрачность и открытость**

> Пользователь должен понимать, **как используются его данные**.

### 🛠️ Решения:
- **Понятная политика конфиденциальности**
- **Интерактивные объяснения** («Почему мы просим это?»)
- **Data Subject Access Request (DSAR) API**
- **Лог доступа к данным** (кто смотрел ваш профиль?)

> 💡 Пример: При наведении на поле — всплывает подсказка.

---

## ✅ 7. **Безопасность по умолчанию (Privacy by Default)**

> Настройки должны быть **максимально приватными из коробки**.

### 🛠️ Решения:
- Все чекбоксы **не отмечены** по умолчанию
- Профиль **закрытый** до явного разрешения
- Данные **не передаются третьим лицам** без согласия

> 💡 Пример: Соцсеть — профиль виден только друзьям.

---

## ✅ 8. **Аудит и мониторинг**

> Отслеживайте, **кто и как использует данные**.

### 🛠️ Решения:
- **Audit logs** для всех операций с персональными данными
- **Alerting** при подозрительной активности
- **Регулярные проверки соответствия** (GDPR, CCPA)

> 💡 Пример: Лог: «Админ X просмотрел данные пользователя Y».

---

## ✅ 9. **Data Protection Impact Assessment ([[DPIA]])**

> Оценивайте риски **до запуска** нового функционала.

### 🛠️ Решения:
- Чек-листы для новых фич
- Вовлечение DPO (Data Protection Officer)
- Тестирование на утечки

> 💡 Пример: Перед запуском facial recognition — провести DPIA.

---

## ✅ 10. **Обучение команды**

> Инженеры и продакты должны **понимать PbD**.

### 🛠️ Решения:
- Внутренние тренинги по GDPR/PbD
- Чек-листы для код-ревью («Проверь минимизацию данных»)
- Включение PbD в Definition of Done

> 💡 Пример: Код не мержится, если нет обработки прав на удаление.

---

## ✅ Финальный вывод

| Категория | Типовое решение |
|----------|------------------|
| Сбор данных | Минимизация, согласие по умолчанию |
| Хранение | Шифрование, анонимизация |
| Использование | Прозрачность, аудит |
| Удаление | Право на забвение, очистка бэкапов |
| Управление | Consent API, DPIA, обучение |

> 💬 _“Privacy by Design is not a feature. It’s a checklist.”_

### история Privacy by Design
**Privacy by Design** — концепция, разработанная Энн Кавукиан (Ann Cavoukian #👨 ) в 90-х годах. Она предполагает, что защита личной информации должна быть **приоритетом** в работе любой организации и заложена в основу систем, процессов и продуктов, а не добавлена постфактум.
