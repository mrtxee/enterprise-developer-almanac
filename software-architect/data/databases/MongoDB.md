## 🧠 Что такое MongoDB?

**MongoDB** — это **документно-ориентированная база данных**, относящаяся к классу **NoSQL** систем.  
Она хранит данные не в таблицах (как SQL-базы: MySQL, PostgreSQL), а в **гибких документах**, похожих на **JSON**.

> 💡 Основная идея: данные хранятся так, как их использует приложение — в виде вложенных структур, без жёсткой схемы.

---

## 📦 Основные понятия MongoDB

| Термин в MongoDB | Аналог в SQL | Описание |
|------------------|--------------|--------|
| **Database** | База данных | Контейнер для коллекций |
| **Collection** | Таблица | Группа документов (аналог строк) |
| **Document** | Строка (запись) | Единица данных в формате BSON (бинарный JSON) |
| **Field** | Столбец | Ключ в документе |

### Пример документа:
```json
{
  "_id": ObjectId("507f1f77bcf86cd799439011"),
  "name": "Алексей",
  "email": "alex@example.com",
  "age": 30,
  "address": {
    "city": "Москва",
    "street": "Тверская"
  },
  "hobbies": ["чтение", "велосипед"]
}
```

> 🔹 `_id` — уникальный идентификатор (автоматически генерируется, если не задан).
> 🔹 Документы в одной коллекции **могут иметь разную структуру** (гибкая схема).

## 🌟 Ключевые особенности MongoDB

### 1. **Документная модель**
- Данные хранятся как вложенные объекты → меньше JOIN’ов.
- Пример: информация о пользователе и его адресе — в одном документе.

### 2. **Гибкая схема (Schema-less)**
- Нет необходимости заранее определять структуру.
- Разные документы в одной коллекции могут содержать разные поля.

> ✅ Удобно для agile-разработки, когда требования часто меняются.

### 3. **Высокая производительность**
- Чтение и запись — очень быстрые благодаря:
  - Встроенной поддержке индексов
  - Хранению данных в формате **BSON** (Binary JSON)
  - Возможности масштабирования

### 4. **Масштабируемость (горизонтальное шардирование)**
- MongoDB легко масштабируется **горизонтально**:
  - Данные распределяются по нескольким серверам (**шардам**).
  - Подходит для больших нагрузок и big data.

### 5. **Репликация и отказоустойчивость**
- **Replica Set** — группа серверов, где:
  - Один — **primary** (принимает запись)
  - Остальные — **secondary** (копии данных)
- При падении primary автоматически выбирается новый → **высокая доступность**.

### 6. **Поддержка транзакций (с версии 4.0)**
- Раньше MongoDB не поддерживала мультидокументные транзакции.
- Сейчас — **да**, включая ACID-гарантии (но с накладными расходами).

## 🛠️ Когда использовать MongoDB?

✅ **Хорошо подходит для:**
- Веб- и мобильных приложений
- Контент-менеджмент систем (CMS)
- IoT и логирование (много структурированных данных)
- Приложений с быстро меняющейся схемой
- Хранения JSON-подобных данных

❌ **Не лучший выбор для:**
- Систем, требующих сложных JOIN’ов и отчётов (лучше SQL)
- Финансовых систем с жёсткими требованиями к согласованности (хотя транзакции есть — но осторожно)
- Когда данные строго реляционные (например, бухгалтерия)

## 🔧 Примеры запросов

### Вставка:
```javascript
db.users.insertOne({
  name: "Иван",
  email: "ivan@example.com"
})
```

### Поиск:
```javascript
db.users.find({ name: "Иван" })
```

### Обновление:
```javascript
db.users.updateOne(
  { email: "ivan@example.com" },
  { $set: { age: 25 } }
)
```

### Индекс:
```javascript
db.users.createIndex({ email: 1 }) // 1 = по возрастанию
```

## 📦 Экосистема MongoDB

- **MongoDB Atlas** — облачная база данных от официального разработчика (как managed-сервис).
- **Compass** — GUI для работы с базой.
- **MongoDB Shell (mongosh)** — интерактивная консоль.
- Поддержка почти всеми языками: Python, Node.js, Java, C#, Go и др.

---

## 🎯 Итог

> **MongoDB — это современная, гибкая, масштабируемая база данных для приложений, где важны скорость разработки, гибкость схемы и производительность.**  
> Она не заменяет SQL, а **дополняет** — выбирается под задачу.

Если вы работаете с JSON-подобными данными, быстро меняющимися требованиями или строите масштабируемое приложение — MongoDB может быть отличным выбором.
