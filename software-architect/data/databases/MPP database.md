### Правильный английский термин

Правильное название — **MPP database**, что расшифровывается как **Massively Parallel Processing database** («база данных с массово‑параллельной обработкой»).

---

### Что это такое

**MPP‑база данных** — это система управления базами данных (СУБД), оптимизированная для параллельной обработки данных. Её ключевая особенность — распределение задач обработки между множеством независимых узлов (серверов).

**Основные компоненты архитектуры:**

1. **Лидер‑узел (leader node)** — координирует работу, принимает запросы от пользователей, распределяет задачи между вычислительными узлами и собирает итоговые результаты.
2. **Вычислительные узлы (compute nodes)** — выполняют обработку данных. Каждый узел:
    * имеет собственную операционную систему и память;
    * работает независимо от других;
    * обрабатывает свою часть данных;
    * может разбивать задачи на более мелкие подзадачи.
3. **Система хранения** — часто использует **колоночное хранение** (columnar storage), что ускоряет выполнение аналитических запросов.
4. **Сетевая инфраструктура** — обеспечивает связь между узлами.

Архитектура MPP следует принципу **«ничего не разделяется» (share‑nothing)**: у каждого узла свои ресурсы (память, процессор, диск), нет общего пула памяти. Это снижает вероятность узких мест (bottlenecks) и повышает масштабируемость.

---

### Для чего нужна MPP‑база данных

MPP‑базы данных предназначены для решения задач, требующих обработки **огромных объёмов структурированных данных** и выполнения **сложных аналитических запросов**.

**Ключевые сценарии использования:**

* **Хранилища данных (data warehouses)** — централизованное хранение больших массивов данных для последующего анализа.
* **Системы поддержки принятия решений (decision support systems, DSS)** — предоставление информации для стратегического планирования.
* **Аналитика больших данных (big data analytics)** — извлечение закономерностей из терабайт и петабайт данных.
* **Облачные вычисления (cloud computing)** — масштабируемые решения для обработки данных в облаке (например, Amazon Redshift).
* **Машинное обучение и симуляции** — подготовка данных и выполнение ресурсоёмких вычислений.
* **Научная обработка данных** — анализ результатов экспериментов, моделирование.
* **Финансы и электронная коммерция** — анализ транзакций, прогнозирование спроса, выявление мошенничества.
* **Телекоммуникации** — обработка данных о вызовах и использовании сети.

### Преимущества MPP‑баз данных

1. **Высокая производительность.** Параллельная обработка позволяет выполнять сложные запросы к большим наборам данных за приемлемое время.
2. **Горизонтальная масштабируемость.** Можно добавлять новые узлы для увеличения мощности без остановки системы. Это даёт почти неограниченную масштабируемость.
3. **Экономическая эффективность.** Не требуется покупать сверхмощные (и дорогие) серверы. Вместо этого используются более дешёвые стандартные узлы.
4. **Отказоустойчивость.** При выходе из строя одного узла остальные продолжают работать, минимизируя риск единой точки отказа.
5. **Локальность данных.** Обработка происходит на том же узле, где хранятся данные, что снижает задержки (latency).
6. **Поддержка SQL.** Большинство MPP‑СУБД совместимы со стандартными инструментами бизнес‑аналитики (BI), такими как Power BI, Tableau, Looker.

---

### Примеры реализаций

* **Amazon Redshift** — облачная MPP‑СУБД от AWS.
* **Google BigQuery** — облачная платформа для аналитики больших данных.
* **Snowflake** — облачное хранилище данных с MPP‑архитектурой.
* **Teradata** — классическое решение для корпоративных хранилищ данных.
* **Vertica** — колоночная MPP‑СУБД.
