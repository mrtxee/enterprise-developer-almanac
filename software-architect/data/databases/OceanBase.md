## OceanBase

**OceanBase** — это распределённая реляционная база данных, изначально разработанная компанией Ant Group (входит в Alibaba Group). Она создавалась для обслуживания финансовой платформы Alipay и способна обрабатывать миллионы транзакций в секунду. С 2021 года код открыт под лицензией Mulan PubL и доступен на GitHub, с 2024 года поддерживается независимой организацией OceanBase Database Foundation.

**Основные особенности:**

- **Совместимость с MySQL и Oracle** — поддерживает синтаксис и протокол MySQL 5.7/8.0, а также значительную часть синтаксиса PL/SQL Oracle, что упрощает миграцию.
- **Leaderless-архитектура** — каждый узел кластера равноправен, нет единой точки отказа. Данные автоматически реплицируются между узлами на основе протокола Paxos.
- **Транзакционность ACID** — строгая согласованность даже в распределённых транзакциях.
- **Горизонтальное масштабирование** — производительность и объём хранения растут линейно при добавлении узлов.
- **Multi-tenant архитектура** — одна инсталляция может обслуживать тысячи изолированных «арендаторов» (тенантов) с независимыми ресурсами.
- **Высокая доступность** — автоматический фейловер с временем восстановления (RTO) менее 8 секунд при отказе узла.
- **HTAP (Hybrid Transactional/Analytical Processing)** — способность выполнять как оперативные транзакции (OLTP), так и сложные аналитические запросы (OLAP) на одном наборе данных без ETL-переноса.
- **Сжатие данных** — использует гибридное сжатие на основе кодирования, уменьшая объём хранения в несколько раз по сравнению с традиционными СУБД.
- **Бесплатная версия OceanBase Community Edition** доступна для production-использования без ограничений по данным.

7На февраль 2025 года база данных OceanBase является эталоном производительности в рейтинге TPC-C, превосходя как традиционные базы данных, так и такие распределённые системы, как CockroachDB и TiDB.

## OceanBase vs Greenplum

**OceanBase** и **Greenplum** — это распределённые реляционные СУБД, но с принципиально разной архитектурой и специализацией. Если кратко: OceanBase — для оперативной обработки транзакций (OLTP) с возможностью аналитики, Greenplum — для тяжёлой аналитики (OLAP) на огромных массивах данных.

### Сравнительная таблица

| Характеристика         | OceanBase                                                     | Greenplum                                                         |
| :--------------------- | :------------------------------------------------------------ | :---------------------------------------------------------------- |
| **Тип нагрузки**       | OLTP + лёгкая аналитика (HTAP)                                | OLAP (сложные аналитические запросы)                              |
| **Архитектура**        | Leaderless (равноправные узлы), Paxos                         | MPP (Massively Parallel Processing), master/segment-узлы          |
| **Масштабирование**    | Горизонтальное, автоматическое                                | Горизонтальное, настройка распределения данных                    |
| **Транзакции**         | Строгие ACID, распределённые                                  | ACID, но оптимизированы для массовой загрузки, а не мелких update |
| **Совместимость**      | MySQL, Oracle (PL/SQL)                                        | PostgreSQL, частично Oracle                                       |
| **Хранение данных**    | Сжатие в несколько раз, LSM-tree                              | Колоночное и строковое, сжатие (zstd, gzip)                       |
| **Типичные сценарии**  | Финансовые транзакции, интернет-сервисы с миллионами операций | Хранилища данных (DWH), BI-отчёты, машинное обучение              |
| **Производительность** | Рекорд TPC-C (транзакции)                                     | Высокая на сложных JOIN и агрегациях по петабайтам                |
| **Open Source**        | Mulan PubL (открытый, 2021)                                   | Apache 2.0 (открытый, 2015)                                       |
| **Разработчик**        | Ant Group (Alibaba)                                           | Изначально Pivotal (VMware), сейчас сообщество                    |

### Когда что выбирать

- **OceanBase** — если нужно заменить Oracle/MySQL в высоконагруженных системах онлайн-обработки (банки, платежи, интернет-магазины) и при этом иногда выполнять аналитику без ETL.
- **Greenplum** — если стоит задача построить корпоративное хранилище данных для сложных отчётов, дашбордов и Data Science на десятках терабайт/петабайт.

Они не столько конкуренты, сколько взаимодополняющие решения в разных сегментах корпоративной IT-инфраструктуры.

## OceanBase vs CockroachDB

**OceanBase** и **CockroachDB** — это распределённые SQL-базы данных, спроектированные для высокой доступности и горизонтального масштабирования. Обе совместимы с PostgreSQL или MySQL, но сильно различаются архитектурой и идеологией.

### 📊 Сравнительная таблица

| Характеристика          | OceanBase                                         | CockroachDB                                          |
| :---------------------- | :------------------------------------------------ | :--------------------------------------------------- |
| **Архитектура**         | Leaderless (равноправные узлы)                    | Один лидер на диапазон ключей (range lease)          |
| **Консенсус**           | Собственный протокол на базе Paxos                | Raft                                                 |
| **Совместимость с SQL** | MySQL 5.7/8.0, частично Oracle PL/SQL             | PostgreSQL (Wire Protocol, синтаксис)                |
| **Транзакции**          | Распределённые ACID, оптимистичные/пессимистичные | Только сериализуемые (Serializable) по умолчанию     |
| **Масштабирование**     | Автоматическое, эластичное добавление узлов       | Автоматический шардинг и ребалансировка диапазонов   |
| **Гео-репликация**      | Репликация между дата-центрами, но менее гибкая   | Нативная multi-region с политиками размещения данных |
| **Производительность**  | Экстремальная для OLTP (рекорды TPC-C)            | Хорошая, но уступает в транзакционной нагрузке       |
| **Хранилище**           | LSM-tree, гибридное сжатие                        | RocksDB (LSM-tree), сжатие Snappy/ZSTD               |
| **Лицензия**            | Mulan PubL (открытая, 2021)                       | Business Source License (BSL), с 2024 частично MIT   |
| **Разработчик**         | Ant Group (Alibaba)                               | Cockroach Labs                                       |

### 🎯 Ключевые различия

**1. Подход к распределённости**

- **CockroachDB** изначально создавалась как глобально-распределённая база данных для выживания при отказах целых дата-центров. Её фишка — политики размещения данных (locality rules), позволяющие хранить строки таблицы в конкретных регионах и соблюдать требования GDPR.
- **OceanBase** создавалась для обработки миллионов транзакций внутри одного ЦОДа (Alipay), а гео-репликация добавлена позже. Она менее гибкая в мульти-региональных сценариях.

**2. Производительность OLTP**

- **OceanBase** — рекордсмен TPC-C, способна утилизировать сотни ядер и показывать минимальные задержки. Использует сложные оптимизации для финансовых транзакций, горячих строк (early lock release).
- **CockroachDB** проигрывает в сырой производительности OLTP из-за обязательной сериализуемости транзакций и архитектуры с лидером на диапазон.

**3. Изоляция транзакций**

- **CockroachDB** поддерживает **только Serializable** — самый строгий уровень изоляции, исключающий любые аномалии. Это плюс для консистентности, но минус для производительности при высоком конкурентном доступе.
- **OceanBase** поддерживает несколько уровней (Read Committed, Repeatable Read, Serializable), что позволяет выбрать баланс между скоростью и консистентностью под конкретную задачу.

**4. Совместимость**

- **OceanBase** хороша для миграции с MySQL или Oracle (поддерживает PL/SQL, пакеты, триггеры Oracle).
- **CockroachDB** удобна для миграции с PostgreSQL (совместимость с драйверами и ORM, большинство типов данных, индексы GIN/GiST).

**5. Десктопное использование**

- **CockroachDB** имеет лёгкий бинарный файл (около 80 МБ), запускается одной командой (`cockroach start-single-node`) без Docker и отлично подходит для локальной разработки.
- **OceanBase** требует значительно больше ресурсов даже для минимальной конфигурации (рекомендуется 6+ ГБ ОЗУ), запускается сложнее.

### 💎 Когда что выбирать

| Сценарий | Рекомендация |
| :--- | :--- |
| Высоконагруженные финансовые транзакции, замена Oracle | **OceanBase** |
| Глобально распределённое приложение с клиентами в разных регионах | **CockroachDB** |
| Миграция с PostgreSQL без переписывания кода | **CockroachDB** |
| Миграция с MySQL/Oracle с хранимыми процедурами | **OceanBase** |
| Стартап, нужна простая в развёртывании распределённая БД | **CockroachDB** |
| Крупный enterprise с собственными дата-центрами и командой DBA | **OceanBase** |
