## DPIA: определение

**Data Protection Impact Assessment (DPIA)** — это **формальный процесс оценки рисков для прав и свобод физических лиц**, связанных с обработкой [[personal-data|персональных данных]].

> **DPIA** — это **анализ потенциальных угроз конфиденциальности**, который проводится **до запуска нового проекта, продукта или процесса**, связанного с обработкой персональных данных.

**Простыми словами:**

> «Перед сбором данных пользователей стоит подумать: не навредим ли мы им?»

---

## Когда требуется DPIA

Согласно **GDPR (статья 35)**, DPIA **обязателен**, если обработка данных:

1. **Вероятно приведёт к высокому риску** для прав и свобод физических лиц.
2. Включает **одну или несколько** из следующих ситуаций:

| Ситуация | Пример |
|----------|--------|
| **Оценка на основе профилирования** | Кредитный скоринг, рекомендации |
| **Автоматическое принятие решений с юридическими последствиями** | Отказ в кредите без участия человека |
| **Наблюдение за публичными зонами в большом масштабе** | Распознавание лиц в камерах наблюдения |
| **Обработка специальных категорий данных** | Здоровье, раса, религия, биометрия |
| **Обработка данных уязвимых групп** | Дети, пожилые, пациенты |
| **Использование новых технологий** | ИИ, блокчейн, IoT-устройства |

> ⚠️ Если проект попадает под эти критерии — **DPIA обязателен**.

## Этапы проведения DPIA

### Описание обработки

- Какие данные собираются?
- Для какой цели?
- Кто получатель данных?

### Оценка необходимости и пропорциональности

- Нужна ли эта обработка?
- Можно ли достичь цели менее инвазивным способом?

### Оценка рисков

- Какие угрозы для конфиденциальности?
- Какова вероятность и тяжесть последствий?

### Меры по снижению рисков

- Шифрование, [[privacy-enhancing-technology|анонимизация]], согласие
- Технические и организационные меры

### Консультация с DPO (Data Protection Officer)

- Если есть DPO — он должен одобрить DPIA

### Документирование и мониторинг

- Сохранение отчёта
- Обновление при изменении системы

## Пример DPIA: мобильное приложение для здоровья

| Этап | Описание |
|------|----------|
| **Обработка** | Сбор данных о пульсе, сне, шагах |
| **Цель** | Персонализированные рекомендации |
| **Риски** | Утечка медицинских данных → дискриминация |
| **Меры** | Анонимизация, шифрование, согласие пользователя |
| **Результат** | Риск снижен до приемлемого уровня |

---

## Инструменты для DPIA

| Инструмент | Описание |
|-----------|----------|
| **Чек-листы от регуляторов** | Например, от ICO (UK), CNIL (France) |
| **Шаблоны DPIA** | Готовые документы от Еврокомиссии |
| **Программное обеспечение** | OneTrust, TrustArc, Securiti.ai |
| **Внутренние процессы** | Интеграция в CI/CD, Definition of Done |

---

## Отличие от других оценок

| Оценка | Фокус | DPIA отличается тем, что... |
|--------|-------|-----------------------------|
| **Risk Assessment** | Общие риски бизнеса | Фокусируется **только на персональных данных** |
| **Security Audit** | Техническая безопасность | Включает **правовые и этические аспекты** |
| **PIA (Privacy Impact Assessment)** | Более широкое понятие | **DPIA — это PIA по стандарту GDPR** |
