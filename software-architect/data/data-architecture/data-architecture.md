## Архитектура данных

**Определение**

Архитектура данных — это описание системы, обеспечивающей работу с информацией на предприятии. Она определяет:

- процессы сбора, хранения, интеграции и использования информации;
- правила, методы и стандарты работы с данными;
- инфраструктуру и инструменты для управления данными.

**Цель** — перевести бизнес-потребности в требования к данным и системам, управлять потоками данных в компании.

**Уровни архитектуры данных**

1. **Концептуальный уровень (бизнес-модель, Conceptual Level)** — описывает перечень объектов данных и их семантическую модель. Отвечает на вопрос «что?» — какие данные нужны бизнесу.
2. **Логический уровень (системная модель, Logical Level)** — определяет взаимосвязи объектов данных, их логическую модель. Отвечает на вопрос «как структурированы?» — схема баз данных, сущности и связи.
3. **Физический уровень (технологическая модель, Physical Level)** — описывает механизмы работы с данными: способы хранения, инструменты, инфраструктуру. Отвечает на вопрос «где и как хранится?» — БД, серверы, облачные хранилища.

**Ключевые компоненты архитектуры данных**

- **Модели данных (Data Models)** — схемы организации данных (реляционные, NoSQL, графовые и др.).
- **Правила и стандарты (Policies and Standards)** — регламенты работы с данными: форматы, безопасность, качество.
- **Инфраструктура хранения (Storage Infrastructure)** — БД, дата-лейки (data lakes), дата-ворхаусы (data warehouses), облачные хранилища.
- **Трубопроводы данных (Data Pipelines)** — процессы сбора, трансформации и доставки данных.
- **API (Application Programming Interfaces)** — интерфейсы для обмена данными между системами.
- **Инструменты аналитики (Analytics Tools)** — системы для обработки и анализа данных (BI-системы, ML-модели).
- **Механизмы безопасности (Security Mechanisms)** — шифрование, контроль доступа, аудит.
- **Системы управления данными (Data Management Systems)** — инструменты для жизненного цикла данных.

**Типы данных в архитектуре данных**

- **Мастер-данные (Master Data)** — ключевая информация для бизнес-функций (клиенты, продукты, сотрудники).
- **Метаданные (Metadata)** — данные о данных (форматы, источники, описания).
- **Транзакционные данные (Transactional Data)** — данные о бизнес-операциях (продажи, платежи).
- **Исторические данные (Historical Data)** — архивная информация для анализа и отчётов.

**Популярные фреймворки для архитектуры данных**

- **[[TOGAF|TOGAF]] (The Open Group Architectural Framework)** — модульный подход к созданию архитектуры предприятия, включая данные.
- **DAMA-DMBOK2 (Data Management Body of Knowledge)** — стандарты управления данными, качество, безопасность.
- **Zachman Framework** — логическая матрица для выравнивания ИТ с бизнес-целями.
- **EDA (Enterprise Data Architecture)** — модель архитектуры корпоративных данных.

**Основные принципы современной архитектуры данных**

- **Масштабируемость (Scalability)** — способность обрабатывать растущие объёмы данных без потери производительности.
- **Гибкость (Flexibility)** — возможность интеграции новых источников данных, технологий.
- **Целостность данных (Data Integrity)** — обеспечение точности, согласованности данных на всём цикле жизни.
- **Безопасность (Security)** — защита данных при передаче и хранении.
- **Согласованность с бизнес-целями (Alignment with Business Needs)** — соответствие архитектуры стратегическим задачам компании.

**Инструменты и технологии**

- **Базы данных:** SQL, NoSQL, NewSQL.
- **Облачные сервисы:** AWS, Google Cloud, Azure.
- **Системы управления данными:** [[map-reduce|Hadoop]], Spark, [[kafka|Kafka]].
- **BI-инструменты:** [[tableau|Tableau]], Power BI, Qlik.
- **Средства оркестрации:** [[kubernetes|Kubernetes]].
- **Технологии аналитики:** ML, AI, [[big-data|Big Data]].
- **Системы ETL/ELT** для извлечения, трансформации и загрузки данных.

**Роли в управлении архитектурой данных**

- **Архитектор данных (Data Architect)** — проектирует архитектуру, выбирает технологии.
- **Инженер данных (Data Engineer)** — реализует архитектуру, создаёт пайплайны, хранилища.
- **Аналитик данных (Data Analyst)** — работает с данными для бизнес-аналитики.
- **Учёный по данным (Data Scientist)** — разрабатывает ML-модели, анализирует данные.
- **Менеджер по качеству данных (Data Quality Manager)** — контролирует точность и полноту данных.

**Примеры архитектуры данных**

- хранение CSV-файлов на локальном диске и анализ в [[tableau|Tableau]];
- потоковая передача данных с POS-терминалов в учётную систему;
- накопление данных в дата-лейке с последующей обработкой через Spark/Hadoop;
- централизованное хранение данных для доступа разных бизнес-единиц.

**Тенденции развития**

- децентрализация управления данными;
- использование Data Fabric для интеграции данных в гибридных средах;
- обработка данных в реальном времени (streaming);
- автоматизация управления данными с помощью ИИ;
- распределённые базы данных для глобальной масштабируемости;
- усиление акцента на кибербезопасность и соответствие нормативам.

### Data Warehouse vs Data Lake

| **Параметры**             | **Data Warehouse**                                               | **Data Lake**                                                                    |
| ------------------------- | ---------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| **Хранение**              | Данные очищаются и хранятся в трансформированном виде            | Данные хранятся в исходном виде и трансформируются, когда готовы к использованию |
| **История** | Концепция [[data-warehouse|хранилищ данных]] используется уже несколько десятилетий | Технологии больших данных, используемые в [[data-lake|озёрах данных]], относительно новые |
| **Типы данных**           | Структурированные данные                                         | Структурированные, полуструктурированные и неструктурированные данные            |
| **Пользователи**          | Операционные пользователи, аналитики данных                      | Аналитики данных, учёные по данным                                               |
| **Подход к обработке**    | Предопределённые запросы для заранее определённых типов данных   | Исследование данных                                                              |
| **Схема загрузки данных** | ETL (извлечение, трансформация, загрузка)                        | ELT (извлечение, загрузка, трансформация)                                        |

### Data Lakehouse vs Warehouse vs Lake

| **[[data-warehouse|Data warehouse]]**                                         | **[[data-lake|Data lake]]**                                                          | **[[data-lakehouse|Data lakehouse]]**                                             |
| -------------------------------------------------------------- | -------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| Не поддерживает полу- и неструктурированные данные             | Поддерживает большие объёмы структурированных и неструктурированных данных | Поддерживает анализ структурированных и неструктурированных данных |
| Отличный анализ структурированных данных                       | Плохо подходит для анализа структурированных данных                        | Поддерживает анализ неструктурированных и структурированных данных |
| Более управляемый                                              | Управление данными — сложная задача                                        | Управляемый                                                        |
| Подтверждённая конфиденциальность и безопасность               | Склонен к превращению в «болото данных»                                    | Надёжная архитектура безопасности                                  |
| Относительно дорогой при масштабировании                       | Относительно недорогой                                                     | Экономически эффективный                                           |
| Недостаток гибкости                                            | Поддерживает быстрое экспериментирование                                   | Гибкий и масштабируемый                                            |
| Больше ориентирован на бизнес-аналитику (BI), менее на ИИ (AI) | Больше ориентирован на искусственный интеллект (AI), менее на BI           | Подходит как для BI, так и для AI                                  |
