## HiveQL и Spark SQL: сравнение языков запросов

**Spark SQL** и **HiveQL** — это два языка запросов, используемых для анализа [[big-data|больших данных]], но они принадлежат к **разным поколениям** и имеют **разные архитектуры выполнения**.

---

## Краткое сравнение

| Характеристика | **HiveQL** | **Spark SQL** |
|----------------|------------|---------------|
| **Поколение** | 1-е (2008) | 2-е (2014) |
| **Движок** | [[MapReduce|MapReduce]] (по умолчанию), Tez, Spark | **Spark Engine** (in-memory processing) |
| **Скорость** | Медленная (дисковые операции) | 🔥 **Быстрая** (in-memory, DAG) |
| **Язык запросов** | Почти SQL92 | **Полный ANSI SQL** + расширения |
| **Интерактивность** | Низкая (минуты/часы) | Высокая (секунды) |
| **Интеграция** | Hadoop-экосистема | Spark-экосистема (MLlib, Streaming) |

---

## HiveQL: язык запросов Hadoop

### История

- Создан в **Facebook** (2008) для анализа логов.
- Цель: позволить **SQL-разработчикам** работать с [[map-reduce|Hadoop]] без Java/MapReduce.

### Как работает

1. Запрос на HiveQL → преобразуется в **MapReduce-задачи**.
2. MapReduce читает данные из HDFS → обрабатывает → пишет обратно на диск.
3. Результат возвращается пользователю.

> ⚠️ **Каждый этап — дисковая операция** → медленно.

### Пример HiveQL

```sql
-- Почти как SQL, но с особенностями
CREATE TABLE logs (
    user_id STRING,
    event_time TIMESTAMP
)
PARTITIONED BY (dt STRING)
STORED AS PARQUET;

SELECT COUNT(*) FROM logs WHERE dt = '2024-05-01';
```

### Особенности

- ✅ поддержка **сложных ETL-процессов**;
- ✅ интеграция с **Hive Metastore** (единый каталог таблиц);
- ✅ работает на **любом Hadoop-кластере**;
- ❌ **медленный** (не подходит для интерактивных запросов);
- ❌ ограниченная поддержка **подзапросов**, **оконных функций** (в старых версиях).

---

## Spark SQL: язык запросов Spark

### История

- Часть **Apache Spark** (2014).
- Цель: объединить **SQL**, **программирование** и [[machine-learning|машинное обучение]] в одной системе.

### Как работает

1. Запрос на Spark SQL → оптимизируется через **Catalyst Optimizer**.
2. Выполняется как **[[DAG|DAG]] (Directed Acyclic Graph)** задач в памяти.
3. Промежуточные результаты **не пишутся на диск** → скорость.

> ✅ **In-memory processing** → до **100x быстрее** Hive на MapReduce.

### Пример Spark SQL

```sql
-- Полный ANSI SQL + расширения
SELECT
    user_id,
    COUNT(*) OVER (PARTITION BY category) AS category_count
FROM sales
WHERE sale_date > current_date() - INTERVAL 7 DAYS;
```

### Особенности

- ✅ **высокая скорость** (in-memory, lazy evaluation);
- ✅ **полная поддержка SQL**: CTE, оконные функции, подзапросы;
- ✅ **интеграция с DataFrame API** (Python, Scala, Java);
- ✅ **единый движок** для SQL, Streaming, ML;
- ❌ требует **больше RAM**;
- ❌ сложнее настроить в legacy-инфраструктуре.

---

## Совместимость

- **Spark SQL поддерживает HiveQL**:
  - может читать таблицы из **Hive Metastore**;
  - поддерживает **Hive UDF**;
  - понимает **Hive-партиции**.

> 💡 HiveQL-запросы можно запускать в Spark SQL почти без изменений.

---

## Выбор инструмента по сценарию

| Сценарий | Рекомендация |
|----------|--------------|
| **Интерактивные запросы** (аналитика, BI) | ✅ **Spark SQL** |
| **Тяжёлые ETL-процессы** (ночные джобы) | ⚠️ Hive на **Tez** или **Spark** |
| **Legacy-система на Hadoop** | HiveQL (но мигрируйте на Spark!) |
| **[[machine-learning|Машинное обучение]] + SQL** | ✅ **Spark SQL** |
| **Ограниченная память, много диска** | Hive на Tez |

## Архитектурное сравнение

### Hive (на MapReduce)

```text
[SQL] → [MapReduce] → [HDFS] → [MapReduce] → [HDFS] → ... → [Результат]
```

→ Каждый этап — **чтение/запись на диск**.

### Spark SQL

```text
[SQL] → [Catalyst Optimizer] → [RDD/Dataset в памяти] → [Результат]
```

→ Промежуточные данные — **в памяти**.

---

**Заключение**

> - **HiveQL** — это «SQL для Hadoop», созданный для batch-обработки.
> - **Spark SQL** — это «SQL для всего», объединяющий аналитику, потоки и ML.

**Современные системы**:

- используют **Hive Metastore** как **каталог метаданных**;
- выполняют запросы через **Spark SQL** (или Trino/Presto).

> 🚀 **HiveQL уходит в прошлое**, но его наследие (Hive Metastore) живёт в новых системах.
