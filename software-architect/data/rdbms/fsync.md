## fsync

**`fsync()`** — это **системный вызов** в Unix/Linux (и аналоги в Windows), который **принудительно сбрасывает буферизованные данные из ОЗУ в постоянное хранилище** (HDD/SSD).

> 💡 Это гарантирует, что данные, которые вы записали в файл, **фактически сохранены на физическом носителе**, а не просто лежат в кэше операционной системы или контроллера диска.

🔹 Почему это важно для БД?

Базы данных используют **журнал перед записью ([[PostgreSQL|WAL]] — Write-Ahead Logging)**.  
Принцип:
1. Перед тем как изменить данные на диске — сначала **пишется журнал изменений**.
2. Когда транзакция коммитится — **должен быть вызван fsync() на WAL-файле**.
3. Только после этого — ответ “OK” клиенту.

Если **не вызвать fsync()**, то:
- OS может отложить запись на минуты (из-за кэша)
- При выключении питания — **все последние изменения пропадут!**
- Нарушается свойство **Durability (D)** из ACID!

Пример ([[PostgreSQL]]):

```bash
# После COMMIT транзакции PostgreSQL:
1. Записывает изменения в WAL-буфер
2. Вызывает fsync() на WAL-файле
3. Только тогда отправляет клиенту: "COMMIT successful"
```

Если `fsync = off` (опасно!):
- БД будет работать **быстрее**
- Но **при сбое питания — потеряете последние секунды данных!**

🔹 Производительность vs Надёжность:

| Режим                                               | Скорость                       | Надёжность                  | Использование                                                               |
| --------------------------------------------------- | ------------------------------ | --------------------------- | --------------------------------------------------------------------------- |
| `fsync = on` / `innodb_flush_log_at_trx_commit = 1` | Медленнее (до 10–50% снижение) | ⭐⭐⭐⭐⭐ (полная Durability)   | **Производственные БД**                                                     |
| `fsync = off` / `= 2`                               | Быстрее                        | ⭐⭐ (потеря данных при сбое) | Тесты, аналитика, временные данные                                          |
| `fsync = every second`                              | Очень быстро                   | ⭐ (потеря до 1 сек)         | Редко — только для критичных к скорости, но терпимых к потере данных систем |

> ⚠️ **Отключение fsync — одна из самых частых причин потери данных в продакшене!**

| Аспект                        | MVCC                                  | fsync                                     |
| ----------------------------- | ------------------------------------- | ----------------------------------------- |
| **Цель**                      | Обеспечить **изоляцию и параллелизм** | Обеспечить **долговечность (Durability)** |
| **Где применяется**           | При чтении/записи строк               | При фиксации транзакции (commit)          |
| **Зависят ли друг от друга?** | **Да, косвенно**                      | **Да, напрямую**                          |

> ✅ **MVCC решает проблему concurrent access, fsync решает проблему crash recovery.  
> Без одного — система не надёжна, без другого — не масштабируема.**

| Понятие   | Что это                                   | Зачем нужно                                           | Ключевая особенность                                    |
| --------- | ----------------------------------------- | ----------------------------------------------------- | ------------------------------------------------------- |
| **MVCC**  | Multi-Version Concurrency Control         | Позволяет читать и писать одновременно без блокировок | Хранит несколько версий строк → изоляция без блокировок |
| **fsync** | Системный вызов для сброса данных на диск | Гарантирует, что данные не потеряются при сбое        | Без него — **нарушается Durability (D)** из ACID        |
