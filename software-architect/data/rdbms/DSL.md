# DSL – Domain-specific language

### Что такое DSL (Domain‑Specific Language)

**DSL** (Domain‑Specific Language) — это специализированный язык программирования или описания, созданный для решения задач **в конкретной предметной области**. В отличие от языков общего назначения (Java, Python, C++), DSL фокусируется на узкой сфере и использует термины и конструкции, понятные экспертам этой области.

**Ключевые признаки DSL:**
- ограниченный круг решаемых задач;
- синтаксис и семантика, близкие к профессиональному жаргону предметной области;
- высокая выразительность для «своих» задач;
- часто не является полнофункциональным языком (может не поддерживать циклы, условия и т. п.).

### Для чего нужен DSL

1. **Упрощение разработки**  
   - Позволяет писать код на «языке предметной области», а не на техническом языке.
   - Пример: бухгалтер пишет правила расчёта налогов, а не алгоритмы на Python.

2. **Снижение порога входа**  
   - Не требует глубоких знаний программирования от конечных пользователей.

3. **Повышение надёжности**  
   - Ограниченный синтаксис уменьшает вероятность ошибок.
   - Валидация на уровне языка (например, проверка единиц измерения).

4. **Улучшение читаемости**  
   - Код понятен экспертам предметной области без перевода.

5. **Автоматизация рутинных операций**  
   - Стандартизация повторяющихся процессов в отрасли.

### Примеры DSL

#### 1. Конфигурационные DSL
- **YAML/JSON для Kubernetes** — описание развёртывания контейнеров.  
  ```yaml
  apiVersion: v1
  kind: Pod
  metadata:
    name: nginx
  spec:
    containers:
    - name: nginx
      image: nginx:1.14.2
  ```

- **Terraform HCL** — описание облачной инфраструктуры.  
  ```hcl
  resource "aws_instance" "web" {
    ami           = "ami-0c55b159cbfafe1f0"
    instance_type = "t2.micro"
  }
  ```

#### 2. Языковые DSL для бизнес‑логики
- **SQL** — язык запросов к базам данных (работа с реляционными данными).  
  ```sql
  SELECT name, salary FROM employees WHERE department = 'IT';
  ```

- **Regular Expressions (RegEx)** — поиск и обработка текста по шаблонам.  
  ```regex
  ^\d{3}-\d{3}-\d{4}$  # Формат телефона XXX-XXX-XXXX
  ```

#### 3. DSL для автоматизации
- **Ansible YAML** — описание задач по управлению серверами.  
  ```yaml
  - name: Install Apache
    apt:
      name: apache2
      state: present
  ```

- **Jenkins Pipeline Groovy** — описание CI/CD‑процессов.  
  ```groovy
  pipeline {
    agent any
    stages {
      stage('Build') {
        steps { sh 'make' }
      }
    }
  }
  ```

#### 4. DSL в науке и инженерии
- **MATLAB/Octave** — математические вычисления и моделирование.  
  ```matlab
  A = [1, 2; 3, 4];
  eig(A)  % Вычисление собственных значений
  ```

- **Verilog/VHDL** — описание цифровых схем (для FPGA/ASIC).  
  ```verilog
  module and_gate(input a, b, output y);
    assign y = a & b;
  endmodule
  ```

#### 5. DSL для веб‑разработки
- **CSS** — описание стилей веб‑страниц.  
  ```css
  body {
    font-family: Arial;
    background-color: #f0f0f0;
  }
  ```

- **GraphQL** — запрос данных из API.  
  ```graphql
  query {
    user(id: 1) {
      name
      email
    }
  }
  ```

#### 6. DSL для анализа данных
- **R (язык статистики)** — анализ данных и визуализация.  
  ```r
  summary(lm(y ~ x1 + x2, data=my_data))
  ```

- **Pandas (Python с DSL‑стилем)** — обработка табличных данных.  
  ```python
  df.groupby('category').agg({'sales': 'sum'})
  ```

### Виды DSL

1. **Внешние DSL**  
   - Имеют собственный синтаксис и парсер.  
   - Примеры: SQL, RegEx, YAML для Kubernetes.  

2. **Внутренние DSL**  
   - Реализованы как подмножество языка общего назначения.  
   - Примеры:  
     - Ruby on Rails (ActiveRecord: `User.where(name: 'John')`).  
     - Kotlin DSL для Android (Anko).  

### Плюсы и минусы DSL

**Плюсы:**
- Высокая продуктивность в своей области.
- Читаемость для экспертов предметной области.
- Снижение ошибок за счёт ограниченной семантики.

**Минусы:**
- Узкая специализация (не подходит для общих задач).
- Требует разработки и поддержки.
- Может усложнить интеграцию с другими системами.

### Вывод

DSL — это «инструмент узкого профиля», который:
- экономит время в конкретной области;
- делает код понятным для непрограммистов;
- требует взвешенного выбора (не стоит изобретать DSL для простых задач).


**Когда стоит использовать DSL?**  
- Есть повторяющиеся задачи в узкой предметной области.  
- Пользователи — не программисты (бухгалтеры, инженеры, аналитики).  
- Требуется стандартизация процессов.
