# ELT vs ETL
Что такое ETL и ELT?

✏️ **ETL (Extract, Transform, Load)** и **ELT (Extract, Load, Transform)** — это два подхода к пакетной загрузке данных в хранилище.

| Аббревиатура | Значение                   | Порядок действий                                        |
| ------------ | -------------------------- | ------------------------------------------------------- |
| **ETL**      | Extract → Transform → Load | Сначала трансформация, потом загрузка в целевую систему |
| **ELT**      | Extract → Load → Transform | Сначала загрузка, потом трансформация в целевой системе |

---

 ✅ Для чего нужны?

> Оба подхода используются для **интеграции данных из разных источников** (например, базы данных, API, файлы) в единый репозиторий ([[Data Warehouse]], [[Data Lake]]).

 💡 Пример:
- Источники: [[PostgreSQL]], Excel, Google Sheets
- Цель: ClickHouse / Redshift / Snowflake

---

## Как работает ETL
 
```mermaid
graph LR
    A[Источник данных] --> B[Extract]
    B --> C[Transform в ETL-сервере]
    C --> D[Load в Data Warehouse]
```

Такой подход заложен в архитектуре хранилища данных [[Data Lake]] (озеро данных)

 🔧 Где используется:
- **Традиционные системы**: Informatica, Talend, SSIS
- **Когда данные нужно очистить, нормализовать, агрегировать перед загрузкой**

 Преимущества / недостатки:
- ✅ Контроль над качеством данных
- ✅ Трансформации можно тестировать отдельно
- ✅ Подходит для сложных бизнес-логик
- ❌ Долго — нужно сначала трансформировать, потом загружать
- ❌ Медленнее, если трансформации сложные
- ❌ Нужен отдельный сервер (ETL-движок)

---

## Как работает ELT

```mermaid
graph LR
    A[Источник данных] --> B[Extract]
    B --> C[Load в Data Warehouse]
    C --> D[Transform в Data Warehouse]
```

 Такой подход заложен в архитектуре хранилища данных [[Data Warehouse]]

 
 🔧 Где используется:
- **Современные системы**: AWS Glue, Azure Data Factory, dbt, Fivetran
- **Когда целевая система мощная** (ClickHouse, Redshift, Snowflake)

 ✅ Преимущества:
- ✅ Быстро — данные сразу загружаются
- ✅ Гибкость — трансформации можно писать прямо в SQL
- ✅ Легко масштабируется — вычисления происходят в DW
- ❌ Риск "грязных" данных — если не проверять на этапе загрузки
- ❌ Требует мощной целевой системы
- ❌ Сложно отлаживать — трансформации внутри [[Data Warehouse|DW]]

 ✅ Сравнение: ETL vs ELT

| Критерий                | **ETL**                               | **ELT**                      |
| ----------------------- | ------------------------------------- | ---------------------------- |
| **Порядок**             | Extract → Transform → Load            | Extract → Load → Transform   |
| **Место трансформации** | Отдельный сервер (ETL-движок)         | В Data Lake                  |
| Назначение              | [[Data Warehouse]]                    | [[Data Lake]]                |
| **Скорость**            | Медленнее                             | Быстрее                      |
| **Гибкость**            | Низкая                                | Высокая                      |
| **Качество данных**     | Высокое (контроль на этапе)           | Зависит от DW                |
| **Масштабируемость**    | Ограниченная (зависит от ETL-сервера) | Высокая (использует мощь DW) |
| **Пример инструментов** | Informatica, Talend, SSIS             | AWS Glue, dbt, Fivetran      |
| **Подходит для**        | Старые системы, сложные логики        | Современные DW, Big Data     |


ыы

---

 ✅ Когда что использовать?

| Сценарий                                           | Рекомендация |
| -------------------------------------------------- | ------------ |
| ✅ Сложные трансформации, много источников          | ➤ **ETL**    |
| ✅ Современный Data Warehouse (Snowflake, Redshift) | ➤ **ELT**    |
| ✅ Нужна высокая скорость загрузки                  | ➤ **ELT**    |
| ✅ Нужен контроль качества данных                   | ➤ **ETL**    |
| ✅ Интеграция с облачными сервисами                 | ➤ **ELT**    |

---

 ✅ Финальный вывод

> ✅ **ETL** — это **классика**, когда трансформации делают **до загрузки**.  
> ✅ **ELT** — это **будущее**, когда трансформации делают **внутри мощного хранилища**.

> 💬 _“ETL is for control. ELT is for speed.”_

# [[ETL]]-процессы
ETL-процессы: основы и применение

**ETL** (Extract, Transform, Load) — это комплексный процесс управления данными, который включает извлечение, преобразование и загрузку информации в целевую систему. Это ключевой элемент в работе с данными для бизнеса и аналитики.

- Основные компоненты ETL

	1. **Извлечение данных (Extract)**
	  - Сбор информации из различных источников
	  - Поддержка разнородных форматов данных
	  - Работа с базами данных, файлами, API и веб-сервисами
	  
	1. **Преобразование данных (Transform)**
	  - Очистка и валидация данных
	  - Агрегация и нормализация
	  - Применение бизнес-правил
	  - Объединение и слияние наборов данных
	
	1. **Загрузка данных (Load)**
	  - Перенос данных в целевую систему
	  - Оптимизация процесса загрузки
	  - Управление конфликтами и ошибками

- Преимущества ETL-процессов
	- **Централизация данных** из различных источников
	- **Повышение качества данных** через очистку и валидацию
	- **Автоматизация процессов** обработки данных
	- **Масштабируемость** решений под растущие потребности
	- **Отказоустойчивость** и контроль ошибок

- Применение ETL в бизнесе
	- Создание **корпоративных хранилищ данных**
	- Построение **систем бизнес-аналитики**
	- Интеграция **различных информационных систем**
	- Подготовка данных для **машинного обучения**
	- Миграция данных между системами

- Современные инструменты ETL
	- **Apache NiFi** — для потоковой обработки данных
	- **Talend** — платформа для интеграции данных
	- **Informatica** — комплексное решение для управления данными
	- **Microsoft SSIS** — инструмент для ETL в экосистеме Microsoft
	- **Apache Airflow** — оркестрация ETL-процессов

- Типичные сценарии использования
	- **Миграция данных** при обновлении систем
	- **Синхронизация данных** между отделами компании
	- **Подготовка отчетов** на основе агрегированных данных
	- **Анализ продаж** и клиентской активности
	- **Мониторинг бизнес-показателей** в реальном времени

- Проблемы и вызовы
	- **Масштабируемость** при работе с большими данными
	- **Качество данных** и необходимость их очистки
	- **Интеграция источников** с разными форматами
	- **Безопасность данных** при передаче и хранении
	- **Оптимизация производительности** ETL-процессов

- Тенденции развития
	- **Облачные решения** для ETL
	- **Автоматизация процессов** с помощью AI
	- **Real-time обработка** данных
	- **Микросервисная архитектура** ETL-систем
	- **Контейнеризация** и оркестрация процессов
