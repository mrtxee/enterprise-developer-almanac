### Паттерн State Machine (Машина состояний)

**State Machine** (машина состояний, конечный автомат) — это поведенческий паттерн проектирования, описывающий объект, который меняет своё поведение в зависимости от внутреннего состояния. Система может находиться **только в одном состоянии** из заранее определённого набора, а переходы между состояниями происходят по чётким правилам.

#### Ключевые компоненты

1. **Состояния (States)** — конкретные режимы работы системы (например, «Ожидание», «Обработка», «Ошибка»).  
2. **События/Триггеры (Events/Triggers)** — внешние или внутренние сигналы, вызывающие переход (например, нажатие кнопки, тайм‑аут).  
3. **Переходы (Transitions)** — правила вида *«из состояния A при событии X перейти в состояние B»*.  
4. **Действия (Actions)** — операции, выполняемые при входе в состояние или во время перехода.  
5. **Начальное состояние (Initial State)** — состояние, в котором система находится при запуске.  
6. **Конечное состояние (Final State)** — состояние завершения работы (необязательно).

#### Визуализация

Машина состояний часто изображается в виде **диаграммы состояний** (UML Statechart):  
- состояния — прямоугольники с закруглёнными углами;  
- переходы — стрелки с подписями (события);  
- начальное состояние — чёрный круг;  
- конечное — круг с точкой внутри.

#### Пример: Автомат вендингового аппарата

**Состояния**:  
- `Idle` (ожидание монеты);  
- `CoinInserted` (монета вставлена);  
- `Dispensing` (выдача товара);  
- `OutOfStock` (товар закончился).  

**Переходы**:  
- Из `Idle` при событии `coin_inserted` → в `CoinInserted`.  
- Из `CoinInserted` при событии `button_pressed` → в `Dispensing`.  
- Из любого состояния при событии `out_of_stock` → в `OutOfStock`.  

**Действия**:  
- При входе в `Dispensing` — выдать товар.  
- При входе в `OutOfStock` — показать сообщение «Товар закончился».

#### Реализация (общий алгоритм)

1. Определяем перечень всех возможных состояний.  
2. Описываем события, вызывающие переходы.  
3. Задаём правила переходов (часто в виде таблицы или графа).  
4. Реализуем обработчики событий, которые:  
   - проверяют текущее состояние;  
   - выполняют действие;  
   - меняют состояние.  
5. Добавляем обработку некорректных переходов (например, ошибка «Недоступно в этом состоянии»).

#### Плюсы паттерна

- **Чёткость логики** — все возможные сценарии явно заданы.  
- **Лёгкость модификации** — добавление нового состояния не ломает существующую логику.  
- **Тестируемость** — можно проверить каждый переход отдельно.  
- **Наглядность** — диаграмма состояний понятна команде.  
- **Контроль некорректных действий** — система не позволяет выполнить операцию в неподходящем состоянии.

#### Минусы

- **Сложность при большом числе состояний** — диаграмма становится запутанной.  
- **Жёсткая структура** — гибкость снижается, если правила часто меняются.  
- **Избыточность** — для простых сценариев overhead неоправдан.

#### Когда применять

- Системы с чёткими этапами работы (платежи, заказы, workflows).  
- Протоколы связи (например, TCP-соединения).  
- Игровые механики (состояния персонажа: «бег», «прыжок», «атака»).  
- Устройства с фиксированными режимами (термостат, лифт, банкомат).  
- Валидация бизнес‑процессов (статусы заявки: «на рассмотрении», «одобрено», «отклонено»).

#### Альтернативы

- **Conditionals** (if/else) — просто, но не масштабируется.  
- **Strategy Pattern** — если поведение меняется, но не зависит от последовательности состояний.  
- **[[Event Sourcing]]** — для систем, где важно хранить историю переходов.

#### Пример кода (упрощённый, на Python)

```python
class VendingMachine:
    def __init__(self):
        self.state = "Idle"
    
    def handle_event(self, event):
        if self.state == "Idle" and event == "coin_inserted":
            self.state = "CoinInserted"
            print("Монета принята")
        elif self.state == "CoinInserted" and event == "button_pressed":
            self.state = "Dispensing"
            print("Выдача товара...")
        else:
            print(f"Действие {event} недоступно в состоянии {self.state}")
```

**Итог**: State Machine — мощное средство для моделирования систем с чётко определёнными режимами работы. Он превращает сложную условную логику в наглядную структуру, облегчая поддержку и расширение функционала.
