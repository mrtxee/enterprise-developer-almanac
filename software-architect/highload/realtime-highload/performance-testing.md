## Performance testing

> тестирование производительности

Performance testing нужен для комплексного анализа производительности.

**Performance testing** — общий термин для всех видов тестирования производительности, включая load testing.

**Performance testing включает в себя тесты:**

1. **Smoke test / Тест сборки (дымовой тест)**
   - Быстрая первичная проверка программного продукта, которая выявляет критические сбои и определяет, готово ли приложение к дальнейшему тестированию.
2. **Load testing / Тест средней нагрузки**
   - Проверяет поведение системы при *ожидаемой* нагрузке (сколько пользователей/запросов система выдерживает в штатных условиях).
3. **Stress test / Тест точки отказа (стресс-тест)**
   - Тестирование на предельных нагрузках, когда система намеренно перегружается, чтобы выяснить точку отказа.
4. **Endurance test (soak test) / Длительное тестирование**
   - Длительное нагрузочное тестирование для выявления утечек памяти, деградации производительности и т. п.
   - Endurance — выносливость, soak — впитывать.
5. **Spike testing / Тест всплеска нагрузки**
   - Проверка реакции системы на резкие скачки нагрузки (например, внезапный наплыв пользователей).

## Профили нагрузки

### Минимально необходимые тесты по профилям нагрузки

| Профиль нагрузки | Smoke-тест | Тест средней нагрузки | Длительное тестирование | Стресс-тест | Тест всплеска нагрузки | Тест точки отказа |
| --- | ---------- | --------------------- | ----------------------- | ----------- | ---------------------- | ----------------- |
| Статический | ✅ | ✅ | ✅ | ❌ | ❌ | ❌ |
| Динамический, регулярный и предсказуемый | ✅ | ✅ | ✅ | ✅ | ❌ | ❌ |
| Динамический, нерегулярный и предсказуемый | ✅ | ✅ | ✅ | ✅ | ✅ | ❌ |
| Динамический, нерегулярный и непредсказуемый | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |

- **Smoke-тест** — базовая работоспособность.
- **Тест средней нагрузки** — производительность при штатной нагрузке.
- **Длительное тестирование** — утечки памяти, стабильность.
- **Стресс-тест** — поведение при превышении нагрузки.
- **Тест всплеска (Spike)** — реакция на резкий скачок пользователей.
- **Тест точки отказа** — что будет при падении БД, сети, сервиса?

## Типы тестов

Сравнительная таблица всех типов тестов:

| **Тип теста** | **Основная цель** | **Условия нагрузки** | **Что проверяем** | **Когда проводить** | **Ключевые метрики** |
| --- | --- | --- | --- | --- | --- |
| **Smoke-тест** | Проверка работоспособности после сборки/деплоя | Минимальная или отсутствует | Критические функции системы | После каждого билда/деплоя | Успешность выполнения, время отклика базовых операций |
| **Тест средней нагрузки** | Проверка производительности в условиях, близких к реальным | Нагрузка, соответствующая типичному использованию (50-80% от пиковой) | Производительность, стабильность, использование ресурсов | Регулярно, перед релизом | Response time (p50, p95), throughput, CPU/memory usage |
| **Стресс-тест** | Определение пределов системы и поведения при экстремальных нагрузках | Нагрузка выше максимальной расчётной (100-150% и более) | Предельная производительность, деградация, восстановление | Перед релизом, при изменении архитектуры | Breaking point, поведение при деградации, recovery time |
| **Spike Test / Тест всплеска нагрузки** | Проверка реакции на резкое увеличение нагрузки | Кратковременные пики нагрузки (резкое увеличение в 2-5 раз) | Устойчивость к резким изменениям, автоскалирование | После изменений в инфраструктуре | Time to scale, стабильность во время всплеска |
| **Тест точки отказа** | Определение конкретного предела, при котором система отказывает | Постепенное увеличение до отказа | Точное значение нагрузки, при которой система ломается | Для определения SLA/SLO | Точное значение нагрузки отказа, поведение вблизи предела |
| **Soak/Endurance (длительное тестирование)** | Проверка стабильности при длительной нагрузке | Средняя или высокая нагрузка в течение длительного времени (часы/дни) | Утечки памяти, накопление ошибок, деградация производительности | Перед крупными релизами | Memory leak, cumulative errors, performance degradation over time |

### Детальное объяснение каждого типа тестов

#### Smoke-тест (Дымовое тестирование)

**Характеристики**

- **Быстрый** (минуты, а не часы)
- **Поверхностный** — проверяет, «дымится ли система» после сборки
- **Критически важный** для [[CI-CD|CI/CD]] pipeline
- **Пример**: после деплоя проверяем, что главная страница открывается, API health-check возвращает 200, база данных доступна

#### Тест средней нагрузки (Load Test)

**Характеристики**

- **Реалистичная нагрузка** — соответствующий production сценарий
- **Длительность** — 30-60 минут
- **Цель** — убедиться, что система соответствует SLA при нормальных условиях
- **Пример**: эмуляция 1000 одновременных пользователей интернет-магазина в «обычный» день

#### Стресс-тест (Stress Test)

**Характеристики**

- **Экстремальные условия** — выше максимальной расчётной нагрузки
- **Проверка деградации** — как система ведёт себя при перегрузке
- **Recovery проверка** — восстанавливается ли система после снижения нагрузки
- **Пример**: что будет, если на сайт придёт в 2 раза больше пользователей, чем мы рассчитывали?

#### Тест всплеска нагрузки (Spike Test)

**Характеристики**

- **Резкие изменения** нагрузки за короткое время
- **Проверка автоскейлинга** — успевает ли инфраструктура масштабироваться
- **Кратковременный** — пики длятся минуты
- **Пример**: эффект от рекламы в телевизоре, когда тысячи пользователей заходят одновременно

#### Тест точки отказа (Breakpoint Test)

**Характеристики**

- **Поиск точного предела** производительности
- **Постепенное увеличение** нагрузки до отказа
- **Анализ поведения** непосредственно перед отказом
- **Пример**: определяем, что наша система выдерживает ровно 437 одновременных пользователей, а на 438-м начинает отказывать

#### Длительное тестирование (Soak/Endurance Test)

**Характеристики**

- **Очень длительный** — часы или даже дни
- **Поиск постепенных проблем** — утечек памяти, фрагментации
- **Проверка стабильности** — не накапливаются ли ошибки со временем
- **Пример**: 24-часовой тест показывает, что память увеличивается на 2MB/час из-за утечки в [[software-architect/highload/caching/caching|кэше]]

### Практические сценарии применения

#### Веб-приложение интернет-магазина

```yaml
# Полный цикл тестирования для релиза
testing_schedule:
  - smoke: "После каждого деплоя (5 минут)"
  - load: "Еженедельно (1 час, 1000 пользователей)"
  - stress: "Перед Черной пятницей (2 часа, 5000 пользователей)"
  - spike: "После обновления базы данных (30 минут)"
  - breakpoint: "При изменении архитектуры (находим новый предел)"
  - soak: "Раз в квартал (12 часов, проверка памяти)"
```

### Ключевые отличия на практике

#### По цели

- **Smoke** → «Система работает?»
- **Load** → «Система работает хорошо при нормальной нагрузке?»
- **Stress** → «Где пределы системы и как она деградирует?»
- **Spike** → «Как система реагирует на внезапные изменения?»
- **Breakpoint** → «Каков точный предел?»
- **Soak** → «Остаётся ли система стабильной долгое время?»
