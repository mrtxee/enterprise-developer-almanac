### Jaeger — система распределённой трассировки

**Jaeger** — это открытый инструмент для мониторинга и анализа выполнения запросов в распределённых системах (микросервисах, облачных архитектурах). Позволяет визуализировать полный путь запроса через множество сервисов, выявлять узкие места и ошибки.

Разработан в Uber, передан в CNCF (Cloud Native Computing Foundation) и стал стандартом для распределённой трассировки.

### Основные задачи

- **Визуализация вызовов**: показать, как запрос проходит через десятки микросервисов.  
- **Анализ задержек**: определить, какой сервис или операция занимает больше времени.  
- **Диагностика ошибок**: локализовать, где именно возникает исключение.  
- **Мониторинг зависимостей**: отобразить карту взаимодействий между сервисами.  
- **Оптимизация производительности**: выявить «узкие горлышки» в архитектуре.

### Ключевые компоненты

1. **Client Libraries (SDK)**  
   - Библиотеки для разных языков (Go, Java, Python, Node.js и др.).  
   - Собирают данные о вызовах, создают спаны (spans), передают их в коллектор.  

2. **Agent**  
   - Лёгкий процесс на каждом хосте.  
   - Принимает спаны от SDK, буферизирует, отправляет в коллектор.  
   - Уменьшает нагрузку на приложения.  

3. **Collector**  
   - Центральный компонент, принимающий спаны от агентов или SDK.  
   - Валидирует, обогащает, хранит данные.  
   - Поддерживает разные бэкенды хранения (Elasticsearch, Cassandra, Kafka).  

4. **Query Service**  
   - Обрабатывает запросы от UI, ищет трассировки в хранилище.  
   - Возвращает данные в формате, понятном интерфейсу.  

5. **UI (веб‑интерфейс)**  
   - Визуализирует трассировки: дерево вызовов, временную шкалу, детали спанов.  
   - Позволяет фильтровать по сервисам, операциям, ошибкам.  

6. **Data Store**  
   - Хранилище для спанов и метаданных (Elasticsearch, Cassandra).  
   - Обеспечивает быстрый поиск и агрегацию.  

### Как работает (поток данных)


1. **Запрос поступает в систему**  
   - SDK в первом сервисе генерирует `trace_id` и корневой `span`.  

2. **Передача контекста**  
   - `trace_id` и `span_id` передаются между сервисами (через HTTP‑заголовки, MQ‑сообщения).  
3. **Сбор спанов**  
   - Каждый сервис создаёт спаны с метаданными (время, операция, ошибки).  
4. **Экспорт данных**  
   - SDK или агент отправляет спаны в коллектор (через gRPC, HTTP).  
5. **Хранение**  
   - Коллектор сохраняет спаны в хранилище (Elasticsearch/Cassandra).  
6. **Визуализация**  
   - Пользователь открывает UI, запрашивает трассировку по `trace_id`.  
   - Query Service извлекает данные из хранилища, отдаёт в UI.  
7. **Анализ**  
   - В интерфейсе видны: дерево вызовов, длительность каждого спана, логи ошибок.  

### Что можно увидеть в UI


- **Дерево вызовов** — иерархию сервисов, участвующих в обработке запроса.  
- **Временную шкалу** — длительность каждого спана (в мс/с).  
- **Детали спана** — метаданные:  
  - имя операции;  
  - теги (HTTP‑метод, код ответа, пользовательский ID);  
  - логи (ошибки, предупреждения);  
  - контекст (родительские/дочерние спаны).  
- **Карту сервисов** — визуальную схему взаимодействий между микросервисами.  
- **Фильтры** — поиск по сервису, операции, ошибкам, временным меткам.  

### Поддерживаемые протоколы и форматы


- **Jaeger Thrift** (устаревший, но ещё встречается).  
- **OTLP** (OpenTelemetry Protocol) — современный стандарт.  
- **Zipkin JSON** — совместимость с Zipkin.  
- Передача через: gRPC, HTTP, Kafka.  

### Интеграция с экосистемой


- **OpenTelemetry** — Jaeger поддерживает приём данных через OTLP.  
- **Kubernetes** — легко развёртывается в кластере (Helm‑чарты, операторы).  
- **Prometheus/Grafana** — экспорт метрик для мониторинга.  
- **Elasticsearch/Loki** — использование в качестве хранилища.  

### Сценарии использования


- **Микросервисы**: анализ запросов, проходящих через 10–100 сервисов.  
- **Serverless**: трассировка функций AWS Lambda, Google Cloud Functions.  
- **Гибридные архитектуры**: мониторинг взаимодействия между VM, контейнерами, облачными сервисами.  
- **CI/CD**: анализ производительности после деплоя новой версии.  
- **Безопасность**: аудит подозрительных вызовов (например, многократные ошибки аутентификации).  


### Плюсы Jaeger


- **Открытый код** — нет лицензионных ограничений.  
- **Поддержка Cloud Native** — интеграция с Kubernetes, Istio, Linkerd.  
- **Масштабируемость** — обработка миллионов трассировок в день.  
- **Гибкость хранения** — выбор бэкенда (Elasticsearch, Cassandra, ScyllaDB).  
- **Богатый UI** — удобная визуализация и фильтрация.  
- **Совместимость** — поддержка OpenTelemetry, Zipkin, gRPC.  

### Минусы и ограничения


- **Сложность настройки** — требует конфигурации коллектора, хранилища, агентов.  
- **Объём данных** — трассировки могут быстро заполнять хранилище (нужен семплинг).  
- **Накладные расходы** — сбор трассировок потребляет CPU/память/сеть.  
- **Конфиденциальность** — спаны могут содержать чувствительные данные (токены, PII).  


### Лучшие практики


1. **Настройте семплинг** (sampling):  
   - *Head-based* — решение о сборе принимается в начале запроса.  
   - *Tail-based* — после завершения запроса (лучше для анализа ошибок).  
2. **Используйте OTLP** вместо Jaeger Thrift — это современный стандарт.  
3. **Ограничьте хранение** — настройте TTL (time‑to‑live) для трассировок (например, 7–30 дней).  
4. **Защитите данные** — маскируйте токены, номера карт в тегах.  
5. **Интегрируйте с мониторингом** — связывайте трассировки с метриками (Prometheus) и логами (Loki).  
6. **Автоматизируйте развёртывание** — используйте Helm, Terraform, Kubernetes Operators.  

### Пример развёртывания (Kubernetes)


```yaml
# Развёртывание Jaeger Operator
apiVersion: jaegertracing.io/v1
kind: Jaeger
metadata:
  name: simple-prod
spec:
  strategy: production
  storage:
    type: elasticsearch
    options:
      es:
        server-urls: http://elasticsearch:9200
```

### Итог

**Jaeger** — это:  
- мощный инструмент для **распределённой трассировки** в микросервисных архитектурах;  
- система, превращающая «чёрные ящики» сервисов в **прозрачные цепочки вызовов**;  
- решение для **диагностики производительности** и **анализа ошибок** в сложных системах.  

Используйте Jaeger, если:  
- у вас более 3–5 микросервисов;  
- нужны детализированные данные о времени выполнения операций;  
- требуется визуализация взаимодействий между компонентами;  
- вы внедряете OpenTelemetry или мигрируете с Zipkin.
