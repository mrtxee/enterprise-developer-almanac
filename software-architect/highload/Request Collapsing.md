### Паттерн Request Collapsing («сворачивание запросов»)

**Суть:** объединение нескольких идентичных или схожих запросов в **один** для снижения нагрузки на систему и ускорения обработки.

### Зачем нужен

В высоконагруженных системах часто возникают ситуации, когда:
- множество клиентов одновременно запрашивают **одни и те же данные** (например, актуальный курс валюты);
- запросы идут с минимальным интервалом, создавая избыточную нагрузку.

Request Collapsing решает эту проблему, «сворачивая» дублирующиеся запросы в один вызов к бэкенду.


### Как работает

1. **Обнаружение дубликатов**  
   Система выявляет запросы с одинаковыми параметрами (или схожими критериями) в заданный временной интервал.

2. **Агрегация**  
   Дублирующиеся запросы объединяются в один «пакетный» запрос к сервису‑источнику.

3. **Распространение результата**  
   Ответ от сервиса распределяется всем клиентам, чьи запросы были объединены.

4. **Кэширование** (опционально)  
   Полученный результат может сохраняться для последующих запросов.

### Ключевые параметры

- **Окно времени** — интервал, в течение которого запросы считаются дубликатами (например, 100 мс).  
- **Критерии совпадения** — по каким параметрам запросы объединяются (URL, параметры, заголовки).  
- **Стратегия обработки** — как распределять ответ (всем одинаково, с учётом приоритетов).
### Примеры реализации

1. **API‑гейтвей**  
   - 10 клиентов одновременно запрашивают `/api/currency/USD`.  
   - Гейтвей отправляет **один запрос** к сервису курсов.  
   - Ответ рассылается всем 10 клиентам.

1. **Микросервисная архитектура**  
   - Несколько сервисов запрашивают статус заказа с ID 123.  
   - Прокси объединяет запросы и делает один вызов к сервису заказов.

3. **Клиентские приложения**  
   - Фронтенд «сворачивает» несколько вызовов к API в один (например, при множественных нажатиях кнопки).
### Преимущества

- **Снижение нагрузки** на бэкенд (меньше вызовов к БД, API, сервисам).  
- **Экономия ресурсов** (CPU, память, сетевые соединения).  
- **Уменьшение latency** для клиентов (ответ приходит быстрее, чем при последовательной обработке).  
- **Защита от всплесков** — предотвращает лавинообразное увеличение запросов.  
- **Масштабируемость** — система выдерживает больше клиентов при той же нагрузке на бэкенд.

### Недостатки и ограничения

- **Сложность реализации** — требуется логика обнаружения дубликатов и синхронизации ответов.  
- **Задержка для поздних запросов** — клиенты, пришедшие в конце окна времени, ждут ответа дольше.  
- **Ограниченная применимость** — работает только для **идентичных** или **схожих** запросов.  
- **Проблемы с кэшированием** — если данные быстро меняются, результат может устареть.  
- **Отладка** — сложнее отслеживать путь отдельных запросов.

### Варианты стратегий

1. **Strict Collapsing**  
   - Объединяются только **полностью идентичные** запросы.  
   - Пример: одинаковые URL и параметры.

1. **Fuzzy Collapsing**  
   - Группирует запросы по **частичным совпадениям** (например, один эндпоинт с разными параметрами).  
   - Требует логики нормализации запросов.

3. **Time‑based**  
   - Запросы объединяются в пределах заданного временного окна (например, 50–500 мс).

4. **Count‑based**  
   - «Сворачивание» происходит, если число дубликатов превышает порог (например, ≥5 запросов).


### Где применяют

- **API‑гейтвеи** и прокси‑серверы.  
- **Микросервисы** с высокой частотой запросов к общим ресурсам.  
- **Клиентские приложения** (мобильные, веб) для оптимизации вызовов к API.  
- **Системы реального времени** (чаты, уведомления) для снижения частоты обновлений.  
- **Сервисы с высокой стоимостью запроса** (например, внешние API с платой за вызов).


### Пример кода (упрощённый)

```javascript
class RequestCollapser {
  constructor(windowMs = 100) {
    this.windowMs = windowMs;
    this.pendingRequests = new Map();
  }

  async collapse(requestKey, fetchFunction) {
    const now = Date.now();

    
    // Если запрос уже в обработке — добавляем в очередь
    if (this.pendingRequests.has(requestKey)) {
      return this.pendingRequests.get(requestKey);
    }
    
    // Создаём промис для нового запроса
    const promise = fetchFunction().finally(() => {
      // Очищаем через окно времени
      setTimeout(() => this.pendingRequests.delete(requestKey), this.windowMs);
    });
    
    this.pendingRequests.set(requestKey, promise);
    return promise;
  }
}
```

### Важные нюансы

- **Балансировка окна времени**: слишком маленькое — не даст эффекта, слишком большое — увеличит задержку.  
- **Обработка ошибок**: если один запрос в группе падает, как отвечать остальным?  
- **Приоритеты**: можно ли «выдвигать» важные запросы вперёд?  
- **Тестирование**: проверять на реальных нагрузках и сценариях дублирования.

### Вывод

Request Collapsing — это **оптимизация на уровне запросов**, которая:
- снижает нагрузку на бэкенд;
- ускоряет отклик для клиентов;
- особенно полезна в системах с частыми идентичными запросами.


Его цель — **не обрабатывать одно и то же многократно**, а использовать ресурсы системы эффективнее.
