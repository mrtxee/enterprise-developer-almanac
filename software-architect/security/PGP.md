**PGP** (Pretty Good Privacy) и **OpenPGP** — технологии шифрования для защиты электронной переписки и файлов. Хотя термины часто используют как синонимы, между ними есть юридическое и техническое различие.

### PGP (Pretty Good Privacy)

- **Проприетарное решение**, принадлежит компании Symantec.
- Создан в 1991 году Филом Циммерманом. #👨 
- Использует комбинацию:
  - **симметричного шифрования** (для данных);
  - **асимметричного шифрования** (для обмена ключами).
- **Принцип работы**:
  1. Генерируется случайный сеансовый ключ (одноразовый).
  2. Сеансовый ключ шифруется **открытым ключом получателя**.
  3. Получатель расшифровывает сеансовый ключ своим **закрытым ключом**.
  4. С помощью сеансового ключа расшифровывается само сообщение.

### OpenPGP

- **Открытый стандарт** (одобрен IETF), не требует лицензий.
- Основан на исходном коде PGP, но развивается сообществом.
- Поддерживается большинством почтовых клиентов.
- Может использоваться с протоколами: FTP, SSL, SSH.
- Имеет открытые реализации (например, **GnuPG/GPG**).

>[!info] IETF
>**IETF** (Internet Engineering Task Force) — **Инженерный совет Интернета**, **международная организация, которая занимается разработкой и поддержкой технических стандартов**, лежащих в основе функционирования интернета.

### Как это работает на практике

1. **Генерация ключей**:  
   - Каждый пользователь создаёт пару ключей: **открытый** (для шифрования) и **закрытый** (для расшифровки, хранится в секрете).  
   - Открытый ключ можно публиковать или передавать другим.

2. **Отправка зашифрованного сообщения**:  
   - Отправитель шифрует данные **симметричным алгоритмом** (быстрый).  
   - Сеансовый ключ шифруется **открытым ключом получателя**.  
   - Получатель использует свой **закрытый ключ**, чтобы расшифровать сеансовый ключ, а затем — сообщение.

3. **Цифровая подпись** (опционально):  
   - Отправитель подписывает сообщение своим **закрытым ключом**.  
   - Получатель проверяет подпись **открытым ключом отправителя** (подтверждает авторство и целостность).

### Где применяется

- Шифрование **электронной почты** (например, в ProtonMail, Thunderbird с Enigmail).  
- Защита **конфиденциальных файлов**.  
- Подписание **документов** для подтверждения авторства.


### Плюсы PGP/OpenPGP
- **Высокая стойкость**: без закрытого ключа расшифровать данные невозможно.  
- **Гибкость**: подходит для почты, файлов, подписей.  
- **Децентрализация**: нет зависимости от централизованных серверов.  
- **Совместимость**: OpenPGP‑решения работают между собой.


### Минусы и ограничения
- **Сложность для новичков**: требуется понимание работы с ключами.  
- **Риск потери ключей**: если закрытый ключ утерян, данные не восстановить.  
- **Не гарантирует анонимность**: метаданные (адреса, темы писем) не шифруются.  
- **Уязвимости в реализациях** (например, Efail), хотя сам алгоритм остаётся надёжным.


### Примеры инструментов
- **GnuPG (GPG)** — открытая реализация OpenPGP для Linux/macOS.  
- **gpg4o** — плагин для Outlook (Windows).  
- **GPGTools** — для Apple Mail (macOS).  
- **Enigmail** — дополнение для Thunderbird.


**Итог**:  
- **PGP** — коммерческая версия шифрования.  
- **OpenPGP** — открытый стандарт, совместимый с PGP, доступный для свободного использования.  
Оба обеспечивают защиту данных через асимметричное шифрование, но OpenPGP предпочтительнее для кросс‑платформенного и бесплатного применения.
