## ✅ Что такое KMS?

> **KMS (Key Management Service)** — это **управляемый сервис** для создания, хранения и использования ключей.  
> Это **логическое решение** — часто в облаке.

### 🔹 Примеры:
- **AWS KMS**
- **Google Cloud KMS**
- **Azure Key Vault**
- **Hashicorp Vault** (частично)
- **Aliyun KMS**

### ✅ Преимущества KMS:
| Плюс                                    | Объяснение                                       |
| --------------------------------------- | ------------------------------------------------ |
| ✅ **Удобство**                          | API, интеграция через IAM                        |
| ✅ **Дешевле [[HSM]]**                   | Часто pay-as-you-go                              |
| ✅ **Автоматическое ротирование ключей** | Можно включить → будет меняться каждый год       |
| ✅ **Интеграция с другими сервисами**    | S3, RDS, EBS, BigQuery — всё шифруется через KMS |
| ✅ **Работает в облаке**                 | Без железа                                       |

### ⚠️ Минусы:
- ❌ Ключи могут быть выгружены (виртуально)
- ❌ Меньше контроля
- ❌ Не все поддерживают FIPS 140-2 Level 3

---


**FIPS 140‑2 Level 3** — это третий (из четырёх) уровень безопасности в американском стандарте **FIPS 140‑2** («Федеральный стандарт обработки информации»), который регламентирует требования к криптографическим модулям (аппаратным, программным или комбинированным).

Уровень 3 усиливает требования уровней 1 и 2 и добавляет **защиту от физического вмешательства**:
- Модуль должен обнаруживать попытки вскрытия/вмешательства и реагировать на них (например, обнулять криптографические ключи при несанкционированном доступе).
- Требуется **разделение интерфейсов**: логические и физические порты для передачи «критических параметров безопасности» (CSP) должны быть чётко отделены.
- Обязательна **аутентификация по идентификатору** (не просто по роли, как на уровне 2).
- Закрытые ключи при передаче **обязательно шифруются** алгоритмами, соответствующими FIPS 140‑2 (AES, 3DES, RSA и др.).
