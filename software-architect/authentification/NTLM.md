### Что такое NTLM

**NTLM (New Technology LAN Manager)** — это проприетарный протокол аутентификации от Microsoft, разработанный для проверки подлинности пользователей и компьютеров в сетях на базе Windows. Протокол обеспечивает целостность и конфиденциальность данных, но считается устаревшим из-за уязвимостей в области безопасности. Заменён на [[Kerberos]] в современных версиях Active Directory, однако всё ещё используется в некоторых сценариях [```1```](https://phoenixnap.com/glossary/ntlm)[```4```](https://www.crowdstrike.com/en-us/cybersecurity-101/identity-protection/windows-ntlm/).

### Как работает NTLM

NTLM использует **механизм «запрос-ответ» (challenge-response)**, при котором пароль пользователя не передаётся по сети в открытом виде. Процесс аутентификации состоит из трёх этапов:

1. **Negotiate (Переговоры)**:
   - клиент отправляет серверу сообщение **NEGOTIATE_MESSAGE** с указанием поддерживаемых функций NTLM;
   - сервер отвечает сообщением **CHALLENGE_MESSAGE** с случайным числом (nonce) для проверки подлинности клиента.

2. **Challenge (Вызов)**:
   - клиент шифрует полученное от сервера число с помощью хэша пароля пользователя;
   - клиент отправляет серверу сообщение **AUTHENTICATE_MESSAGE**, содержащее:
     - зашифрованный вызов (challenge);
     - имя пользователя, хоста и домена.

3. **Authentication (Аутентификация)**:
   - сервер проверяет зашифрованный вызов, используя хэш пароля пользователя из базы данных;
   - если значения совпадают — пользователь аутентифицирован, устанавливается сеанс связи.

Иногда добавляется четвёртое сообщение для контроля целостности данных [```2```](https://securelist.ru/ntlm-abuse-in-2025/114067/).

### Ключевые особенности NTLM

1. **Хэширование паролей** — вместо хранения паролей в открытом виде используются хэши (NT hashes), созданные с помощью криптографических алгоритмов (например, MD4).
2. **Поддержка целостности и конфиденциальности** — механизмы **message signing** (подписание сообщений) и **message sealing** (шифрование содержимого) защищают от подмены и перехвата.
3. **Совместимость с устаревшими системами** — используется в средах, где Kerberos не поддерживается.
4. **Несколько версий** — LM, NTLMv1, NTLMv2. NTLMv2 считается более безопасным благодаря использованию HMAC-MD5 и улучшенной обработки запросов.
5. **Ограниченная поддержка SSO** — позволяет использовать учётные данные для доступа к нескольким ресурсам в рамках одной сессии.

### Где используется NTLM

- доступ к общим папкам и принтерам в рабочих группах (workgroups);
- аутентификация удалённых пользователей на устаревших системах;
- резервная аутентификация в доменах Active Directory при сбое Kerberos (например, из-за проблем с DNS или SPN);
- интеграция с третьими сторонами (NAS-системы, прокси-серверы, веб-серверы с NTLM-аутентификацией по HTTP);
- локальная аутентификация на компьютерах, не присоединённых к домену.

### Версии NTLM

- **LM (LAN Manager)** — самая уязвимая версия, не рекомендуется к использованию.
- **NTLMv1** — улучшена по сравнению с LM, но всё ещё считается небезопасной.
- **NTLMv2** — наиболее защищённая версия (использует HMAC-MD5), однако уступает Kerberos по уровню безопасности.

### Уязвимости NTLM

1. **Pass-the-Hash атаки** — злоумышленники могут использовать хэши паролей для имитации пользователя без расшифровки самого пароля.
2. **Relay-атаки** — пересылка аутентификационных сообщений между клиентом и сервером для получения несанкционированного доступа.
3. **Man-in-the-Middle (MitM) атаки** — отсутствие взаимной аутентификации позволяет злоумышленнику подменять сервер.
4. **Brute-force атаки** — устаревшие алгоритмы хэширования (MD4) уязвимы для перебора паролей.
5. **Атаки с предпросмотром файлов** — фишинговые сообщения могут инициировать NTLM-аутентификацию и привести к утечке хэшей.
6. **Коercion-based атаки** — принуждение системы к аутентификации на подконтрольном злоумышленнику сервисе (утилиты PetitPotam, PrinterBug).

### Отличия NTLM от Kerberos

- **Механизм аутентификации**: NTLM — «запрос-ответ», Kerberos — система билетов (ticket-based).
- **Взаимная аутентификация**: отсутствует в NTLM, есть в Kerberos.
- **Масштабируемость**: NTLM менее эффективен в крупных сетях из-за отсутствия делегирования и тикетов.
- **Поддержка MFA**: отсутствует в NTLM, доступна в современных реализациях Kerberos.
- **Использование в современных средах**: Kerberos является стандартом, NTLM — резервный протокол.

### Текущий статус

Microsoft постепенно отказывается от NTLM, но протокол всё ещё актуален в следующих случаях:
- работа с устаревшим ПО и оборудованием;
- сценарии, где Kerberos недоступен или не настроен;
- интеграция с legacy-системами (Windows 95/98/NT 4.0).

**Итог**: NTLM остаётся важным элементом инфраструктуры Windows, несмотря на известные уязвимости. Рекомендуется минимизировать использование NTLM и по возможности переходить на более безопасные протоколы аутентификации.
