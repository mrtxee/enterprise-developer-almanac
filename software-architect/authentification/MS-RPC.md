### Что такое MS-RPC (Microsoft Remote Procedure Call)

**MS-RPC (Microsoft Remote Procedure Call)** — это проприетарная реализация протокола удалённого вызова процедур (RPC) от Microsoft, производная от технологии **DCE/RPC (Distributed Computing Environment / Remote Procedure Calls)**.

Протокол позволяет программам вызывать функции и процедуры на удалённом узле (компьютере) так, будто они выполняются локально. Широко используется в операционных системах Windows для межпроцессного взаимодействия (IPC) [`1`](https://habr.com/ru/companies/rvision/articles/716656/)[`4`](https://superuser.com/questions/616098/what-is-rpc-and-why-is-it-so-important).

### Как работает MS-RPC

NaN. **Инициализация соединения:**
    
    - клиент отправляет **Bind-запрос** к службе **Endpoint Mapper (EPM)** (работает на портах TCP/135 или TCP/593 — RPC over HTTP) [`1`](https://habr.com/ru/companies/rvision/articles/716656/).
        
    - EPM помогает определить параметры подключения к нужному RPC-сервису.
        
    - после аутентификации устанавливается сессия между клиентом и сервером [`1`](https://habr.com/ru/companies/rvision/articles/716656/).
        
NaN. **Вызов процедуры:**
    
    - клиент формирует запрос к удалённой процедуре, упаковывая параметры (сериализация).
        
    - запрос передаётся по сети на сервер.
        
    - сервер выполняет процедуру, используя локальные ресурсы.
        
    - результат сериализуется и возвращается клиенту [`2`](https://ru.ruwiki.ru/wiki/%D0%A3%D0%B4%D0%B0%D0%BB%D1%91%D0%BD%D0%BD%D1%8B%D0%B9_%D0%B2%D1%8B%D0%B7%D0%BE%D0%B2_%D0%BF%D1%80%D0%BE%D1%86%D0%B5%D0%B4%D1%83%D1%80).
        
NaN. **Завершение сессии:**
    
    - после выполнения процедуры соединение может быть закрыто или оставлено для последующих вызовов [`2`](https://ru.ruwiki.ru/wiki/%D0%A3%D0%B4%D0%B0%D0%BB%D1%91%D0%BD%D0%BD%D1%8B%D0%B9_%D0%B2%D1%8B%D0%B7%D0%BE%D0%B2_%D0%BF%D1%80%D0%BE%D1%86%D0%B5%D0%B4%D1%83%D1%80).
        

### Компоненты MS-RPC

- **Endpoint Mapper (EPM)** — служба на сервере, управляющая зарегистрированными RPC-интерфейсами (хранит базу интерфейсов, каждый из которых связан с исполняемым файлом или DLL) [`1`](https://habr.com/ru/companies/rvision/articles/716656/).
    
- **Клиентские и серверные заглушки (stubs)** — промежуточный код, преобразующий вызовы процедур в сетевые сообщения и обратно.
    
- **Транспортная подсистема** — управляет соединениями (использует TCP, UDP, SMB и другие протоколы).
    
- **Компонент маршалинга** — упаковывает параметры вызовов в поток байт, независимый от архитектуры системы.
    
- **Механизмы аутентификации и шифрования** — обеспечивают безопасность передачи данных [`2`](https://ru.ruwiki.ru/wiki/%D0%A3%D0%B4%D0%B0%D0%BB%D1%91%D0%BD%D0%BD%D1%8B%D0%B9_%D0%B2%D1%8B%D0%B7%D0%BE%D0%B2_%D0%BF%D1%80%D0%BE%D1%86%D0%B5%D0%B4%D1%83%D1%80).
    

### Где используется MS-RPC

MS-RPC критически важен для работы Windows и Active Directory. Примеры использования:

- удалённое изменение значений в реестре;
    
- создание и управление задачами и сервисами;
    
- функции аутентификации в домене (Active Directory);
    
- репликация данных между контроллерами домена;
    
- работа MMC-консолей (например, Computer Management);
    
- управление службами и драйверами;
    
- интеграция с DCOM (Distributed COM) для вызова COM-объектов удалённо;
    
- доступ к общим ресурсам (принтеры, папки) [`1`](https://habr.com/ru/companies/rvision/articles/716656/)[`4`](https://superuser.com/questions/616098/what-is-rpc-and-why-is-it-so-important).
    

### Транспортные протоколы

MS-RPC поддерживает несколько транспортных механизмов:

- **TCP/UDP** — базовые сетевые протоколы;
    
- **SMB (Server Message Block)** — для доступа к IPC$ (Interprocess Communication);
    
- **HTTP** (RPC over HTTP) — для работы через веб-прокси;
    
- **Named Pipes** — именованные каналы для локального и сетевого взаимодействия;
    
- **NPs (Named Pipes) и RPC на localhost** — для локальных вызовов [`1`](https://habr.com/ru/companies/rvision/articles/716656/).
    

### Локальные и удалённые вызовы

- **LRPC (Local RPC)** — оптимизирован для локальных вызовов (работает поверх **ALPC — Advanced Local Procedure Call**). Быстрее, чем сетевые RPC.
    
- **DCOM (Distributed COM)** — расширение MS-RPC для работы с COM-объектами. Сначала инициализирует COM-объект, затем вызывает его методы [`1`](https://habr.com/ru/companies/rvision/articles/716656/).
    
- **LPC (Local Procedure Call)** — устаревший механизм локального взаимодействия (используется внутри Microsoft, не напрямую сторонними приложениями) [`1`](https://habr.com/ru/companies/rvision/articles/716656/).
    

### Безопасность

- **Аутентификация** — использует учётные записи Windows (NTLM, Kerberos).
    
- **Шифрование** — поддерживает защиту трафика (например, через RPC over HTTPS).
    
- **Контроль доступа** — использует ACL (Access Control Lists) для ограничения вызовов.
    

### Уязвимости и риски

Из-за широкой распространённости и привилегированного доступа MS-RPC является целью атак:

- **Relay-атаки** (например, PetitPotam) — пересылка аутентификационных запросов.
    
- **DCSync-атаки** — компрометация учётных записей в домене.
    
- **Эксплуатация уязвимостей в EPM** — позволяет злоумышленнику управлять сервисами.
    
- **Использование фреймворков** (например, Impacket) для отправки вредоносных RPC-команд.
    

### Итог

MS-RPC — ключевой механизм межпроцессного взаимодействия в Windows, обеспечивающий:

- прозрачность вызовов (как локальные процедуры);
    
- поддержку распределённых приложений;
    
- интеграцию с Active Directory и DCOM;
    
- совместимость с разными транспортными протоколами.
    

Несмотря на риски безопасности, MS-RPC остаётся неотъемлемой частью инфраструктуры Windows и требует тщательного мониторинга и защиты.
