**Векторный индекс (Vector Index)** — это структура данных для быстрого поиска *похожих векторов* в больших наборах эмбеддингов. Он лежит в основе семантического поиска, рекомендательных систем и [[RAG]]‑приложений.
### Зачем нужен

Без индекса поиск ближайшего вектора требовал бы полного перебора всех записей — это слишком медленно для больших датасетов. Индекс ускоряет поиск в тысячи раз, позволяя находить «ближайших соседей» за доли секунды.
### Как работает

1. **Векторизация**. Данные (текст, изображения и др.) преобразуются в векторы (эмбеддинги) с помощью нейросетей.
2. **Построение индекса**. Векторы организуются в специальную структуру, оптимизированную для поиска по сходству.
3. **Поиск по запросу**. Вектор запроса сравнивается с индексированными векторами; возвращаются наиболее близкие.
### Ключевые метрики сходства
- **Косинусное сходство** (Cosine Similarity): угол между векторами (1 — идентичны, 0 — ортогональны).
- **Евклидово расстояние** (Euclidean Distance): геометрическое расстояние между точками (0 — идентичны).
- **Скалярное произведение** (Dot Product): мера сонаправленности векторов.
### Методы построения индексов (ANN)

**ANN (Approximate Nearest Neighbor)** — класс алгоритмов для *приближённого* поиска ближайших соседей. Они жертвуют долей точности ради скорости.

Распространённые подходы:
1. **Flat Indexing**
   - Полный перебор всех векторов.
   - Точный, но медленный для больших данных.
2. **Locality Sensitive Hashing (LSH)**
   - Векторы хешируются в «корзины» по сходству.  
   - Поиск ведётся только внутри корзины хеша запроса.  
   - Быстро, но возможны пропуски.
3. **Inverted File (IVF)**  
   - Векторы группируются в кластеры (например, k‑means).  
   - Поиск: сначала определяется ближайший кластер, затем перебор внутри него.  
   - Баланс скорости и точности.
4. **HNSW (Hierarchical Navigable Small World)**  
   - Граф с иерархическими слоями: от грубого к детальному поиску.  
   - Высокая скорость и хорошая точность.
5. **DiskANN**  
   - Использует SSD для хранения графа индексов.  
   - Подходит для очень больших датасетов (миллиарды векторов).  
   - Минимизирует чтение с диска.
6. **SPANN (SPTAG‑based ANN)**  
   - Гибридный подход: часть данных в памяти, часть на диске.  
   - Оптимизирован для ультрабольших масштабов.
### Где применяется
- **Семантический поиск**: нахождение документов по смыслу, а не ключевым словам.
- **Рекомендательные системы**: поиск товаров/контента, похожего на предпочтения пользователя.
- **RAG (Retrieval‑Augmented Generation)**: подбор контекста для языковых моделей.
- **Поиск изображений/аудио**: нахождение медиа по содержанию.
- **Антивирусные системы**: обнаружение похожих вредоносных паттернов.
### Плюсы векторного индекса
- **Скорость**: поиск за миллисекунды даже в миллиардах векторов.
- **Масштабируемость**: работа с ультрабольшими датасетами (через DiskANN/SPANN).
- **Гибкость**: поддержка разных типов данных (текст, изображения, аудио).
- **Семантика**: понимание смысла, а не только точного совпадения.
### Минусы
- **Приближённость**: ANN‑алгоритмы могут пропускать самые близкие векторы.
- **Ресурсы**: требует памяти/диска для хранения индекса.
- **Сложность настройки**: выбор алгоритма и параметров зависит от задачи.
### Пример работы
Допустим, у вас есть 10 млн векторов статей.  
1. Вы создаёте IVF‑индекс с 10 000 кластерами.  
2. При запросе вектор статьи преобразуется в эмбеддинг.  
3. Индекс находит 5 ближайших кластеров, затем перебирает 1 000 векторов внутри них.  
4. Возвращает 10 самых похожих статей — в тысячи раз быстрее полного перебора.

**Итог:** векторный индекс + ANN — это «двигатель» современного семантического поиска, позволяющий находить смысл в огромных массивах данных за доли секунды.
