**MLflow** — это открытая (open‑source) платформа для управления **жизненным циклом машинного обучения** (ML). Она помогает организовать эксперименты, обеспечить воспроизводимость, упростить упаковку и развёртывание моделей.

### Ключевые задачи MLflow

- **Отслеживание экспериментов** — фиксация параметров, метрик, версий кода и артефактов (обученных моделей, графиков и др.) для каждого запуска.
- **Воспроизводимость** — упаковка кода и зависимостей так, чтобы любой мог повторить эксперимент и получить те же результаты.
- **Управление моделями** — централизованное хранилище с версионированием и стадиями жизненного цикла («разработка», «тестирование», «продакшн»).
- **Развёртывание моделей** — инструменты для упрощения деплоя в разных средах (локально, в облаке и др.).

### Основные компоненты

1. **MLflow Tracking** — ядро платформы:
   - логирует параметры, метрики и артефакты экспериментов;
   - имеет веб‑интерфейс для просмотра и сравнения запусков;
   - поддерживает разные бэкенды (файловая система, облачные хранилища).

2. **MLflow Projects** — стандарт для упаковки кода ML:
   - описывает проект в файле `MLproject` (YAML);
   - указывает окружение (например, через `conda.yaml`);
   - определяет точки входа (команды для запуска).

3. **MLflow Models** — унифицированный формат упаковки моделей:
   - поддерживает разные фреймворки (scikit‑learn, TensorFlow, PyTorch и др.);
   - автоматически создаёт API для развёртывания.

4. **MLflow Model Registry** — реестр моделей:
   - централизованное хранение обученных моделей;
   - версионирование (например, `ChurnPredictor v2`);
   - управление стадиями: `Staging` (тестирование), `Production` (продакшн), `Archived` (архив);
   - добавление описаний, тегов, отслеживание происхождения модели.

### Как это работает (упрощённо)

1. Вы описываете эксперимент на Python, используя API MLflow (например, `mlflow.log_param()`, `mlflow.log_metric()`).
2. MLflow сохраняет параметры, метрики и артефакты в хранилище (локально или в облаке).
3. Веб‑интерфейс (`mlflow ui`) позволяет просматривать, сравнивать и фильтровать эксперименты.
4. Лучшую модель регистрируете в `Model Registry`, присваивая ей версию и стадию.
5. Модель можно развернуть как REST API или интегрировать в продакшн‑систему.

### Преимущества

- **Открытый код** и активное сообщество.
- **Гибкость** — поддержка разных языков, фреймворков и окружений.
- **Воспроизводимость** — любой может повторить эксперимент с теми же данными и кодом.
- **Централизованное управление** — единый реестр моделей с версионированием и стадиями.
- **Интеграции** — работа с популярными библиотеками (scikit‑learn, TensorFlow, PyTorch) и облаками (AWS, GCP, Azure).
- **Автоматизация** — например, `autolog` автоматически логирует параметры и метрики для многих фреймворков.

### Типичные сценарии использования

- **Исследователи/Data Scientists**: отслеживание экспериментов, сравнение результатов, выбор лучшей модели.
- **ML‑инженеры**: упаковка моделей, развёртывание в продакшн, мониторинг.
- **Команды**: совместная работа над моделями, ревью экспериментов, документирование.
- **DevOps**: интеграция ML‑пайплайнов в CI/CD, деплой в облако.

### Итог

MLflow — это **универсальный «организатор» ML‑проектов**, который:
- убирает хаос в экспериментах;
- обеспечивает воспроизводимость результатов;
- упрощает управление моделями от разработки до продакшна;
- подходит как для одиночных исследователей, так и для команд.

Платформа особенно полезна, если вы:
- проводите много экспериментов с разными параметрами;
- хотите легко воспроизводить результаты;
- планируете развёртывать модели в продакшн;
- работаете в команде и нуждаетесь в общем реестре моделей.

## Эксперимент в MLflow

**Эксперимент в MLflow** — это *основная единица организации и отслеживания работ* в процессе разработки ML‑модели. Он объединяет серию запусков (runs) кода, позволяя сравнивать их параметры, метрики и результаты.

### Суть эксперимента

Эксперимент служит «контейнером», внутри которого:
- фиксируются отдельные запуски модели (*runs*);
- сохраняются параметры, метрики, код и артефакты каждого запуска;
- обеспечивается сравнение версий и выбор лучшей конфигурации.

### Что фиксируется в рамках эксперимента

Для каждого запуска (*run*) автоматически или вручную регистрируются:
- **Параметры** — гиперпараметры модели и настройки (например, `learning_rate=0.01`, `batch_size=32`).
- **Метрики** — числовые показатели качества (accuracy, F1, RMSE и т. п.), замеряемые во время обучения/валидации.
- **Артефакты** — файлы, созданные в ходе запуска:  
  - обученная модель (в форматах pickle, ONNX, TensorFlow SavedModel и др.);
  - графики и визуализации (PNG, PDF);
  - отчёты, логи, таблицы предсказаний (CSV, JSON).
- **Версия кода** — ссылка на коммит в Git или снимок кода на момент запуска.
- **Окружение** — зависимости (conda.yaml, requirements.txt).
- **Теги и заметки** — произвольные метаданные для классификации и поиска (например, `team=cv`, `purpose=baseline`).

### Как создать эксперимент

1. **Через UI**  
   - В веб‑интерфейсе MLflow нажмите «Create Experiment».
   - Укажите имя (например, `churn-prediction-v1`).
   - Получите уникальный ID эксперимента.

2. **Через API (Python)**  
   ```python
   import mlflow

   # Создать новый эксперимент
   experiment_id = mlflow.create_experiment("churn-prediction-v1")

   # Или активировать существующий
   mlflow.set_experiment("churn-prediction-v1")
   ```

### Как записать запуск в эксперимент

Внутри кода эксперимента:
```python
with mlflow.start_run():
    mlflow.log_param("learning_rate", 0.01)
    mlflow.log_metric("accuracy", 0.92)
    mlflow.log_artifact("confusion_matrix.png")
    # Сохранить модель
    mlflow.sklearn.log_model(model, "model")
```

### Зачем нужны эксперименты

- **Воспроизводимость** — можно повторить запуск с теми же параметрами и данными.
- **Сравнение версий** — легко увидеть, какая комбинация гиперпараметров дала лучший результат.
- **Аудит и документация** — все шаги и результаты зафиксированы в едином месте.
- **Совместная работа** — команда видит, кто и что запускал, какие были итоги.
- **Выбор лучшей модели** — на основе метрик и артефактов можно зарегистрировать лучшую версию в `Model Registry`.

### Где хранятся данные эксперимента

- **Локально** — в директории `mlruns/` (по умолчанию).
- **В удалённом сервере MLflow** — если настроен трекинг‑URI (например, `http://your-mlflow-server:5000`).
- **В облаке** — S3, Azure Blob, Google Cloud Storage (при соответствующей настройке бэкенда).

### Как просматривать эксперименты

1. Запустите веб‑интерфейс:  
   ```bash
   mlflow ui
   ```
2. Откройте `http://localhost:5000`.
3. Выберите эксперимент из списка — увидите таблицу всех запусков.
4. Кликните на запуск, чтобы посмотреть:  
   - параметры и метрики;
   - артефакты;
   - график обучения;
   - код и окружение.

### Ключевые преимущества
- **Централизация** — все запуски одного исследования в одном месте.
- **Поиск и фильтрация** — можно отбирать запуски по тегам, метрикам, параметрам.
- **Интеграция с CI/CD** — эксперименты автоматизируют тестирование и деплой.
- **Поддержка команд** — прозрачность для всей команды.


**Итог:** эксперимент в MLflow — это структурированный способ вести «журнал» ML‑исследований: фиксировать, сравнивать и выбирать лучшие модели, не теряя контекста и воспроизводимости.
