## Embedding-model

**Embedding-model** (модель эмбеддингов) — это тип модели машинного обучения, которая преобразует сложные данные (текст, изображения, аудио и др.) в **компактные числовые векторы** (эмбеддинги), сохраняющие смысловые и контекстные связи между объектами.

## Метрики Embedding моделей

### Размер

**Что это?**

Объём модели в памяти — обычно измеряется в **мегабайтах (МБ)** или по количеству **параметров** (например, 110M = 110 миллионов параметров). Английский термин — **Model Size**.

**Зачем это важно?**

- **Маленькие модели** (например, `all-MiniLM-L6-v2`, ~22 МБ) быстро работают даже на CPU и подходят для устройств с ограниченными ресурсами (мобильные, edge-устройства).
- **Большие модели** (например, `e5-mistral-7b`, ~14 ГБ) требуют мощного GPU, но могут давать более точные эмбеддинги.
- Размер влияет на:
  - время загрузки в память;
  - потребление RAM/VRAM;
  - скорость инференса (вывода).

**Пример**

Модель в 500 МБ может не поместиться на Raspberry Pi, но отлично работать на сервере с GPU.

### Dim

**Что это?**

Количество чисел (координат) в одном векторе-эмбеддинге. Например, `dim = 384` означает, что каждый текст превращается в массив из 384 чисел с плавающей точкой. Английский термин — **Dimensionality (размерность эмбеддинга)**.

**Зачем это важно?**

- **Чем выше dim**, тем больше информации может хранить вектор — **но не всегда лучше**.
- Высокая размерность:
  - повышает выразительную способность (в теории);
  - увеличивает потребление памяти и время поиска (особенно в векторных БД);
  - может привести к «проклятию размерности» (разреженность, шум).
- Низкая размерность:
  - экономит ресурсы;
  - иногда даёт сопоставимое качество (если модель хорошо обучена).

**Пример**

- `all-MiniLM-L6-v2` → 384D
- `text-embedding-ada-002` → 1536D
- `bge-m3` → 1024D

При хранении 1 млн эмбеддингов:

- 384D ≈ 1.5 ГБ;
- 1536D ≈ 6 ГБ (только float32).

### Контекст

**Что это?**

Максимальное количество **токенов** (слов, подслов), которое модель может обработать за один вызов. Английский термин — **Context Length (Max Sequence Length)**.

**Зачем это важно?**

- Если текст длиннее контекста — его нужно **разбивать на части (chunking)**, что может испортить смысл.
- Для задач типа **анализа документов, отчётов, книг** критичен длинный контекст.
- Короткий контекст (256 токенов) — норма для старых моделей, но недостаточен для RAG с длинными документами.

**Пример**

- `all-MiniLM-L6-v2`: 256 токенов → ~180 слов
- `bge-m3`: 8192 токенов → ~6000 слов
- `e5-mistral-7b`: 32768 токенов → целые статьи!

### MTEB Score

**Что это?**

Стандартизированный **оценочный бенчмарк**, разработанный Hugging Face и исследователями (2023). Он оценивает эмбеддинг-модели по **57 задачам** в 6 категориях:

1. **Semantic Textual Similarity (STS)** — насколько хорошо модель оценивает схожесть пар предложений.
2. **Retrieval** — поиск релевантных документов по запросу (ключевая для RAG).
3. **Clustering** — группировка похожих текстов.
4. **Classification** — насколько эмбеддинги полезны для ML-классификаторов.
5. **Pair Classification** — бинарная классификация пар (например, «следствие» или нет).
6. **Reranking** — переупорядочивание результатов по релевантности.

**Интерпретация**

- Это **усреднённый нормализованный балл** от 0 до 100 (в реальности максимум ~70–72 на 2025 г.).
- Чем **выше** — тем **универсальнее и точнее** модель.
- Не все задачи одинаково важны: если вы делаете **semantic search**, смотрите подкатегорию **Retrieval**.

**Пример (2025)**

- `bge-m3`: **66.5** → лидер
- `text-embedding-ada-002`: ~62.3
- `all-MiniLM-L6-v2`: ~47.7 → базовый уровень

**Итог**

Выбор модели по ключевой цели:

| Цель | На что смотреть в первую очередь |
|------|-------------------------------|
| **Быстрая работа на слабом устройстве** | → **Размер** и **Dim** |
| **Поиск по длинным документам** | → **Контекст** |
| **Высокая точность в RAG / поиске** | → **MTEB Score**, особенно **Retrieval** |
| **Экономия памяти в векторной БД** | → **Dim** (меньше = дешевле хранить) |

## Сравнение Embedding моделей

Подробное сравнение трёх популярных эмбеддинг-моделей для английского языка — **all-MiniLM-L6-v2**, **text-embedding-ada-002** и **bge-base-en** — по ключевым параметрам на 2025 год.

### Сравнительная таблица

| Параметр | **all-MiniLM-L6-v2** | **text-embedding-ada-002** (OpenAI) | **bge-base-en** (BAAI) |
|----------|----------------------|-------------------------------------|------------------------|
| **Тип модели** | Sentence Transformer (на базе MiniLM, distilled from MPNet) | Проприетарная модель OpenAI | BERT-based (Bidirectional Encoder from BAAI) |
| **Размер модели** | ~22 МБ, 22M параметров | Неизвестен (закрытая), но легче GPT-3 | ~110 МБ, ~110M параметров |
| **Длина контекста** | 256 токенов | **8191 токен** (очень длинный) | 512 токенов |
| **Размер эмбеддинга** | 384 | **1536** | 768 |
| **Производительность (inference speed)** | Очень быстрая (CPU-friendly) | Зависит от API-задержек; нет локального запуска | Умеренная (BERT-уровень) |
| **Локальный запуск** | ✅ Да (Hugging Face, Sentence-Transformers) | ❌ Только через OpenAI API | ✅ Да (Hugging Face) |
| **Лицензия** | MIT (свободная) | Проприетарная (условия использования через API) | Apache 2.0 |
| **Поддержка мультиязычности** | Основной фокус — английский (ограниченная мультиязычность) | Поддерживает множество языков (но обучена в основном на англ.) | Английский (bge-base-en), есть мультиязычные версии (например, **bge-m3**) |
| **Качество (MTEB Benchmark)** | ≈ **47.7** (средний рейтинг по retrieval, STS и др.) | ≈ **62.3** | ≈ **63.0** |
| **Оптимизация под задачи** | Общие sentence embeddings | Универсальная, но особенно хороша в retrieval | Специально обучена для **retrieval** и **semantic search** |
| **Стоимость использования** | Бесплатно | $0.0001/1k токенов (на 2025 г.) | Бесплатно |
| **Поддержка инструкций (instruction-aware)** | ❌ Нет | ❌ Нет | ✅ **Да** (в bge-base-en используется пассивная инструкция, например: *"Represent this sentence for searching relevant passages..."*) |

**MTEB (Massive Text Embedding Benchmark)** — общепринятый бенчмарк для оценки качества эмбеддинг-моделей. Максимум ≈ 70–72 в 2025 г.

### Когда что использовать

| Сценарий | Рекомендуемая модель |
|----------|----------------------|
| **Локальное приложение, ограниченные ресурсы (CPU, память)** | ✅ **all-MiniLM-L6-v2** — маленькая, быстрая, достаточна для простых задач |
| **Высококачественный semantic search в продакшене (облако, нет ограничений на API)** | ✅ **text-embedding-ada-002** — простота, надёжность, длинный контекст |
| **Лучшее качество + локальный запуск + retrieval** | ✅ **bge-base-en** — лидер по качеству среди open-source на 2024–2025 гг. |
| **Длинные документы (>512 токенов)** | ✅ **ada-002** (до 8191) или чанковать текст для BGE |
| **Полный контроль, open-source, модификация модели** | ✅ **bge-base-en** или **all-MiniLM-L6-v2** |

### Примеры использования

**all-MiniLM-L6-v2** (Sentence-Transformers):

```python
from sentence_transformers import SentenceTransformer
model = SentenceTransformer('all-MiniLM-L6-v2')
embeddings = model.encode(["Hello world"])
```

**bge-base-en**:

```python
from sentence_transformers import SentenceTransformer
model = SentenceTransformer('BAAI/bge-base-en')
embeddings = model.encode(["Represent this sentence for searching relevant passages: Hello world"])
```

**text-embedding-ada-002** (OpenAI API):

```python
from openai import OpenAI
client = OpenAI()
response = client.embeddings.create(
    input="Hello world",
    model="text-embedding-ada-002"
)
embeddings = response.data[0].embedding
```

**Вывод**

- **Качество**: `bge-base-en ≈ ada-002 > all-MiniLM-L6-v2`
- **Скорость и размер**: `all-MiniLM-L6-v2 > bge-base-en > ada-002` (если считать локальный инференс)
- **Гибкость**: `bge-base-en` и `all-MiniLM` выигрывают за счёт open-source и локального запуска
- **Долгий контекст**: только **ada-002**

Если вы строите **production-решение без зависимости от API**, **bge-base-en** — лучший выбор в 2025 г.

Если важна **максимальная простота и длинные тексты** — **ada-002**.

Если нужны **минимальные ресурсы и приемлемое качество** — **all-MiniLM-L6-v2**.

## On-Premise Embedding-модели

На 2025 год локальные (on-premise) эмбеддинг-модели стали критически важны для задач, где важны **конфиденциальность, низкая задержка, отсутствие зависимости от API и контроль над инфраструктурой**. Ниже — список самых популярных **open-source эмбеддинг-моделей для локального запуска**, с фокусом на качество, скорость, лицензирование и поддержку.

| **BAAI/bge-m3** | BAAI (Китай) | ~560M | 1024 | 8192 | **66.5** | MIT | ✅ Мультиязычность, dense + sparse + ColBERT эмбеддинги, лидер MTEB |
| **BAAI/bge-base-en-v1.5** | BAAI | ~110M | 768 | 512 | 63.0 | Apache 2.0 | ✅ Инструкция-условная, excellent for retrieval |

## Подробное сравнение

### BAAI/bge-m3

**Особенности**

- ✅ Лучший результат на MTEB (66.5)
- ✅ Поддерживает **dense**, **sparse** и **ColBERT-style** эмбеддинги — можно использовать гибридный поиск
- ✅ Контекст до **8192 токенов**
- ✅ Поддержка **100+ языков**
- ❌ Больше по размеру (требует ~2–4 ГБ VRAM для инференса)

**Идеально для**

Продвинутых retrieval-систем, гибридного поиска, мультиязычных приложений.

### BAAI/bge-base-en-v1.5

**Особенности**

- ✅ Отличное качество при умеренном размере
- ✅ Явная поддержка **инструкций** (автоматически добавляет префикс)
- ✅ Быстро работает даже на CPU
- ❌ Только английский (но есть `bge-m3` для мультиязыка)
- ❌ Контекст ограничен 512 токенами

**Идеально для**

English-only semantic search, RAG, локальных ИИ-ассистентов.

### e5-mistral-7b-instruct

**Особенности**

- ✅ Один из самых длинных контекстов — **32768 токенов**
- ✅ Высокое качество благодаря архитектуре Mistral
- ✅ Поддержка сложных инструкций
- ❌ Требует **GPU с 16+ ГБ VRAM**
- ❌ Медленнее и тяжелее остальных

**Идеально для**

Обработки длинных документов (отчёты, статьи), high-end RAG.

### multilingual-e5-large

**Особенности**

- ✅ Отличная мультиязычная поддержка
- ✅ Хорошее качество (61.5 по MTEB)
- ❌ Контекст всего 512
- ❌ Уступает bge-m3 в качестве и функциональности

**Идеально для**

Мультиязычных приложений без требований к длинному контексту.

### all-MiniLM-L6-v2

**Особенности**

- ✅ Работает на слабых CPU, почти мгновенно
- ✅ Маленький размер (22 МБ)
- ✅ Простая интеграция через `sentence-transformers`
- ❌ Низкое качество по сравнению с новыми моделями
- ❌ Короткий контекст (252 токена)

**Идеально для**

Прототипов, edge-устройств, PoC, когда качество вторично.

### nomic-embed-text-v1.5

**Особенности**

- ✅ Длинный контекст (8192)
- ✅ Открытые данные обучения (на основе Nomic Atlas)
- ✅ Хорошее качество (62.3)
- ❌ Менее популярна, меньше сообщество
- ❌ Требует чуть больше ресурсов, чем bge-base

**Идеально для**

Прозрачных open-data систем с длинными текстами.

## Пример запуска с sentence-transformers

```python
from sentence_transformers import SentenceTransformer

# Пример: bge-m3
model = SentenceTransformer('BAAI/bge-m3', trust_remote_code=True)
embeddings = model.encode("Your text here",
                          batch_size=8,
                          max_length=8192)
```

**Примечание**

Для `bge-m3` требуется `trust_remote_code=True` и установка `flag_embedding`.

## Обновления в 2025 г.

- **bge-m3** вытеснила `e5` и `ada` в open-source сегменте.
- **ColBERT-подобные эмбеддинги** (late interaction) набирают популярность — bge-m3 поддерживает их «из коробки».
- **Long-context embedding** становится стандартом (8K+ токенов).
- Акцент на **instruction-aware** представлениях: модели ожидают, что вы задаёте цель (например, для поиска).
