Разберу все варианты использования аннотации `@Scheduled` в Spring — подробно и с примерами.


## Предварительные требования


Перед использованием `@Scheduled` необходимо **активировать планировщик**, добавив аннотацию `@EnableScheduling` в любой конфигурационный класс:

```java
@Configuration
@EnableScheduling
public class AppConfig { }
```

**Требования к методам с `@Scheduled`:**
* возвращаемый тип — `void`;
* отсутствие параметров;
* не должен быть `private`.

## Варианты настройки @Scheduled


### 1. fixedDelay

Запускает задачу с **фиксированной задержкой** после завершения предыдущей задачи.

* **Принцип:** отсчёт времени начинается **после завершения** предыдущего выполнения.
* **Поток:** по умолчанию все задачи выполняются в одном потоке.
* **Единица измерения:** миллисекунды.

**Пример:**
```java
@Scheduled(fixedDelay = 5000)
public void scheduleFixedDelayTask() {
    log.info("Fixed delay task executed at {}", LocalDateTime.now());
}
```
**Сценарий:** если метод выполняется 3 секунды, а `fixedDelay` = 5 секунд, то между окончанием одной задачи и началом следующей пройдёт 5 секунд (всего 8 секунд).

### 2. fixedRate

Запускает задачу через **фиксированный интервал** времени, **не дожидаясь** завершения предыдущей.

* **Принцип:** новый запуск происходит через указанный интервал, независимо от состояния предыдущей задачи.
* **Проблема:** если задача выполняется дольше, чем интервал `fixedRate`, задачи начнут накапливаться.

**Пример:**
```java
@Scheduled(fixedRate = 3000)
public void scheduleFixedRateTask() {
    log.info("Fixed rate task executed at {}", LocalDateTime.now());
}
```
**Сценарий:** при `fixedRate = 3 с` и выполнении задачи за 5 секунд следующий запуск произойдёт через 3 секунды после начала предыдущей задачи (задачи будут накладываться).

### 3. initialDelay

Задаёт **начальную задержку** перед первым выполнением задачи. Используется совместно с `fixedDelay` или `fixedRate`.

**Пример с `fixedDelay`:**
```java
@Scheduled(fixedDelay = 2000, initialDelay = 5000)
public void delayedTask() {
    log.info("First execution after 5 s, then every 2 s");
}
```
**Результат:** первое выполнение через 5 секунд после старта приложения, последующие — каждые 2 секунды после завершения предыдущей задачи.

### 4. cron

Использует **cron‑выражения** для гибкого планирования задач (например, «каждый день в 3:00»).

**Формат cron‑выражения (6 полей):**
1. секунды (0–59);
2. минуты (0–59);
3. часы (0–23);
4. день месяца (1–31);
5. месяц (1–12 или JAN–DEC);
6. день недели (0–7 или SUN–SAT, где 0 и 7 — воскресенье).

**Примеры:**
* `0 0 9 * * *` — каждый день в 9:00;
* `0 */15 * * * *` — каждые 15 минут;
* `0 0 * * * 1` — каждый понедельник в 0:00.

**Использование:**
```java
@Scheduled(cron = "0 0 3 * * *")
public void dailyCleanup() {
    log.info("Daily cleanup at 3:00 AM");
}
```

### 5. fixedDelayString / fixedRateString / initialDelayString

Позволяют задавать значения задержек **через внешние параметры** (например, из `application.properties`).

**В `application.properties`:**
```properties
task.delay=5000
task.rate=3000
```

**В коде:**
```java
@Scheduled(fixedDelayString = "${task.delay}")
public void parametrizedTask() {
    log.info("Executed with delay from properties");
}

@Scheduled(fixedRateString = "${task.rate}", initialDelayString = "2000")
public void rateParametrizedTask() {
    log.info("Executed with rate from properties");
}
```

### 6. timeUnit

Задаёт единицу измерения времени для `fixedDelayString` / `fixedRateString` (по умолчанию — миллисекунды).

**Допустимые значения:**
* `TimeUnit.MILLISECONDS` (по умолчанию);
* `TimeUnit.SECONDS`;
* `TimeUnit.MINUTES` и т. д.

**Пример:**
```java
@Scheduled(
    fixedDelayString = "5",
    timeUnit = TimeUnit.SECONDS
)
public void delayInSeconds() {
    log.info("Executed every 5 seconds");
}
```

## Практические примеры комбинаций

### Пример 1. Ежедневная отчётность в 2:00
```java
@Scheduled(cron = "0 0 2 * * *")
public void generateDailyReport() {
    reportService.generate();
}
```

### Пример 2. Очистка кэша каждые 10 минут с начальной задержкой 1 минута
```java
@Scheduled(fixedRate = 600_000, initialDelay = 60_000)
public void clearCache() {
    cacheManager.clear();
}
```

### Пример 3. Параметризованная задача с единицами времени
```java
@Scheduled(
    fixedDelayString = "${cache.refresh.interval}",
    timeUnit = TimeUnit.MINUTES
)
public void refreshCache() {
    cacheService.refresh();
}
```
В `application.properties`:
```properties
cache.refresh.interval=15
```

## Важные нюансы и рекомендации

1. **Многопоточность.** По умолчанию все задачи выполняются в одном потоке. Для параллельного выполнения:
   * добавьте `@EnableAsync` на класс;
   * поставьте `@Async` на метод.
   **Осторожно:** может привести к утечке памяти, если задачи выполняются долго.

2. **Обработка ошибок.** Исключения в `@Scheduled`-методах могут остановить выполнение последующих задач. Используйте try‑catch или настройте обработку ошибок.

3. **Распределённые системы.** В кластере Spring запускает задачи на всех узлах. Для запуска один раз на кластер используйте:
   * распределённые блокировки (JDBC, Redis);
   * библиотеки типа ShedLock.

4. **Мониторинг.** Для отслеживания выполнения задач:
   * логируйте начало/конец выполнения;
   * используйте метрики (Prometheus, Micrometer).

5. **Тестирование.** Для тестирования планировщика:
   * отключайте `@Scheduled` в тестах (`@Profile("!test")` или `@ConditionalOnProperty`);
   * тестируйте бизнес‑логику отдельно от планировщика.

6. **Приоритет параметров.** Если указаны несколько параметров, приоритет:
   7. `cron`;
   8. `fixedRate`;
   9. `fixedDelay`.

10. **Проверка корректности cron‑выражений.** Используйте онлайн‑генераторы или валидаторы cron‑выражений.

## Краткий итог

| Параметр | Назначение | Когда использовать |
|--------|-----------|----------------|
| `fixedDelay` | Задержка после завершения предыдущей задачи | Задачи, которые не должны накладываться друг на друга |
| `fixedRate` | Фиксированный интервал между запусками | Регулярные задачи с точным интервалом |
| `initialDelay` | Начальная задержка перед первым запуском | Нужно отложить первое выполнение |
| `cron` | Гибкое расписание по cron‑выражению | Запуск в определённое время (ежедневно, еженедельно и т. д.) |
| `fixedDelayString`/`fixedRateString` | Внешние параметры задержки | Нужно настраивать интервалы через `application.properties` |
| `timeUnit` | Единица измерения времени | Использование секунд/минут вместо миллисекунд |
