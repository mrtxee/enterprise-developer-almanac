В Spring-приложении можно легко использовать значения из переменных окружения либо значения по умолчанию — это делается в конфигурационных файлах через синтаксис плейсхолдеров `${VAR:default}`. Spring Boot сам по себе берет настройки из переменных окружения, system properties или файлов конфигурации, при этом переменные окружения имеют приоритет над файлами.

Пример в application.yml
```yml
# Здесь будет использовано значение из переменной окружения PORT, если она задана; иначе будет использоваться значение 8080.
server:
  port: ${PORT:8080}
```

Пример в application.properties
```toml
# Если переменная окружения MY_ENV_VAR не установлена, будет использовано defaultValue.
custom.value=${MY_ENV_VAR:defaultValue}
```

В коде с помощью `@Value`
```java
// сначала ищется переменная окружения MY_ENV_VAR, если такой нет — используется defaultVal.
@Value("${MY_ENV_VAR:defaultVal}")
private String myValue;

```

Особенности работы
В именах переменных окружения нельзя использовать точки, их обычно заменяют на подчеркивания (MY_ENV_VAR), а в Java-проперти можно все обозначить точками (my.env.var). Spring автоматически преобразует такие имена из переменных окружения.

Приоритеты: 
- параметры командной строки 
	- переменные окружения 
		- `application.yml/properties` внутри JAR 
			- значения по умолчанию в коде.

Этот механизм универсален для Spring Boot и стандартного Spring, и позволяет гибко конфигурировать приложение для разных окружений без изменения исходников или пересборки.
