# Immutable-объекты

> **Immutable-объекты нужны для безопасности, потокобезопасности, простоты и предсказуемости.**  
> Они **не могут быть изменены после создания**, что исключает множество ошибок и уязвимостей.

---

## 🧩 Подробнее: ключевые причины использования immutable-объектов

### 1. 🔒 Потокобезопасность (Thread Safety)

Immutable-объекты **автоматически потокобезопасны** — их можно свободно передавать между потоками **без синхронизации**.

> 💡 **Мутируемые объекты** в многопоточной среде требуют `synchronized`, `volatile`, `Lock` и т.д. — это сложно и подвержено ошибкам.

---

### 2. 🛡️ Защита от побочных эффектов

Если метод возвращает immutable-объект — ты **гарантированно знаешь**, что:
- Он не изменится "под капотом".
- Вызывающий код не сможет его испортить.

Например в сервисе упраления доступом или кэширования при запросе состояний следует воз возвращать копию или immutable-коллекцию

---

### 3. ✅ Простота и предсказуемость

Immutable-объекты:

- Легко понимать — их состояние фиксировано.
- Легко тестировать — нет скрытых изменений состояния.
- Не имеют "истории" — всегда в одном, известном состоянии.

> 💡 Это особенно важно в **функциональном программировании**, где чистые функции не имеют побочных эффектов.

---

### 4. 🗃️ Использование в качестве ключей в хеш-таблицах

Immutable-объекты **безопасны как ключи в `HashMap`, `HashSet`**.

Почему?

- Хеш-код (`hashCode()`) должен быть **стабильным**.
- Если объект изменится после добавления в `HashMap` — он может "потеряться", потому что его хеш-код изменится.

### 5. 🧪 Кэширование и переиспользование

Immutable-объекты можно **безопасно кэшировать и переиспользовать**.

Примеры в Java:
- **String Pool**:  
  ```java
  String a = "hello";
  String b = "hello";
  assert a == b; // true — один и тот же объект в пуле
  ```

- **Константы `BigInteger`, `BigDecimal`**:  
  `BigInteger.ZERO`, `BigDecimal.ONE` — глобальные immutable-константы.

---

### 6. 🧱 Построение надёжных систем

Immutable-объекты упрощают:
- **[[Domain-Driven Design]] ([[Domain-Driven Development]])** — value objects должны быть immutable.
- **[[Event Sourcing]]** — события immutable по определению.
- **React-style UI** — состояние immutable → легко отслеживать изменения.

## **Когда использовать Immutable объекты?**

✅ **Идеально для**:
- [[PoEAA|DTO]]
- Конфигурационные объекты
- Ключи в Map
- Состояния в многопоточных приложениях
- Значения, которые не должны меняться

## ✅ Как создать immutable-класс в Java?

```java
public final class Person {
    private final String name;
    private final int age;

    public Person(String name, int age) {
        this.name = name;
        this.age = age;
    }

    public String getName() { return name; }
    public int getAge() { return age; }

    // НЕТ сеттеров!
    // Все поля — final
    // Класс — final (чтобы нельзя было наследоваться и добавить mutable-поля)
}
```

> 💡 Для коллекций: оборачивай в `Collections.unmodifiableList()` или используй `List.copyOf()` (Java 10+).

## 🆚 Mutable vs Immutable: сравнение

| Критерий | Mutable | Immutable |
|---------|--------|----------|
| Потокобезопасность | ❌ Требует синхронизации | ✅ Автоматически безопасен |
| Безопасность как ключ в Map | ❌ Опасно | ✅ Безопасно |
| Побочные эффекты | ✅ Возможны | ❌ Исключены |
| Потребление памяти | ✅ Менее (изменяется на месте) | ⚠️ Более (создаётся новый объект при "изменении") |
| Производительность | ✅ Быстрее при частых изменениях | ⚠️ Медленнее при частых "изменениях" |
| Простота отладки | ❌ Сложнее (состояние меняется) | ✅ Проще (состояние фиксировано) |

## 📌 Где в Java используются immutable-объекты?

| Класс | Почему immutable? |
|------|-------------------|
| `String` | Безопасность, String Pool, ключи в Map |
| `Integer`, `Long`, ... (wrapper-классы) | Безопасность, кэширование, ключи |
| `LocalDateTime`, `Instant` (java.time) | Предсказуемость, безопасность в многопоточности |
| `BigInteger`, `BigDecimal` | Точность, безопасность в вычислениях |
| `Optional<T>` | Логическая целостность |

# effectively immutable
## ⚠️ Важный нюанс: "эффективная неизменяемость"

Иногда объект **mutable по структуре**, но **effectively immutable** — если после публикации его никто не изменяет.

Пример:

```java
final List<String> items = List.of("a", "b", "c"); // immutable list
```

→ Такой объект можно безопасно использовать как immutable.

## ✅ Вывод

> **Immutable-объекты — это фундаментальный паттерн для написания надёжного, безопасного и простого кода.**  
> Они особенно важны в:
> - многопоточных приложениях,
> - системах с высокими требованиями к безопасности,
> - функциональном и реактивном программировании.

> 💡 **Правило большого пальца**:  
> **Делай классы immutable по умолчанию. Делай их mutable только если есть веская причина.**

---

## 🚀 Советы

- Используй `record` (Java 14+) — они immutable по умолчанию:
  ```java
  public record Person(String name, int age) {}
  ```
- В коллекциях — используй `List.copyOf()`, `Set.copyOf()`, `Map.copyOf()`.
- Избегай публичных mutable-полей.
- Возвращай копии или immutable-обёртки из геттеров.
