Разберу подробно, что такое `package‑info.java` — назначение, структуру и практическое применение.


## Что это за файл

**`package-info.java`** — специальный Java‑файл, который **описывает и аннотирует пакет целиком**, а не отдельный класс. Он:
* располагается в той же директории, что и классы пакета;
* не содержит определения класса;
* служит для хранения метаданных и документации на уровне пакета.

## Структура файла

Базовый шаблон `package-info.java`:

```java
/**
 * Javadoc‑документация пакета: описание назначения,
 * состава, принципов использования и т. д.
 */
@PackageAnnotation1
@PackageAnnotation2
package com.yourcompany.yourpackage;

import some.package.AnnotationClass;
```

Обязательные элементы:
1. **Javadoc‑комментарий** (опционально, но рекомендуется) — описание пакета.
2. **Объявление пакета** (`package ...;`) — обязательно.
3. **Аннотации уровня пакета** (опционально) — метаданные для всего пакета.
4. **Импорты** (если нужны для аннотаций) — опционально.

## Основные функции

### 1. Документация пакета (Javadoc)

Позволяет дать высокоуровневое описание пакета, которое будет включено в сгенерированную документацию.

**Пример:**
```java
/**
 * Пакет содержит сервисы бизнес‑логики приложения.
 *
 * Основные компоненты:
 * <ul>
 *   <li>UserService — управление пользователями</li>
 *   <li>OrderService — обработка заказов</li>
 * </ul>
 *
 * @since 1.0
 * @author Team A
 */
package com.example.service;
```

### 2. Аннотации уровня пакета

Применяет метаданные ко **всем классам в пакете** без дублирования.

**Популярные примеры:**
* `@NonNullApi` (Spring) — все параметры и возвращаемые значения не могут быть `null` по умолчанию;
* `@NonNullFields` (Spring) — поля классов не могут быть `null`;
* `@Experimental` — пакет считается экспериментальным;
* `@Deprecated` — пакет устарел;
* `@TypeDefs` (Hibernate) — определение пользовательских типов для всего пакета.

**Пример с @NonNullApi:**
```java
/**
 * Все параметры методов и возвращаемые значения в этом пакете
 * не могут быть null, если не указано иное @Nullable.
 */
@NonNullApi
package com.example.utils;

import org.springframework.lang.NonNullApi;
```

## Практические примеры использования

### Пример 1. Базовая документация

Файл: `src/main/java/com/example/model/package-info.java`
```java
/**
 * Модели данных приложения (DTO, сущности).
 *
 * Пакеты этого слоя:
 * <ul>
 *   <li>entity — JPA‑сущности</li>
 *   <li>dto — объекты передачи данных</li>
 * </ul>
 *
 * @version 2.1
 */
package com.example.model;
```

### Пример 2. Аннотации для null‑безопасности

Файл: `src/main/java/com/example/service/package-info.java`
```java
/**
 * Сервисы бизнес‑логики. Все методы ожидают не‑null параметры
 * и возвращают не‑null результаты, если не помечено @Nullable.
 */
@NonNullApi
@NonNullFields
package com.example.service;

import org.springframework.lang.NonNullApi;
import org.springframework.lang.NonNullFields;
```

### Пример 3. Устаревший пакет

Файл: `src/main/java/com/example/legacy/package-info.java`
```java
/**
 * Устаревшие компоненты. Не использовать в новом коде.
 * Мигрируйте на com.example.service.
 *
 * @deprecated С версии 2.0, будет удалён в 3.0.
 */
@Deprecated
package com.example.legacy;
```

## Преимущества использования

1. **Централизованная документация** — описание пакета в одном месте, доступное через Javadoc.
2. **Снижение дублирования** — аннотации применяются ко всем классам пакета разом.
3. **Улучшение анализа кода** — инструменты (IDEA, FindBugs, компилятор) используют аннотации для проверок.
4. **Чёткие контракты API** — разработчики сразу видят правила использования пакета (например, null‑безопасность).
5. **Поддержка фреймворков** — Hibernate, Spring и др. читают аннотации уровня пакета для конфигурации.
6. **Версионирование и метаданные** — указание автора, версии, статуса (устарел/экспериментальный).

## Важные нюансы

* **Расположение:** файл должен находиться в той же папке, что и классы пакета.
* **Имя:** строго `package-info.java` (не `package_info.java`, не `PackageInfo.java`).
* **Компиляция:** включается в сборку как обычный `.java`-файл.
* **Ограничения:**
    * не может содержать классы, интерфейсы или перечисления;
    * аннотации должны иметь `@Target(ElementType.PACKAGE)`;
    * не заменяет документацию отдельных классов.

## Когда стоит создавать package-info.java

Создавайте файл, если нужно:
* документировать назначение пакета и его компонентов;
* применить общие аннотации ко всем классам (null‑безопасность, экспериментальный статус и т. п.);
* указать версию, автора или лицензию пакета;
* пометить пакет как устаревший (`@Deprecated`);
* настроить фреймворк (Hibernate, Spring) через аннотации уровня пакета;
* обеспечить совместимость с инструментами статического анализа.

## Краткий итог

**`package-info.java`** — это «паспорт» Java‑пакета. Он:
* даёт высокоуровневое описание содержимого пакета (через Javadoc);
* позволяет применять аннотации ко всем классам сразу;
* улучшает поддерживаемость и понимание кода;
* интегрируется с инструментами разработки и фреймворками.

Используйте его для:
* публичных библиотек и API;
* крупных проектов с множеством пакетов;
* команд, где важна стандартизация и документация;
* проектов, использующих Spring, Hibernate или строгие правила null‑безопасности.
